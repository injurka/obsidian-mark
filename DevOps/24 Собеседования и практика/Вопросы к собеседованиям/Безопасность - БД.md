# Безопасность Баз Данных (БД)

## 📖 DevOps-история: Боль и Решение
**Боль:** В пятницу вечером техподдержка получает сообщение об утечке данных пользователей. Оказалось, что база данных PostgreSQL была развернута в публичной подсети с открытым портом 5432, а пароль `admin:admin` был захардкожен в репозитории микросервиса.
**Решение:** База перенесена в изолированную приватную подсеть (VPC Private Subnet). Доступ к ней ограничен через Security Groups. Хардкод убран: внедрен HashiCorp Vault для динамической генерации временных учетных данных и ротации паролей. Включено шифрование данных в покое (at-rest) и в транзите (in-transit).

## 💻 Примеры

### Настройка динамических секретов (HashiCorp Vault)
```bash
# Включаем database secrets engine
vault secrets enable database

# Настраиваем подключение Vault к PostgreSQL
vault write database/config/my-postgres \
    plugin_name="postgresql-database-plugin" \
    allowed_roles="my-role" \
    connection_url="postgresql://{{username}}:{{password}}@postgres:5432/mydb" \
    username="vault_admin" \
    password="strong_vault_password"

# Создаем роль, которая будет генерировать read-only учетки
vault write database/roles/my-role \
    db_name="my-postgres" \
    creation_statements="CREATE ROLE \"{{name}}\" WITH LOGIN PASSWORD '{{password}}' VALID UNTIL '{{expiration}}'; GRANT SELECT ON ALL TABLES IN SCHEMA public TO \"{{name}}\";" \
    default_ttl="1h" \
    max_ttl="24h"
```

### Настройка TLS в PostgreSQL (`postgresql.conf`)
```ini
ssl = on
ssl_cert_file = '/etc/ssl/certs/db.crt'
ssl_key_file = '/etc/ssl/private/db.key'
# Требовать TLS v1.2+
ssl_min_protocol_version = 'TLSv1.2'
```

## 🛠️ Day 2 Operations (Советы по эксплуатации)
- **Ротация без даунтайма:** При использовании Vault настраивайте приложения так, чтобы они умели обрабатывать потерю соединения и запрашивать новые креды (connection pool management).
- **Audit Logging:** Включайте и собирайте логи аудита (кто, когда и какие запросы делал). Отправляйте их в SIEM/Elasticsearch, изолированно от разработчиков.
- **Мониторинг:** Настройте алерты на аномальное количество неудачных попыток входа (brute-force).

## 🚫 Антипаттерны
- **Общий пользователь (Superuser):** Использование одной и той же УЗ `postgres` или `root` для всех микросервисов. (Каждому сервису — свой юзер с минимальными правами).
- **Секреты в Git:** Хранение логинов и паролей от продакшена в `.env` файлах, закомиченных в репозиторий.
- **Публичный доступ:** Открытые порты 5432, 3306 или 27017 в мир `0.0.0.0/0`.
- **Отсутствие шифрования диска:** Хранение данных на нешифрованных EBS/SSD томах (отсутствие Encryption At-Rest).
