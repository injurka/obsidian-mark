# Основы Terraform и OpenTofu

## 📖 DevOps-история: Решение боли

**Боль:** Инженеры вручную создавали серверы через веб-консоль провайдера. Конфигурация серверов стала различаться (configuration drift), никто не знал актуальное состояние инфраструктуры, а масштабирование занимало недели. Ошибка в клике привела к удалению важной базы данных без возможности аудита.

**Решение:** Внедрение **Terraform** (и его open-source форка **OpenTofu**). Инфраструктура стала описываться кодом (IaC). Появился предсказуемый процесс деплоя: код проверяется в Git, изменения планируются до применения, а текущее состояние хранится в `tfstate`.

## 🏗 Архитектура и Workflow

```mermaid
graph TD
    A[🧑‍💻 Инженер (Код)] -->|terraform init| B(Загрузка провайдеров)
    A -->|terraform plan| C{Сравнение со State}
    C -->|Diff| D[Ожидаемые изменения]
    A -->|terraform apply| E[Изменение в Cloud/API]
    E --> F[(Terraform State)]
    F --> C
```

## 🛠 Примеры

### Bash: Базовый рабочий процесс
```bash
# Инициализация (загрузка провайдеров и модулей)
terraform init

# Проверка форматирования и валидация
terraform fmt -check
terraform validate

# Планирование изменений
terraform plan -out=tfplan

# Применение изменений
terraform apply tfplan
```

### HCL: Пример базового ресурса

## 🌅 Day 2 Operations (Обслуживание)

1. **State Management:**
   - Хранение `terraform.tfstate` удаленно (S3, GCS, Consul).
   - Обязательное использование **State Locking** (например, DynamoDB для AWS) для предотвращения одновременного изменения состояния разными инженерами.
2. **Управление Drift:** 
   - Регулярный запуск `terraform plan` в CI/CD (например, каждую ночь) для обнаружения ручных изменений в облаке.
3. **Безопасность:**
   - Интеграция `tfsec` или `checkov` в пайплайн для сканирования уязвимостей до деплоя.
   - Использование RBAC для доступа к State-файлу.

## 🚫 Антипаттерны

- ❌ **Hardcode секретов:** Хранение паролей и токенов прямо в коде (используйте AWS Secrets Manager, Vault или переменные окружения).
- ❌ **ClickOps:** Ручное изменение ресурсов через консоль облака в обход Terraform.
- ❌ **Монолитный State:** Хранение всей инфраструктуры компании в одном state-файле. (Разделяйте по окружениям и компонентам: `prod/network`, `prod/app`).
- ❌ **Игнорирование версий:** Отсутствие жесткой фиксации версий провайдеров и модулей (приведет к поломкам при обновлениях).
