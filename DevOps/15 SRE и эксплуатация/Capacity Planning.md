# Capacity Planning (Планирование мощностей)

## DevOps-история: Боль и Решение
**Боль:** Проект готовился к масштабной рекламной кампании (Черная пятница). Владельцы бизнеса попросили "добавить серверов". Админы увеличили мощности в 3 раза вручную, потратив огромный бюджет. Однако сервис всё равно упал, так как узким местом оказался не CPU, а IOPS на дисках базы данных.
**Решение:** Внедрение нагрузочного тестирования, профилирования и автоматического масштабирования. Вместо угадывания — принятие решений на основе метрик (Data-Driven) и прогнозирования трендов.

## Примеры: Практическая реализация

### Kubernetes Horizontal Pod Autoscaler (HPA)
Автоматическое управление capacity на уровне приложения:

```yaml
apiVersion: autoscaling/v2
kind: HorizontalPodAutoscaler
metadata:
  name: frontend-scaler
spec:
  scaleTargetRef:
    apiVersion: apps/v1
    kind: Deployment
    name: frontend
  minReplicas: 3
  maxReplicas: 20
  metrics:
  - type: Resource
    resource:
      name: cpu
      target:
        type: Utilization
        averageUtilization: 70
```

### PromQL для прогнозирования
Предсказание исчерпания диска через 7 дней на основе линейной регрессии за последние сутки:

```promql
predict_linear(node_filesystem_free_bytes{fstype="ext4"}[24h], 7 * 24 * 3600) < 0
```

## Советы: Day 2 Operations
- **Dark Launches и Теневой трафик:** Проверяйте capacity, дублируя реальный трафик с продакшена на тестовые стенды.
- **Graceful Degradation:** Планируйте, какие некритичные функции можно отключить при перегрузке (например, рекомендации товаров), чтобы спасти основной флоу (чекаут).
- **Chaos Engineering:** Регулярно "убивайте" ресурсы, чтобы проверить, как инфраструктура справляется с потерей capacity.

## Антипаттерны
- ❌ **Масштабирование только по CPU/RAM:** Игнорирование сетевых лимитов, квот облачных провайдеров, IOPS или лимитов пула коннектов БД.
- ❌ **"Запас карман не тянет":** Запуск кластера с 50% запасом по ресурсам "на всякий случай" без HPA, что приводит к гигантским счетам за облако.
- ❌ **Разовое тестирование перед релизом:** Capacity planning — это непрерывный процесс, а не разовая задача перед запуском.
