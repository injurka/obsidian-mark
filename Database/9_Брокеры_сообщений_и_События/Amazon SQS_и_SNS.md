# Amazon SQS и SNS

Два основных сервиса для обмена сообщениями и событийно-ориентированной архитектуры в AWS. Часто используются вместе.

## Amazon SQS (Simple Queue Service)
Полностью управляемый брокер сообщений (Message Queue).
- **Модель**: Point-to-Point. Один издатель кладет сообщение в очередь, один из обработчиков (Consumer) забирает его. Сообщение обрабатывается только один раз.
- **Типы очередей**:
    - **Standard**: Гарантирует доставку хотя бы один раз (At-Least-Once), максимальная пропускная способность, но порядок сообщений может нарушаться (Best-effort ordering).
    - **FIFO (First-In-First-Out)**: Строго гарантирует порядок и доставку ровно один раз (Exactly-Once), но имеет лимиты по пропускной способности.
- **Применение**: Развязка (Decoupling) микросервисов, сглаживание пиковых нагрузок (Buffer/Spike smoothing), фоновая обработка задач (например, отправка email, обработка изображений).

## Amazon SNS (Simple Notification Service)
Управляемый сервис обмена сообщениями типа Publish/Subscribe.
- **Модель**: Pub/Sub. Один издатель отправляет сообщение в "Топик" (Topic). Сообщение получают все подписчики этого топика.
- **Подписчики**: Могут быть очереди SQS, AWS Lambda, HTTP/S эндпоинты, Email, SMS.
- **Применение**: Вещание событий множеству систем (Fan-out). Например: заказ оплачен -> SNS Topic -> (SQS Склад, SQS Нотификации, Lambda Аналитика).
