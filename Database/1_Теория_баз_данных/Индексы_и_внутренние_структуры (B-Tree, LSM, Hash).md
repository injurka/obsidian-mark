# Индексы и внутренние структуры (B-Tree, LSM, Hash)

## B-Tree (B-деревья)
Классическая структура для реляционных БД (OLTP).
- **Структура**: Сбалансированное дерево поиска. Данные (или указатели на них) хранятся в листовых узлах.
- **Особенности**:
    - Глубина дерева мала, что обеспечивает быстрый поиск O(log N).
    - Оптимизировано для чтения (Point reads) и сканирования диапазонов (Range scans).
    - При случайной записи может происходить фрагментация и перестроение дерева (overhead).
- **Применение**: Основной индекс в PostgreSQL, MySQL, Oracle.

## LSM-Tree (Log-Structured Merge-Tree)
Структура, оптимизированная для высокой скорости записи (Write-heavy workloads).
- **Структура**: Данные сначала пишутся в память (MemTable) и в последовательный лог (WAL). При заполнении MemTable сбрасывается на диск в виде неизменяемого отсортированного файла (SSTable).
- **Особенности**:
    - **Запись**: Очень быстрая, так как является последовательной (append-only).
    - **Чтение**: Может быть медленнее, так как требует поиска по MemTable и нескольким SSTable. Для ускорения применяются Bloom-фильтры.
    - **Compaction (Сжатие)**: Периодический процесс слияния нескольких SSTable в один, удаления удаленных и старых версий данных.
- **Применение**: Cassandra, RocksDB, ClickHouse (MergeTree), LevelDB.

## Hash-индексы
Используют хэш-таблицы для поиска данных.
- **Особенности**:
    - Очень быстрый точечный поиск O(1).
    - **Не поддерживают** поиск по диапазону (например, `WHERE age > 20`), сортировку или поиск по префиксу.
- **Применение**: In-memory БД (Redis, Memcached), PostgreSQL (как опциональный индекс).
