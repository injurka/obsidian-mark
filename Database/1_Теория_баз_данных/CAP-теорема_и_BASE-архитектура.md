# CAP-теорема и BASE-архитектура

## CAP-теорема
CAP-теорема (теорема Брюера) утверждает, что распределенная система данных может обеспечить одновременно не более двух из трех следующих свойств:
- **C (Consistency, Согласованность)**: Каждое чтение получает самую последнюю запись или ошибку. Все узлы видят одни и те же данные в одно и то же время.
- **A (Availability, Доступность)**: Каждый запрос получает (не содержащий ошибку) ответ, без гарантии, что он содержит самую последнюю запись.
- **P (Partition tolerance, Устойчивость к разделению)**: Система продолжает работать, несмотря на произвольное количество сообщений, отброшенных (или задержанных) сетью между узлами.

В условиях реальных сетей (где всегда может произойти P) системы делятся на:
- **CP-системы**: Гарантируют согласованность при разделении сети, но могут быть недоступны. (Примеры: MongoDB, HBase, Redis (в некоторых режимах)).
- **AP-системы**: Гарантируют доступность при разделении сети, но могут возвращать устаревшие данные. (Примеры: Cassandra, CouchDB).
- *(CA-системы существуют только в теории или локальных сетях без разделений)*.

## BASE-архитектура
В противовес строгим ACID транзакциям реляционных БД, многие NoSQL решения используют BASE архитектуру для достижения высокой доступности и масштабируемости:
- **BA (Basically Available, Базовая доступность)**: Система гарантирует наличие ответа на запрос (хотя бы ответа об ошибке или устаревших данных), сбои отдельных узлов не приводят к отказу всей системы.
- **S (Soft state, Гибкое состояние)**: Состояние системы может изменяться со временем, даже если нет входных данных (из-за процесса синхронизации).
- **E (Eventual consistency, Согласованность в конечном счете)**: Система в конечном итоге (при отсутствии новых изменений) придет к согласованному состоянию.
