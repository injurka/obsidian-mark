# Паттерны кеширования (Cache-Aside, Write-Through)

Кеширование используется для снижения нагрузки на основную БД и ускорения ответов системы.

## Cache-Aside (Lazy Loading)
Приложение само управляет как кешем, так и БД.
- **Чтение**: Приложение сначала ищет данные в кеше (Cache Hit). Если данных нет (Cache Miss), оно читает их из БД, записывает в кеш и возвращает.
- **Запись**: Приложение пишет данные в БД, а затем **инвалидирует** (удаляет) соответствующие данные в кеше.
- **Плюсы**: Кешируются только запрашиваемые данные; простая логика при сбоях кеша.
- **Минусы**: Задержка при Cache Miss (приходится делать 3 операции); риск получить устаревшие данные (Stale Data) при проблемах с инвалидацией.

## Write-Through
Кеш находится "между" приложением и БД. Приложение общается только с кешем.
- **Запись**: Приложение пишет данные в кеш. Кеш **синхронно** пишет данные в БД.
- **Плюсы**: Данные в кеше всегда актуальны; код приложения проще.
- **Минусы**: Запись становится медленнее (надо ждать записи и в кеш, и в БД); в кеш могут попадать данные, которые никогда не будут прочитаны.

## Write-Behind (Write-Back)
- **Запись**: Приложение пишет в кеш, и на этом его работа заканчивается. Кеш **асинхронно** (через какое-то время или порциями) сбрасывает данные в БД.
- **Плюсы**: Максимальная скорость записи.
- **Минусы**: Высокий риск потери данных, если кеш упадет до того, как сбросит данные в БД; сложная реализация консистентности.

## Read-Through
Аналогичен Write-Through, но для чтения.
- **Чтение**: Приложение запрашивает кеш. Если данных нет, кеш **сам** (прозрачно для приложения) подтягивает их из БД, сохраняет у себя и отдает.
