# Блокировки и MVCC

## Блокировки (Locks)
Механизм контроля конкурентного доступа к данным.
- **Pessimistic Locking (Пессимистическая блокировка)**: Блокирует данные на всё время транзакции, предполагая высокий риск конфликтов.
    - **Shared Lock (S-lock, Блокировка чтения)**: Позволяет другим транзакциям читать, но не изменять данные.
    - **Exclusive Lock (X-lock, Блокировка записи)**: Запрещает и чтение, и запись другим транзакциям.
- **Optimistic Locking (Оптимистическая блокировка)**: Не блокирует данные при чтении. При записи проверяет (например, по версии или timestamp), не изменил ли данные кто-то другой. Если изменил — транзакция откатывается. Эффективна при редких конфликтах.

## MVCC (Multi-Version Concurrency Control)
Механизм обеспечения конкурентного доступа, используемый для избежания блокировок чтения.
- **Принцип**: Каждая транзакция видит "снимок" (snapshot) базы данных на определенный момент времени. Запись не блокирует чтение, а чтение не блокирует запись.
- **Как работает**: 
    - При обновлении строки БД не перезаписывает её, а создает новую версию (с меткой времени или идентификатором транзакции).
    - Старые версии сохраняются до тех пор, пока есть активные транзакции, которые могут их читать.
    - Сборщик мусора (Vacuum в PostgreSQL) удаляет устаревшие версии строк, которые больше никому не нужны.
- **Преимущества**: Высокая производительность и согласованность чтения при конкурентной нагрузке.
- **Примеры**: Широко используется в PostgreSQL, MySQL (InnoDB), Oracle.
