### **Шаг 2.1: Реализация атрибутов: Здоровье, Голод, Жажда, Температура тела**

**Задача:** Создать модульную и расширяемую систему, которая управляет основными физиологическими показателями персонажа. Эта система должна работать независимо от самого персонажа (в виде компонента), отслеживать текущие и максимальные значения атрибутов, а также обеспечивать их постепенное изменение с течением времени.

**Философия:**
1.  **Компонентный Подход:** Вместо того чтобы перегружать класс `FF_Character` логикой выживания, мы создадим отдельный `ActorComponent` под названием `USurvivalComponent`. Это делает систему модульной: в будущем мы сможем прикрепить ее к любому другому актору, если потребуется (например, к прирученному существу).
2.  **Структура данных `FAttribute`:** Чтобы не создавать кучу отдельных переменных (`CurrentHealth`, `MaxHealth`, `CurrentHunger`, `MaxHunger` и т.д.), мы создадим одну универсальную структуру `FAttribute`, которая будет содержать текущее и максимальное значение. Это сделает код чище и проще для расширения.
3.  **Event-Driven (Событийно-ориентированный) подход:** Вместо того чтобы HUD (пользовательский интерфейс) каждый кадр "спрашивал" у компонента "а какое у тебя здоровье?", мы сделаем наоборот. Компонент сам будет "кричать" (транслировать событие/делегат) каждый раз, когда его атрибут изменяется. HUD подпишется на эти события и будет обновляться только тогда, когда это действительно нужно. Это гораздо эффективнее и является лучшей практикой.
4.  **Репликация (Задел на будущее):** Мы сразу добавим макросы и функции для репликации, чтобы, если игра когда-нибудь станет многопользовательской, система выживания уже была к этому готова.

### **Подробная Реализация Шага**

#### **1. Создание Структуры `FAttribute` и Глобальных Типов**

Нам нужен центральный файл для общих структур и перечислений.

1.  В Visual Studio / Rider, в папке `Source/FaunaLocus/Core`, создайте новый заголовочный файл `FF_Types.h`.
2.  **Заполните `FF_Types.h`:**
    ```cpp
    // FaunaLocus/Source/FaunaLocus/Core/FF_Types.h
    
    #pragma once
    
    #include "CoreMinimal.h"
    #include "FF_Types.generated.h"
    
    // Структура для представления любого атрибута, у которого есть текущее и максимальное значение.
    USTRUCT(BlueprintType)
    struct FAttribute
    {
    	GENERATED_BODY()
    
    	// Текущее значение атрибута.
    	UPROPERTY(EditAnywhere, BlueprintReadWrite, Category = "Attribute")
    	float CurrentValue = 100.0f;
    
    	// Максимальное значение атрибута.
    	UPROPERTY(EditAnywhere, BlueprintReadWrite, Category = "Attribute")
    	float MaxValue = 100.0f;
    
    	FAttribute() = default;
    
    	FAttribute(float InCurrent, float InMax)
    		: CurrentValue(InCurrent), MaxValue(InMax) {}
    };
    ```
    *Эта простая структура будет основой для всех наших потребностей.*

#### **2. Создание Компонента `USurvivalComponent`**

Это сердце нашей системы.

1.  В редакторе Unreal Engine выберите **Tools -> New C++ Class...**.
2.  Выберите родительский класс **Actor Component**.
3.  Назовите его `SurvivalComponent` и поместите в папку `FaunaLocus/Character/Components/`.

4.  **Откройте `SurvivalComponent.h` и заполните его:**

    ```cpp
    // FaunaLocus/Source/FaunaLocus/Character/Components/SurvivalComponent.h
    
    #pragma once
    
    #include "CoreMinimal.h"
    #include "Components/ActorComponent.h"
    #include "Core/FF_Types.h" // Подключаем наш новый файл с типами
    #include "SurvivalComponent.generated.h"
    
    // Объявляем динамический делегат, который будет транслировать изменение атрибута.
    // Он будет доступен в Blueprints для привязки к UI.
    DECLARE_DYNAMIC_MULTICAST_DELEGATE_OneParam(FOnAttributeChanged, const FAttribute&, Attribute);
    
    UCLASS( ClassGroup=(Custom), meta=(BlueprintSpawnableComponent) )
    class FAUNALOCUS_API USurvivalComponent : public UActorComponent
    {
    	GENERATED_BODY()
    
    public:	
    	USurvivalComponent();
    
    	// Делегаты, на которые подпишется наш UI
    	UPROPERTY(BlueprintAssignable, Category = "Events")
    	FOnAttributeChanged OnHealthChanged;
    
    	UPROPERTY(BlueprintAssignable, Category = "Events")
    	FOnAttributeChanged OnHungerChanged;
    
    	UPROPERTY(BlueprintAssignable, Category = "Events")
    	FOnAttributeChanged OnThirstChanged;
    
    	UPROPERTY(BlueprintAssignable, Category = "Events")
    	FOnAttributeChanged OnTemperatureChanged;
    
    	// --- Публичный API для взаимодействия с системой ---
    	UFUNCTION(BlueprintCallable, Category = "Survival")
    	void ApplyDamage(float DamageAmount);
    
    	UFUNCTION(BlueprintCallable, Category = "Survival")
    	void ApplyHealthChange(float HealthAmount);
    
    	UFUNCTION(BlueprintCallable, Category = "Survival")
    	void ApplyHungerChange(float HungerAmount);
    
    	UFUNCTION(BlueprintCallable, Category = "Survival")
    	void ApplyThirstChange(float ThirstAmount);
    
    protected:
    	virtual void BeginPlay() override;
    
    	// --- Атрибуты ---
    	// ReplicatedUsing = OnRep_... - это функция, которая будет вызвана на клиентах при изменении переменной на сервере.
    	UPROPERTY(EditDefaultsOnly, BlueprintReadOnly, Category = "Attributes", ReplicatedUsing = OnRep_Health)
    	FAttribute Health;
    
    	UPROPERTY(EditDefaultsOnly, BlueprintReadOnly, Category = "Attributes", ReplicatedUsing = OnRep_Hunger)
    	FAttribute Hunger;
    
    	UPROPERTY(EditDefaultsOnly, BlueprintReadOnly, Category = "Attributes", ReplicatedUsing = OnRep_Thirst)
    	FAttribute Thirst;
    
    	UPROPERTY(EditDefaultsOnly, BlueprintReadOnly, Category = "Attributes", ReplicatedUsing = OnRep_Temperature)
    	FAttribute Temperature;
    
    	// --- Параметры Системы ---
    	// Скорость уменьшения голода в секунду.
    	UPROPERTY(EditDefaultsOnly, Category = "Survival Settings")
    	float HungerDecayRate = 0.5f;
    
    	// Скорость уменьшения жажды в секунду.
    	UPROPERTY(EditDefaultsOnly, Category = "Survival Settings")
    	float ThirstDecayRate = 0.8f;
    
    	// Урон в секунду, получаемый при голоде или жажде = 0.
    	UPROPERTY(EditDefaultsOnly, Category = "Survival Settings")
    	float DamagePerSecondFromNeeds = 2.0f;
    
    	// --- Функции для репликации ---
    	// UFUNCTION() обязателен для функций репликации.
    	UFUNCTION()
    	void OnRep_Health();
    
    	UFUNCTION()
    	void OnRep_Hunger();
    
    	UFUNCTION()
    	void OnRep_Thirst();
    
    	UFUNCTION()
    	void OnRep_Temperature();
    
    	// Функция для получения переменных, которые нужно реплицировать
    	virtual void GetLifetimeReplicatedProps(TArray<FLifetimeProperty>& OutLifetimeProps) const override;
    
    public:	
    	virtual void TickComponent(float DeltaTime, ELevelTick TickType, FActorComponentTickFunction* ThisTickFunction) override;
    };
    ```

5.  **Откройте `SurvivalComponent.cpp` и реализуйте логику:**

    ```cpp
    // FaunaLocus/Source/FaunaLocus/Character/Components/SurvivalComponent.cpp
    
    #include "Character/Components/SurvivalComponent.h"
    #include "Net/UnrealNetwork.h" // Для репликации
    
    USurvivalComponent::USurvivalComponent()
    {
    	// Включаем Tick, чтобы мы могли обновлять значения со временем.
    	PrimaryComponentTick.bCanEverTick = true;
    	// Включаем репликацию для компонента.
    	SetIsReplicatedByDefault(true);
    }
    
    void USurvivalComponent::BeginPlay()
    {
    	Super::BeginPlay();
    
    	// Инициализируем атрибуты максимальными значениями
    	Health.CurrentValue = Health.MaxValue;
    	Hunger.CurrentValue = Hunger.MaxValue;
    	Thirst.CurrentValue = Thirst.MaxValue;
    	Temperature.CurrentValue = 36.6f; // Начальная температура тела
    
    	// Транслируем начальные значения в UI
    	// Проверяем, являемся ли мы "владельцем" этого компонента на сервере (для мультиплеера)
    	if (GetOwner()->HasAuthority())
    	{
    		OnHealthChanged.Broadcast(Health);
    		OnHungerChanged.Broadcast(Hunger);
    		OnThirstChanged.Broadcast(Thirst);
    		OnTemperatureChanged.Broadcast(Temperature);
    	}
    }
    
    void USurvivalComponent::TickComponent(float DeltaTime, ELevelTick TickType, FActorComponentTickFunction* ThisTickFunction)
    {
    	Super::TickComponent(DeltaTime, TickType, ThisTickFunction);
    
    	// Эта логика должна выполняться только на сервере в мультиплеере.
    	// В синглплеере HasAuthority() всегда true.
    	if (!GetOwner()->HasAuthority())
    	{
    		return;
    	}
    
    	// Уменьшаем голод и жажду со временем
    	ApplyHungerChange(-HungerDecayRate * DeltaTime);
    	ApplyThirstChange(-ThirstDecayRate * DeltaTime);
    
    	// Если голод или жажда на нуле, наносим урон
    	if (Hunger.CurrentValue <= 0.0f || Thirst.CurrentValue <= 0.0f)
    	{
    		ApplyDamage(DamagePerSecondFromNeeds * DeltaTime);
    	}
    
    	// TODO: Логика температуры будет сложнее (зависимость от биома, одежды).
    	// Пока просто держим ее стабильной.
    }
    
    // --- Реализация публичного API ---
    
    void USurvivalComponent::ApplyDamage(float DamageAmount)
    {
    	if (DamageAmount <= 0.0f || Health.CurrentValue <= 0.0f)
    	{
    		return;
    	}
    
    	Health.CurrentValue = FMath::Clamp(Health.CurrentValue - DamageAmount, 0.0f, Health.MaxValue);
    	OnHealthChanged.Broadcast(Health);
    
    	if (Health.CurrentValue <= 0.0f)
    	{
    		// TODO: Логика смерти персонажа
    	}
    }
    
    void USurvivalComponent::ApplyHealthChange(float HealthAmount)
    {
    	Health.CurrentValue = FMath::Clamp(Health.CurrentValue + HealthAmount, 0.0f, Health.MaxValue);
    	OnHealthChanged.Broadcast(Health);
    }
    
    void USurvivalComponent::ApplyHungerChange(float HungerAmount)
    {
    	Hunger.CurrentValue = FMath::Clamp(Hunger.CurrentValue + HungerAmount, 0.0f, Hunger.MaxValue);
    	OnHungerChanged.Broadcast(Hunger);
    }
    
    void USurvivalComponent::ApplyThirstChange(float ThirstAmount)
    {
    	Thirst.CurrentValue = FMath::Clamp(Thirst.CurrentValue + ThirstAmount, 0.0f, Thirst.MaxValue);
    	OnThirstChanged.Broadcast(Thirst);
    }
    
    // --- Реализация функций репликации ---
    
    void USurvivalComponent::OnRep_Health()
    {
    	OnHealthChanged.Broadcast(Health);
    }
    
    void USurvivalComponent::OnRep_Hunger()
    {
    	OnHungerChanged.Broadcast(Hunger);
    }
    
    void USurvivalComponent::OnRep_Thirst()
    {
    	OnThirstChanged.Broadcast(Thirst);
    }
    
    void USurvivalComponent::OnRep_Temperature()
    {
    	OnTemperatureChanged.Broadcast(Temperature);
    }
    
    void USurvivalComponent::GetLifetimeReplicatedProps(TArray<FLifetimeProperty>& OutLifetimeProps) const
    {
    	Super::GetLifetimeReplicatedProps(OutLifetimeProps);
    
    	// Указываем движку, какие переменные нужно реплицировать
    	DOREPLIFETIME(USurvivalComponent, Health);
    	DOREPLIFETIME(USurvivalComponent, Hunger);
    	DOREPLIFETIME(USurvivalComponent, Thirst);
    	DOREPLIFETIME(USurvivalComponent, Temperature);
    }
    ```

#### **3. Интеграция Компонента в `FF_Character`**

Теперь, когда компонент готов, добавим его нашему персонажу.

1.  **Откройте `FF_Character.h`:**
    Раскомментируйте объявление компонента, которое мы сделали ранее.
    ```cpp
    // ...
    class USurvivalComponent; // Убедитесь, что прямое объявление есть
    // ...
    // Компонент, управляющий показателями выживания (голод, жажда, температура).
	UPROPERTY(VisibleAnywhere, BlueprintReadOnly, Category = "Components", meta = (AllowPrivateAccess = "true"))
	TObjectPtr<USurvivalComponent> SurvivalComponent;
    // ...
    ```

2.  **Откройте `FF_Character.cpp`:**
    Раскомментируйте создание компонента в конструкторе и добавьте нужный `#include`.
    ```cpp
    // ...
    #include "Character/Components/SurvivalComponent.h" // Добавьте этот инклюд
    // ...
    
    AFF_Character::AFF_Character()
    {
        // ...
        // --- Создание Будущих Компонентов (пока без логики) ---
        SurvivalComponent = CreateDefaultSubobject<USurvivalComponent>(TEXT("SurvivalComponent"));
    ```

#### **4. Создание Тестового HUD для Визуализации**

Без UI мы не увидим результат нашей работы. Создадим простейший HUD.

1.  **Скомпилируйте код.**
2.  В редакторе, в папке `Content/UI/Widgets`, создайте новый **Widget Blueprint**. Назовите его `WBP_HUD`.
3.  **Откройте `WBP_HUD` и соберите интерфейс:**
    *   Перетащите на холст `Vertical Box`.
    *   Внутрь `Vertical Box` перетащите 4 `Horizontal Box`.
    *   В каждый `Horizontal Box` перетащите `Text` и `Progress Bar`.
    *   Переименуйте виджеты для удобства: `Text_HealthLabel`, `ProgressBar_Health`, `Text_HungerLabel`, `ProgressBar_Hunger` и т.д.
    *   В текстовых блоках напишите "Health:", "Hunger:" и т.д.
4.  **Реализуйте логику в графе `WBP_HUD`:**
    *   Перейдите на вкладку **Graph**.
    *   Создайте 4 функции: `UpdateHealth`, `UpdateHunger`, `UpdateThirst`, `UpdateTemperature`. Каждая функция должна принимать на вход один параметр типа `Attribute` (наша C++ структура).
    *   Внутри каждой функции:
        *   Возьмите входной `Attribute`, разверните его (`Break FAttribute`).
        *   Установите процент для соответствующего `ProgressBar`: `CurrentValue` / `MaxValue`.
        *   Установите текст для соответствующего текстового блока, отформатировав значения.
    *   В главном графе, в событии **Event Construct**:
        *   Получите `Get Owning Player Pawn` -> `Cast To FF_Character`.
        *   Из `FF_Character` вытащите `Get Survival Component`.
        *   Сохраните `Survival Component` в переменную для удобства.
        *   Из переменной `Survival Component` вытащите ноды **Bind Event to OnHealthChanged** (и для других атрибутов).
        *   Подключите пин `Event` от каждого `Bind` к новой функции, которую вы создали (`UpdateHealth` и т.д.).
5.  **Отобразите HUD на экране:**
    *   Откройте `BP_PlayerController`.
    *   В `Event BeginPlay`, после добавления `Mapping Context`, добавьте ноды: `Create Widget` (выберите `WBP_HUD`) -> `Add to Viewport`.
