Теперь сделаем систему строительства по-настоящему удобной и умной, добавив две критически важные функции:
1.  **Проверка на коллизии:** Нельзя строить один объект внутри другого или внутри скалы.
2.  **Привязка (Snapping):** Строительные блоки должны "магнититься" друг к другу, позволяя легко и быстро строить ровные стены, полы и потолки.

### **Шаг 3.2: Реализация проверки на коллизии и привязки строительных блоков друг к другу**

**Задача:** Усовершенствовать нашу систему строительства, чтобы "призрак" предпросмотра не только следовал за взглядом, но и интеллектуально искал точки привязки на соседних строениях и менял цвет на красный, если его размещению что-то мешает.

**Философия:**
1.  **Точки Привязки (Snap Points):** Мы добавим к нашим строительным блокам специальные компоненты-маркеры (`USceneComponent`) в тех местах, где к ним могут присоединяться другие блоки. Например, у фундамента будут точки привязки по центру каждой из четырех верхних граней.
2.  **Двухэтапный Поиск:** Логика предпросмотра в `BuildingComponent` теперь будет работать в два этапа:
    *   **Этап 1: Поиск Точек Привязки.** Сначала мы будем искать не просто поверхность, а ближайшую *точку привязки* на других строительных блоках в радиусе. Если находим — "призрак" мгновенно перемещается и выравнивается по этой точке.
    *   **Этап 2: Поиск Поверхности.** Если в радиусе нет подходящих точек привязки, система работает как раньше — ищет поверхность ландшафта.
3.  **Проверка Коллизий через Overlap:** Самый надежный способ проверить, можно ли разместить объект — это использовать `Overlap` (проверка на пересечение объемов). Мы временно разместим "призрака" в нужной точке и спросим у физического движка: "Пересекается ли этот объем с чем-нибудь еще?". Если да — строить нельзя.
4.  **Совместимость Точек Привязки:** В будущем мы можем добавить теги к точкам привязки (например, "стена", "пол"), чтобы разрешать привязку только совместимых элементов (стена к фундаменту, но не фундамент к стене). Пока что сделаем простую систему.

#### **3. Улучшение `BuildingComponent` для Использования Точек Привязки**

Это самая сложная часть. Мы полностью перепишем `UpdateGhostPreview`.

1.  **Откройте `BuildingComponent.cpp`:**

    ```cpp
    // ...
    #include "World/Building/BuildingPieceBase.h"
    #include "Kismet/GameplayStatics.h" // Для поиска других акторов
    #include "Components/SceneComponent.h"
    
    // ... (конструктор и другие функции)
    
    void UBuildingComponent::UpdateGhostPreview()
    {
        if (!GhostBuildingPiece) return;
    
        APlayerController* PC = Cast<APlayerController>(GetOwner()->GetInstigatorController());
        if (!PC) return;
    
        FVector TraceStart;
        FRotator ViewRotation;
        PC->GetPlayerViewPoint(TraceStart, ViewRotation);
        FVector TraceEnd = TraceStart + ViewRotation.Vector() * BuildDistance;
    
        FTransform BestSnapTransform;
        bool bHasFoundSnapPoint = false;
        float ClosestSnapDistance = -1.0f;
    
        // --- ЭТАП 1: Поиск точек привязки ---
        TArray<AActor*> FoundActors;
        UGameplayStatics::GetAllActorsOfClass(GetWorld(), ABuildingPieceBase::StaticClass(), FoundActors);
    
        for (AActor* Actor : FoundActors)
        {
            ABuildingPieceBase* BuildingPiece = Cast<ABuildingPieceBase>(Actor);
            if (!BuildingPiece) continue;
    
            for (USceneComponent* SnapPoint : BuildingPiece->GetSnapPoints())
            {
                FVector SnapPointLocation = SnapPoint->GetComponentLocation();
                float DistanceToTraceEnd = FVector::Dist(TraceEnd, SnapPointLocation);
    
                // Ищем ближайшую к концу луча точку привязки
                if (DistanceToTraceEnd < 200.0f) // Радиус поиска
                {
                    if (!bHasFoundSnapPoint || DistanceToTraceEnd < ClosestSnapDistance)
                    {
                        bHasFoundSnapPoint = true;
                        ClosestSnapDistance = DistanceToTraceEnd;
                        // Вычисляем трансформацию для призрака, чтобы он идеально состыковался
                        BestSnapTransform.SetLocation(SnapPointLocation);
                        BestSnapTransform.SetRotation(SnapPoint->GetComponentRotation().Quaternion());
                    }
                }
            }
        }
    
        // --- ЭТАП 2: Если не нашли точку привязки, ищем поверхность ---
        if (!bHasFoundSnapPoint)
        {
            FHitResult HitResult;
            FCollisionQueryParams QueryParams;
            QueryParams.AddIgnoredActor(GetOwner());
            QueryParams.AddIgnoredActor(GhostBuildingPiece);
    
            if (GetWorld()->LineTraceSingleByChannel(HitResult, TraceStart, TraceEnd, ECC_Visibility, QueryParams))
            {
                // Выравниваем по нормали поверхности
                FRotator AlignedRotation = FRotationMatrix::MakeFromZ(HitResult.ImpactNormal).Rotator();
                BestSnapTransform.SetLocation(HitResult.Location);
                BestSnapTransform.SetRotation(AlignedRotation.Quaternion());
            }
            else
            {
                // Если луч никуда не попал, прячем призрака
                GhostBuildingPiece->SetActorLocation(TraceEnd + FVector(0,0,10000)); // Убираем далеко
                return;
            }
        }
    
        // Устанавливаем итоговую трансформацию для призрака
        GhostBuildingPiece->SetActorTransform(BestSnapTransform, false, nullptr, ETeleportType::TeleportPhysics);
    
        // Проверяем, можно ли здесь строить, и обновляем материал
        const bool bCanBePlaced = GhostBuildingPiece->CanBePlaced();
        GhostBuildingPiece->SetPlacementMaterial(bCanBePlaced);
    }
    ```

**Разбор логики `UpdateGhostPreview`:**
1.  **Сбор Кандидатов:** Мы получаем все уже построенные `ABuildingPieceBase` в мире. В большой игре это нужно будет оптимизировать (например, искать только в определенном радиусе), но для начала этого достаточно.
2.  **Поиск Ближайшей Точки:** Мы итерируем по всем точкам привязки всех найденных блоков. Если точка находится достаточно близко к тому месту, куда целится игрок, мы запоминаем ее как лучшего кандидата.
3.  **Приоритет Привязки:** Если мы нашли хотя бы одну точку привязки (`bHasFoundSnapPoint` = true), мы полностью игнорируем результат трассировки по земле и используем трансформацию точки привязки.
4.  **Резервный Вариант:** Если ни одной точки не найдено, мы возвращаемся к старой логике — привязываемся к земле по результату `LineTrace`.
5.  **Финальная Проверка:** После того как "призрак" установлен в наилучшее положение (либо по точке, либо по земле), мы вызываем `CanBePlaced()`, который теперь делает проверку на пересечение, и красим "призрака" в соответствующий цвет.
