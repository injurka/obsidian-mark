Данный раздел описывает технологическую основу игры, выбранные инструменты, планируемые платформы и общие технические требования, необходимые для разработки, функционирования и распространения проекта.

- #### 8.1. Платформы Разработки и Выпуска

    - **Платформы Разработки:** Разработка игры будет осуществляться на рабочих станциях под управлением операционной системы Windows [или MacOS/Linux, если планируется поддержка на этапе разработки].
    - **Платформы Выпуска (Целевые):** Изначальный выпуск игры планируется на следующих платформах:
        - **PC (Windows):** Распространение через цифровые дистрибуционные платформы (например, Steam, Epic Games Store). Это является приоритетной платформой для жанра цифровых карточных стратегий.

- #### 8.2. Игровой Движок (UE5)

    - **Выбранный Движок:** Разработка игры "Polye" ведется с использованием игрового движка **Unreal Engine 5 (UE5)**.
    - **Обоснование Выбора:** UE5 был выбран по следующим причинам:
        - **Высококачественная Графика:** Несмотря на жанр карточной игры, UE5 позволяет создать детализированное и визуально привлекательное игровое поле, юнитов и эффекты, что повышает вовлеченность игрока.
        - **Мощная Сетевая Архитектура:** UE5 предоставляет robust (надежный) и гибкий фреймворк для разработки сетевых игр, критически важный для реализации стабильного PvP.
        - **Мультиплатформенность:** Движок хорошо адаптирован для портирования на множество платформ, что соответствует долгосрочным планам по расширению аудитории.
        - **Инструменты Разработки:** Наличие развитых инструментов для художников, дизайнеров (Blueprints, UMG для UI) и программистов (C++ API) ускоряет процесс разработки.
        - **Сообщество и Ресурсы:** Большое сообщество разработчиков и обширная документация по UE5 облегчают поиск решений и обучение.
    - **Роль Движка в Проекте:** UE5 будет использоваться для:
        - Визуализации 3D-игрового поля, юнитов, строений и ландшафтов.
        - Разработки и реализации всей игровой логики (ход игры, правила карт, механики полей, Затухающее Влияние, расчеты боя, экономика Эфира) с использованием C++ и Blueprints.
        - Разработки пользовательского интерфейса (UI/HUD) с помощью UMG.
        - Интеграции и управления звуковыми эффектами и музыкой (MetaSound).
        - Создания визуальных эффектов (VFX) с помощью Niagara.
        - Подключения сетевых функций и взаимодействия с бэкендом.

- #### 8.4. Сетевая Архитектура (Для PvP)

    - **Модель Сетевой Игры:** Для обеспечения честной игры и минимизации возможностей для читерства будет использоваться **клиент-серверная модель**. Клиенты (игроки) будут отправлять свои действия на центральный сервер, который будет выполнять всю критически важную игровую логику (разыгрыш карт, расчеты боя, проверка правил, синхронизация состояния поля) и рассылать обновленное состояние клиентам.
    - **Серверная Инфраструктура:** (Требует решения)
        - Использование выделенных серверов (Dedicated Servers), которые запускаются специально для каждого матча.
        - Сервера могут быть размещены в облачной инфраструктуре (например, AWS, Google Cloud, Azure) для масштабируемости и глобального охвата.
        - Альтернатива: Использование "Listen Servers", где один из клиентов выступает в роли сервера (менее надежно для конкурентного PvP). Скорее всего, будут использоваться выделенные сервера.
    - **Сетевой Код UE5:** Будут задействованы встроенные сетевые возможности Unreal Engine 5, включая репликацию акторов и свойств, RPC (Remote Procedure Calls) для вызова функций на сервере/клиентах, и управление сетевым состоянием.
    - **Обработка Соединений:**
        - Использование надежных протоколов (например, TCP) для передачи важных данных (начальная синхронизация, разыгранные карты, окончательный результат боя).
        - Возможно, использование UDP для менее критичных данных или с дополнительной логикой обработки потерь пакетов, если потребуется особая реактивность (менее вероятно для пошаговой игры).
    - **Матчмейкинг:** Отдельная серверная служба или логика, отвечающая за поиск подходящих соперников для PvP матча, исходя из рейтинга игрока, региона и других параметров.
    - **Борьба с Читерством:** Основные меры включают:
        - Перемещение критической игровой логики на сервер (сервер авторитетен). Клиент лишь отображает происходящее и отправляет запросы на действия.
        - Серверная валидация всех входящих действий от клиента.
        - [Возможно, использование анти-чит решений, но в карточной игре это обычно менее остро стоит, чем в шутерах].
    - **Обеспечение Стабильности:** Реализация логики переподключения при временной потере соединения, синхронизации состояния при восстановлении.
