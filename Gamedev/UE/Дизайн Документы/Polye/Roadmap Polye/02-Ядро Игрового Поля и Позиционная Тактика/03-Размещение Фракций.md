**Цель:** Реализовать механику выбора и применения Фракции игроком к одному из своих активируемых полей во время фазы активации. Это включает:
    1.  Предоставление игроку UI для выбора фракции.
    2.  Передачу выбранной фракции вместе с индексом поля на сервер при запросе активации.
    3.  Серверную валидацию правила размещения фракций (разные фракции должны быть разделены как минимум одним нейтральным или неактивным полем).
    4.  Обновление логического состояния поля (`FPolyeFieldState::CurrentFaction`) в `APolyeGameStateBase`.
    5.  Визуальное отображение примененной фракции на соответствующей плитке поля (`AFieldTile`).

**Предпосылки (Уже Реализованы):**

1.  **Сетевая Архитектура:** `APolyeGameModeBase`, `APolyeGameStateBase`, `APolyePlayerController`, `APolyePlayerStateBase`.
2.  **Система Данных:** `EPolyeFaction` (в `PolyeTypes.h`), `UPolyeFactionData` (Data Asset для данных фракции), `FPolyeFieldState` (содержит `EPolyeFaction CurrentFaction`).
3.  **Структура Игрового Поля:** Логическое состояние в `APolyeGameStateBase::BoardState`, идентификация через `UPolyeBoardStatics`, визуал `AGameBoard` и `AFieldTile`.
4.  **Фаза Активации Полей:** Логика в `APolyeGameModeBase`, RPC в `APolyePlayerController` для активации полей и завершения фазы.
5.  **Обработка Ввода:** `APolyePlayerController` обрабатывает клики по полю.

**Ключевые Компоненты и Их Роли:**

*   **`APolyePlayerController` (Клиент & Сервер):**
    *   **Клиент:**
        *   Управляет UI выбора фракции.
        *   Хранит локально текущую выбранную игроком фракцию (`ClientSelectedFaction`).
        *   При клике на поле (`OnGameBoardClicked`) отправляет `Server_RequestActivateFieldWithFaction(FieldIndex, ClientSelectedFaction)`.
    *   **Сервер:** Получает Server RPC и делегирует обработку `APolyeGameModeBase`.
*   **`APolyeGameModeBase` (Сервер):**
    *   Получает запрос на активацию поля с указанной фракцией.
    *   Выполняет валидацию (фаза, принадлежность поля, лимит активации, **правило размещения фракций**).
    *   Если валидация успешна, обновляет `APolyeGameStateBase::BoardState[FieldIndex].bIsActive = true` и `BoardState[FieldIndex].CurrentFaction = SelectedFaction`.
    *   Уведомляет клиента об успехе/ошибке через Client RPC.
*   **`UPolyeBoardStatics` (Утилиты):**
    *   `GetAdjacentFieldIndices()` используется `APolyeGameModeBase` для проверки правила соседства.
*   **`APolyeGameStateBase` (Сервер -> Клиенты):**
    *   `BoardState` реплицируется, включая обновленное поле `CurrentFaction`.
    *   `OnRep_BoardState()` на клиенте инициирует обновление визуала.
*   **`AFieldTile` (Клиент):**
    *   В `UpdateFromState()` (или через `OnStateUpdated` BP event) реагирует на `NewState.CurrentFaction` и вызывает `BlueprintImplementableEvent` `SetFactionVisuals(EPolyeFaction Faction)` для изменения своего внешнего вида.
*   **UI (`WBP_FactionSelection` или часть `WBP_FieldActivationOverlay`) (Клиент):**
    *   Предоставляет кнопки/иконки для выбора доступных фракций.
    *   Сообщает `APolyePlayerController` о выборе игрока.

```cpp
// Polye/Source/Polye/Core/PolyeGameModeBase.cpp
#include "Utilities/PolyeBoardStatics.h" // Для GetAdjacentFieldIndices
// ...

void APolyeGameModeBase::HandlePlayerFieldActivationRequest(APolyePlayerController* RequestingPC, int32 FieldIndex, EPolyeFaction SelectedFaction)
{
    if (CurrentMatchPhase != EPolyeMatchPhase::FieldActivation)
    {
        RequestingPC->Client_NotifyActivationError(FText::FromString(TEXT("Not in Field Activation phase.")));
        return;
    }

    APolyePlayerStateBase* RequestingPS = nullptr;
    int32 PlayerIdx = INDEX_NONE;
    if (!GetPlayerInfo(RequestingPC, RequestingPS, PlayerIdx)) // Ваша вспомогательная функция
    {
        RequestingPC->Client_NotifyActivationError(FText::FromString(TEXT("Player data error.")));
        return;
    }

    APolyeGameStateBase* GS = GetGameState<APolyeGameStateBase>();
    if (!GS || !GS->BoardState.IsValidIndex(FieldIndex))
    {
        RequestingPC->Client_NotifyActivationError(FText::FromString(TEXT("Invalid field.")));
        return;
    }

    FPolyeFieldState& TargetFieldState = GS->BoardState[FieldIndex]; // Получаем неконстантную ссылку

    // 1. Поле принадлежит игроку?
    if (TargetFieldState.InitialOwnerPlayerIndex != PlayerIdx)
    {
        RequestingPC->Client_NotifyActivationError(FText::FromString(TEXT("Not your field.")));
        return;
    }
    // 2. Поле еще не активно?
    if (TargetFieldState.bIsActive)
    {
        RequestingPC->Client_NotifyActivationError(FText::FromString(TEXT("Field already active.")));
        return;
    }
    // 3. Не превышен лимит активации?
    int32* CurrentCountPtr = PlayerActivatedFieldCounts.Find(RequestingPS); // Используем PlayerState как ключ
    if (!CurrentCountPtr) // Должен быть инициализирован в PostLogin
    {
        PlayerActivatedFieldCounts.Add(RequestingPS, 0);
        CurrentCountPtr = PlayerActivatedFieldCounts.Find(RequestingPS);
    }

    if (*CurrentCountPtr >= MaxFieldsToActivate)
    {
        RequestingPC->Client_NotifyActivationError(FText::Format(NSLOCTEXT("Polye", "MaxFieldsError", "Maximum {0} fields already activated."), MaxFieldsToActivate));
        return;
    }

    // 4. Валидация правила размещения фракций
    // "Разные фракции (например, Братство топей и Дети угля) должны располагаться так,
    // чтобы между их полями было как минимум одно нейтральное или неактивное поле."
    // Это означает, что если мы ставим НЕЙТРАЛЬНУЮ фракцию, это правило не применяется к НЕЙ.
    // Если мы ставим НЕ НЕЙТРАЛЬНУЮ фракцию, то у соседей не должно быть ДРУГОЙ НЕ НЕЙТРАЛЬНОЙ фракции.
    if (SelectedFaction != EPolyeFaction::Neutral) // Правило действует только если мы ставим НЕ нейтральную фракцию
    {
        // Используем NumRows и NumColumns из AGameBoard или UPolyeBoardStatics
        // Предположим, они доступны через GameState или BoardStatics
        int32 NumRows = 3; // Замените на реальные значения
        int32 NumCols = 5; // Замените на реальные значения
        TArray<int32> AdjacentIndices = UPolyeBoardStatics::GetAdjacentFieldIndices(FieldIndex, NumRows, NumCols, false);

        for (int32 AdjIndex : AdjacentIndices)
        {
            if (GS->BoardState.IsValidIndex(AdjIndex))
            {
                const FPolyeFieldState& AdjacentField = GS->BoardState[AdjIndex];
                // Если соседнее поле АКТИВНО, имеет НЕ НЕЙТРАЛЬНУЮ фракцию, И эта фракция ОТЛИЧНА от выбранной нами
                if (AdjacentField.bIsActive && AdjacentField.CurrentFaction != EPolyeFaction::Neutral && AdjacentField.CurrentFaction != SelectedFaction)
                {
                    RequestingPC->Client_NotifyActivationError(FText::Format(NSLOCTEXT("Polye", "FactionPlacementError", "Cannot place {0} next to active {1}."),
                        UEnum::GetDisplayValueAsText(SelectedFaction), UEnum::GetDisplayValueAsText(AdjacentField.CurrentFaction)));
                    return;
                }
            }
        }
    }
    
    // --- Валидация пройдена ---
    GS->SetFieldActive(FieldIndex, true); // Активируем поле в GameState
    GS->ApplyFactionToField(FieldIndex, SelectedFaction); // Применяем фракцию в GameState

    (*CurrentCountPtr)++;
    
    // Уведомляем клиента об успехе, передавая и фракцию
    RequestingPC->Client_NotifyFieldActivatedWithFaction(FieldIndex, SelectedFaction, *CurrentCountPtr);
    UE_LOG(LogTemp, Log, TEXT("GameMode: Player %d activated field %d with faction %s. Count: %d"), PlayerIdx, FieldIndex, *UEnum::GetValueAsString(SelectedFaction), *CurrentCountPtr);
}
```

**Ключевые Моменты:**

*   **Источник Истины:** Сервер (`APolyeGameModeBase` и `APolyeGameStateBase`) всегда является авторитетом по состоянию поля и правилам.
*   **Клиентская Валидация (UX):** Хотя основная валидация на сервере, клиент может выполнять предварительную "мягкую" валидацию (например, подсвечивать допустимые/недопустимые поля для выбранной фракции) для улучшения пользовательского опыта. Но эта клиентская проверка не должна заменять серверную.
*   **Четкие RPC:** Использовать RPC с понятными именами и параметрами. `Client_NotifyFieldActivatedWithFaction` важен для корректного обновления UI клиента.
*   **Визуальная Обратная Связь:** Игрок должен четко видеть, какая фракция выбрана, какие поля активированы и с какой фракцией.
