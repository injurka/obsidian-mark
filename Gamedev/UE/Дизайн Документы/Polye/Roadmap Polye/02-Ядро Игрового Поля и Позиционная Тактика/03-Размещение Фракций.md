**Цель:** Реализовать механику выбора и применения Фракции к активному полю игрока во время фазы активации полей. Это включает модификацию запроса на активацию поля, реализацию серверной валидации правила размещения разных фракций и обновление визуального представления поля для отображения выбранной фракции.

**Предпосылки:**

*   **Базовая Сетевая Архитектура (Шаг 2):** Реализованы ключевые C++ классы (`AGameModeBase`, `AGameStateBase`, `APolyePlayerController`, `APolyePlayerStateBase`) с базовой сетевой настройкой (репликация).
*   **Система Данных (Шаг 3):** Определены структуры данных (`EPolyeFaction`, `FPolyeFieldState` и т.д.) и `UDataAsset`ы для игрового контента, включая Фракции (`UPolyeFactionData`).
*   **Базовая Система Сущностей (Шаг 4):** Создана иерархия сущностей на поле.
*   **Игровое Поле (Шаг 4):** Реализовано логическое представление поля (`FPolyeFieldState` в реплицируемом `AGameStateBase::BoardState`), система идентификации полей (`FieldIndex`, `UPolyeBoardStatics`) и базовое визуальное представление (`AGameBoard`, `AFieldTile`), которое обновляется на основе реплицированного `GameState`. `AFieldTile` умеет визуально реагировать на `bIsActive`.
*   **Фаза Активации Полей (Шаг 5 (предыдущий)):** Реализована фаза активации в `AGameModeBase`, отслеживание активированных полей (`FieldsActivatedCount`, `PlayersFinishedActivation`), базовый Server RPC для активации поля (`Server_RequestFieldActivation`), и соответствующие Client RPC и UI управление.
*   **Обработка Ввода:** Настроена обработка ввода (Enhanced Input) в `APolyePlayerController`, включая клики по игровому полю, которые определяют `FieldIndex` кликнутой плитки.

**Ключевые Компоненты и Их Роли в Этом Шаге:**

*   **`APolyePlayerController` (Клиент-Владелец и Сервер):** На стороне клиента: добавляется логика для получения выбора Фракции от игрока (через UI). Существующая обработка клика по полю (`OnClickGameBoard`) модифицируется, чтобы отправлять Server RPC, включающий *выбранную фракцию* в дополнение к `FieldIndex`. На стороне сервера: реализация нового Server RPC, который принимает `FactionType` и передает его GameMode.
*   **`APolyeGameModeBase` (Сервер):** Основной обработчик запросов. Получает запрос на активацию поля *с указанной фракцией* от PlayerController. Выполняет все предыдущие проверки (фаза, принадлежность поля, лимит активации) И добавляет новую, критически важную проверку: **правило размещения разных фракций**. Если все проверки проходят, он обновляет `FPolyeFieldState` этого поля в `GameState`, устанавливая `bIsActive = true` и `CurrentFaction = ВыбраннаяФракция`.
*   **`UPolyeBoardStatics` (Утилиты):** Вспомогательные функции для получения списка соседних полей (`GetAdjacentFields`) будут использоваться GameMode на сервере для проверки правила соседства.
*   **`APolyeGameStateBase` (Сервер и Клиенты):** Хранит реплицируемое состояние доски, включая `FPolyeFieldState::CurrentFaction` для каждого поля. Сервер изменяет это свойство. Клиенты получают обновление через репликацию (`OnRep_BoardState`) и используют для обновления визуала.
*   **`AFieldTile` (Клиенты - Визуал):** Добавляется логика для изменения внешнего вида плитки в зависимости от значения `FPolyeFieldState::CurrentFaction`, полученного через репликацию. `SetFactionVisuals` BlueprintImplementableEvent будет реализован в BP наследнике.
*   **UI (Клиенты - Визуал/Ввод):** Виджеты UMG модифицируются, чтобы предложить игроку выбор Фракции (например, кнопки с иконками фракций). UI должен как-то запоминать выбранную игроком фракцию перед кликом по полю или запрашивать ее после клика.

2.  **Обновление Логики GameMode для Валидации и Применения Фракции (в `APolyeGameModeBase`):**
    *   **Роль:** `APolyeGameModeBase` - это серверный мозг, который получает запрос с фракцией и проверяет его на соответствие всем правилам, включая правило "разные фракции должны быть через нейтральное/неактивное поле". Реализовать эту функцию в `.cpp`, включив в нее все проверки из старой логики активации *плюс* новую проверку правила соседства фракций, используя `UPolyeBoardStatics::GetAdjacentFields`.               return;

         APolyePlayerStateBase* PS = Cast<APolyePlayerStateBase>(RequestingPlayer->PlayerState);
         if (!PS)
         {
             UE_LOG(LogTemp, Error, TEXT("HandlePlayerFieldActivationAndFactionRequest failed: Requesting PlayerState is null."));
             RequestingPlayer->Client_NotifyActivationError(TEXT("Player state error."));
             return;
         }

         // Получаем ссылку на структуру состояния поля в GameState (для изменения на сервере)
         // ВАЖНО: Получаем не константную ссылку, чтобы иметь возможность изменять структуру напрямую.
         FPolyeFieldState& FieldState = GS->BoardState[FieldIndex];

         // --- Игровая Валидация ---

         // 1. Поле принадлежит игроку?
         if (FieldState.InitialOwnerPlayerIndex == INDEX_NONE || FieldState.InitialOwnerPlayerIndex != PS->PlayerIndex)
         {
              UE_LOG(LogTemp, Warning, TEXT("Player %s (Index %d) tried to activate field %d which is not theirs (InitialOwnerIndex %d)."), *RequestingPlayer->GetName(), PS->PlayerIndex, FieldIndex, FieldState.InitialOwnerPlayerIndex);
              RequestingPlayer->Client_NotifyActivationError(TEXT("You can only activate your own starting fields."));
              return;
         }

         // 2. Поле еще не активно?
         if (FieldState.bIsActive)
         {
              UE_LOG(LogTemp, Warning, TEXT("Player %s tried to activate already active field %d."), *RequestingPlayer->GetName(), FieldIndex);
              RequestingPlayer->Client_NotifyActivationError(TEXT("This field is already active."));
              return;
         }

         // 3. Игрок не превысил максимальное количество полей?
         // Проверяем, что счетчик + 1 не превысит лимит.
         if (FieldsActivatedCount.FindOrAdd(PS->PlayerIndex) + 1 > MaxFieldsToActivate)
         {
             UE_LOG(LogTemp, Warning, TEXT("Player %s tried to activate field %d but exceeded max limit (%d/%d)."),
                 *RequestingPlayer->GetName(), FieldIndex, FieldsActivatedCount.FindOrAdd(PS->PlayerIndex), MaxFieldsToActivate);
             RequestingPlayer->Client_NotifyActivationError(FText::Format(NSLOCTEXT("Polye", "ActivationLimit", "You can activate maximum of {0} fields."), FText::AsNumber(MaxFieldsToActivate)).ToString());
             return;
         }

         // 4. **ВАЛИДАЦИЯ ПРАВИЛА РАЗМЕЩЕНИЯ ФРАКЦИЙ**
         // Правило: Разные фракции не могут быть на соседних (ортогонально) активных полях.
         // Если игрок пытается поставить фракцию X на поле A, и у поля A есть активный сосед B с фракцией Y (где X != Y), то действие недопустимо.

         // Предполагаем, что игроки могут выбирать только одну из своих фракций (напр. из PlayerState->PlayerFaction)
         // TODO: Проверить, что FactionType является допустимой фракцией для этого игрока.
         //       Напр.: if (FactionType != PS->PlayerFaction) { ... ошибка ... return; }

         // bIncludeDiagonal = false, если диагональ не считается "соседством" для этого правила.
         TArray<int32> AdjacentFields = UPolyeBoardStatics::GetAdjacentFields(FieldIndex, false);
         for (int32 AdjacentIndex : AdjacentFields)
         {
              if (GS->BoardState.IsValidIndex(AdjacentIndex))
              {
                   const FPolyeFieldState& AdjacentFieldState = GS->BoardState[AdjacentIndex];

                   // Если соседнее поле активно И имеет Фракцию (не Neutral), И эта Фракция ОТЛИЧНА от той, которую мы пытаемся поставить
                   if (AdjacentFieldState.bIsActive && AdjacentFieldState.CurrentFaction != EPolyeFaction::EF_Neutral && AdjacentFieldState.CurrentFaction != FactionType)
                   {
                        UE_LOG(LogTemp, Warning, TEXT("Player %s tried to place %s at %d, but adjacent field %d is active with %s. Violates adjacency rule."),
                             *RequestingPlayer->GetName(), *UEnum::GetValueAsString(FactionType), FieldIndex, AdjacentIndex, *UEnum::GetValueAsString(AdjacentFieldState.CurrentFaction));
                        RequestingPlayer->Client_NotifyActivationError(TEXT("Cannot place different factions next to each other on active fields."));
                        return; // Валидация не пройдена
                   }
              }
         }

         // --- ВСЕ ВАЛИДАЦИИ ПРОШЛИ УСПЕШНО! Изменяем состояние на сервере ---
         UE_LOG(LogTemp, Log, TEXT("Player %s (Index %d) successfully activated field %d with faction %s. Total activated: %d."),
             *RequestingPlayer->GetName(), PS->PlayerIndex, FieldIndex, *UEnum::GetValueAsString(FactionType), FieldsActivatedCount.FindOrAdd(PS->PlayerIndex) + 1);
