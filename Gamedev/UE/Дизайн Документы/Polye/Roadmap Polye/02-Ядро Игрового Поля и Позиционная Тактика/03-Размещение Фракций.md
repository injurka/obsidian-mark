**Цель:** Реализовать механику выбора и применения Фракции к активному полю игрока во время фазы активации полей, включая хранение выбранной фракции в состоянии поля и валидацию правила размещения разных фракций.

**Предпосылки:**

*   Реализована Фаза 1: Фундамент и Базовые Системы (архитектура, репликация, управление данными, базовые сущности).
*   Реализован Пункт 2.1: Структура Игрового Поля (логическое состояние в GameState, визуальное представление AGameBoard/AFieldTile, система индексов).
*   Реализован Пункт 2.2: Система Активации Полей (фаза активации в GameMode, отслеживание активированных полей, базовый RPC для активации поля).
*   Определены структуры данных для Фракций и Полей (`EPolyeFaction`, `FPolyeFieldState` в `PolyeDataTypes.h`).
*   Созданы Data Assets для Фракций (`UPolyeFactionData`).
*   Созданы C++ классы `APolyeGameModeBase`, `APolyeGameStateBase`, `APolyePlayerController`, `APolyePlayerStateBase`.

**Ключевые Компоненты:**

*   **Обновленная Логика Активации:** RPC для активации поля теперь должен включать выбор Фракции.
*   **Серверная Валидация Правила Соседства:** Основная логика проверки правила "разные фракции должны быть через нейтральное/неактивное поле".
*   **Обновление GameState:** Хранение выбранной Фракции для каждого поля в `FPolyeFieldState`.
*   **Обновление Визуала Поля:** `AFieldTile` должен визуально отображать примененную Фракцию.
*   **UI Выбора Фракции:** Интерфейс для игрока, позволяющий выбрать Фракцию перед активацией поля.

    *   **Реализация (в `Core/PolyeGameModeBase.cpp`):**
        ```cpp
        #include "Utilities/PolyeBoardStatics.h" // Для GetAdjacentFields

        // SERVER ONLY - Обработка запроса игрока на активацию поля И применение фракции
        void APolyeGameModeBase::HandlePlayerFieldActivationAndFactionRequest(APolyePlayerController* RequestingPlayer, int32 FieldIndex, EPolyeFaction FactionType)
        {
             // **ВАЛИДАЦИЯ НА СЕРВЕРЕ!!!**
             if (!RequestingPlayer || CurrentMatchPhase != EPolyeMatchPhase::FieldActivation)
             {
                  RequestingPlayer->Client_NotifyActivationError(TEXT("Not the correct phase to activate fields."));
                  return;
             }

             APolyeGameStateBase* GS = GetGameState<APolyeGameStateBase>();
             if (!GS || !GS->BoardState.IsValidIndex(FieldIndex))
             {
                  RequestingPlayer->Client_NotifyActivationError(TEXT("Invalid field selected."));
                  return;
             }

             APolyePlayerStateBase* PS = Cast<APolyePlayerStateBase>(RequestingPlayer->PlayerState);
             if (!PS)
             {
                 RequestingPlayer->Client_NotifyActivationError(TEXT("Invalid player state.")); // Should not happen normally
                 return;
             }

             FPolyeFieldState& FieldState = GS->BoardState[FieldIndex]; // Получаем ссылку на состояние поля в GameState

             // 1. Поле принадлежит игроку?
             if (FieldState.InitialOwnerPlayerIndex != PS->PlayerIndex)
             {
                  RequestingPlayer->Client_NotifyActivationError(TEXT("You can only activate your own fields."));
                  return;
             }

             // 2. Поле еще не активно?
             if (FieldState.bIsActive)
             {
                  RequestingPlayer->Client_NotifyActivationError(TEXT("This field is already active."));
                  return;
             }

             // 3. Игрок не превысил максимальное количество полей?
             if (FieldsActivatedCount.FindOrAdd(PS->PlayerIndex) >= MaxFieldsToActivate) // Используем >= т.к. еще не увеличили
             {
                 RequestingPlayer->Client_NotifyActivationError(FText::Format(NSLOCTEXT("Polye", "ActivationLimit", "You can activate maximum of {0} fields."), FText::AsNumber(MaxFieldsToActivate)).ToString());
                 return;
             }

             // 4. **ВАЛИДАЦИЯ ПРАВИЛА РАЗМЕЩЕНИЯ ФРАКЦИЙ**
             if (FactionType == EPolyeFaction::EF_Neutral) // Нельзя активировать с нейтральной фракцией
             {
                  RequestingPlayer->Client_NotifyActivationError(TEXT("Cannot activate field with Neutral faction."));
                  return;
             }

             // Проверяем всех активных соседей
             TArray<int32> AdjacentFields = UPolyeBoardStatics::GetAdjacentFields(FieldIndex, false); // false для без диагоналей по умолчанию
             for (int32 AdjacentIndex : AdjacentFields)
             {
                  if (GS->BoardState.IsValidIndex(AdjacentIndex))
                  {
                       const FPolyeFieldState& AdjacentFieldState = GS->BoardState[AdjacentIndex];
                       // Если соседнее поле активно И имеет Фракцию, ОТЛИЧНУЮ от той, которую мы пытаемся поставить
                       if (AdjacentFieldState.bIsActive && AdjacentFieldState.CurrentFaction != EPolyeFaction::EF_Neutral && AdjacentFieldState.CurrentFaction != FactionType)
                       {
                            UE_LOG(LogTemp, Warning, TEXT("Player %s tried to place %s at %d, but adjacent field %d is active with %s."),
                                 *RequestingPlayer->GetName(), *UEnum::GetValueAsString(FactionType), FieldIndex, AdjacentIndex, *UEnum::GetValueAsString(AdjacentFieldState.CurrentFaction));
                            RequestingPlayer->Client_NotifyActivationError(TEXT("Cannot place different factions next to each other (needs neutral/inactive field between)."));
                            FieldsActivatedCount.FindOrAdd(PS->PlayerIndex)--; // На всякий случай откатываем, хотя не должны были увеличивать до валидации
                            return;
                       }
                  }
             }


             // --- ВСЕ ВАЛИДАЦИИ ПРОШЛИ УСПЕШНО! Активируем поле с фракцией на сервере ---
             UE_LOG(LogTemp, Warning, TEXT("Player %s activated field %d with faction %s."), *RequestingPlayer->GetName(), FieldIndex, *UEnum::GetValueAsString(FactionType));

             FieldState.bIsActive = true; // Активируем поле
             FieldState.CurrentFaction = FactionType; // Устанавливаем фракцию

             FieldsActivatedCount.FindOrAdd(PS->PlayerIndex)++; // Увеличиваем счетчик активированных полей

             // TODO: Обновить GameState: GS->UpdateFieldState(FieldIndex, FieldState); // Если BoardState[FieldIndex] = FieldState не вызовет репликацию

             // Уведомляем клиента об успешной активации, фракции и текущем количестве
             RequestingPlayer->Client_NotifyFieldActivatedWithFaction(FieldIndex, FactionType, FieldsActivatedCount[PS->PlayerIndex]);

             // TODO: Проверить, завершили ли все игроки активацию (логика из Пункта 2.2)
             // EndFieldActivationPhase(); // Вызвать, когда все готовы
        }

        // TODO: Добавить Client RPC в PlayerController: Client_NotifyFieldActivatedWithFaction
        // UFUNCTION(Client, Reliable)
        // void Client_NotifyFieldActivatedWithFaction(int32 FieldIndex, EPolyeFaction FactionType, int32 CurrentActivatedCount);

        ```
    *   **Обоснование:** Новая функция в GameMode обрабатывает полный запрос. Она включает все проверки из базовой активации и добавляет проверку правила соседства. Получение списка соседних полей из `UPolyeBoardStatics` и проверка их состояния в GameState позволяет выполнить валидацию на сервере. Установка `FieldState.CurrentFaction` на сервере гарантирует, что данные реплицируются.
    *   **Outcome:** В `APolyeGameModeBase` реализована серверная логика для валидации и применения фракции при активации поля, включая проверку правила соседства.

**Ключевые Соображения и Тестирование:**

*   **Валидация Соседства:** Тщательно протестировать правило соседства на сервере. Проверить разные сценарии: активация первого поля, активация рядом с полем той же фракции, активация рядом с полем другой фракции, активация через одно поле от другой фракции (должно быть разрешено, если поле между ними нейтральное/неактивное), активация нейтрального/неактивного поля между двумя разными фракциями (должно оставаться нейтральным/неактивным, пока не будет активировано самим игроком с правилами).
*   **Диагональное Соседство:** В дизайн-документе есть вопрос про диагональ ("по горизонтали или вертикали, диагональ?"). Текущая реализация `UPolyeBoardStatics::GetAdjacentFields` с `false` для `bIncludeDiagonal` *не* учитывает диагональ. Если диагональ *должна* блокировать размещение разных фракций, нужно изменить `GetAdjacentFields` и соответствующую валидацию.
*   **Визуал Валидации на Клиенте:** Хотя сервер выполняет основную валидацию, хороший UX предполагает, что клиентский UI *заранее* показывает, какие поля являются допустимыми целями для размещения выбранной фракции (например, подсвечивая их зеленым/красным при наведении). Это требует дублирования *части* логики валидации на клиенте (без доверия, только для визуала!).
*   **Затухающее Влияние:** Реализация этой фазы тесно связана с будущей реализацией Затухающего Влияния (следующий пункт). Система Влияния будет *читать* установленную на полях фракцию, чтобы применить соответствующие Ауры.
