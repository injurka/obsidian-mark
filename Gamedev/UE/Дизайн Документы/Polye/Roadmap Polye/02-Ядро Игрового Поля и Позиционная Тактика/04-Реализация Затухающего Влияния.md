**Цель:** Реализовать ключевую игровую механику "Затухающего Влияния", при которой активные поля с фракциями проецируют Ауры на другие активные поля. Эти Ауры воздействуют на сущности, находящиеся на затронутых полях, с силой, зависящей от расстояния от источника (100% на поле источника, 50% на соседних ортогонально, 25% через одно ортогонально). Система должна корректно складывать влияние от нескольких источников и применять соответствующие эффекты к сущностям.

**Предпосылки:**

*   **Базовая Сетевая Архитектура (Шаг 2):** Реализованы ключевые C++ классы (`AGameModeBase`, `AGameStateBase`, `APolyePlayerController`, `APolyePlayerStateBase`) с базовой сетевой настройкой.
*   **Система Данных (Шаг 3):** Определены структуры данных (`EPolyeFaction`, `FPolyeFieldState`, `FDecayingInfluenceAuraConfig`, `FPolyeEffectConfig`, `EPolyeEffectType`, `EPolyeAttributeType`) в `PolyeDataTypes.h`. Созданы Data Assets для Фракций (`UPolyeFactionData`) и доступ к ним через Менеджер Данных (`UPolyeFactionManager` - предполагается или является частью общего Менеджера Данных, доступного, напр., через `GameInstance`).
*   **Базовая Система Сущностей (Шаг 4):** Создана иерархия сущностей на поле (`ABoardEntityBase`, `AUnit`, `AStructure`) с базовыми атрибутами (HP, Attack и т.д.). **Важно:** Добавление механизма применения эффектов к сущностям является частью этого шага.
*   **Игровое Поле (Шаг 4):** Реализовано логическое представление поля (`FPolyeFieldState` в реплицируемом `AGameStateBase::BoardState`), система идентификации полей (`FieldIndex`, `UPolyeBoardStatics`) с функциями расчета соседних полей (`GetAdjacentFields`, `GetFieldsTwoStepsAway`). Базовое визуальное представление (`AGameBoard`, `AFieldTile`) обновляется на основе GameState.
*   **Фаза Активации Полей (Шаг 5):** Реализовано управление фазами в GameMode (`EPolyeMatchPhase`), активация полей (`bIsActive` в `FPolyeFieldState` обновляется), и выбор/применение Фракции (`CurrentFaction` в `FPolyeFieldState` обновляется) с серверной валидацией правила соседства.
*   **Базовый Класс Эффекта:** Необходимо определить базовый класс для экземпляров эффектов, который может быть применен к сущности.

**Ключевые Компоненты и Их Роли в Этом Шаге:**

*   **`UPolyeGameplayEffectBase` (Новый C++ Класс):** Базовый `UObject` класс, представляющий *экземпляр* активного эффекта (Ауры, Баффа, Дебаффа, Статуса), примененного к сущности. Содержит виртуальные функции для инициализации, применения, удаления, тика и модификации атрибутов. Должен быть настроен для репликации внутри компонента.
*   **`UPolyeEffectManagerComponent` (Новый C++ Компонент):** `UActorComponent`, добавляемый к `ABoardEntityBase`. Владеет списком активных `UPolyeGameplayEffectBase` экземпляров на этой сущности. Управляет их жизненным циклом (применение, удаление, возможно, тик, отслеживание длительности/стеков). Предоставляет функции для запроса состояния (есть ли статус) и получения эффективных значений атрибутов (с учетом всех модификаторов). Список активных эффектов реплицируется.
*   **`AGameStateBase` (Сервер и Клиенты):** Является центральным хранилищем реплицируемого состояния. **Сервер:** Добавляется логика (`CalculateAndApplyInfluence`) для расчета эффективного влияния всех активных полей с фракциями на каждое другое активное поле. Хранит *результат* этого расчета (`ActiveInfluenceState`) в реплицируемой структуре/мапе. **Клиенты:** Получают реплицированное `ActiveInfluenceState` и используют его для визуализации Аур на поле.
*   **`UPolyeBoardStatics` (Утилиты):** Используется GameState (на сервере) для определения полей на расстоянии 1, 2 шагов от источников влияния.
*   **`UPolyeFactionManager` (Менеджер Данных):** Используется GameState (на сервере) для доступа к данным Фракций (`UPolyeFactionData`), чтобы узнать, какие Ауры проецирует каждая фракция, и получить конфигурацию эффекта для каждой Ауры при разной силе влияния.
*   **`FDecayingInfluenceAuraConfig` & `FPolyeEffectConfig` (Структуры Данных):** Определяют, какие эффекты связаны с Аурами и с какими параметрами при разной силе (100%, 50%, 25%).
*   **`AGameBoard` & `AFieldTile` (Клиенты - Визуал):** `AFieldTile` обновляется для визуального отображения активных Аур на поле, используя данные из `ActiveInfluenceState`, реплицированного в `GameState`.

1.  **Базовый Класс Игрового Эффекта (`UPolyeGameplayEffectBase`):**
    *   **Роль:** `UPolyeGameplayEffectBase` является абстрактным предком для всех конкретных типов эффектов в игре (снижение лечения, бонус к атаке, статус скрытности и т.д.).     void UPolyeEffectManagerComponent::EndPlay(const EEndPlayReason::Type EndPlayReason)
    {
         // **ВАЖНО: Эта функция вызывается ТОЛЬКО на СЕРВЕРЕ и на КЛИЕНТЕ, когда компонент уничтожается.**
         // На сервере: очищаем активные эффекты и помечаем их на удаление.
         // На клиенте: очищаем локальные визуальные эффекты, связанные с активными эффектами.

         // Создаем копию списка, чтобы безопасно итерировать во время удаления элементов.
         TArray<TObjectPtr<UPolyeGameplayEffectBase>> EffectsToCleanup = ActiveEffects;
         for (UPolyeGameplayEffectBase* Effect : EffectsToCleanup)
         {
              // Проверяем на валидность указателя и что объект не ожидает удаления.
              if (IsValid(Effect))
              {
                   // Вызываем логику удаления эффекта. На сервере это серверная реализация, на клиенте - клиентская (если есть BP).
                   // Передаем сущность-владельца.
                   Effect->RemoveEffect(GetOwnerEntity());

                   // На сервере, также удаляем из реплицируемого массива и помечаем на удаление.
                   if (GetOwner()->HasAuthority())
                   {
                        // RemoveEffectInstance(Effect); // Эта функция уже делает Remove из массива и MarkPendingKill
                        // Если мы уже в цикле по копии, просто помечаем на удаление и удаляем из оригинального списка.
                        ActiveEffects.Remove(Effect);
                        Effect->MarkPendingKill(); // Помечаем объект UObject для сборщика мусора
                   }
              }
         }
         ActiveEffects.Empty(); // Очищаем реплицируемый массив (на сервере это реплицируется как пустой список)

         // TODO: Очистить локальные клиентские визуальные эффекты, если они не удалились в RemoveEffect_Implementation
         //       или если OnRep_ActiveEffects не успел сработать перед EndPlay.

         Super::EndPlay(EndPlayReason);
    }


    // SERVER ONLY: Применить эффект
    UPolyeGameplayEffectBase* UPolyeEffectManagerComponent::ApplyEffect(TSubclassOf<UPolyeGameplayEffectBase> EffectClass, const FPolyeEffectConfig& EffectConfig)
    {
        // **ВАЖНО: Выполняется ТОЛЬКО на СЕРВЕРЕ.**
        if (!GetOwner()->HasAuthority() || !EffectClass) return nullptr;

        ABoardEntityBase* OwnerEntity = GetOwnerEntity();
        if (!OwnerEntity) return nullptr;

        // TODO: Добавить логику проверки на уникальность эффекта, максимальное количество стеков,
        //       правила обновления длительности/стеков при повторном применении того же эффекта.
        //       Например, если эффект уже есть, обновить его длительность или увеличить стек.

        // Создаем новый экземпляр эффекта. Владельцем UObject должен быть реплицируемый Актер или Компонент.
        // Владелец - этот компонент (UPolyeEffectManagerComponent), который сам реплицируется.
        UPolyeGameplayEffectBase* NewEffect = NewObject<UPolyeGameplayEffectBase>(this, EffectClass);
        if (NewEffect)
        {
             NewEffect->InitializeEffect(EffectConfig); // Инициализируем эффект с его параметрами (серверная инициализация)
             NewEffect->ApplyEffect(OwnerEntity); // Вызываем логику применения эффекта (серверная реализация ApplyEffect_Implementation)

             ActiveEffects.Add(NewEffect); // Добавляем в реплицируемый массив
             // Unreal Engine должен автоматически отследить изменение в TArray<TObjectPtr<UObject>> и реплицировать его.
             // MarkNetDirty(); // Может помочь принудительно реплицировать, если изменения массива не отслеживаются автоматически.

             UE_LOG(LogTemp, Log, TEXT("Applied effect type %s to %s on server. Total effects: %d"),
                 *UEnum::GetValueAsString(EffectConfig.EffectType), *GetOwner()->GetName(), ActiveEffects.Num());

             return NewEffect; // Возвращаем указатель на созданный эффект (валиден только на сервере)
        }
        return nullptr; // Не удалось создать эффект
    }

    // ТОЛЬКО СЕРВЕР: Удалить конкретный экземпляр эффекта
    bool UPolyeEffectManagerComponent::RemoveEffectInstance(UPolyeGameplayEffectBase* EffectInstance)
    {
        // **ВАЖНО: Выполняется ТОЛЬКО на СЕРВЕРЕ.**
        if (!GetOwner()->HasAuthority() || !IsValid(EffectInstance)) return false; // Проверяем валидность на сервере

        ABoardEntityBase* OwnerEntity = GetOwnerEntity();
        if (!OwnerEntity) return false;

        // Проверяем, что экземпляр эффекта действительно находится в нашем списке активных эффектов
        int32 RemovedCount = ActiveEffects.Remove(EffectInstance);
        if (RemovedCount > 0)
        {
             UE_LOG(LogTemp, Log, TEXT("Removing effect instance type %s from %s on server."),
                 *UEnum::GetValueAsString(EffectInstance->GetConfig().EffectType), *GetOwner()->GetName());

             // Вызываем логику удаления эффекта (серверная реализация RemoveEffect_Implementation)
             EffectInstance->RemoveEffect(OwnerEntity);

             // Помечаем объект UObject для сборщика мусора.
             // Unreal Engine автоматически удалит объект UObject, когда на него больше не будет ссылок
             // и он помечен как PendingKill. Удаление из ActiveEffects убирает сильную ссылку.
             EffectInstance->MarkPendingKill();

             // MarkNetDirty(); // Может помочь принудительно реплицировать

             return true;
        }

        return false; // Эффект не был найден в списке
    }

    // ТОЛЬКО СЕРВЕР: Удалить эффекты по критериям (напр., по типу)
    int32 UPolyeEffectManagerComponent::RemoveEffectsBy(EPolyeEffectType EffectTypeToMatch)
    {
         // **ВАЖНО: Выполняется ТОЛЬКО на СЕРВЕРЕ.**
         if (!GetOwner()->HasAuthority()) return 0;

         int32 Count = 0;
         // Создаем копию массива, чтобы безопасно удалять элементы во время итерации.
         TArray<TObjectPtr<UPolyeGameplayEffectBase>> EffectsToProcess = ActiveEffects;
         for (TObjectPtr<UPolyeGameplayEffectBase>& Effect : EffectsToProcess)
         {
              // Проверяем, что эффект валиден и соответствует критерию удаления (напр., по типу).
              if (IsValid(Effect) && Effect->GetConfig().EffectType == EffectTypeToMatch)
              {
                   // Важно: вызываем RemoveEffectInstance, чтобы корректно удалить из ActiveEffects
                   // и пометить UObject на удаление.
                   RemoveEffectInstance(Effect); // Эта функция удаляет из ActiveEffects и помечает PendingKill
                   Count++;
              }
         }

         // Нет необходимости вызывать MarkNetDirty() здесь, т.к. RemoveEffectInstance делает это.
         return Count;
    }

    // SERVER ONLY - Рассчитывает влияние и применяет эффекты
    void APolyeGameStateBase::CalculateAndApplyInfluence()
    {
         // **ВАЖНО: Выполняется ТОЛЬКО на СЕРВЕРЕ!**
         if (!HasAuthority()) return;

         UE_LOG(LogTemp, Log, TEXT("Начинаю расчет и применение Влияния..."));

         // Получаем доступ к Менеджеру Фракций
         UPolyeFactionManager* FactionManager = GetFactionManager();
         if (!FactionManager)
         {
              UE_LOG(LogTemp, Error, TEXT("Менеджер Фракций не найден! Не могу рассчитать влияние."));
              return;
         }

         // Временная мапа для построения *нового* состояния влияния
         // Map: FieldIndex -> (AuraType -> EffectiveAuraState) - Используем AuraType как ключ для упрощения сложения
         TMap<int32, TMap<EPolyeEffectType, FEffectiveAuraState>> NewInfluenceStateMapForComparison;


         // 1. Определить все поля-источники (Активные поля с Фракциями)
         TArray<int32> SourceFieldIndices;
         for (const FPolyeFieldState& State : BoardState)
         {
              // Источниками влияния являются только активные поля с фракциями (не нейтральными)
              if (State.bIsActive && State.CurrentFaction != EPolyeFaction::EF_Neutral)
              {
                   SourceFieldIndices.Add(State.FieldIndex);
              }
         }

         // 2. Для каждого поля-источника определить затронутые поля и потенциальные Ауры с их силой
         for (int32 SourceIndex : SourceFieldIndices)
         {
              const FPolyeFieldState& SourceState = BoardState[SourceIndex];
              EPolyeFaction SourceFaction = SourceState.CurrentFaction;

              // Получаем данные Фракции, чтобы знать, какие Ауры эта фракция испускает
              const UPolyeFactionData* FactionData = FactionManager->GetFactionData(SourceFaction); // Нужен геттер в FactionManager
              if (!FactionData)
              {
                  UE_LOG(LogTemp, Error, TEXT("Data Asset для Фракции %s не найден!"), *UEnum::GetValueAsString(SourceFaction));
                  continue;
              }

              // Определяем затронутые поля на расстоянии 50% и 25%.
              // Используем GetAdjacentFields(false) для 50% (ортогонально)
              TArray<int32> Fields50Percent = UPolyeBoardStatics::GetAdjacentFields(SourceIndex, false);
              // Используем GetFieldsTwoStepsAway(false) для 25% (через одно ортогонально).
              TArray<int32> Fields25Percent = UPolyeBoardStatics::GetFieldsTwoStepsAway(SourceIndex); // Default в PolyeBoardStatics.cpp - ортогонально через одно.

              // Определяем силу влияния для каждого затронутого поля
              TMap<int32, float> AffectedFieldsAndStrengths;
              AffectedFieldsAndStrengths.Add(SourceIndex, 1.0f); // Поле источника - 100%
              for (int32 AffectedIndex : Fields50Percent)
              {
                  AffectedFieldsAndStrengths.FindOrAdd(AffectedIndex, 0.0f); // Добавляем, если нет
                  // Применяем максимальную силу от текущего источника, если она выше уже записанной
                  AffectedFieldsAndStrengths[AffectedIndex] = FMath::Max(AffectedFieldsAndStrengths[AffectedIndex], 0.5f);
              }
              for (int32 AffectedIndex : Fields25Percent)
              {
                  AffectedFieldsAndStrengths.FindOrAdd(AffectedIndex, 0.0f); // Добавляем, если нет
                  // Применяем максимальную силу от текущего источника, если она выше уже записанной
                  AffectedFieldsAndStrengths[AffectedIndex] = FMath::Max(AffectedFieldsAndStrengths[AffectedIndex], 0.25f);
              }


              // Для каждого затронутого поля, которое *активно*, добавляем потенциальное влияние от этого источника
              for (auto const& [AffectedIndex, Strength] : AffectedFieldsAndStrengths)
              {
                  // Влияние действует только на *активные* поля.
                  if (!BoardState.IsValidIndex(AffectedIndex) || !BoardState[AffectedIndex].bIsActive)
                  {
                       continue;
                  }

                  // Для каждой Ауры, которую испускает фракция-источник
                  for (const FDecayingInfluenceAuraConfig& AuraConfig : FactionData->DecayingInfluenceAuras)
                  {
                       // TODO: Проверить специфические правила Ауры (напр., иммунитет к себе на поле источника)
                       //       If (AffectedIndex == SourceIndex && AuraConfig.AuraType == EPolyeEffectType::PET_DecayingInfluence_HealReduction && SourceFaction == EPolyeFaction::EF_SwampBrotherhood) continue; // Пример иммунитета БТ к своей ауре лечения

                       // Создаем структуру эффективной ауры для данного типа, силы и конфига
                       FEffectiveAuraState PotentialAura;
                       PotentialAura.AuraType = AuraConfig.AuraType;
                       PotentialAura.Strength = Strength;

                       // Получаем FPolyeEffectConfig с *параметрами*, соответствующими этой силе влияния
                       // Эта логика должна быть в FDecayingInfluenceAuraConfig::GetConfigForStrength
                       const FPolyeEffectConfig* AuraEffectConfig = AuraConfig.GetConfigForStrength(Strength);
                       if (!AuraEffectConfig)
                       {
                           UE_LOG(LogTemp, Error, TEXT("Конфигурация эффекта для Ауры %s с силой %f не найдена!"),
                               *UEnum::GetValueAsString(AuraConfig.AuraType), Strength);
                           continue;
                       }
                       PotentialAura.EffectConfig = *AuraEffectConfig; // Копируем конфиг с параметрами

                       // --- Правило Сложения: Максимальная сила для каждого УНИКАЛЬНОГО Типа Ауры ---
                       // Если для этого поля (AffectedIndex) уже есть потенциальная аура такого же Типа,
                       // оставляем ту, у которой больше Strength. Иначе добавляем новую.
                       if (NewInfluenceStateMapForComparison.Contains(AffectedIndex) && NewInfluenceStateMapForComparison[AffectedIndex].Contains(PotentialAura.AuraType))
                       {
                            // Если новая аура сильнее старой для этого типа, заменяем ее
                            if (PotentialAura.Strength > NewInfluenceStateMapForComparison[AffectedIndex][PotentialAura.AuraType].Strength)
                            {
                                 NewInfluenceStateMapForComparison[AffectedIndex].Add(PotentialAura.AuraType, PotentialAura); // Заменит существующую
                            }
                       }
                       else
                       {
                            // Добавляем новую ауру для этого поля
                            NewInfluenceStateMapForComparison.FindOrAdd(AffectedIndex).Add(PotentialAura.AuraType, PotentialAura);
                       }
                   }
              }
         } // Конец итерации по полям-источникам

         // 3. Компилируем финальное состояние влияния в формате TMap<int32, FActiveInfluenceOnField>
         //    которое будет реплицироваться.
         TMap<int32, FActiveInfluenceOnField> NewActiveInfluenceState;
         for (auto const& [FieldIndex, AuraMap] : NewInfluenceStateMapForComparison)
         {
              NewActiveInfluenceState.Add(FieldIndex, FActiveInfluenceOnField());
              for (auto const& [AuraType, EffectiveAura] : AuraMap)
              {
                   NewActiveInfluenceState[FieldIndex].EffectiveAuras.Add(EffectiveAura);
              }
              // TODO: Отсортировать EffectiveAuras по AuraType для стабильного сравнения в дальнейшем?
              // NewActiveInfluenceState[FieldIndex].EffectiveAuras.Sort(...);
         }


         // 4. Сравниваем старое состояние ActiveInfluenceState с новым и применяем/удаляем эффекты на сущностях.
         //    Это самая сложная часть. Нужно минимизировать переприменение эффектов.

         // Получаем старое состояние до его обновления
         TMap<int32, FActiveInfluenceOnField> OldActiveInfluenceState = ActiveInfluenceState;

         // Обновляем реплицируемое состояние *до* применения эффектов.
         // Визуал клиентов будет реагировать на это обновление через OnRep_ActiveInfluenceState.
         ActiveInfluenceState = NewActiveInfluenceState;
         // MarkNetDirty(); // UE должен сам отследить изменение TMap


         // Теперь проходим по всем полям, которые были или стали активными,
         // и сравниваем старый и новый набор эффективных Аур на каждом поле.

         TArray<int32> RelevantFieldIndices;
         OldActiveInfluenceState.GetKeys(RelevantFieldIndices); // Поля, которые имели влияние раньше
         TArray<int32> NewInfluenceKeys;
         NewActiveInfluenceState.GetKeys(NewInfluenceKeys);
         RelevantFieldIndices.Append(NewInfluenceKeys); // Поля, которые имеют влияние сейчас

Параметры из `FPolyeEffectConfig` делают эффекты настраиваемыми из Data Assets.
    *   **Outcome:** Реализованы конкретные типы эффектов, которые модифицируют атрибуты сущностей или применяют другую специфическую логику, готовую к применению Компонентом Управления Эффектами.

    ```cpp
    // Effects/PolyeEffect_HealReduction.cpp

    #include "Effects/PolyeEffect_HealReduction.h"
    #include "Board/BoardEntityBase.h" // Для доступа к атрибутам или другим данным, если нужно (например, в Apply/Remove)

    // КЛИЕНТ/СЕРВЕР: Модификация атрибута
    float UPolyeEffect_HealReduction::ModifyAttributeValue_Implementation(EPolyeAttributeType AttributeType, float CurrentValue) const
    {
         // **ВАЖНО: Выполняется как на СЕРВЕРЕ, так и на КЛИЕНТЕ. Должна быть Pure/Const.**
         // Проверяем, модифицируется ли атрибут "Полученное Исцеление"
         if (AttributeType == EPolyeAttributeType::HealingReceivedModifier)
         {
              // Предполагаем, что EffectConfig.NumericParameters содержит "ReductionAmount"
              // которое установлено в FDecayingInfluenceAuraConfig::GetConfigForStrength (например, 2 для 50%, 1 для 25%).
              // FindRef возвращает ссылку, если ключ найден, или дефолтное значение (0.0f для float), если нет.
              float Reduction = EffectConfig.NumericParameters.FindRef(FName("ReductionAmount"));
              // Применяем снижение. Текущее значение HealingReceivedModifier по умолчанию = 1.0 (100%).
              // Если эффект снижает на 2, то HealingReceivedModifier становится 1.0 - 2 = -1.0.
              // Если исцеление = 10, то ActualHeal = 10 * (-1.0) = -10. Это неправильно.
              // Модификаторы должны быть добавочными или множительными.
              // Если ReductionAmount - это АБСОЛЮТНОЕ снижение, то:
              // return CurrentValue - Reduction; // Применяем как добавочный модификатор

              // Если ReductionAmount - это % снижения (напр. 0.5 для 50%), то:
              // return CurrentValue * (1.0f - Reduction); // Применяем как множитель

              // Если CurrentValue - это уже эффективное значение модификатора (напр. 1.0),
              // а Reduction - это ЧИСЛОВОЕ значение снижения (напр., -2), то:
               return CurrentValue + EffectConfig.NumericParameters.FindRef(FName("HealingReductionValue")); // Применяем как добавочный модификатор к базовому (например, 0)

               // Или, если в EffectConfig хранится сам множитель (напр., 0.5 для 50% силы):
               // return CurrentValue * EffectConfig.NumericParameters.FindRef(FName("HealingModifierMultiplier"));
         }
         return CurrentValue; // Не модифицируем другие атрибуты
    }

        *   Config25Percent: NumericParameters: {"HealingReductionValue": 1.0}

**Ключевые Соображения и Альтернативы:**

*   **Сложность Пользовательской Системы Эффектов:** Создание надежной, расширяемой и сетевой системы эффектов с нуля (управление длительностью, стеками, источниками, тегами, иммунитетами, порядком применения модификаторов) очень сложно. `UPolyeGameplayEffectBase` и `UPolyeEffectManagerComponent` предоставляют основу, но требуют значительной доработки.
*   **Gameplay Ability System (GAS):** GAS - это мощный фреймворк UE для управления атрибутами, эффектами (GameplayEffects) и способностями. GameplayEffects в GAS уже имеют встроенную сетевую репликацию, управление длительностью/стеками, модификаторы атрибутов и теги. Использование GAS сильно упростило бы этот шаг и последующие, связанные с боем и способностями. **Если вы планируете сложную систему эффектов и атрибутов, настоятельно рекомендуется изучить GAS.** Ваша текущая структура `UPolyeGameplayEffectBase` и `UPolyeEffectManagerComponent` является "облегченной" версией концепций GAS.
*   **Производительность Расчета Влияния:** Алгоритм расчета влияния (`CalculateAndApplyInfluence`) должен быть оптимизирован для больших досок или большого количества источников. Текущая реализация итерирует по источникам, затем по затронутым полям, затем по аурам, затем по сущностям. Это может стать узким местом.
*   **Идентификация Эффектов:** Для надежного удаления эффектов, особенно при изменении силы Ауры, экземпляры `UPolyeGameplayEffectBase` должны иметь способ идентифицировать *источник* и *тип* эффекта (напр., FieldIndex источника, AuraType, уникальный ID экземпляра Ауры) и удаление должно происходить по этим критериям, а не только по типу эффекта.
*   **Визуализация Аур vs. Визуализация Эффектов:** Различайте:
    *   Визуализация АУР на ПОЛЕ (напр., свечение плитки, иконка фракции/ауры). Это основано на `ActiveInfluenceState` в GameState и делается в `AFieldTile::SetInfluenceVisuals`.
    *   Визуализация ЭФФЕКТОВ на СУЩНОСТИ (напр., партиклы "Горение", иконка баффа над юнитом). Это основано на `ActiveEffects` в `EffectManagerComponent` и делается в `ABoardEntityBase::OnRep_ActiveEffects` или в BP сущностей.
*   **Правила Сложения:** Текущее правило сложения "максимальная сила для каждого уникального типа Ауры" реализовано в `CalculateAndApplyInfluence`. Если правила изменятся (напр., Ауры одной фракции стекаются, Ауры разных фракций суммируются по-другому), нужно будет изменить этот алгоритм.
