**Цель:** Реализовать игровую фазу в начале матча, во время которой каждый игрок может выбрать и активировать от 2 до 5 своих полей. Эта система должна обрабатывать ввод игрока, валидировать его на сервере, обновлять состояние игры и синхронизировать визуальное представление, а также позволять игрокам сигнализировать о готовности к переходу в следующую фазу.

**Предпосылки:**

*   **Базовая Сетевая Архитектура (Шаг 2):** Реализованы ключевые C++ классы (`AGameModeBase`, `AGameStateBase`, `APolyePlayerController`, `APolyePlayerStateBase`) с базовой сетевой настройкой (репликация).
*   **Система Данных (Шаг 3):** Определены структуры данных (Enums, `USTRUCT`) и `UDataAsset`ы для игрового контента.
*   **Базовая Система Сущностей (Шаг 4):** Создана иерархия сущностей на поле (`ABoardEntityBase`, `AUnit`, `AStructure`) с базовыми атрибутами и логикой здоровья/смерти.
*   **Игровое Поле (Шаг 4):** Реализовано логическое представление поля (`FPolyeFieldState` в `AGameStateBase`), система идентификации полей (`FieldIndex`, `UPolyeBoardStatics`) и базовое визуальное представление (`AGameBoard`, `AFieldTile`), которое обновляется на основе реплицированного `GameState`.
*   **Обработка Ввода:** Настроена обработка ввода (Enhanced Input) в `APolyePlayerController`, включая клики по игровому полю (через трассировку луча и `UPolyeBoardStatics::GetFieldIndexAtLocation`).

**Ключевые Компоненты и Их Роли в Этом Шаге:**

*   **`APolyeGameModeBase` (Сервер):** Является центральным управляющим матчем. Он отслеживает текущую фазу игры (`EPolyeMatchPhase`), получает и валидирует запросы игроков на активацию полей и сигнализирование о готовности. Управляет переходом между фазами и инициирует начало основного игрового цикла. Хранит временное состояние фазы (количество активированных полей каждым игроком).
*   **`APolyeGameStateBase` (Сервер и Клиенты):** Хранит реплицируемое состояние всей доски (`TArray<FPolyeFieldState> BoardState`). Сервер обновляет статус `bIsActive` для полей в этом массиве. Клиенты получают это обновление через репликацию (`OnRep_BoardState`) и используют для обновления визуального представления.
*   **`APolyePlayerController` (Клиент-Владелец и Сервер):** На стороне клиента обрабатывает ввод игрока (клик по полю, нажатие кнопки "Готов"). Использует Server RPC для отправки запросов на сервер (`Server_RequestFieldActivation`, `Server_RequestFinishActivation`). На стороне сервера эти RPC выполняются и передают управление GameMode. На стороне клиента получает уведомления от сервера через Client RPC (`Client_StartFieldActivationPhase`, `Client_NotifyFieldActivated`, `Client_NotifyActivationError`, `Client_NotifyFinishedActivationPhase`) для управления UI и локальным состоянием фазы.
*   **`APolyePlayerStateBase` (Сервер и Клиенты):** Хранит реплицируемое состояние конкретного игрока. В этом шаге может использоваться для хранения индекса игрока (`PlayerIndex`) и, возможно, статуса "готовности к следующей фазе" (хотя GameMode может отслеживать это сам).
*   **`AFieldTile` (Клиенты - Визуал):** Визуальное представление плитки поля. Реализует логику (`SetActiveStateVisuals`), чтобы изменить внешний вид плитки в зависимости от ее статуса активности (`bIsActive`) из `FPolyeFieldState`, который приходит через репликацию GameState -> GameBoard.
*   **UI (Клиенты - Визуал/Ввод):** Виджеты UMG, управляемые PlayerController клиента, отображают информацию о текущей фазе (счетчик активированных полей) и предоставляют кнопку "Готов".

**Шаги Реализации:**

1.  **Управление Игровыми Фазами (в `APolyeGameModeBase` - Сервер):**
    *   **Роль:** `APolyeGameModeBase` действует как конечный автомат матча. Он определяет, какая фаза игры активна, когда она начинается, когда заканчивается и какие действия допустимы в текущей фазе. В фазе активации полей он также отслеживает прогресс каждого игрока.
    *   **Что Хранить Здесь:** Переменная `CurrentMatchPhase`, счетчики `FieldsActivatedCount` (сколько полей активировал каждый игрок), `PlayersFinishedActivation` (сколько игроков завершили активацию), лимиты активации (`Min/MaxFieldsToActivate`).
    *   **Что Не Хранить Здесь:** Состояние доски (`BoardState` - это в `GameState`), состояние конкретного игрока (это в `PlayerState`), обработку пользовательского ввода (это в `PlayerController`).
    *   **Действие:** Добавить Enum `EPolyeMatchPhase`, переменную `CurrentMatchPhase`, счетчики и лимиты в `APolyeGameModeBase.h`. Реализовать функции для инициации фазы активации и обработки запросов от PlayerController в `APolyeGameModeBase.cpp`.
    *   **Обоснование Реализации:** Использование Enum для фаз делает логику матча более структурированной. Все изменения фаз и обработка запросов, зависящих от фазы, происходят только на сервере (`HasAuthority()`). Счетчики и флаги хранятся в GameMode как временное состояние матча. Функции `HandlePlayer...Request` служат точками входа для Server RPC из PlayerController.
    *   **Outcome:** В `APolyeGameModeBase` добавлена структура для управления фазами игры и логика отслеживания прогресса игроков в фазе активации полей.

    {
         // Убедимся, что мы в правильной фазе
         if (CurrentMatchPhase != EPolyeMatchPhase::Setup)
         {
              UE_LOG(LogTemp, Warning, TEXT("StartFieldActivationPhase called from incorrect phase: %s"), *UEnum::GetValueAsString(CurrentMatchPhase));
              return;
         }

         CurrentMatchPhase = EPolyeMatchPhase::FieldActivation; // Переключаем фазу на сервере
         FieldsActivatedCount.Empty(); // Сбрасываем счетчики для каждого игрока
         PlayersFinishedActivation = 0; // Сбрасываем счетчик завершивших игроков

         UE_LOG(LogTemp, Warning, TEXT("APolyeGameModeBase: Starting Field Activation Phase. Players must choose %d to %d fields."), MinFieldsToActivate, MaxFieldsToActivate);

         for (FConstPlayerControllerIterator Iterator = GetWorld()->GetPlayerControllerIterator(); Iterator; ++Iterator)
         {
              if (APlayerController* PC = Iterator->Get())

                   if (APolyePlayerController* PolyePC = Cast<APolyePlayerController>(PC))
                   {
                        // Отправляем RPC на клиент этого игрока.
                        // Клиентская сторона PlayerController получит этот вызов и обновит свой UI.
                        PolyePC->Client_StartFieldActivationPhase(MinFieldsToActivate, MaxFieldsToActivate);
                   }
              }
         }

         // TODO: Возможно, запустить таймер на эту фазу (если есть ограничение по времени)

    // SERVER ONLY: Обработка запроса игрока на активацию поля
    // Вызывается из Server_RequestFieldActivation_Implementation в PlayerController.
    void APolyeGameModeBase::HandlePlayerFieldActivationRequest(APolyePlayerController* RequestingPlayer, int32 FieldIndex)
    {
         // **ЭТА ФУНКЦИЯ ВЫПОЛНЯЕТСЯ ТОЛЬКО НА СЕРВЕРЕ.**
         // **Здесь происходит основная игровая валидация запроса.**

         // Базовые проверки (фаза игры, валидность игрока)
         if (!RequestingPlayer || CurrentMatchPhase != EPolyeMatchPhase::FieldActivation)
         {
              UE_LOG(LogTemp, Warning, TEXT("HandlePlayerFieldActivationRequest failed: Invalid player or phase."));
              RequestingPlayer->Client_NotifyActivationError(TEXT("Cannot activate field in this phase."));
              return;
         }

         APolyeGameStateBase* GS = GetGameState<APolyeGameStateBase>();
         if (!GS || !GS->BoardState.IsValidIndex(FieldIndex))
         {
              UE_LOG(LogTemp, Warning, TEXT("HandlePlayerFieldActivationRequest failed: Invalid GameState or FieldIndex %d."), FieldIndex);
              RequestingPlayer->Client_NotifyActivationError(TEXT("Invalid field selected."));
              return;
         }

         // Получаем PlayerState запросившего игрока для доступа к его индексу и другим данным
         APolyePlayerStateBase* PS = Cast<APolyePlayerStateBase>(RequestingPlayer->PlayerState);
         if (!PS)
         {
              UE_LOG(LogTemp, Error, TEXT("HandlePlayerFieldActivationRequest failed: Requesting PlayerState is null."));
              RequestingPlayer->Client_NotifyActivationError(TEXT("Player state error."));
              return;
         }

         // Получаем ссылку на структуру состояния поля в GameState (для изменения на сервере)
         FPolyeFieldState& FieldState = GS->BoardState[FieldIndex];

         // --- Игровая Валидация ---

         // 1. Поле принадлежит игроку, запросившему активацию?
         // Сравниваем InitialOwnerPlayerIndex поля с PlayerIndex игрока.
         if (FieldState.InitialOwnerPlayerIndex == INDEX_NONE || FieldState.InitialOwnerPlayerIndex != PS->PlayerIndex)
         {
              UE_LOG(LogTemp, Warning, TEXT("Player %s (Index %d) tried to activate field %d which is not theirs (InitialOwnerIndex %d)."), *RequestingPlayer->GetName(), PS->PlayerIndex, FieldIndex, FieldState.InitialOwnerPlayerIndex);
              RequestingPlayer->Client_NotifyActivationError(TEXT("You can only activate your own starting fields."));
              return;
         }

         // 2. Поле еще не активно?
         if (FieldState.bIsActive)
         {
              UE_LOG(LogTemp, Warning, TEXT("Player %s tried to activate already active field %d."), *RequestingPlayer->GetName(), FieldIndex);
              RequestingPlayer->Client_NotifyActivationError(TEXT("This field is already active."));
              return;
         }

         // 3. Игрок не превысил максимальное количество полей для активации?
         FieldsActivatedCount.FindOrAdd(PS->PlayerIndex)++; // Увеличиваем счетчик временно для проверки
         if (FieldsActivatedCount[PS->PlayerIndex] > MaxFieldsToActivate)
         {
              FieldsActivatedCount[PS->PlayerIndex]--; // Откатываем счетчик
              UE_LOG(LogTemp, Warning, TEXT("Player %s tried to activate field %d but exceeded max limit (%d/%d)."), *RequestingPlayer->GetName(), FieldIndex, FieldsActivatedCount[PS->PlayerIndex] + 1, MaxFieldsToActivate);
              RequestingPlayer->Client_NotifyActivationError(FText::Format(NSLOCTEXT("Polye", "ActivationLimit", "You can activate maximum of {0} fields."), FText::AsNumber(MaxFieldsToActivate)).ToString());
              return;
         }

         // --- ВАЛИДАЦИЯ ПРОШЛА УСПЕШНО! Изменяем состояние на сервере ---
         UE_LOG(LogTemp, Log, TEXT("Player %s (Index %d) successfully activated field %d. Total activated: %d."),
             *RequestingPlayer->GetName(), PS->PlayerIndex, FieldIndex, FieldsActivatedCount[PS->PlayerIndex]);

         // Активируем поле в GameState. Это изменение реплицируется всем клиентам.
         // Изменение BoardState[FieldIndex].bIsActive вызовет OnRep_BoardState на клиентах.
         FieldState.bIsActive = true;

2.  **Player Controller (Клиентская Инициация и Серверная Валидация/Вызов):**
    *   **Роль:** `APolyePlayerController` на клиенте отвечает за принятие пользовательского ввода (клики, нажатия кнопок), определение намерения игрока (активировать поле, завершить фазу) и отправку запросов на сервер через Server RPC. На сервере он служит точкой входа для этих запросов, передавая их GameMode для обработки. На клиенте он также получает команды от GameMode через Client RPC для управления UI и локальным состоянием фазы.
    *   **Что Хранить Здесь:** Ссылки на UI виджеты, временное клиентское состояние фазы (флаг `bIsInFieldActivationPhase`, локальные счетчики и лимиты для UI), ссылки на Input Actions.
    *   **Что Не Хранить Здесь:** Игровую логику валидации (это в GameMode), состояние доски (это в GameState), состояние игрока (это в PlayerState).
    *   **Действие:** Добавить Client RPC для уведомлений от сервера и Server RPC для отправки запросов на сервер. Реализовать обработку кликов по полю для отправки запроса активации. Добавить локальные переменные для клиентского состояния фазы.
    *   **Обоснование Реализации:** RPC являются стандартным механизмом взаимодействия клиент-сервер в UE. Server RPC с `WithValidation` обеспечивают безопасную передачу запросов на сервер. Client RPC позволяют серверу инициировать действия на конкретном клиенте (обновить UI, показать сообщение). Обработка ввода (`OnClickGameBoard`) выполняется только на клиенте, который владеет этим PlayerController (`IsLocalPlayerController()` неявная проверка при привязке ввода).
    *   **Outcome:** Реализованы Client и Server RPC для управления фазой активации полей. Логика клика по доске в PlayerController отправляет запрос на активацию. PlayerController готов принимать команды от GameMode для управления UI фазы.

**Важные Примечания:**

*   **Серверный Авторитет:** Валидация *всегда* на сервере. Клиент только запрашивает.
*   **Репликация -> Визуал:** Изменения состояния на сервере (GameState) реплицируются, и только *после этого* клиенты обновляют свое локальное визуальное представление. Локальные счетчики в PC для UI могут быть обновлены немедленно для отзывчивости, но источником истины является серверный счетчик в GameMode.
*   **UI vs. Геймплей:** UI (UMG) должен быть отделен от основной логики геймплея (GameMode, GameState, сущности). PlayerController служит связующим звеном.
*   **Доступ к GameState/GameMode:** На сервере GameMode может получить доступ к GameState (`GetGameState<APolyeGameStateBase>()`). На клиенте PlayerController может получить доступ к GameState (`GetGameState<APolyeGameStateBase>()`) для чтения реплицированных данных, но не к GameMode напрямую (т.к. GameMode только на сервере).
*   **UX:** Добавьте визуальную обратную связь при клике на поле, даже если действие еще не подтверждено сервером (например, временная подсветка плитки). Уберите ее, если сервер отклонил запрос, или оставьте, если сервер подтвердил.
