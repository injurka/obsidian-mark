**Цель:** Реализовать игровую механику привязки Ландшафта к активному полю с фракцией. Это включает хранение выбранного `UPolyeLandscapeData` в состоянии поля, серверную валидацию выбора, применение уникального "Ульта" эффекта этого Ландшафта к сущностям на поле и обновление визуального представления поля для отображения выбранного Ландшафта и его "Ульты".

**Предпосылки:**

*   **Базовая Сетевая Архитектура (Шаг 2):** Реализованы ключевые C++ классы (`AGameModeBase`, `AGameStateBase`, `APolyePlayerController`, `APolyePlayerStateBase`) с базовой сетевой настройкой.
*   **Система Данных (Шаг 3):** Определены структуры данных (`EPolyeFaction`, `FPolyeFieldState`, `FFieldUltConfig`, `FPolyeEffectConfig`, `EPolyeEffectType`, `EPolyeAttributeType`) в `PolyeDataTypes.h`. Созданы Data Assets для Фракций (`UPolyeFactionData`) и Ландшафтов (`UPolyeLandscapeData`). `UPolyeFactionData` содержит список доступных `UPolyeLandscapeData`. `UPolyeLandscapeData` содержит `FFieldUltConfig`. `FFieldUltConfig` содержит `TSubclassOf<UPolyeGameplayEffectBase>` и `FPolyeEffectConfig`. Создан Менеджер Фракций (`UPolyeFactionManager`), способный предоставлять данные о фракциях и их доступных ландшафтах (доступен, напр., через `GameInstance`).
*   **Базовая Система Сущностей (Шаг 4) и Система Эффектов (Шаг 5):** Создана иерархия сущностей на поле (`ABoardEntityBase`) с компонентом `UPolyeEffectManagerComponent`. Создан базовый класс эффекта (`UPolyeGameplayEffectBase`) и его наследники. Система эффектов может создавать экземпляры `UPolyeGameplayEffectBase` на сущностях через `EffectManagerComponent::ApplyEffect`, удалять их (`RemoveEffectInstance`, `RemoveEffectsBy`), и эти эффекты могут модифицировать атрибуты (`GetEffectiveAttributeValue`). Список активных эффектов на сущности реплицируется.
*   **Игровое Поле (Шаг 4):** Реализовано логическое состояние поля (`FPolyeFieldState::BoardState` в реплицируемом `AGameStateBase`), система идентификации полей (`FieldIndex`, `UPolyeBoardStatics`). Базовое визуальное представление (`AGameBoard`, `AFieldTile`) обновляется на основе GameState. `AFieldTile` умеет визуально реагировать на `bIsActive`. `FPolyeFieldState` включает `TSoftObjectPtr<const UPolyeLandscapeData> CurrentLandscapeDataAsset` для хранения ссылки на ландшафт.
*   **Фаза Активации Полей (Шаг 5):** Реализовано управление фазами в GameMode (`EPolyeMatchPhase`), активация полей (`bIsActive` обновляется), и выбор/применение Фракции (`CurrentFaction` обновляется) с серверной валидацией правила соседства. RPC для активации поля принимает тип Фракции. UI для выбора Фракции существует.
*   **Затухающее Влияние (Шаг 5):** Система расчета Влияния и применения эффектов Ауры реализована. `AGameStateBase::CalculateAndApplyInfluence()` существует и вызывается при изменении источников влияния. **Важно:** Ульты полей - это отдельный механизм эффектов, который не распространяется как Аура, а действует только на сущности *на своем* поле.

**Ключевые Компоненты и Их Роли в Этом Шаге:**

*   **`APolyePlayerController` (Клиент-Владелец и Сервер):** На стороне клиента: добавляется логика UI для выбора Ландшафта. Модифицируется обработка ввода (клика по полю), чтобы отправлять Server RPC, включающий *выбранный ландшафт* в дополнение к `FieldIndex` и `FactionType`. На стороне сервера: реализация нового Server RPC, принимающего `LandscapeID` и передающего его GameMode.
*   **`APolyeGameModeBase` (Сервер):** Центральный обработчик запросов активации поля. Получает запрос на активацию поля *с указанной фракцией и ландшафтом*. Выполняет все предыдущие проверки (фаза, принадлежность поля, лимит, правило соседства) И добавляет новую, критически важную проверку: **доступен ли выбранный Ландшафт для выбранной Фракции**. Если все проверки проходят, он обновляет `FPolyeFieldState` этого поля в `GameState`, устанавливая `CurrentLandscapeDataAsset = ВыбранныйЛандшафт`. Инициирует применение эффекта Ульты Ландшафта.
*   **`AGameStateBase` (Сервер и Клиенты):** Хранит реплицируемое состояние доски, включая `FPolyeFieldState::CurrentLandscapeDataAsset` для каждого поля. **Сервер:** Реализует функции (`ApplyLandscapeUltEffectToField`, `RemoveLandscapeUltEffectFromField`) для управления экземплярами эффектов Ульты на сущностях поля, используя `UPolyeEffectManagerComponent`. **Клиенты:** Получают реплицированное `CurrentLandscapeDataAsset` через `OnRep_BoardState` (или `OnRep_Landscape` если настроено) и используют его для визуального отображения Ландшафта.
*   **`UPolyeFactionManager` (Менеджер Данных):** Используется GameMode (на сервере) для доступа к данным Фракций (`UPolyeFactionData`), чтобы получить список доступных Ландшафтов и проверить валидность выбора игрока. Используется GameState (на сервере) для доступа к данным Ландшафтов (`UPolyeLandscapeData`) и получения конфига Ульты.
*   **`UPolyeLandscapeData` (Data Asset):** Хранит параметры конкретного Ландшафта, включая структуру `FFieldUltConfig`, которая определяет эффект его Ульты.
*   **`FFieldUltConfig` (Структура Данных):** Связывает Ландшафт с конкретным типом `UPolyeGameplayEffectBase` (`TSubclassOf`) и его параметрами (`FPolyeEffectConfig`) для Ульты.
*   **`ABoardEntityBase` & `UPolyeEffectManagerComponent` (Сервер):** Сущности на поле, к которым применяются эффекты Ульты Ландшафта через их `EffectManagerComponent`.
*   **`UPolyeGameplayEffectBase` & Наследники (Сервер):** Экземпляры эффектов Ульты, создаваемые и применяемые к сущностям. Реализуют специфическую логику Ульты (напр., модификация атрибутов, периодический урон, применение статуса).
*   **`AFieldTile` (Клиенты - Визуал):** Добавляется логика (`SetLandscapeVisuals`) для изменения внешнего вида плитки в зависимости от примененного `UPolyeLandscapeData`. Также отвечает за визуализацию эффектов самой Ульты на поле (если они не привязаны к сущностям).
*   **UI (Клиенты - Визуал/Ввод):** Виджеты UMG модифицируются, чтобы предложить игроку выбор Ландшафта после выбора Фракции, отобразить доступные варианты и зарегистрировать выбор игрока.

**Шаги Реализации:**

1.  **Хранение Ландшафта в `FPolyeFieldState` (Проверка):**
    *   **Роль:** `FPolyeFieldState` - это реплицируемая структура, представляющая состояние одного поля. Она должна хранить ссылку на примененный Ландшафт, чтобы это состояние было синхронизировано на всех клиентах.
    *   **Что Хранить Здесь:** Свойство `TSoftObjectPtr<const UPolyeLandscapeData> CurrentLandscapeDataAsset`.
    *   **Действие:** Убедиться, что в структуре `FPolyeFieldState` (в `Core/PolyeDataTypes.h`) есть свойство для хранения ссылки на выбранный `UPolyeLandscapeData` и что оно помечено `UPROPERTY(Replicated)`.
    *   **Обоснование Реализации:** Использование `TSoftObjectPtr` позволяет ссылаться на Data Asset Ландшафта, не загружая его в память на сервере или клиентах, пока это не потребуется. `UPROPERTY(Replicated)` гарантирует, что эта ссылка реплицируется. `const` указывает, что сам ассет не будет меняться после загрузки.
    *   **Outcome:** Структура состояния поля может хранить ссылку на выбранный Ландшафт и настроена на репликацию. `OnRep_BoardState` в GameState вызовет обновление визуала.

    **Реализация (Проверка в `Core/PolyeDataTypes.h`):**
    ```cpp
    // Core/PolyeDataTypes.h (в структуре FPolyeFieldState)
    // ... существующие свойства FieldIndex, bIsActive, InitialOwnerPlayerIndex, CurrentFaction

    // Ссылка на Data Asset Ландшафта, примененного к полю (если активное и принадлежит игроку).
    // Реплицируется всем клиентам. TSoftObjectPtr реплицирует путь к ассету.
    // OnRep_Landscape (если настроен) или OnRep_BoardState (если BoardState реплицируется через ReplicatedUsing)
    // будет вызван на клиентах при изменении.
    UPROPERTY(Replicated, BlueprintReadOnly, Category = "Field State")
    TSoftObjectPtr<const UPolyeLandscapeData> CurrentLandscapeDataAsset;

    // ... остальная часть структуры
    ```
    *   *Примечание:* В предыдущих шагах мы использовали `ReplicatedUsing=OnRep_Landscape` для этой переменной в структуре. Однако, поскольку `FPolyeFieldState` находится в `TArray<FPolyeFieldState>` в `AGameStateBase`, более надежно полагаться на `ReplicatedUsing=OnRep_BoardState` на самом массиве `BoardState` в `GameState` и обрабатывать все изменения полей в одной `OnRep` функции на клиенте. Если вы настроили `OnRep_Landscape` внутри структуры, она может не вызываться корректно. Убедитесь, что `BoardState` в GameState реплицируется с `ReplicatedUsing=OnRep_BoardState`.

2.  **Обновление RPC Активации Поля для Включения Выбора Ландшафта (в `APolyePlayerController`):**
    *   **Роль:** Позволить клиенту отправить на сервер полный запрос, включающий выбор поля, Фракции и Ландшафта.

    // SERVER RPC Validation (Выполняется на СЕРВЕРЕ перед _Implementation)
    bool APolyePlayerController::Server_RequestActivateFieldWithFactionAndLandscape_Validate(int32 FieldIndex, EPolyeFaction FactionType, FName LandscapeID)
    {
         // **ВАЖНО: Этот код выполняется ТОЛЬКО на СЕРВЕРЕ.**
         // **Быстрая базовая валидация RPC.**

         if (!HasAuthority()) return false; // Проверяем, что вызвано на сервере
         if (FieldIndex < 0 || FieldIndex >= UPolyeBoardStatics::TotalFields) // Базовая валидация FieldIndex
         {
              UE_LOG(LogTemp, Warning, TEXT("Server_RequestActivateFieldWithFactionAndLandscape_Validate failed: Invalid FieldIndex %d."), FieldIndex);
              return false;

    void APolyeGameModeBase::HandlePlayerFieldActivationFactionAndLandscapeRequest(APolyePlayerController* RequestingPlayer, int32 FieldIndex, EPolyeFaction FactionType, FName LandscapeID)
    {
         // **ВАЖНО: Эта функция выполняется ТОЛЬКО на СЕРВЕРЕ!**
         // **Здесь происходит основная игровая валидация запроса.**

         if (!RequestingPlayer || CurrentMatchPhase != EPolyeMatchPhase::FieldActivation)
         {
              RequestingPlayer->Client_NotifyActivationError(TEXT("Неправильная фаза для активации полей."));
              return;
         }
         APolyeGameStateBase* GS = GetGameState<APolyeGameStateBase>();
         if (!GS || !GS->BoardState.IsValidIndex(FieldIndex))
         {
              RequestingPlayer->Client_NotifyActivationError(TEXT("Выбрано неверное поле."));
              return;
         }
         APolyePlayerStateBase* PS = Cast<APolyePlayerStateBase>(RequestingPlayer->PlayerState);
         if (!PS)
         {
             RequestingPlayer->Client_NotifyActivationError(TEXT("Неверное состояние игрока."));
             return;
         }
         FPolyeFieldState& FieldState = GS->BoardState[FieldIndex]; // Получаем ссылку на состояние поля в GameState

         // Игровая Валидация (из предыдущих шагов)
         // 1. Поле принадлежит игроку?
         if (FieldState.InitialOwnerPlayerIndex == INDEX_NONE || FieldState.InitialOwnerPlayerIndex != PS->PlayerIndex)
         {
              RequestingPlayer->Client_NotifyActivationError(TEXT("Вы можете активировать только свои поля."));
              return;
         }
         // 2. Поле еще не активно?
         if (FieldState.bIsActive)
         {
              RequestingPlayer->Client_NotifyActivationError(TEXT("Это поле уже активно."));
              return;
         }
         // 3. Игрок не превысил максимальное количество полей?
         if (FieldsActivatedCount.FindOrAdd(PS->PlayerIndex) + 1 > MaxFieldsToActivate)
         {
             RequestingPlayer->Client_NotifyActivationError(FText::Format(NSLOCTEXT("Polye", "ActivationLimit", "Вы можете активировать максимум {0} полей."), FText::AsNumber(MaxFieldsToActivate)).ToString());
             return;
         }
         // 4. Правило размещения фракций (не Neutral, правило соседства)
         if (FactionType == EPolyeFaction::EF_Neutral)
         {
              RequestingPlayer->Client_NotifyActivationError(TEXT("Нельзя активировать поле с нейтральной фракцией."));
              return;
         }
         TArray<int32> AdjacentFields = UPolyeBoardStatics::GetAdjacentFields(FieldIndex, false); // Ортогональные соседи
         for (int32 AdjacentIndex : AdjacentFields)
         {
              if (GS->BoardState.IsValidIndex(AdjacentIndex))

                   if (AdjacentFieldState.bIsActive && AdjacentFieldState.CurrentFaction != EPolyeFaction::EF_Neutral && AdjacentFieldState.CurrentFaction != FactionType)

                        return;
                   }
              }

         UPolyeFactionManager* FactionManager = GetGameInstance() ? Cast<UPolyeFactionManager>(GetGameInstance()->GetFactionManager()) : nullptr;
         if (!FactionManager)
         {
              UE_LOG(LogTemp, Error, TEXT("Менеджер Фракций не найден! Невозможно валидировать Ландшафт."));
              RequestingPlayer->Client_NotifyActivationError(TEXT("Произошла внутренняя ошибка."));
              return;

         if (!FactionData)
         {
             UE_LOG(LogTemp, Error, TEXT("Данные фракции %s не найдены!"), *UEnum::GetValueAsString(FactionType));
             RequestingPlayer->Client_NotifyActivationError(TEXT("Произошла внутренняя ошибка."));
             return;
         }

         // Ищем TSoftObjectPtr, а не загруженный ассет.
         TSoftObjectPtr<const UPolyeLandscapeData> SelectedLandscapePtr;
         for (const TSoftObjectPtr<const UPolyeLandscapeData>& AvailableLandscapePtr : FactionData->AvailableLandscapes)
         {
              // Используем GetAssetName() для сравнения FName ID с именем ассета.
              if (!AvailableLandscapePtr.IsNull() && AvailableLandscapePtr.GetAssetName() == LandscapeID.ToString())
              {

                   break;
              }
         }

         if (SelectedLandscapePtr.IsNull()) // Проверяем, что ссылка не Null (валидация IsValid() на TSoftObjectPtr не загружает ассет, а IsValid() на T* проверяет, что объект не PendingKill)
         {
              UE_LOG(LogTemp, Warning, TEXT("Player %s tried to activate field %d with invalid Landscape ID %s for Faction %s. Landscape not found in available list."),
                   *RequestingPlayer->GetName(), FieldIndex, *LandscapeID.ToString(), *UEnum::GetValueAsString(FactionType));
               RequestingPlayer->Client_NotifyActivationError(TEXT("Выбран неверный Ландшафт для этой Фракции."));
               return;
         }

         // TODO: Валидация: Является ли FactionType допустимой фракцией для этого игрока? (Сравнить с PlayerState->PlayerFaction)
         // if (FactionType != PS->PlayerFaction) { ... ошибка ... return; }

         UE_LOG(LogTemp, Log, TEXT("Player %s activated field %d with faction %s and landscape %s."),
              *RequestingPlayer->GetName(), FieldIndex, *UEnum::GetValueAsString(FactionType), *LandscapeID.ToString());

         // Сохраняем старое состояние поля, чтобы знать, был ли раньше Ландшафт (для удаления старого эффекта)
         FPolyeFieldState OldFieldState = FieldState; // Копируем структуру

         // Устанавливаем новые реплицируемые свойства на сервере.

         FieldState.bIsActive = true;
         FieldState.CurrentFaction = FactionType;
         FieldState.CurrentLandscapeDataAsset = SelectedLandscapePtr; // Устанавливаем TSoftObjectPtr

         FieldsActivatedCount.FindOrAdd(PS->PlayerIndex)++; // Увеличиваем счетчик активированных полей

         if (OldFieldState.bIsActive && OldFieldState.CurrentLandscapeDataAsset.IsValid() && OldFieldState.CurrentLandscapeDataAsset != FieldState.CurrentLandscapeDataAsset)

             }
         }

         // Применяем эффект Ульты НОВОГО Ландшафта (если он есть)
         // Применяем, только если новое поле активно и имеет валидный Ландшафт
         if (FieldState.bIsActive && FieldState.CurrentLandscapeDataAsset.IsValid())
         {
              ApplyLandscapeUltEffectToField(FieldIndex); // Вызываем функцию применения в GameState
         }


         // **ПЕРЕРАСЧЕТ ВЛИЯНИЯ АУР**
         // Активация поля с фракцией меняет карту влияния Аур. Перерасчитываем Ауры.

         //        но, возможно, ДО применения/удаления эффектов Ульты, если Ульта влияет на Ауры.
         //        Однако, по дизайну Ульта действует только на своем поле, а Ауры распространяются.
         //        Так что перерасчет влияния Аур после управления Ультой, вероятно, правильный порядок.
         GS->CalculateAndApplyInfluence(); // Функция из Шага 5 (предыдущего)


         // Уведомляем клиента об успешной активации, фракции, ландшафте и текущем количестве
         // TODO: Добавить Client RPC: Client_NotifyFieldActivatedWithFactionAndLandscape в PlayerController

         // **ВАЖНО: Выполняется ТОЛЬКО на СЕРВЕРЕ!**
         if (!HasAuthority() || !BoardState.IsValidIndex(FieldIndex)) return;

         const FPolyeFieldState& FieldState = BoardState[FieldIndex];

         if (!FieldState.bIsActive || FieldState.CurrentLandscapeDataAsset.IsNull()) // Проверяем, что TSoftObjectPtr не Null

              UE_LOG(LogTemp, Error, TEXT("Не удалось загрузить Data Asset Ландшафта для поля %d!"), FieldIndex);

         if (!UltConfig.EffectClass || UltConfig.EffectParameters.EffectType == EPolyeEffectType::PET_None)

              return; // Нет валидной Ульты для применения
         }

         UE_LOG(LogTemp, Log, TEXT("Применяем Ульту Ландшафта %s (Эффект %s) к сущностям на поле %d."),
              *LandscapeData->GetName(), *UEnum::GetValueAsString(UltConfig.EffectParameters.EffectType), FieldIndex);

         // Применяем эффект Ульты к каждой сущности, которая НАХОДИТСЯ на этом поле СЕЙЧАС.
         // Используем актуальный список EntitiesOnField из BoardState.
         for (ABoardEntityBase* Entity : FieldState.EntitiesOnField)
         {
              if (IsValid(Entity) && Entity->GetEffectManagerComponent()) // Проверяем валидность сущности и наличие компонента

                   // Применяем эффект Ульты.

                   //       Entity->GetEffectManagerComponent()->ApplyEffect(UltConfig.EffectClass, UltConfig.EffectParameters, FieldIndex); // Передаем индекс поля как источник
                   Entity->GetEffectManagerComponent()->ApplyEffect(UltConfig.EffectClass, UltConfig.EffectParameters); // MVP: пока без SourceField в конфиге
              }

        void APolyeGameStateBase::RemoveLandscapeUltEffectFromField(int32 FieldIndex, const UPolyeLandscapeData* OldLandscapeData)
        {
             // **ВАЖНО: Выполняется ТОЛЬКО на СЕРВЕРЕ!**
             if (!HasAuthority() || !BoardState.IsValidIndex(FieldIndex) || !OldLandscapeData || !OldLandscapeData->LandscapeUlt.EffectClass)
             {
                 UE_LOG(LogTemp, Warning, TEXT("RemoveLandscapeUltEffectFromField failed: Invalid parameters (Field %d, Landscape Valid=%d)."),
                      FieldIndex, IsValid(OldLandscapeData));
                 return;
             }

             const FFieldUltConfig& OldUltConfig = OldLandscapeData->LandscapeUlt;

             UE_LOG(LogTemp, Log, TEXT("Удаляем Ульту Ландшафта %s (Эффект %s) с сущностей на поле %d."),
                  *OldLandscapeData->GetName(), *UEnum::GetValueAsString(OldUltConfig.EffectParameters.EffectType), FieldIndex);

             // Удаляем эффект Ульты с каждой сущности, которая НАХОДИТСЯ на поле СЕЙЧАС.
             const FPolyeFieldState& FieldState = BoardState[FieldIndex]; // Берем актуальное состояние

             for (ABoardEntityBase* Entity : FieldState.EntitiesOnField)
             {
                  if (IsValid(Entity) && Entity->GetEffectManagerComponent())
                  {
                       // TODO: Нужен надежный способ удалить *именно* эффект Ульты от *этого* поля/ландшафта.
                       //       Лучше всего - если эффект Ульты имеет SourceField и удаляется по нему.
                       //       Entity->GetEffectManagerComponent()->RemoveEffectsBySourceField(FieldIndex, OldUltConfig.EffectClass);

                       //      Предполагаем, что тип эффекта хранится в FPolyeEffectConfig.
                       Entity->GetEffectManagerComponent()->RemoveEffectsBy(OldUltConfig.EffectParameters.EffectType); // Удалить все эффекты этого типа
                  }
             }

              // TODO: Возможно, остановить визуальный эффект Ульты на самом поле
