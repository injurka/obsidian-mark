**Цель:** Реализовать механику привязки Ландшафта (`UPolyeLandscapeData`) к активному полю с фракцией. Это включает:
    1.  UI для выбора Ландшафта игроком (из списка доступных для выбранной Фракции).
    2.  Передачу выбранного Ландшафта на сервер при активации поля.
    3.  Серверную валидацию доступности Ландшафта для Фракции.
    4.  Хранение и репликацию примененного Ландшафта в `FPolyeFieldState`.
    5.  Применение/удаление уникального "Ульта"-эффекта Ландшафта к сущностям на этом поле.
    6.  Визуальное отображение Ландшафта и эффектов его "Ульты".

**Предпосылки (Уже Реализованы):**

1.  **Сетевая Архитектура:** Все базовые классы (`AGameModeBase`, `AGameStateBase`, `APolyePlayerController`, `APolyePlayerStateBase`).
2.  **Система Данных:**
    *   `PolyeTypes.h`: `EPolyeFaction`, `FPolyeFieldState` (содержит `TSoftObjectPtr<UPolyeLandscapeData> AppliedLandscape`), `FEffectDefinition`.
    *   `UPolyeLandscapeData`: Содержит `FFieldAbilityDefinition LandscapeFieldAbility` (ранее `FFieldUltConfig`), которая в свою очередь имеет `FEffectDefinition AbilityEffect`.
    *   `UPolyeFactionData`: Содержит `TArray<TSoftObjectPtr<UPolyeLandscapeData>> AvailableLandscapes`.
    *   `UPolyeDataManager`: Предоставляет доступ к этим Data Assets.
3.  **Система Сущностей и Эффектов:**
    *   `APolyeBoardEntityBase` с `UPolyeEntityEffectComponent`.
    *   `UPolyeGameplayEffect` (базовый класс для эффектов).
    *   `UPolyeEntityEffectComponent` может применять (`ApplyAuraEffect_Server`) и удалять (`RemoveAllAuraEffectsFromSource_Server`, `RemoveAuraEffectByTypeAndSource_Server`) эффекты.
4.  **Игровое Поле:** Логическое состояние в `AGameStateBase::BoardState`, визуал `AGameBoard` и `AFieldTile`.
5.  **Фаза Активации Полей:** Логика в `APolyeGameModeBase`. RPC для активации поля принимает фракцию.
6.  **Затухающее Влияние:** Система расчета аур реализована. *Ульты полей не распространяются как ауры*.

**Ключевые Компоненты и Их Роли (Уточнение):**

*   **`APolyePlayerController` (Клиент & Сервер):**
    *   **Клиент:** Отображает UI выбора Ландшафта (после выбора Фракции). Хранит `ClientSelectedLandscapeID` (тип `FName`, должен соответствовать `LandscapeID` в `UPolyeLandscapeData`). Отправляет `Server_RequestActivateFieldWithFactionAndLandscape(FieldIndex, Faction, LandscapeID)`.
*   **`APolyeGameModeBase` (Сервер):**
    *   В `HandlePlayerFieldActivationRequest` (переименованной или новой `HandlePlayerFieldActivationFactionAndLandscapeRequest`):
        *   Валидирует доступность `LandscapeID` для `FactionType` через `UPolyeDataManager` (проверяя `UPolyeFactionData::AvailableLandscapes`).
        *   Если все ок, обновляет `APolyeGameStateBase::BoardState[FieldIndex].AppliedLandscape` (сохраняя `TSoftObjectPtr` на `UPolyeLandscapeData`).
        *   **Важно:** Инициирует применение/удаление эффекта Ульты через функции в `APolyeGameStateBase`.
*   **`APolyeGameStateBase` (Сервер & Клиенты):**
    *   `BoardState[FieldIndex].AppliedLandscape` (тип `TSoftObjectPtr<UPolyeLandscapeData>`) реплицируется.
    *   **Сервер:**
        *   `ApplyOrUpdateFieldAbilityEffect_Server(int32 FieldIndex)`:
            *   Загружает `UPolyeLandscapeData` по `BoardState[FieldIndex].AppliedLandscape`.
            *   Получает `LandscapeFieldAbility.AbilityEffect` (тип `FEffectDefinition`).
            *   Для всех сущностей на `BoardState[FieldIndex].EntitiesOnField`:
                *   **Сначала удаляет предыдущий эффект Ульты от этого поля** (если был). Эффекты Ульты должны быть идентифицируемы (например, специальный `EPolyeEffectType` или GameplayTag, или по уникальному ID, связанному с полем).
                *   Применяет новый эффект Ульты (`Entity->EffectComponent->ApplyGameplayEffect_Server(EffectClassFromAbility, AbilityEffectData, FieldIndexAsSource)`).
        *   `RemoveFieldAbilityEffect_Server(int32 FieldIndex, UPolyeLandscapeData* OldLandscapeData)`: (Если ландшафт был изменен/удален). Использует `OldLandscapeData`, чтобы знать, какой эффект удалять.
    *   **Клиент:** `OnRep_BoardState()` триггерит обновление визуала `AFieldTile`.
*   **`UPolyeDataManager` (или `UPolyeFactionManager`):**
    *   Предоставляет `UPolyeFactionData`.
    *   Предоставляет `UPolyeLandscapeData` по его `FName LandscapeID`.
    *   **Новое:** Предоставляет `TSubclassOf<UPolyeGameplayEffect>` по `EPolyeEffectType` (или другому идентификатору), указанному в `FEffectDefinition` Ульты.
*   **`APolyeBoardEntityBase` и `UPolyeEntityEffectComponent`:**
    *   `UPolyeGameplayEffect` для Ульты будет хранить `SourceFieldIndex_Rep` и, возможно, `SourceAbilityID_Rep` для идентификации.
    *   `UPolyeEntityEffectComponent::RemoveGameplayEffectBySourceAndAbilityID_Server(int32 SourceField, FName AbilityID)` - новая функция для точного удаления.
*   **`AFieldTile` (Клиент):**
    *   `UpdateFromState()` (или `OnStateUpdated` BP event) получает `NewState.AppliedLandscape`.
    *   Вызывает `SetLandscapeVisuals(UPolyeLandscapeData* LoadedLandscape)` (BP event).
    *   В `SetLandscapeVisuals` также может инициироваться отображение постоянных визуальных эффектов Ульты на самом поле (не на сущностях), если они есть.

```cpp
// ...
void APolyeGameModeBase::HandlePlayerFieldActivationRequest(APolyePlayerController* RequestingPC, int32 FieldIndex, EPolyeFaction SelectedFaction, FName SelectedLandscapeID)
{
    // ... (все предыдущие проверки: фаза, принадлежность, лимит, соседство фракций) ...
    // Если какая-то проверка не прошла, return;

    UPolyeDataManager* DataManager = GetWorld()->GetGameInstance()->GetSubsystem<UPolyeDataManager>();
    if (!DataManager) { /* ошибка, return */ }

    const UPolyeFactionData* FactionData = DataManager->GetFactionData(SelectedFaction);
    if (!FactionData) { /* ошибка, return */ }

    const UPolyeLandscapeData* LandscapeDataToApply = DataManager->GetLandscapeData(SelectedLandscapeID);
    if (!LandscapeDataToApply)
    {
        RequestingPC->Client_NotifyActivationError(FText::Format(NSLOCTEXT("Polye", "LandscapeNotFound", "Landscape '{0}' not found."), FText::FromName(SelectedLandscapeID)));
        return;
    }

    // Проверка доступности ландшафта для фракции
    bool bIsLandscapeAvailable = false;
    for (const TSoftObjectPtr<UPolyeLandscapeData>& AvailableLandscapePtr : FactionData->AvailableLandscapes)
    {
        // Сравниваем Soft Ptr или загруженный объект, если необходимо (Get() на SoftPtr)
        // Для сравнения по ID, если LandscapeData имеет FName ID:
        if (AvailableLandscapePtr.ToSoftObjectPath() == LandscapeDataToApply->GetPathName()) // Сравнение путей
        // ИЛИ если UPolyeLandscapeData имеет FName LandscapeID (как в вашем дизайне):
        // if (AvailableLandscapePtr.LoadSynchronous()->LandscapeID == SelectedLandscapeID) // Загрузит для проверки ID
        {
            bIsLandscapeAvailable = true;
            break;
        }
    }
    if (!bIsLandscapeAvailable)
    {
        RequestingPC->Client_NotifyActivationError(FText::Format(NSLOCTEXT("Polye", "LandscapeNotAvailable", "Landscape '{0}' is not available for faction {1}."), 
                                                                FText::FromName(SelectedLandscapeID), FactionData->FactionName));
        return;
    }

    // --- Все проверки пройдены ---
    APolyeGameStateBase* GS = GetGameState<APolyeGameStateBase>();
    if (!GS) { /* ошибка, return */ } // Должен быть всегда

    FPolyeFieldState& TargetField = GS->BoardState[FieldIndex];
    TSoftObjectPtr<UPolyeLandscapeData> OldLandscapeSoftPtr = TargetField.AppliedLandscape; // Сохраняем старый

    TargetField.bIsActive = true;
    TargetField.CurrentFaction = SelectedFaction;
    TargetField.AppliedLandscape = LandscapeDataToApply; // Присваиваем SoftPtr

    PlayerActivatedFieldCounts.FindOrAdd(RequestingPS)++; // Обновляем счетчик

    if (OldLandscapeSoftPtr.IsValid() && OldLandscapeSoftPtr != TargetField.AppliedLandscape) // Если был другой ландшафт

        if (OldLoadedLandscape) GS->RemoveFieldAbilityEffect_Server(FieldIndex, OldLoadedLandscape);
    }
    GS->ApplyOrUpdateFieldAbilityEffect_Server(FieldIndex); // Применяем/обновляем Ульту нового ландшафта

    GS->RecalculateInfluenceAndApplyEffects_Server(); // Пересчитываем ауры

    RequestingPC->Client_NotifyFieldActivationSuccess(FieldIndex, SelectedFaction, SelectedLandscapeID, PlayerActivatedFieldCounts.FindRef(RequestingPS));
```

**4. Реализация Логики Ульты Ландшафта в `APolyeGameStateBase`**

*   **Действие:**
    *   В `APolyeGameStateBase.h`:
        *   `void ApplyOrUpdateFieldAbilityEffect_Server(int32 FieldIndex);`
        *   `void RemoveFieldAbilityEffect_Server(int32 FieldIndex, UPolyeLandscapeData* LandscapeDataSource);` (принимает `LandscapeDataSource` для идентификации эффекта).
    *   В `APolyeGameStateBase.cpp`:
        *   `ApplyOrUpdateFieldAbilityEffect_Server`:
            1.  Проверяет `HasAuthority()`.
            2.  Получает `FPolyeFieldState` для `FieldIndex`.
            3.  Если `!State.bIsActive` или `State.AppliedLandscape.IsNull()`, то вызывает `RemoveFieldAbilityEffect_Server` (на случай, если поле деактивировалось или ландшафт сняли) и выходит.
            4.  Загружает `UPolyeLandscapeData* CurrentLandscape = State.AppliedLandscape.LoadSynchronous()`.
            5.  Если `CurrentLandscape` валиден:
                *   Получает `FFieldAbilityDefinition AbilityDef = CurrentLandscape->LandscapeFieldAbility`.
                *   Получает `FEffectDefinition EffectToApply = AbilityDef.AbilityEffect`.
                *   **Удаление предыдущего эффекта Ульты от этого поля:** Для каждой сущности на поле, вызывает `EffectComp->RemoveGameplayEffectBySourceFieldAndAbilityID_Server(FieldIndex, AbilityDef.AbilityID);` (или другой механизм идентификации эффекта Ульты этого поля).
                *   **Применение нового эффекта:** Для каждой сущности на поле:
                    *   Получает `TSubclassOf<UPolyeGameplayEffect>` из `DataManager` по `EffectToApply.EffectID_DEPRECATED` (или `EffectTag`).
                    *   Вызывает `EffectComp->ApplyGameplayEffect_Server(EffectClass, EffectToApply, FieldIndex, AbilityDef.AbilityID);` (передаем источник).
        *   `RemoveFieldAbilityEffect_Server`:
            1.  Проверяет `HasAuthority()`.
            2.  Если `LandscapeDataSource` валиден, получает его `AbilityDef.AbilityID`.
            3.  Для каждой сущности на `BoardState[FieldIndex].EntitiesOnField`, вызывает `EffectComp->RemoveGameplayEffectBySourceFieldAndAbilityID_Server(FieldIndex, AbilityIDFromOldLandscape);`.
*   **Outcome:** `APolyeGameStateBase` корректно применяет и удаляет эффекты Ульт на сущностях.

**`APolyeGameStateBase.cpp` (реализация функций управления ультой):**
```cpp
// ...
void APolyeGameStateBase::ApplyOrUpdateFieldAbilityEffect_Server(int32 FieldIndex)
{
    if (!HasAuthority() || !BoardState.IsValidIndex(FieldIndex)) return;

    FPolyeFieldState& CurrentFieldState = BoardState[FieldIndex]; // Неконстантная ссылка

    // Сначала удаляем любые старые эффекты УЛЬТЫ, которые могли быть на этом поле
    // Это важно, если ландшафт изменился или поле было деактивировано и снова активировано.
    // Мы идентифицируем "старую" ульту по SourceFieldIndex.
    // Если мы не знаем ID старой ульты, придется удалить все эффекты с SourceFieldIndex.
    // Лучше, если UPolyeGameplayEffect будет хранить FName SourceAbilityID.
    for (APolyeBoardEntityBase* Entity : CurrentFieldState.EntitiesOnField)
    {
        if (Entity && Entity->GetEntityEffectComponent())
        {
            // TODO: Более точное удаление. Например, если UPolyeGameplayEffect имеет SourceAbilityID
            Entity->GetEntityEffectComponent()->RemoveGameplayEffectsBySourceFieldAndAbilityID_Server(FieldIndex, NAME_None); // NAME_None как плейсхолдер, нужна реальная логика
        }
    }
    
    // Если поле неактивно или нет ландшафта, просто выходим после очистки
    if (!CurrentFieldState.bIsActive || CurrentFieldState.AppliedLandscape.IsNull())
    {
        return;
    }

    UPolyeLandscapeData* Landscape = CurrentFieldState.AppliedLandscape.LoadSynchronous();
    if (!Landscape) return;

    const FFieldAbilityDefinition& AbilityDef = Landscape->LandscapeFieldAbility;
    const FEffectDefinition& EffectDefToApply = AbilityDef.AbilityEffect;

    UPolyeDataManager* DataManager = GetWorld()->GetGameInstance()->GetSubsystem<UPolyeDataManager>();
    if (!DataManager) return;
    TSubclassOf<UPolyeGameplayEffect> EffectClass = DataManager->GetGameplayEffectClass(EffectDefToApply.EffectID_DEPRECATED); // Или по тегу/FName
    if (!EffectClass) return;

    UE_LOG(LogTemp, Log, TEXT("GS: Applying Field Ability '%s' from Landscape '%s' to Field %d"), 
        *AbilityDef.AbilityName.ToString(), *Landscape->LandscapeName.ToString(), FieldIndex);

    for (APolyeBoardEntityBase* Entity : CurrentFieldState.EntitiesOnField)
    {
        if (Entity && Entity->GetEntityEffectComponent())
        {
            // Создаем и применяем новый эффект
            UPolyeEntityEffectComponent* EffectComp = Entity->GetEntityEffectComponent();
            UPolyeGameplayEffect* NewEffect = NewObject<UPolyeGameplayEffect>(Entity, EffectClass);
            if(NewEffect)
            {
                // Инициализируем эффект данными Ульты
                NewEffect->EffectData = EffectDefToApply; // Копируем конфиг
                NewEffect->SourceFieldOriginIndex_Rep = FieldIndex;
                NewEffect->SourceAbilityID_Rep = AbilityDef.AbilityID; // Сохраняем ID способности
                // Добавляем в компонент (эта функция должна быть в EffectComp)
                EffectComp->AddRawGameplayEffect_Server(NewEffect); // Предполагается новая функция в компоненте
                NewEffect->OnAppliedToEntity(Entity);
            }
        }
    }
}

void APolyeGameStateBase::RemoveFieldAbilityEffect_Server(int32 FieldIndex, UPolyeLandscapeData* OldLandscapeData)
{
    if (!HasAuthority() || !BoardState.IsValidIndex(FieldIndex) || !OldLandscapeData) return;

    const FFieldAbilityDefinition& OldAbilityDef = OldLandscapeData->LandscapeFieldAbility;
    UE_LOG(LogTemp, Log, TEXT("GS: Removing Field Ability '%s' (from old Landscape '%s') from Field %d"), 
        *OldAbilityDef.AbilityName.ToString(), *OldLandscapeData->LandscapeName.ToString(), FieldIndex);

    for (APolyeBoardEntityBase* Entity : BoardState[FieldIndex].EntitiesOnField)
    {
        if (Entity && Entity->GetEntityEffectComponent())
        {
            Entity->GetEntityEffectComponent()->RemoveGameplayEffectsBySourceFieldAndAbilityID_Server(FieldIndex, OldAbilityDef.AbilityID);
        }
    }
}
```

**5. Визуализация Ландшафта и Его Ульты (в `AFieldTile`)**

*   **Действие:**
    *   В `BP_FieldTile` реализовать `SetLandscapeVisuals(UPolyeLandscapeData* LoadedLandscape)`. Изменять меш/материал плитки на основе `LoadedLandscape->FieldMeshOverride` / `FieldMaterialOverride`.
    *   **Визуализация Ульты:**
        *   Когда эффект Ульты применяется к сущности, `UPolyeEntityEffectComponent::OnRep_ActiveEffects` на клиенте должен как-то триггерить визуал. Сущность (`APolyeBoardEntityBase`) может иметь `BlueprintImplementableEvent void OnEffectAppliedVisuals(UPolyeGameplayEffect* Effect)` и `OnEffectRemovedVisuals`.
        *   Для Ульт, которые являются визуалом на самом поле (не на сущности), `BP_FieldTile::SetLandscapeVisuals` может спавнить/управлять постоянным визуальным эффектом (Niagara) на основе `LoadedLandscape->LandscapeFieldAbility.AbilityEffect.VFX`.
*   **Outcome:** Клиенты видят примененный ландшафт и эффекты его Ульты.

**Интеграция и Тестирование:**

*   **Data Assets:** Тщательно заполнить `UPolyeFactionData::AvailableLandscapes` и `UPolyeLandscapeData::LandscapeFieldAbility` (включая `EffectClass` и `EffectiveConfig` в `FEffectDefinition`). Убедиться, что `UPolyeDataManager` может предоставить `TSubclassOf<UPolyeGameplayEffect>` по идентификатору из `FEffectDefinition`.
*   **Тестирование Ульт:**
    1.  Активировать поле с ландшафтом, разместить юнита. Убедиться, что эффект Ульты применяется (логи, изменение статов).
    2.  Деактивировать поле / сменить ландшафт. Убедиться, что эффект Ульты снимается.
    3.  Разместить юнита на уже активное поле с ландшафтом. Убедиться, что Ульта применяется к новому юниту.
    4.  Убрать юнита с поля. Эффект на нем должен остаться (если он на сущности) или исчезнуть (если это модификатор поля, который пересчитывается). Ваша текущая логика применяет эффект к сущностям, так что он должен остаться с ними, если не будет снят специально. *Это важное место для уточнения дизайна: Ульта поля действует, пока сущность НА ПОЛЕ, или эффект Ульты дается сущности перманентно/на время?* Если "пока на поле", то при уходе с поля эффект Ульты должен сниматься.
*   **Полный Цикл:** Протестировать весь флоу от выбора фракции -> выбора ландшафта -> активации поля -> применения аур и ульт -> взаимодействия с сущностями.

**Ключевые моменты для эффектов Ульты:**
*   **Идентификация:** Эффекты Ульты, применяемые к сущностям, должны быть четко идентифицируемы (по `SourceFieldOriginIndex_Rep` и `SourceAbilityID_Rep` в `UPolyeGameplayEffect`), чтобы их можно было корректно удалить, когда:
    *   Ландшафт на поле меняется.
    *   Поле деактивируется.
    *   Сущность покидает поле (если Ульта действует только пока сущность на поле).
*   **Жизненный цикл Ульты:**
    *   **Применение:** Когда поле с ландшафтом становится активным ИЛИ когда сущность появляется/перемещается на активное поле с ландшафтом.
    *   **Удаление:** Когда поле с ландшафтом деактивируется ИЛИ ландшафт меняется ИЛИ сущность покидает поле.
