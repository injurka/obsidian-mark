**Цель:** Создать визуальное и логическое представление игрового поля 3x5, определить систему идентификации полей, настроить их сетевую синхронизацию, реализовать базовую визуализацию их состояния (принадлежность, активность) и заложить основу для отображения сущностей на полях.

**Зачем Нужна Отдельная Система Поля:**

*   **Центральный Элемент:** Поле – это основа игровой механики Polye, определяющая тактическое пространство.
*   **Сетевая Синхронизация:** Состояние каждого поля (владелец, фракция, ландшафт, сущности, активность) должно быть авторитетно на сервере и синхронизировано со всеми клиентами (`AGameStateBase`).
*   **Визуальная Ясность:** Игрокам необходимо четкое и понятное визуальное представление поля и его текущего состояния.
*   **Интерактивность:** Визуальные плитки поля служат точками взаимодействия для игрока (выбор поля для карты, атаки).

**Ключевые Компоненты и Подход:**

1.  **Логическое Состояние (`FPolyeFieldState` в `PolyeTypes.h`):**
    *   Структура, описывающая все данные одного поля, необходимые для игровой логики.
    *   Хранится в реплицируемом массиве внутри `APolyeGameStateBase`.
2.  **Система Идентификации (`UPolyeBoardStatics`):**
    *   Использует `int32 FieldIndex` (0-14).
    *   Предоставляет функции для преобразования `Index <-> Координаты (ряд/колонка)` и `Index <-> Мировые Координаты`.
    *   Функции для определения соседних полей.
3.  **Визуальное Представление (Клиентское):**
    *   **`AGameBoard`:** Актер-контейнер, размещаемый на игровой карте. Спавнит и управляет визуальными плитками (`AFieldTile`). Существует локально на каждом клиенте (и на сервере, если там нужен визуал для отладки). Не реплицирует свое состояние динамически, а читает его из `AGameStateBase`.
    *   **`AFieldTile`:** Актер, представляющий одну визуальную плитку. Отображает состояние поля (цвет, эффекты, сущности). Существует локально. Получает данные от `AGameBoard`.
4.  **Связь Логики и Визуала:**
    *   Сервер изменяет `TArray<FPolyeFieldState>` в `APolyeGameStateBase`.
    *   Эти изменения реплицируются на клиенты.
    *   `APolyeGameStateBase::OnRep_BoardState()` на клиенте уведомляет локальный `AGameBoard`.
    *   `AGameBoard` обновляет соответствующие `AFieldTile` актеры.

---

**Шаги Реализации:**

**1. Определение/Дополнение Логической Структуры Поля (`FPolyeFieldState` в `PolyeTypes.h`)**

*   **Действие:** Убедитесь, что структура `FPolyeFieldState` в `Source/Polye/Core/PolyeTypes.h` содержит все необходимые поля. Важно, чтобы ссылки на другие реплицируемые актеры (как `EntitiesOnField`) использовали `TObjectPtr` для корректной работы с GC и репликацией.
*   **Outcome:** `FPolyeFieldState` полностью определена.

**`PolyeTypes.h` (актуализация `FPolyeFieldState`):**
```cpp
// Polye/Source/Polye/Core/PolyeTypes.h

class APolyeBoardEntityBase; // Используем APolyeBoardEntityBase из предыдущего шага
class UPolyeFactionData;
class UPolyeLandscapeData;

USTRUCT(BlueprintType)
struct FPolyeFieldState
{
    GENERATED_BODY()

    FPolyeFieldState()
        : FieldIndex(INDEX_NONE)
        , bIsActive(false)
        , InitialOwnerPlayerIndex(INDEX_NONE) // 0 для игрока 1, 1 для игрока 2, INDEX_NONE для нейтральных
        , CurrentFaction(EPolyeFaction::Neutral)
        , AppliedLandscape(nullptr) // TSoftObjectPtr инициализируется в nullptr
    {}

    // Уникальный индекс поля (0-14)
    UPROPERTY(BlueprintReadOnly, Category = "Field State") // Не нужно реплицировать сам индекс, если он константен для позиции в массиве
    int32 FieldIndex;

    // Активно ли поле (влияет на Затухающее Влияние, размещение)
    UPROPERTY(BlueprintReadOnly, Category = "Field State")
    bool bIsActive;

    // Изначальный владелец поля (0, 1, или INDEX_NONE для нейтрального)
    // Устанавливается на сервере при инициализации, реплицируется
    UPROPERTY(BlueprintReadOnly, Category = "Field State")
    int32 InitialOwnerPlayerIndex;

    // Текущая фракция, примененная к полю
    UPROPERTY(BlueprintReadOnly, Category = "Field State")
    EPolyeFaction CurrentFaction;

    // Примененный ландшафт (мягкая ссылка на UDataAsset)
    UPROPERTY(BlueprintReadOnly, Category = "Field State")
    TSoftObjectPtr<UPolyeLandscapeData> AppliedLandscape;

    // Сущности (Юниты, Строения) на этом поле
    // TObjectPtr используется для ссылок на UObject (включая AActor) и хорошо работает с репликацией и GC
    UPROPERTY(BlueprintReadOnly, Category = "Field State")
    TArray<TObjectPtr<APolyeBoardEntityBase>> EntitiesOnField;

    // Примечание: Для репликации этой структуры внутри TArray<FPolyeFieldState> в GameState,
    // сами поля структуры не нужно помечать UPROPERTY(Replicated).
    // Репликация будет обрабатываться для всего массива в GameState.
    // OnRep-функции для отдельных полей структуры внутри массива не сработают автоматически.
    // Вместо этого используется OnRep на самом массиве в GameState.
};
```

```cpp
void APolyeGameStateBase::InitializeBoard(int32 NumPlayerRowsPerPlayer, int32 NumNeutralRows, int32 NumColumns)
{
    if (!HasAuthority()) return;

    const int32 TotalRows = (NumPlayerRowsPerPlayer * 2) + NumNeutralRows; // Предполагаем 2 игроков
    const int32 TotalFields = TotalRows * NumColumns;
    BoardState.Empty(TotalFields);
    BoardState.SetNum(TotalFields);

    for (int32 i = 0; i < TotalFields; ++i)
    {
        BoardState[i].FieldIndex = i;
        BoardState[i].bIsActive = false; // По умолчанию неактивны
        BoardState[i].CurrentFaction = EPolyeFaction::Neutral;
        BoardState[i].AppliedLandscape = nullptr;
        BoardState[i].EntitiesOnField.Empty();

        int32 Row = i / NumColumns;
        // Примерное определение владельца для 2 игроков
        if (Row < NumPlayerRowsPerPlayer) // Поля первого игрока
        {
            BoardState[i].InitialOwnerPlayerIndex = 0;
        }
        else if (Row < NumPlayerRowsPerPlayer + NumNeutralRows) // Нейтральные поля
        {
            BoardState[i].InitialOwnerPlayerIndex = INDEX_NONE;
        }
        else // Поля второго игрока
        {
            BoardState[i].InitialOwnerPlayerIndex = 1;
        }
    }
    // Вызов OnRep на сервере, чтобы обновить любые серверные слушатели,
    // и это также "загрязняет" свойство для репликации.
    if (GetNetMode() != NM_Client) OnRep_BoardState();
    UE_LOG(LogTemp, Log, TEXT("GameState: Board initialized with %d fields on server."), TotalFields);
}

void APolyeGameStateBase::SetFieldActive(int32 FieldIndex, bool bNewActiveState)
{
    if (!HasAuthority() || !BoardState.IsValidIndex(FieldIndex)) return;
    if (BoardState[FieldIndex].bIsActive != bNewActiveState)
    {
        BoardState[FieldIndex].bIsActive = bNewActiveState;
        if (GetNetMode() != NM_Client) OnRep_BoardState(); // Триггер для серверных слушателей и репликации
        UE_LOG(LogTemp, Log, TEXT("GameState: Field %d active state set to %s on server."), FieldIndex, bNewActiveState ? TEXT("True") : TEXT("False"));
    }
}

        if (GetNetMode() != NM_Client) OnRep_BoardState();
        UE_LOG(LogTemp, Log, TEXT("GameState: Field %d faction set to %s on server."), FieldIndex, *UEnum::GetValueAsString(NewFaction));
    }
}

        BoardState[FieldIndex].AppliedLandscape = NewLandscape;

void APolyeGameStateBase::AddEntityToField_Server(int32 FieldIndex, APolyeBoardEntityBase* Entity)
{
    if (!HasAuthority() || !BoardState.IsValidIndex(FieldIndex) || !Entity) return;
    if (!BoardState[FieldIndex].EntitiesOnField.Contains(Entity))
    {
        BoardState[FieldIndex].EntitiesOnField.Add(Entity);
        if (GetNetMode() != NM_Client) OnRep_BoardState();
        UE_LOG(LogTemp, Log, TEXT("GameState: Entity %s added to field %d on server."), *Entity->GetName(), FieldIndex);
    }
}

void APolyeGameStateBase::RemoveEntityFromField_Server(int32 FieldIndex, APolyeBoardEntityBase* Entity)
{
    if (!HasAuthority() || !BoardState.IsValidIndex(FieldIndex) || !Entity) return;
    if (BoardState[FieldIndex].EntitiesOnField.Remove(Entity) > 0)
    {
        if (GetNetMode() != NM_Client) OnRep_BoardState();
        UE_LOG(LogTemp, Log, TEXT("GameState: Entity %s removed from field %d on server."), *Entity->GetName(), FieldIndex);
    }
}
```

**4. Создание Визуального Представления Доски (`AGameBoard` и `AFieldTile`)**

*   **`AGameBoard` (Актер, размещенный на уровне):**
    *   **Действие:**
        *   В конструкторе или `BeginPlay`, он должен получить размеры доски (например, из `APolyeGameStateBase` после его инициализации или из `UPolyeBoardStatics`, если они там константны).
        *   Спавнит необходимое количество `AFieldTile` актеров (локально на каждом клиенте). Лучше использовать `TSubclassOf<AFieldTile> FieldTileClass` и установить его в Blueprint `BP_GameBoard`.
        *   Сохраняет ссылки на заспавненные `AFieldTile` в `TArray<TObjectPtr<AFieldTile>> VisualTiles;`.
        *   Имеет публичную функцию `UpdateBoardVisuals(const TArray<FPolyeFieldState>& InBoardState)`, которая вызывается из `APolyeGameStateBase::OnRep_BoardState()`. Эта функция итерирует по `InBoardState` и вызывает соответствующую функцию обновления на каждом `AFieldTile`.
    *   **Outcome:** `AGameBoard` создает и управляет визуальными плитками.

```cpp
    if (!FieldTileClass)
    {
        UE_LOG(LogTemp, Error, TEXT("AGameBoard: FieldTileClass not set!"));
        return;
    }

    VisualTiles.Empty();
    const int32 TotalTiles = NumRows * NumColumns;
    VisualTiles.Reserve(TotalTiles);

    UWorld* World = GetWorld();
    if (!World) return;

    for (int32 i = 0; i < TotalTiles; ++i)
    {
        // Используем статик функцию или логику здесь для расчета позиции
        FVector TileLocation = UPolyeBoardStatics::GetWorldLocationForFieldTile(this, i, NumColumns, TileSizeX, TileSizeY, BoardCenterOffset);
        // Смещение относительно позиции AGameBoard
        TileLocation += GetActorLocation(); 
        
        AFieldTile* NewTile = World->SpawnActor<AFieldTile>(FieldTileClass, TileLocation, GetActorRotation());
        if (NewTile)
        {
            NewTile->SetFieldIndex(i); // Сообщаем плитке ее логический индекс
            NewTile->AttachToActor(this, FAttachmentTransformRules::KeepWorldTransform); // Прикрепляем к доске
            VisualTiles.Add(NewTile);
        }
    }
    UE_LOG(LogTemp, Log, TEXT("AGameBoard: Spawned %d visual tiles."), VisualTiles.Num());
}

void AGameBoard::UpdateBoardVisuals(const TArray<FPolyeFieldState>& InBoardState)
{
    if (VisualTiles.Num() != InBoardState.Num())
    {
        UE_LOG(LogTemp, Warning, TEXT("AGameBoard: Mismatch in visual tiles (%d) and board state (%d). Respawning tiles might be needed."), VisualTiles.Num(), InBoardState.Num());
        // Возможно, здесь нужна логика пересоздания плиток, если размеры доски изменились.
        // Но для Polye размеры фиксированы.
        return;
    }

    for (int32 i = 0; i < InBoardState.Num(); ++i)
    {
        if (VisualTiles.IsValidIndex(i) && VisualTiles[i])
        {
            VisualTiles[i]->UpdateFromState(InBoardState[i]);
        }
    }
    UE_LOG(LogTemp, Log, TEXT("AGameBoard: Updated visuals for %d tiles."), InBoardState.Num());
}

AFieldTile* AGameBoard::GetVisualTile(int32 FieldIndex) const
{
    if (VisualTiles.IsValidIndex(FieldIndex))
    {
        return VisualTiles[FieldIndex];
    }
    return nullptr;
}
```

**5. Визуализация Состояния Поля в `BP_FieldTile`**

*   **Действие:**
    *   Создайте Blueprint `BP_FieldTile` на основе `AFieldTile`. Установите для `TileMeshComponent` дефолтный меш и материал.
    *   Реализуйте событие `OnStateUpdated` (или отдельные события `ShowActiveState`, `ShowFaction` и т.д.).
    *   Внутри `OnStateUpdated` используйте данные из `NewState` (например, `NewState.bIsActive`, `NewState.CurrentFaction`), чтобы изменять материалы меша, спавнить/скрывать индикаторы, декали и т.д.
    *   Для отображения сущностей (`NewState.EntitiesOnField`):
        *   Возможно, вы захотите иметь "слоты" (например, `USceneComponent`) на плитке, к которым будут прикрепляться BP актеры юнитов/строений.
        *   Или же BP актеры юнитов/строений сами будут знать свой `FieldIndex` и позиционироваться на основе `UPolyeBoardStatics::GetWorldLocationForFieldTile`.
*   **Outcome:** `BP_FieldTile` динамически изменяет свой внешний вид в соответствии с логическим состоянием поля.

**Интеграция и Ключевые Моменты:**

*   **Настройка `BP_GameBoard`:** Разместите экземпляр `BP_GameBoard` на уровне `Map_GameplayBoard.umap`. В его свойствах укажите `BP_FieldTile` в качестве `FieldTileClass`. Настройте `NumRows`, `NumColumns`, `TileSizeX`, `TileSizeY` в соответствии с вашим дизайном и размерами ассетов.
*   **GameMode Инициализация:** Ваш `APolyeGameModeBase` (или наследник, например `APolyeGameplayGameMode`) должен в `BeginPlay` или при старте матча вызывать `GameState->InitializeBoard(...)`.
*   **Спавн `AGameBoard`:** Если `AGameBoard` не размещается на уровне вручную, то `APolyeGameplayGameMode` (сервер) или `APolyePlayerController` (клиент, при подключении к уровню) должен его заспавнить. Если он `bReplicates=true`, сервер спавнит, и он появляется у клиентов. Если `bReplicates=false`, каждый клиент должен спавнить свою копию (например, в `APolyePlayerController::ClientPostLogin` или при загрузке уровня). **Для простоты начните с размещения `BP_GameBoard` на уровне вручную.**
*   **Клик по Полю:** В `APolyePlayerController` обработайте клик мыши, выполните LineTrace, используя канал коллизии, на который реагирует `AFieldTile::TileMeshComponent`. Если попали в `AFieldTile`, получите его `LogicalFieldIndex` и используйте в Server RPC.
*   **Сущности на Поле:** Когда сервер спавнит `APolyeBoardEntityBase`, он должен вызвать `GameState->AddEntityToField_Server(...)`. `OnRep_BoardState` уведомит клиентов, и `BP_FieldTile::OnStateUpdated` (или `DisplayEntities`) сможет отобразить эти сущности. Сами сущности (`APolyeBoardEntityBase`) также реплицируются, поэтому клиенты будут иметь их актеры. Логика в `BP_FieldTile` может просто позиционировать уже существующие реплицированные актеры сущностей или отображать их "иконки" на плитке.
