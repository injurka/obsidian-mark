**Цель:** Реализовать детальную логику получения урона и исцеления сущностями (`ABoardEntityBase`) на сервере, включая применение модификаторов от активных эффектов и специфическую механику "Древесного здоровья" (Overhealing) для Корневых стражей. Обеспечить корректную синхронизацию состояния здоровья по сети.

**Зачем Нужна Эта Система:**

*   **Фундамент Боя:** Получение урона и исцеления - это базовые механики, определяющие выживаемость сущностей в бою.
*   **Влияние Эффектов:** Эта система позволяет Баффам, Дебаффам и Ауре Затухающего Влияния напрямую влиять на то, сколько урона получает сущность или насколько эффективно она исцеляется.
*   **Специфические Механики Polye:** Реализация "Древесного здоровья" придает уникальность фракции Корневых стражей и добавляет глубину в их геймплей.
*   **Синхронизация Состояния:** Состояние здоровья сущностей должно быть точно синхронизировано на всех клиентах, чтобы игроки видели актуальную картину боя.

**Предпосылки:**

*   **Базовая Сетевая Архитектура (Фаза 1):** Реализованы ключевые C++ классы и сетевая настройка. Сервер является авторитетом.
*   **Система Данных (Фаза 1, 3):** Определены структуры данных (`FPolyeEffectConfig`, `EPolyeEffectType`, `EPolyeAttributeType` - включая типы атрибутов, связанные с уроном/исцелением/защитой/HP) и `UDataAsset`ы, содержащие параметры эффектов и базовые HP сущностей. Определен `EPolyeFaction` (для механики Древесного здоровья).
*   **Система Сущностей и Эффектов (Фаза 1, 2, 5, 6):** Определены базовые сущности (`ABoardEntityBase` с `CurrentHP`, `MaxHP`, `OnDeath`). `UPolyeEffectManagerComponent` присоединен к `ABoardEntityBase` и может получать эффективные атрибуты (`GetEffectiveAttributeValue`) и управлять эффектами. `UPolyeGameplayEffectBase` и его наследники реализуют специфическую логику эффектов и модификацию атрибутов (например, `ModifyAttributeValue_Implementation` для снижения получаемого урона/исцеления). `ABoardEntityBase::CurrentHP` и `MaxHP` являются `UPROPERTY(ReplicatedUsing=OnRep_...)`. Multicast RPC для визуальной/звуковой синхронизации получения урона/исцеления/смерти (`Multicast_PlayReceiveDamageVisuals`, `Multicast_PlayHealVisuals`, `Multicast_PlayDeathVisuals`) реализованы или намечены.
*   **Фаза 4.2: Система Атак (Логика Индивидуальной Атаки):** `UPolyeCombatManager::ResolveAttack` вызывает `Target->TakeDamage(CalculatedDamage)` на цели.

**Ключевые Компоненты и Их Роли в Этом Пункте:**

*   **`ABoardEntityBase` (Сервер и Клиенты):** Является владельцем состояния здоровья (`CurrentHP`, `MaxHP`) и реализует серверную логику получения урона (`TakeDamage`) и исцеления (`Heal`). Также будет хранить состояние "Древесного здоровья" (`OverhealHP`) и проверять условие "жива ли" (`IsAlive`). Клиентская сторона реагирует на репликацию HP/Overheal.
*   **`UPolyeEffectManagerComponent` (Сервер):** Предоставляет функцию `GetEffectiveAttributeValue` для расчета финального получаемого урона и исцеления с учетом всех активных эффектов на сущности.
*   **`UPolyeGameplayEffectBase` & Наследники (Сервер):** Реализуют эффекты, которые модифицируют атрибуты `EPolyeAttributeType::DamageReceivedModifier`, `EPolyeAttributeType::HealingReceivedModifier` или другие атрибуты, влияющие на получение/исцеление (напр., "Броня", "Сопротивление").
*   **Network:** Репликация `CurrentHP`, `MaxHP`, `OverhealHP` (новое свойство) синхронизирует состояние здоровья. `OnRep_CurrentHP`, `OnRep_MaxHP`, `OnRep_OverhealHP` (новое) триггерят клиентские UI/визуальные обновления. Multicast RPC синхронизируют визуальные/звуковые события получения урона/исцеления.
*   **Data System (Фаза 1):** Предоставляет базовые значения HP (`UPolyeCardData::BaseHP`) и параметры эффектов (`FPolyeEffectConfig::NumericParameters`) для модификаторов.

**Шаги Реализации:**

1.  **Реализация Механики "Древесного здоровья" (Overhealing):**
    *   **Роль:** Позволить сущностям определенной фракции (Корневые стражи) накапливать дополнительное здоровье сверх их максимального HP при исцелении, до определенного лимита. Это дополнительное здоровье должно быть первым, что теряется при получении урона.
    *   **Что Хранить Здесь:** Дополнительная реплицируемая переменная `int32 OverhealHP` в `ABoardEntityBase`.
    *   **Что Не Хранить Здесь:** Логику, которая решает, *какие* сущности имеют эту механику (это определяется их Фракцией `Faction`).

    *   **Обобоснование Реализации:** "Древесное здоровье" - это специфичное состояние сущности, которое должно быть синхронизировано между сервером и клиентами (`UPROPERTY(Replicated)`). Логика его изменения (`Heal`, `TakeDamage`) должна быть на сервере. `OnRep` позволяет клиентам визуально отображать это дополнительное здоровье.
    *   **Outcome:** `ABoardEntityBase` может хранить и синхронизировать "Древесное здоровье", и эта механика корректно обрабатывается при получении урона и исцеления для сущностей Корневых стражей.

    // SERVER ONLY - Обработка получения урона
    float ABoardEntityBase::TakeDamage(float DamageAmount, FGameplayEffectContextHandle DamageContext /* = FGameplayEffectContextHandle() */)
    {
         // **ВАЖНО: Эта функция должна выполняться ТОЛЬКО на СЕРВЕРЕ!**
         if (!HasAuthority() || !IsAlive()) return 0.f; // Не обрабатываем урон, если уже мертвы

         float ActualDamage = DamageAmount;

         // TODO: Применить модификаторы получаемого урона/защиты от эффектов (включая Ауры)
         //       float DamageReceiveModifier = GetEffectManagerComponent()->GetEffectiveAttributeValue(EPolyeAttributeType::DamageReceivedModifier, 1.0f); // Базовое значение 1.0 (100%)
         //       float DamageReduction = GetEffectManagerComponent()->GetEffectiveAttributeValue(EPolyeAttributeType::DamageReductionAmount, 0.0f); // Пример атрибута для плоской редукции
         //       ActualDamage = ActualDamage * DamageReceiveModifier - DamageReduction;

         ActualDamage = FMath::Max(0.f, ActualDamage); // Финальный урон не может быть отрицательным

         int32 DamageToApply = FMath::FloorToInt(ActualDamage); // Преобразуем в целое

         UE_LOG(LogTemp, Log, TEXT("Entity %s receives %d damage (%.2f raw). HP: %d/%d (+%d OH)"),
              *GetName(), DamageToApply, DamageAmount, CurrentHP, MaxHP, OverhealHP);


         // **ЛОГИКА ДРЕВЕСНОГО ЗДОРОВЬЯ: Урон сначала по OverhealHP**
         int32 DamageRemaining = DamageToApply;

         // 1. Вычитаем из OverhealHP
         if (DamageRemaining > 0 && OverhealHP > 0)
         {
              int32 DamageToOverheal = FMath::Min(DamageRemaining, OverhealHP);
              OverhealHP -= DamageToOverheal;
              DamageRemaining -= DamageToOverheal;

              UE_LOG(LogTemp, Log, TEXT("  - %d damage to OverhealHP. OH: %d"), DamageToOverheal, OverhealHP);
              // OverhealHP может стать отрицательным, если урон превысил Overheal.
              // Отрицательное OverhealHP означает, что этот урон перешел на CurrentHP.
         }

         // 2. Вычитаем оставшийся урон из CurrentHP
         if (DamageRemaining > 0)
         {
              CurrentHP -= DamageRemaining;
              UE_LOG(LogTemp, Log, TEXT("  - %d damage to CurrentHP. HP: %d"), DamageRemaining, CurrentHP);
         }

         // Обрезаем HP и OverhealHP до нуля, если они стали отрицательными
         int32 DamageThatOverflowedFromOverheal = FMath::Max(0, -OverhealHP); // Урон, который прошел сквозь Overheal в минус
         OverhealHP = FMath::Max(0, OverhealHP); // OverhealHP не может быть меньше 0

         CurrentHP = FMath::Max(0, CurrentHP); // CurrentHP не может быть меньше 0

         // TODO: Воспроизвести визуальный/звуковой эффект получения урона на всех клиентах.
         //       Multicast_PlayReceiveDamageVisuals(DamageToApply); // Вызываем Multicast RPC на себе. Передаем общий урон.

         // **ПРОВЕРКА СМЕРТИ**
         if (!IsAlive()) // IsAlive() теперь учитывает OverhealHP
         {
              UE_LOG(LogTemp, Warning, TEXT("Entity %s died!"), *GetName());
              OnDeath(); // Вызвать серверную функцию обработки смерти
         }
         else
         {
              UE_LOG(LogTemp, Log, TEXT("Entity %s after damage: HP %d/%d, OH %d"), *GetName(), CurrentHP, MaxHP, OverhealHP);
         }


         return ActualDamage; // Вернуть фактически нанесенный урон (float)
    }

    // SERVER ONLY - Обработка получения исцеления
    void ABoardEntityBase::Heal(float HealAmount)
    {
        // **ВАЖНО: Эта функция должна выполняться ТОЛЬКО на СЕРВЕРЕ!**
        if (!HasAuthority() || HealAmount <= 0) return; // Не исцеляем на отрицательную/нулевую величину

        // Проверяем, жива ли сущность (если нет спец. механик воскрешения)
        if (!IsAlive())
        {
            UE_LOG(LogTemp, Warning, TEXT("Tried to heal dead entity %s!"), *GetName());
            return;
        }

        float ActualHeal = HealAmount;

        // TODO: Применить модификаторы получаемого исцеления от эффектов (включая Ауру Болотников)
        //       float HealingReceiveModifier = GetEffectManagerComponent()->GetEffectiveAttributeValue(EPolyeAttributeType::HealingReceivedModifier, 1.0f); // Базовое значение 1.0 (100%)
        //       float HealingReduction = GetEffectManagerComponent()->GetEffectiveAttributeValue(EPolyeAttributeType::HealingReductionAmount, 0.0f); // Пример атрибута для плоской редукции
        //       ActualHeal = ActualHeal * HealingReceiveModifier - HealingReduction;

        ActualHeal = FMath::Max(0.f, ActualHeal); // Финальное исцеление не может быть отрицательным (наносить урон)

        int32 HealAmountInt = FMath::FloorToInt(ActualHeal); // Преобразуем в целое

        if (HealAmountInt <= 0) // Не исцеляем на нулевую или отрицательную величину после модификаторов
        {
             UE_LOG(LogTemp, Log, TEXT("Entity %s received %.2f raw heal, but it became %d after modifiers. No healing applied."), *GetName(), HealAmount, HealAmountInt);
             return;
        }


        UE_LOG(LogTemp, Log, TEXT("Entity %s receives %d healing (%.2f raw). HP: %d/%d (+%d OH)"),
             *GetName(), HealAmountInt, HealAmount, CurrentHP, MaxHP, OverhealHP);


        // **ЛОГИКА ДРЕВЕСНОГО ЗДОРОВЬЯ: Исцеление может идти в OverhealHP**

        // 1. Исцеляем CurrentHP до MaxHP
        int32 HealToCurrent = FMath::Min(HealAmountInt, MaxHP - CurrentHP); // Сколько можно исцелить в CurrentHP
        HealToCurrent = FMath::Max(0, HealToCurrent); // Не исцеляем, если CurrentHP уже >= MaxHP

        CurrentHP += HealToCurrent;
        int32 RemainingHeal = HealAmountInt - HealToCurrent; // Сколько исцеления осталось


        // 2. Если есть оставшееся исцеление И сущность является Корневым стражем, добавляем в OverhealHP
        if (RemainingHeal > 0 && Faction == EPolyeFaction::EF_RootGuardians) // Проверяем фракцию
        {
             // TODO: Определить максимальный лимит Древесного здоровья для Корневых стражей.
             //       Это может быть процент от MaxHP (напр., 50%) или фиксированное значение.
             //       int32 MaxOverheal = FMath::FloorToInt(MaxHP * 0.5f); // Пример: 50% от MaxHP
             const int32 MaxOverheal = 50; // MVP: Пример фиксированного лимита

             int32 HealToOverheal = FMath::Min(RemainingHeal, MaxOverheal - OverhealHP); // Сколько можно добавить в OverhealHP
             HealToOverheal = FMath::Max(0, HealToOverheal); // Не добавляем, если OverhealHP уже >= MaxOverheal

             OverhealHP += HealToOverheal;
             RemainingHeal -= HealToOverheal;

             UE_LOG(LogTemp, Log, TEXT("  - %d healing to OverhealHP. OH: %d/%d"), HealToOverheal, OverhealHP, MaxOverheal);

             // TODO: Если есть оставшееся исцеление после заполнения OverhealHP (RemainingHeal > 0), оно просто теряется.

        }
        else if (RemainingHeal > 0 && Faction != EPolyeFaction::EF_RootGuardians)
        {
             // Если не Корневой страж, любое исцеление сверх MaxHP теряется.
             UE_LOG(LogTemp, Log, TEXT("  - %d healing lost (over MaxHP) for non-Root Guardian."), RemainingHeal);
        }

        // CurrentHP обрезается до MaxHP неявно в логике выше (HealToCurrent).
        // OverhealHP обрезается до MaxOverheal неявно в логике выше (HealToOverheal).
        // Обе переменные не могут стать отрицательными после применения урона/исцеления, т.к. мы их обрезали до 0.

        UE_LOG(LogTemp, Log, TEXT("Entity %s after heal: HP %d/%d, OH %d"), *GetName(), CurrentHP, MaxHP, OverhealHP);

2.  **Применение Рассчитанного Урона и Исцеления:**
    *   **Роль:** Фактически изменить значения `CurrentHP` и `OverhealHP` на сервере после всех расчетов и модификаций.
    *   **Что Хранить Здесь:** Логика изменения значений.
    *   **Что Не Хранить Здесь:** Логику расчета урона/исцеления (это делает вызывающий код, напр., Combat Manager или эффект).
    *   **Действие:** В серверных функциях `ABoardEntityBase::TakeDamage` и `ABoardEntityBase::Heal`, после определения финального количества урона/исцеления (с учетом модификаторов от эффектов, полученных через `GetEffectiveAttributeValue`), вычесть урон или добавить исцеление к `CurrentHP` и/или `OverhealHP`, соблюдая правила "Древесного здоровья" и лимиты (0, MaxHP, MaxOverhealHP).
    *   **Обоснование Реализации:** Изменение реплицируемых переменных HP происходит только на сервере в этих функциях. Логика "Древесного здоровья" интегрирована здесь, потому что она влияет на то, как распределяется урон/исцеление между обычным и древесным здоровьем.
    *   **Outcome:** Урон и исцеление корректно применяются к HP сущности, соблюдая правила "Древесного здоровья".

    **Реализация:** Логика изменения `CurrentHP` и `OverhealHP` уже добавлена в `ABoardEntityBase::TakeDamage` и `ABoardEntityBase::Heal` в шаге 1.
