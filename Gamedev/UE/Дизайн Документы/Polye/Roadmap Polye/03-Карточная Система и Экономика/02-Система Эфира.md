**Цель:** Реализовать игровой ресурс "Эфир", используемый для розыгрыша карт и активации способностей. Система должна включать:
    1.  Хранение и репликацию текущего запаса (`CurrentEther`) и максимального лимита (`MaxEther`) Эфира для каждого игрока.
    2.  Механизм естественного прироста Эфира в начале хода игрока.
    3.  Механизм траты Эфира при выполнении действий.
    4.  Правило ограничения максимального запаса Эфира ("сгорание" излишка).
    5.  Возможность изменения максимального лимита Эфира (например, от строений).

**Зачем Нужна Эта Система:**

*   **Экономика Игры:** Эфир — основной ресурс, регулирующий действия игрока и темп игры.
*   **Стратегическое Планирование:** Управление Эфиром (накопление, трата, прирост) — важный тактический элемент.
*   **Синхронизация Состояния:** Информация об Эфире должна быть актуальной и синхронизированной для всех участников матча (UI, валидация действий).

**Предпосылки (Уже Реализованы):**

1.  **Сетевая Архитектура:** `APolyeGameModeBase`, `APolyeGameStateBase`, `APolyePlayerController`, `APolyePlayerStateBase`.
2.  **Система Данных:** Структуры и Data Assets.
3.  **Система Карт:** `UPolyeCardComponent` на `APolyePlayerStateBase`.
4.  **Управление Ходами:** `APolyeGameModeBase` управляет сменой ходов.

**Ключевые Компоненты и Их Роли:**

1.  **`APolyePlayerStateBase` (Сервер & Клиенты):**
    *   **Роль:** Центральное, реплицируемое хранилище Эфира для конкретного игрока.
    *   **Данные (Реплицируемые):** `int32 CurrentEther`, `int32 MaxEther`.
    *   **Функции (Серверные):** `Server_SetInitialEther()`, `Server_AddEther(Amount)`, `Server_SpendEther(Amount)`, `Server_SetMaxEther(NewMax)`, `Server_IncreaseMaxEther(Amount)`, `CanAfford(Amount) const`. (Приставка `Server_` не обязательна, если функции помечены `BlueprintAuthorityOnly` или имеют проверку `HasAuthority()`).
    *   **Функции (Клиентские, `OnRep_`):** `OnRep_CurrentEther()`, `OnRep_MaxEther()` для обновления UI.
2.  **`AGameModeBase` (Сервер):**
    *   **Роль:** Управляет правилами игры и ходом матча.
    *   **Действия:**
        *   В начале матча вызывает `PlayerState->Server_SetInitialEther()` для каждого игрока.
        *   В начале хода игрока вызывает `PlayerState->Server_AddEther()` для текущего игрока (естественный прирост).
        *   При обработке запросов на платные действия (например, розыгрыш карты), проверяет `PlayerState->CanAfford()` и вызывает `PlayerState->Server_SpendEther()`.
    *   **Данные:** `InitialCurrentEther`, `InitialMaxEther`, `BaseEtherGainPerTurn` (как `EditDefaultsOnly` свойства).
3.  **UI (`WBP_ResourceDisplay` или часть `WBP_GameplayScreen`) (Клиент):**
    *   **Роль:** Отображает `CurrentEther` и `MaxEther` локального игрока.
    *   **Действия:** Обновляется на основе `OnRep_CurrentEther` и `OnRep_MaxEther` из `APolyePlayerStateBase` (или через прямую привязку к свойствам PlayerState).

void APolyePlayerStateBase::SetInitialEther(int32 InitialCurrent, int32 InitialMax)
{
    if (!HasAuthority()) return;
    MaxEther = FMath::Max(0, InitialMax);
    CurrentEther = FMath::Clamp(InitialCurrent, 0, MaxEther);
    // Ручной вызов OnRep на сервере, если нужно для серверных слушателей (NetMode != NM_Client)
    // и чтобы REPNOTIFY_Always сработал при первом присвоении (если значение не меняется с дефолтного 0).
    if (GetNetMode() != NM_Client)
    {
        OnRep_MaxEther(); // Вызываем для консистентности, т.к. MaxEther мог измениться
        OnRep_CurrentEther();
    }
}

void APolyePlayerStateBase::AddEther(int32 AmountToAdd)
{
    if (!HasAuthority() || AmountToAdd <= 0) return;
    int32 OldEther = CurrentEther;
    CurrentEther = FMath::Min(CurrentEther + AmountToAdd, MaxEther); // Прирост, но не выше MaxEther ("сгорание")
    if (OldEther != CurrentEther || AmountToAdd > 0) // Вызываем OnRep, если значение изменилось или был прирост
    {
        if (GetNetMode() != NM_Client) OnRep_CurrentEther();
    }
    if(CurrentEther > OldEther) UE_LOG(LogTemp, Log, TEXT("[Server %s] Added %d Ether. Now: %d/%d"), *GetPlayerName(), AmountToAdd, CurrentEther, MaxEther);
}

bool APolyePlayerStateBase::SpendEther(int32 AmountToSpend)
{
    if (!HasAuthority() || AmountToSpend <= 0) return false;
    if (CanAfford(AmountToSpend))
    {
        CurrentEther -= AmountToSpend;
        if (GetNetMode() != NM_Client) OnRep_CurrentEther();
        UE_LOG(LogTemp, Log, TEXT("[Server %s] Spent %d Ether. Remaining: %d/%d"), *GetPlayerName(), AmountToSpend, CurrentEther, MaxEther);
        return true;
    }
    UE_LOG(LogTemp, Warning, TEXT("[Server %s] Failed to spend %d Ether. Has: %d/%d"), *GetPlayerName(), AmountToSpend, CurrentEther, MaxEther);
    return false;
}

void APolyePlayerStateBase::SetMaxEther(int32 NewMaxAmount)
{
    if (!HasAuthority()) return;
    MaxEther = FMath::Max(0, NewMaxAmount);
    CurrentEther = FMath::Min(CurrentEther, MaxEther); // Обрезаем текущий, если он превышает новый максимум
    if (GetNetMode() != NM_Client) 
    {
        OnRep_MaxEther();
        OnRep_CurrentEther(); // CurrentEther тоже мог измениться
    }
     UE_LOG(LogTemp, Log, TEXT("[Server %s] MaxEther set to: %d. Current: %d"), *GetPlayerName(), MaxEther, CurrentEther);
}
void APolyePlayerStateBase::IncreaseMaxEther(int32 AmountToIncrease)
{
    if (!HasAuthority() || AmountToIncrease <= 0) return;
    SetMaxEther(MaxEther + AmountToIncrease); // Используем SetMaxEther для обработки обрезки CurrentEther
}


bool APolyePlayerStateBase::CanAfford(int32 AmountNeeded) const
{
    return CurrentEther >= AmountNeeded;
}

**Интеграция и Тестирование:**

*   **Стартовый Эфир:** Убедиться, что игроки начинают матч с `InitialPlayerEther`/`InitialPlayerMaxEther`.
*   **Прирост за Ход:** Проверить, что `EtherGainPerTurn` корректно добавляется в начале каждого хода текущему игроку.
*   **Лимит и Сгорание:** Попробовать накопить Эфир сверх `MaxEther` (через читы или временное увеличение прироста). Убедиться, что `CurrentEther` не превышает `MaxEther`.
*   **Трата Эфира:** Интегрировать с системой розыгрыша карт. Попробовать разыграть карту дороже, чем есть Эфира – действие должно быть отклонено. Разыграть карту по стоимости – Эфир должен списаться.
*   **Изменение `MaxEther`:** (Позже) При добавлении строений, увеличивающих `MaxEther`, проверить, что лимит корректно обновляется, и `CurrentEther` не обрезается, если он был ниже нового `MaxEther`.
*   **UI:** Убедиться, что UI всегда отображает актуальные `CurrentEther` и `MaxEther`.

**Ключевые Моменты:**

*   **Серверный Авторитет:** Все изменения `CurrentEther` и `MaxEther`, а также проверки `CanAfford` и списание `SpendEther` — **строго на сервере**.
*   **Репликация Состояния:** `PlayerState` — идеальное место для реплицируемых ресурсов игрока.
*   **Минимизация Репликации:** Реплицируются только сами значения. Логика прироста/траты на сервере.
*   **`REPNOTIFY_Always`:** Использование этого флага с `DOREPLIFETIME_CONDITION_NOTIFY` для `CurrentEther` и `MaxEther` гарантирует, что `OnRep_` функции будут вызваны на клиенте даже если новое значение совпадает со старым (но было установлено сервером). Это полезно для инициализации UI, если начальное значение 0 и новое тоже 0.
