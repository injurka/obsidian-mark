**Цель:** Создать чистый, правильно настроенный проект Unreal Engine, готовый для начала разработки с учетом лучших практик для масштабируемой сетевой игры.

**Шаги Реализации:**

1.  **Создание Пустого C++ Проекта в UE 5.5.4:**
    *   **Действие:** Запустить Epic Games Launcher, перейти в библиотеку и запустить Unreal Engine версии 5.5.4. В появившемся окне выбора проекта нажать "Games" -> "Blank" (Пустой шаблон). Убедиться, что в настройках выбрано "C++" (а не Blueprint) и "No Starter Content" (Без стартового контента) для максимальной чистоты проекта. Указать путь к проекту и задать имя `Polye`.
    *   **Обоснование:** Создание C++ проекта необходимо, потому что большая часть базовой логики, сетевого взаимодействия, сложных систем (вроде системы эффектов, о которой речь пойдет позже) и оптимизации будет реализована на C++. Это обеспечивает производительность и гибкость, которые сложно достичь только на Blueprint, особенно для PvP игры. Пустой шаблон гарантирует, что проект не содержит ненужного контента, который может затруднить организацию или внести путаницу.
    *   **Outcome:** Создан каталог проекта `Polye/` с базовыми файлами (`Polye.uproject`, `Source/Polye/Polye.Build.cs` и т.д.) и открыт проект в Unreal Editor. Сгенерировано решение Visual Studio (или другого IDE).

2.  **Установка Базовой Структуры Папок и Соглашений по Именованию:**
    *   **Действие:** В Unreal Editor, используя Content Browser, создать базовую структуру папок внутри корневой папки `Content/`. Следуйте структуре, предложенной вами в дизайн-документе:
        *   `Content/Maps/`
        *   `Content/Blueprints/`
        *   `Content/UI/`
        *   `Content/Data/`
        *   `Content/Art/`
        *   `Content/Audio/`
        *   `Content/Developer/`
        *   По мере необходимости внутри этих папок создавать подпапки согласно функциональному назначению (например, `Blueprints/Core/`, `Blueprints/GameModes/`, `Data/DataAssets/`, `Art/Meshes/`).
    *   **Действие (Соглашения):** Определить и **задокументировать** соглашения по именованию для всех типов ассетов и C++ классов. Используйте стандартные префиксы Unreal Engine и логичные, понятные имена. Примеры:
        *   **C++ Классы:** `UPolye...` (для `UObject`), `APolye...` (для `AActor`), `FPolye...` (для структур), `EPolye...` (для перечислений). Названия должны отражать функционал (напр., `APolyePlayerStateBase`, `UPolyeEtherComponent`).
        *   **Blueprint Классы:** `BP_Polye...` (для наследующих от C++), `BP_` (для чистых BP, если их немного, или `BP_Type_` напр., `BP_UI_WidgetName`), `WBP_...` (для Widget Blueprints). Напр., `BP_MainMenuGameMode`, `WBP_MainMenuScreen`.
        *   **Ассеты:** `SM_...` (Static Mesh), `SKM_...` (Skeletal Mesh), `T_...` (Texture), `M_...` (Master Material), `MI_...` (Material Instance), `DT_...` (Data Table), `DA_...` (Data Asset), `NS_...` (Niagara System), `SC_...` (Sound Cue), `AM_...` (Animation Montage). Напр., `SM_GameBoardTile`, `DA_Unit_SwampBrotherhood_XYZ`, `DT_CardCatalog`.
    *   **Обоснование:** Раннее создание четкой структуры папок и строгое следование соглашениям по именованию критически важно для поддержания порядка в крупном проекте. Это значительно упрощает навигацию, поиск ассетов, совместную работу в команде и интеграцию нового контента. Это основа масштабируемости на уровне организации проекта.
    *   **Outcome:** Создана базовая структура папок в `Content/`. Определен документ с соглашениями по именованию, которым будут пользоваться все разработчики.

3.  **Настройка Базовых Плагинов:**
    *   **Действие:** В Unreal Editor открыть меню `Edit -> Plugins`. Найти и включить следующие плагины:
        *   **Online Subsystem (and specific implementation, e.g., Online Subsystem Null):** В разделе `Online Platform`. Включить базовый Online Subsystem и как минимум "Online Subsystem Null" для локального тестирования сетевой игры без внешних сервисов. *Примечание:* Для реального онлайн-игры позже потребуется включить и настроить плагин для конкретного сервиса (Steam, EOS и т.д.). Включение на этом этапе необходимо, потому что наличие Online Subsystem влияет на дизайн сетевого кода.
        *   **Enhanced Input:** В разделе `Input`. Это современная, более гибкая система обработки ввода в Unreal Engine, которая хорошо интегрируется с GAS (если вы решите его использовать) и упрощает привязку действий к кнопкам.
    *   **Обоснование:** Включение фундаментальных плагинов на ранней стадии гарантирует, что вся последующая разработка (особенно сетевая логика и ввод) будет использовать выбранные инструменты с самого начала, избегая необходимости сложного рефакторинга позже. Сетевой подсистеме особенно важно быть активной с момента создания первых сетевых классов.
    *   **Outcome:** Необходимые плагины включены. Может потребоваться перезапуск редактора. Конфигурационные файлы проекта (.uproject) обновлены.

**Ключевые Соображения на Этом Этапе:**

*   **Документация:** Написание и поддержание в актуальном состоянии документа по соглашениям именования и структуре папок является критически важным, особенно если над проектом работает более одного человека.
*   **Выбор IDE:** Убедиться, что Visual Studio (или другое IDE) правильно настроено для работы с проектом UE C++.
*   **Система Контроля Версий:** Настроить систему контроля версий (Git с LFS, Perforce) с самого начала. Добавить базовый `.gitignore` или правила исключения для Unreal Engine.
*   **Минимализм:** На этом этапе важно сосредоточиться только на *основах*. Не добавляйте плагины или настройки "на всякий случай". Добавляйте их по мере необходимости.
