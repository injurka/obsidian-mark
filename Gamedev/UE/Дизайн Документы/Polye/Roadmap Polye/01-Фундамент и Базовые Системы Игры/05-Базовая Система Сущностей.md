**Цель:** Создать иерархию C++ классов для представления игровых сущностей (Юнитов и Строений), определить их общие атрибуты, реализовать базовую систему здоровья, получения урона и уничтожения. Эти сущности будут инициализироваться данными, полученными из системы управления данными (Data Assets).

**Зачем:**

*   **Общая База:** `APolyeBoardEntityBase` предоставит общую функциональность и атрибуты для всех объектов на поле, избегая дублирования кода.
*   **Специализация:** Наследники `APolyeUnitBase` и `APolyeStructureBase` позволят добавить специфическую логику и атрибуты для каждого типа сущностей.
*   **Управляемость Данными:** Инициализация характеристик сущностей (HP, Атака и т.д.) из Data Assets сделает их легко настраиваемыми гейм-дизайнерами.
*   **Сетевая Корректность:** Система будет спроектирована с учетом серверной авторизации и репликации состояния на клиенты.
*   **Фундамент для Боя:** Эта система является обязательным предварительным условием для реализации боевой системы, эффектов и способностей.

**Ключевые Компоненты:**

1.  **`APolyeBoardEntityBase`:** Абстрактный базовый класс для всех сущностей.
    *   **Атрибуты (Реплицируемые):**
        *   `CurrentHP`, `MaxHP`: Текущее и максимальное здоровье.
        *   `OwningPlayerState`: Указатель на `APolyePlayerStateBase` игрока-владельца.
        *   `EntityFaction`: Фракционная принадлежность (`EPolyeFaction`).
        *   `EntityUID`: Уникальный идентификатор сущности в рамках матча (назначается сервером).
        *   `CardDataID`: `FName`, ссылающееся на `RowName` в `DT_CardCatalog`, для получения исходных данных карты.
        *   `CurrentAttackValue`: Базовое значение атаки (может быть 0 для большинства строений, но некоторые могут атаковать).
        *   `CurrentPriority`: Значение приоритета цели (Таунт).
    *   **Функционал:**
        *   Инициализация на сервере (`InitializeEntity`).
        *   Получение урона (`ApplyDamage`).
        *   Исцеление (`Heal`).
        *   Логика "смерти" (`Die`).
        *   RPC для визуальных/звуковых эффектов смерти (`Multicast_OnDeathEffects`).
        *   `OnRep_` функции для клиентских обновлений.

2.  **`APolyeUnitBase`:** Класс для всех боевых юнитов, наследуется от `APolyeBoardEntityBase`.
    *   **Дополнительные Атрибуты (Реплицируемые, если нужно):** Например, `bCanAttackThisTurn`.
    *   **Функционал:**
        *   Логика атаки (`PerformAttack`).
        *   Проверка возможности атаки (`CanAttack`).
        *   Специфическая логика для юнитов.

3.  **`APolyeStructureBase`:** Класс для всех строений, наследуется от `APolyeBoardEntityBase`.
    *   **Функционал:**
        *   Специфическая логика для строений (например, пассивные эффекты, генерация ресурсов – будет добавлено позже через компоненты или системы).

void APolyeBoardEntityBase::InitializeEntity(APolyePlayerStateBase* InOwningPlayerState, FName InCardDataID, int32 InEntityUID)
{
    if (HasAuthority()) // Только на сервере
    {
        OwningPlayerState = InOwningPlayerState;
        CardDataID = InCardDataID;
        EntityUID = InEntityUID;

        ResolvedCardData = GetCardData(); // Загружаем и кэшируем данные карты на сервере

        if (ResolvedCardData)
        {
            MaxHP = 0; // Сброс перед чтением из DA
            CurrentAttackValue = 0;
            CurrentPriority = 0;

            EntityFaction = ResolvedCardData->Faction; // Устанавливаем фракцию из данных карты

            // Пытаемся привести к специфичным типам CardData для доступа к HP, Attack, Priority
            if (const UPolyeUnitCardData* UnitData = Cast<UPolyeUnitCardData>(ResolvedCardData))
            {
                MaxHP = UnitData->BaseHP;
                CurrentAttackValue = UnitData->BaseAttack;
                CurrentPriority = UnitData->BasePriority;
            }
            else if (const UPolyeStructureCardData* StructureData = Cast<UPolyeStructureCardData>(ResolvedCardData))
            {
                MaxHP = StructureData->BaseHP;
                // Атака для строений по умолчанию 0, если не указано в StructureData
                CurrentPriority = StructureData->BasePriority;
            }
            
            if (MaxHP <= 0) MaxHP = 1; // Гарантируем, что MaxHP > 0
            CurrentHP = MaxHP;

            UE_LOG(LogTemp, Log, TEXT("Entity %d (%s) initialized on server. HP: %d, Attack: %d, Priority: %d, Faction: %s"),
                EntityUID, *CardDataID.ToString(), CurrentHP, CurrentAttackValue, CurrentPriority, *UEnum::GetValueAsString(EntityFaction));
        }
        else
        {
            UE_LOG(LogTemp, Error, TEXT("Failed to initialize Entity %d: CardData for ID '%s' not found."), EntityUID, *InCardDataID.ToString());
            // Установить дефолтные значения, чтобы избежать проблем
            MaxHP = 1; CurrentHP = 1; CurrentAttackValue = 0; CurrentPriority = 0; EntityFaction = EPolyeFaction::Neutral;
        }
    }
}

        return ResolvedCardData;
    }

    if (DataManager && CardDataID != NAME_None)
    {
        // Мы не можем присвоить ResolvedCardData здесь, так как функция константная.
        // Это означает, что ResolvedCardData должен быть установлен при инициализации на сервере

        // Третий вариант - сервер передает нужные поля через RPC или реплицируемые переменные.

        return DataManager->GetCardData(CardDataID);
    }
    return nullptr;

bool APolyeUnitBase::CanAttackTarget(const APolyeBoardEntityBase* Target) const
{
    if (!HasAuthority() || !IsAlive() || !Target || !Target->IsAlive())
    {
        return false;
    }
    if (!bCanAttackThisTurn) // Проверка на возможность атаковать в этот ход
    {
        UE_LOG(LogTemp, Warning, TEXT("Unit %d cannot attack: bCanAttackThisTurn is false."), EntityUID);
        return false;
    }
    if (OwningPlayerState == Target->OwningPlayerState) // Нельзя атаковать своих
    {
        UE_LOG(LogTemp, Warning, TEXT("Unit %d cannot attack: Target is friendly."), EntityUID);
        return false;
    }
    if (CurrentAttackValue <= 0) // Должен иметь атаку
    {

**4. Интеграция с Системой Данных и GameMode**

*   **GameMode (`APolyeGameplayGameMode`):**
    *   Должен иметь механизм для спавна этих сущностей (`APolyeUnitBase`, `APolyeStructureBase`) при розыгрыше карт.
    *   При спавне он должен получать `CardDataID` (например, из разыгранной карты), назначать `EntityUID` (вести счетчик UID на сервере) и вызывать `InitializeEntity`, передавая владельца.
    *   Должен обрабатывать события смерти сущностей (например, для проверки условий победы).
*   **DataManager (`UPolyeDataManager`):**
    *   Используется в `APolyeBoardEntityBase::InitializeEntity` для получения `UPolyeCardData` (юнита или строения) и установки начальных характеристик (`MaxHP`, `EntityFaction`, `CurrentAttackValue`, `CurrentPriority`).
*   **PlayerState (`APolyePlayerStateBase`):**
    *   Передается в `InitializeEntity` для установки `OwningPlayerState`.

**Ключевые Соображения:**

*   **Серверная Логика:** Вся инициализация сущностей, применение урона, исцеление, смерть – происходят на сервере. Клиенты получают обновления через репликацию.
*   **`UPROPERTY` и `UFUNCTION` Спецификаторы:** Правильно используйте `Replicated`, `ReplicatedUsing`, `BlueprintAuthorityOnly`, `NetMulticast` и т.д.
*   **Местоположение Сущностей:** Пока мы не реализовали систему поля (`APolyeField`), сущности просто спавнятся в мире. На следующем этапе они будут привязаны к конкретным клеткам поля.
*   **Визуальное Представление:** Меши и другие визуальные компоненты пока не добавлены в базовые C++ классы. Их лучше добавлять в Blueprint-наследниках (`BP_Unit_XYZ`, `BP_Structure_ABC`), которые будут созданы на основе этих C++ классов. `UnitBlueprint` и `StructureBlueprint` в `UPolyeCardData` будут ссылаться именно на эти BP.
*   **Баланс и Данные:** Все начальные статы (MaxHP, Attack, Priority) должны браться из `UPolyeCardData` через `UPolyeDataManager`.
