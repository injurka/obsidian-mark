**Цель:** Настроить базовые сетевые функции Unreal Engine для ключевых игровых классов, реализовать простой обмен данными и действиями между клиентом и сервером, и создать минимальную возможность подключения двух игроков для тестирования.

**Шаги Реализации:**

1.  **Настройка Базовой Репликации для Ключевых Игровых Классов:**
    *   **Действие:** Для каждого из созданных в предыдущем пункте C++ классов, которые должны существовать и синхронизироваться по сети (`APolyeGameStateBase`, `APolyePlayerStateBase`, `ABoardEntityBase` и его наследники `AUnit`, `AStructure`, а также опционально `APolyePlayerPawn`), необходимо:
        *   В конструкторе класса (в файле `.cpp`) добавить строку:
            ```cpp
            // В конструкторе APolyeGameStateBase::APolyeGameStateBase()
            bReplicates = true;
            // В конструкторе APolyePlayerStateBase::APolyePlayerStateBase()
            bReplicates = true;
            // В конструкторе ABoardEntityBase::ABoardEntityBase()
            bReplicates = true;
            ```
            *   *Примечание:* `AGameModeBase` существует только на сервере по определению движка, ему `bReplicates = true` не нужен. `APlayerController` тоже имеет свои особенности репликации и не требует этого флага в конструкторе для базовой функциональности.
        *   Для классов, которые должны быть *всегда* релевантны для всех игроков (GameState, PlayerState, и, вероятно, все сущности на небольшой игровой доске Polye), также добавить в конструкторе:
            ```cpp
            // В конструкторе APolyeGameStateBase::APolyeGameStateBase()
            bAlwaysRelevant = true; // GameState всегда виден всем
            // В конструкторе APolyePlayerStateBase::APolyePlayerStateBase()
            bAlwaysRelevant = true; // PlayerState всегда виден всем
            // В конструкторе ABoardEntityBase::ABoardEntityBase()
            bAlwaysRelevant = true; // Сущности на доске всегда видны всем
            ```
    *   **Обоснование:** Флаг `bReplicates = true` сообщает движку, что данный Актер может быть создан на сервере и его копия должна быть реплицирована на клиенты. `bAlwaysRelevant = true` гарантирует, что движок будет всегда синхронизировать этот Актер со всеми клиентами, независимо от расстояния или других условий релевантности. Это подходит для объектов глобального состояния или объектов на небольшой, всегда видимой арене, как в Polye.
    *   **Outcome:** Все ключевые Акторы игры настроены для репликации на базовом уровне.

2.  **Реализация Репликации Свойств (Переменных):**
    *   **Действие:** В каждом из реплицируемых классов (`AGameStateBase`, `APolyePlayerStateBase`, `ABoardEntityBase`, `AUnit`, `AStructure`), для переменных, которые должны синхронизироваться с клиентами, необходимо:
        *   В файле `.h`, перед объявлением переменной, добавить спецификатор `UPROPERTY(Replicated)`.
        *   В файле `.cpp` класса реализовать функцию `GetLifetimeReplicatedProps(TArray<FLifetimeProperty>& OutLifetimeProps) const override`.
        *   Внутри этой функции использовать макрос `DOREP(ClassName, PropertyName)`.
        *   Для переменных, которые должны реплицироваться только на владельца (`APolyePlayerStateBase::HandCards`), использовать макрос `DOREP_WITH_COND(ClassName, PropertyName, COND_OwnerOnly)`.
        *   (Опционально) Для переменных, чье изменение на клиенте должно вызывать специальную функцию-обработчик (например, обновление UI при изменении Эфира или HP), использовать спецификатор `UPROPERTY(ReplicatedUsing=OnRep_PropertyName)` и реализовать функцию `void OnRep_PropertyName()`.
    *   **Примеры (в `.h`):**
        ```cpp
        // В APolyeGameStateBase.h
        UPROPERTY(Replicated)
        TArray<FPolyeFieldState> BoardState; // Структура состояния поля, определим позже

        UPROPERTY(Replicated)
        int32 CurrentTurnNumber;

        UPROPERTY(ReplicatedUsing=OnRep_CurrentPlayer)
        APolyePlayerStateBase* CurrentPlayer; // Ссылка на PlayerState текущего игрока

        // В APolyePlayerStateBase.h
        UPROPERTY(ReplicatedUsing=OnRep_CurrentEther)
        int32 CurrentEther;

        UPROPERTY(ReplicatedUsing=OnRep_MaxEther)
        int32 MaxEther;

        UPROPERTY(Replicated, ReplicatedUsing=OnRep_HandCards) // ReplicatedUsing для владельца
        TArray<FCardData> HandCards; // Структура данных карты, определим позже

        // В ABoardEntityBase.h
        UPROPERTY(ReplicatedUsing=OnRep_CurrentHP)
        int32 CurrentHP;

        UPROPERTY(Replicated)
        int32 MaxHP;

        UPROPERTY(Replicated)
        int32 FieldIndex; // Индекс поля, на котором находится сущность
        ```
    *   **Примеры (в `.cpp`):**
        ```cpp
        // В APolyeGameStateBase.cpp

        {

        }

        {
            Super::GetLifetimeReplicatedProps(OutLifetimeProps);
            DOREP(APolyePlayerStateBase, CurrentEther);
            DOREP(APolyePlayerStateBase, MaxEther);
            DOREP_WITH_COND(APolyePlayerStateBase, HandCards, COND_OwnerOnly); // Только для владельца!
        }
        void APolyePlayerStateBase::OnRep_CurrentEther()
        {

            // Добавить реализацию
        }
        void APolyePlayerStateBase::OnRep_HandCards()
        {
             // Логика на клиенте при изменении руки (добор, розыгрыш), напр., обновление виджета руки
             // Добавить реализацию
        }
        ```
    *   **Обоснование:** `GetLifetimeReplicatedProps` – это функция, которую вызывает движок, чтобы узнать, какие переменные данного Актера должны реплицироваться и при каких условиях. `DOREP` – стандартный макрос для этого. `DOREP_WITH_COND` позволяет указать условия репликации (например, `COND_OwnerOnly` – только владельцу). `ReplicatedUsing` очень полезен для клиентской стороны, чтобы реагировать на получение новых данных.
    *   **Outcome:** Переменные, хранящие состояние игры и игрока, настроены для синхронизации между сервером и клиентами (полностью или частично).

3.  **Реализация Базового Клиент-Серверного Взаимодействия (RPC):**
    *   **Действие:** Определить действия, которые игрок (клиент) может инициировать, и которые требуют выполнения на сервере (например, розыгрыш карты, завершение хода, использование способности). Эти действия реализуются как **Server RPC** функции в `APolyePlayerController`. Определить действия, которые сервер должен вызвать на конкретном клиенте (например, обновить UI, показать сообщение). Эти действия реализуются как **Client RPC** функции в `APolyePlayerController`. Определить действия, которые сервер должен сообщить *всем* клиентам (например, показать эффект взрыва на поле). Эти действия реализуются как **NetMulticast RPC**.
    *   **Реализация (в `.h` файла `APolyePlayerController`):**
        ```cpp

        UFUNCTION(Server, Reliable, WithValidation) // Reliable - гарантированная доставка, WithValidation - генерирует _Validate функцию
        void Server_TryPlayCard(const FCardData& CardToPlay, int32 TargetFieldIndex); // Передавать данные карты и поле

        UFUNCTION(Server, Reliable, WithValidation)
        void Server_EndTurn();

        // Client RPC: Вызываются на сервере, выполняются на конкретном owning client
        UFUNCTION(Client, Reliable)
        void Client_NotifyTurnStart();

        UFUNCTION(Client, Reliable)
        void Client_UpdateGameplayUI(); // Обновить UI, используя реплицированные PlayerState/GameState

        // NetMulticast RPC: Вызываются на сервере, выполняются на сервере И на всех клиентах
        UFUNCTION(NetMulticast, Reliable)
        void Multicast_PlayEffectOnField(EPolyeEffectType EffectType, int32 FieldIndex); // Тип эффекта и поле
        ```

4.  **(MVP) Простой Лобби/Система Подключения Двух Игроков для Теста:**
    *   **Действие (Конфигурация Проекта):**
        *   Открыть файл `DefaultEngine.ini` в папке `Config` вашего проекта.
        *   Добавить или изменить секцию `[OnlineSubsystem]` следующим образом:
```
[OnlineSubsystem]
DefaultPlatformService=Null // Использовать Online Subsystem Null для локального тестирования
PollingIntervalInSeconds=0.02
```
-  (Опционально) Добавить секцию для GameMode по умолчанию, если вы хотите, чтобы ваш `APolyeGameModeBase` использовался по умолчанию для всех карт, если не указано иное:
```ini
[Engine]
DefaultGameMode=/Script/Polye.PolyeGameModeBase // Указать ваш базовый GameMode
```
- **Действие (Запуск Игры):**
        *   **Запустить Сервер:** Самый простой способ для локального теста с двумя игроками — запустить игру из редактора. В меню `Play` редактора, в выпадающем списке "Number of Players" выбрать `2` и поставить галочку "Run Dedicated Server" (или "Listen Server"). Нажать `Play`. Редактор запустит одно окно как сервер (если выделенный) или клиент-слушатель, и одно/два дополнительных окна как клиенты.
        *   **Подключение Клиента Вручную:** Запустить игру отдельно (либо exe-файл, либо из редактора как Standalone Game). Открыть консоль (`~`) и ввести команду `open [ServerIP]` (например, `open 127.0.0.1` для локального подключения к серверу, запущенному на той же машине).
        *   **Запуск Listen Server через Консоль/Блюпринты:** Запустить игру (exe или Standalone Game). Открыть консоль и ввести `open [MapName]?listen` (например, `open Map_Lobby?listen`). Это запустит игру как сервер, и вы сами станете первым клиентом. Затем другие клиенты могут подключиться к вашему IP.
    *   **Действие (Начало Матча):**
        *   В вашем `APolyeGameModeBase` (серверная сторона) реализовать простую логику для начала матча, когда подключается второй игрок (в функции `PostLogin`).
        *   Например:
            ```cpp
            void APolyeGameModeBase::PostLogin(APlayerController* NewPlayer)
            {
                Super::PostLogin(NewPlayer);

                // Простая логика для 2 игроков
                if (GetNumPlayers() >= 2)
                {
                    // Подготовка к матчу (раздача карт, активация полей и т.д.)
                    // ...
                    // Запуск матча (вызов HandleMatchHasStarted() или StartMatch())
                    // ...
                    UE_LOG(LogTemp, Warning, TEXT("Enough players joined, starting match!"));
                    StartMatch(); // Стандартная функция GameMode для запуска матча
                }
            }
            ```
    *   **Обоснование:** Online Subsystem Null позволяет тестировать сетевые функции без необходимости настраивать внешний сервис. Запуск игры с несколькими клиентами из редактора или через консольные команды – самый быстрый способ проверить базовую репликацию и RPC на локальной машине. `PostLogin` – удобное место в GameMode (серверном) для обнаружения нового игрока и выполнения логики, связанной с его присоединением.
    *   **Outcome:** Проект настроен на использование базовой сетевой подсистемы. Есть возможность запускать игру как сервер и подключать клиентов (минимум одного) для тестирования. Базовая логика GameMode реагирует на подключение игроков для старта MVP матча.

**Важные Примечания:**

*   **Валидация Серверных RPC:** Никогда не доверяйте данным, приходящим в Server RPC. Всегда выполняйте тщательную валидацию на сервере, чтобы убедиться, что действие допустимо согласно правилам игры и состоянию игрока. Это основная защита от читерства.
*   **Не Реплицируйте Все:** Реплицируйте только те данные, которые *необходимы* на клиенте. Чрезмерная репликация ухудшает производительность сети.
*   **Сетевой Профилировщик:** Используйте встроенные инструменты Unreal Engine (такие как Network Profiler) для анализа сетевого трафика и выявления проблем с репликацией или RPC.
*   **Это Не Полноценное Лобби:** Система подключения через `open` команду или запуск из редактора очень проста. Полноценная система лобби с поиском игр, комнатами, выбором колоды и т.д. будет реализована позже (в мета-системах). Этого достаточно только для тестирования основных сетевых механик MVP.
