**Цель:** Создать основные C++ классы, которые будут представлять ключевые сущности и состояния игры, определив их роли и сетевые свойства для будущей реализации мультиплеера.

**Концепция Сетевой Архитектуры Unreal Engine (Кратко):**

*   **Сервер Владеет (Server Authority):** В сетевой игре на Unreal Engine сервер является источником истины. Все критически важные игровые правила, состояния и логика должны выполняться на сервере. Клиенты "просят" сервер выполнить действия и "смотрят", что сервер им реплицирует в ответ.
*   **Репликация:** Изменения в свойствах (переменных) Актеров и компонентов могут быть автоматически синхронизированы с подключенными клиентами.
*   **RPC (Remote Procedure Calls):** Механизм для вызова функций на другой машине (клиент -> сервер, сервер -> клиент, сервер -> все клиенты).

**Ключевые Классы и Их Роли в Polye:**

1.  **`AGameModeBase` (Наследуем: `APolyeGameModeBase`)**
    *   **Общая Роль в UE:** Определяет правила игры, управляет состоянием матча (начало, конец), спавнит игроков (PlayerController и Pawn), выбирает базовые классы для GameState, PlayerController, PlayerState, Pawn. **Существует ТОЛЬКО на сервере.**
    *   **Роль в Polye (Сетевая Игра):**
        *   **Серверные Правила:** Будет содержать или ссылаться на системы, определяющие правила Polye: как начинается матч (активация полей), как происходит смена ходов, как рассчитывается базовый прирост Эфира, как проверяются условия победы/поражения (уничтожение всех Строений противника).
        *   **Управление Матчем:** Обрабатывает присоединение/отключение игроков, инициализацию их PlayerState и PlayerController, подготовку игрового поля к матчу.
        *   **Состояние Игры (Правила):** Хотя само состояние игры (что на поле, сколько Эфира у игрока) хранится в GameState и PlayerState, GameMode использует эти данные для принятия решений по правилам.
    *   **Что Не Хранить:** Не хранит данные, которые должны быть видны всем клиентам (для этого GameState) или данные конкретного игрока (для этого PlayerState). Не обрабатывает пользовательский ввод напрямую.
    *   **Реализация (C++):**
        *   Создать новый C++ класс, наследующий от `AGameModeBase`, назвать его `APolyeGameModeBase`.
        *   В конструкторе установить классы по умолчанию для `GameStateClass`, `PlayerControllerClass`, `PlayerStateClass`, `DefaultPawnClass`.
        *   Переопределить базовые функции, такие как `PostLogin` (присоединение игрока), `Logout` (отключение игрока), `HandleMatchHasStarted` (начало матча), `HandleMatchHasEnded` (конец матча).
        *   Добавить логику для инициализации игрового поля (пока логическую структуру, не визуал).
        *   Добавить логику управления ходами игроков (смена активного игрока).

2.  **`AGameStateBase` (Наследуем: `APolyeGameStateBase`)**
    *   **Общая Роль в UE:** Хранит состояние игры, которое **реплицируется на всех клиентов**. Список всех PlayerState в матче.
    *   **Роль в Polye (Сетевая Игра):**
        *   **Реплицируемое Состояние Поля:** Критически важно! Будет хранить и реплицировать состояние *всего* игрового поля: какие поля активны, какая Фракция и Ландшафт на каждом поле, какие сущности (Юниты, Строения) находятся на каждом поле, их HP, статусы и другую видимую информацию.
        *   **Общее Состояние Матча:** Текущий номер хода, какой игрок сейчас ходит.
        *   **Список Игроков:** Предоставляет доступ к PlayerState всех подключенных игроков.
    *   **Что Не Хранить:** Не хранит секретные данные игрока (например, содержимое колоды до вытягивания в руку), не обрабатывает правила игры (GameMode), не обрабатывает ввод игрока (PlayerController).
    *   **Реализация (C++):**
        *   Создать новый C++ класс, наследующий от `AGameStateBase`, назвать его `APolyeGameStateBase`.
        *   Объявить переменные, которые должны реплицироваться (например, массив структур, описывающих состояние каждого поля; переменная для текущего номера хода; переменная для PlayerState текущего игрока). Использовать спецификатор `Replicated`.
        *   Реализовать функцию `GetLifetimeReplicatedProps` для настройки репликации переменных.
        *   Добавить функции для доступа к состоянию поля, текущему игроку и т.д. (логика изменения состояния будет на сервере, но доступ к нему нужен всем).

3.  **`APlayerController` (Наследуем: `APolyePlayerController`)**
    *   **Общая Роль в UE:** Связующее звено между вводом игрока (мышь, клавиатура, геймпад) и его представлением в игре (Pawn/Character, взаимодействие с миром). **Существует на сервере и на клиенте, которым управляет данный игрок (owning client).**
    *   **Роль в Polye (Сетевая Игра):**
        *   **Обработка Ввода:** Принимает ввод от игрока (клики по полю, выбор карты, выбор цели). Использует Enhanced Input (Фаза 1).
        *   **Взаимодействие с UI:** Управляет отображением пользовательского интерфейса для данного игрока (игровой экран, меню).
        *   **Коммуникация с Сервером:** **Отправляет RPC на сервер**, чтобы запросить выполнение игровых действий (разыграть карту на поле X, атаковать сущность Y юнитом Z, завершить ход). Серверная сторона PlayerController получает этот RPC, валидирует действие (хватает ли Эфира, корректное ли поле, его ли сейчас ход и т.д.) и, если действие допустимо, передает выполнение соответствующей серверной системе (например, GameMode или специализированному менеджеру).
        *   **Управление Камерой:** Управляет положением игровой камеры для данного игрока.
    *   **Что Не Хранить:** Не хранит состояние игры (GameState), не хранит данные других игроков, не выполняет игровую логику, которую должен выполнять сервер (например, расчет урона, применение эффектов - это должно быть на сервере).
    *   **Реализация (C++):**
        *   Создать новый C++ класс, наследующий от `APlayerController`, назвать его `APolyePlayerController`.
        *   Настроить привязку Enhanced Input Actions к функциям-обработчикам ввода (например, `OnLeftClickPressed`, `OnRightClickReleased`).
        *   В функциях-обработчиках, если это действие требует серверной логики (например, розыгрыш карты), вызвать соответствующий **Server RPC**. Объявить эти функции как `Server`, `Reliable`, `WithValidation`.
        *   Добавить логику для спавна и управления виджетами UI на клиенте (`Client` RPC или напрямую в клиентской части PlayerController).
        *   Добавить логику управления игровой камерой.
