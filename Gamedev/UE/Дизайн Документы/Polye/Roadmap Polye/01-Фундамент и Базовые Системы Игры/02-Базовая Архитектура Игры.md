**Задача:** Создать основные C++ классы, которые будут представлять ключевые сущности и состояния игры "Polye", определив их роли, ответственность и сетевые свойства для будущей реализации мультиплеера.

**Зачем:**
*   **Понимание Ролей:** Ясное определение задач каждого класса (GameMode, GameState, PlayerController, PlayerState, Pawn, BoardEntity) критически важно для правильного построения архитектуры игры, особенно сетевой.
*   **Надежная Основа:** C++ классы обеспечивают более стабильную и производительную базу для основных систем игры по сравнению с чисто Blueprint-решениями.
*   **Сетевая Архитектура:** Правильное определение ролей и владения (ownership) этими классами, а также понимание, какие данные где реплицируются, необходимо для создания стабильной и предсказуемой сетевой игры в Unreal Engine.
*   **Структура для Логики Polye:** Создание этих базовых классов предоставляет четкие "контейнеры" для размещения специфичной логики Polye.
*   **Расширяемость:** Базовые классы позволят легко создавать специализированные Blueprint- или C++ наследники.

**Концепция Сетевой Архитектуры Unreal Engine (Кратко):**
Прежде чем создавать классы, напомним ключевые принципы сетевой работы в UE:

*   **Сервер Владеет (Server Authority):** Сервер является источником истины для состояния игры. Вся критически важная логика (правила, расчеты, проверка действий игрока) выполняется только на сервере.
*   **Репликация:** Свойства (переменные) Актеров и Компонентов могут быть автоматически синхронизированы с клиентами. Только сервер может *изменять* реплицируемые переменные, клиенты их только *получают*.
*   **RPC (Remote Procedure Calls):** Механизм для вызова функций на удаленной машине. Клиент может вызвать функцию на сервере (Server RPC), а сервер может вызвать функцию на конкретном клиенте (Client RPC) или на всех клиентах (Multicast RPC).

1.  **Откройте Unreal Editor** вашего проекта Polye.
2.  Перейдите в меню: **Tools -> New C++ Class...**
3.  В открывшемся окне выберите **родительский класс (Parent Class)**:
    *   Для `APolyeGameModeBase`: Выберите `Game Mode Base`.

    *   Для `APolyePlayerStateBase`: Выберите `Player State`.
    *   Для `APolyePawnBase`: Выберите `Pawn`.
    *   Для `APolyeBoardEntityBase`: Выберите `Actor`.
4.  Нажмите **Next**.
5.  Введите **Имя (Name)** нового класса (например, `PolyeGameModeBase`).
6.  Убедитесь, что **Путь (Path)** установлен в основную папку исходного кода вашего проекта (обычно `Polye/Source/Polye/` или `Polye/Source/Polye/Core/` в соответствии с вашей структурой). *Рекомендуется помещать базовые классы в подпапку, например, `Core/` или `Framework/` внутри вашего модуля `Polye/Source/Polye/`.*

**1. `AGameModeBase` (Наследуем: `APolyeGameModeBase`)**

*   **Общая Роль в UE:** Определяет правила игры, управляет состоянием матча (начало, конец), спавнит игроков (PlayerController и Pawn), выбирает базовые классы для GameState, PlayerController, PlayerState, Pawn. **Существует ТОЛЬКО на сервере.**
*   **Роль в Polye (Сетевая Игра):**
    *   **Серверные Правила:** Будет содержать или ссылаться на системы, определяющие правила Polye: как начинается матч (активация полей), как происходит смена ходов, как рассчитывается базовый прирост Эфира, как проверяются условия победы/поражения (уничтожение всех Строений противника).
    *   **Управление Матчем:** Обрабатывает присоединение/отключение игроков (`PostLogin`, `Logout`), инициализацию их PlayerState и PlayerController. Поскольку `AGameModeBase` не имеет встроенных функций управления состоянием матча, таких как `HandleMatchHasStarted` (они есть в `AGameMode`), вам потребуется реализовать свою логику старта, завершения матча и отслеживания его состояния.
    *   **Обработка RPC:** Получает и обрабатывает серверные RPC (Server RPC) от PlayerController игроков, валидирует запрошенные действия и передает выполнение соответствующим серверным системам.

**2. `AGameStateBase` (Наследуем: `APolyeGameStateBase`)**

*   **Общая Роль в UE:** Хранит состояние игры, которое **реплицируется на всех клиентов**. Содержит список всех PlayerState в матче. Существует как на сервере, так и на всех клиентах.
*   **Роль в Polye (Сетевая Игра):**
    *   **Реплицируемое Состояние Поля:** Критически важно! Будет хранить и реплицировать состояние *всего* игрового поля: какие поля активны, какая Фракция и Ландшафт на каждом поле, какие сущности (Юниты, Строения) находятся на каждом поле, их HP, статусы и другую видимую информацию.
    *   **Общее Состояние Матча:** Текущий номер хода, какой игрок сейчас ходит (ссылка на его PlayerState), текущее состояние матча (например, EPolyeMatchState).
    *   **Список Игроков:** Предоставляет доступ к PlayerState всех подключенных игроков на всех машинах.
*   **Что Не Хранить:** Секретные данные игрока (это в PlayerState с `COND_OwnerOnly`). Не выполняет правила игры (GameMode). Не обрабатывает ввод (PlayerController). Изменяться должно только на сервере.

**3. `APlayerController` (Наследуем: `APolyePlayerController`)**

*   **Общая Роль в UE:** Связующее звено между вводом игрока и его представлением в игре. **Существует на сервере и на клиенте, которым управляет данный игрок (owning client).**
*   **Роль в Polye (Сетевая Игра):**
    *   **Обработка Ввода:** Принимает ввод от игрока (клики по полю, выбор карты, выбор цели). Использует Enhanced Input.
    *   **Взаимодействие с UI:** Управляет отображением UI для данного игрока.
    *   **Коммуникация с Сервером:** **Отправляет RPC на сервер** (`Server RPC`) для запроса игровых действий.
    *   **Получение Команд с Сервера:** Может получать команды с сервера через `Client RPC`.
    *   **Управление Камерой:** Управляет игровой камерой.
*   **Что Не Хранить:** Полное состояние игры (GameState). Данные других игроков. Критическую игровую логику (это на сервере, часто в GameMode или системах). Состояние игрока, видимое всем (PlayerState).

**4. `APlayerState` (Наследуем: `APolyePlayerStateBase`)**

*   **Общая Роль в UE:** Хранит состояние *конкретного игрока*, которое **реплицируется на ВСЕХ клиентов**. Существует как на сервере, так и на всех клиентах.
*   **Роль в Polye (Сетевая Игра):**
    *   **Реплицируемое Состояние Игрока (Публичное):** Текущий Эфир, максимальный Эфир, выбранная Фракция (если применимо до матча или на уровне игрока), возможно, количество уничтоженных строений противника.
    *   **Реплицируемое Состояние Игрока (Приватное):** С `COND_OwnerOnly` – содержимое руки карт, возможно, текущая активная колода.
    *   **Владение Компонентами:** Может владеть компонентами, отвечающими за ресурсы (Эфир), руку, колоду.
*   **Что Не Хранить:** Общее состояние игры (GameState). Не обрабатывает ввод (PlayerController). Не выполняет серверную логику (GameMode).

**6. `AActor` (Наследуем: `APolyeBoardEntityBase`)**

*   **Общая Роль в UE:** Базовый класс для любого объекта, который может быть размещен или заспавнен в мире. Обладает Transform, может иметь компоненты, реплицироваться.

**Следующие Шаги После Создания Классов:**

1.  **Компиляция:** Убедитесь, что проект успешно компилируется в Visual Studio/Rider или через кнопку `Compile` в редакторе Unreal Engine.
2.  **Проверка в Редакторе:** Откройте Content Browser, найдите папку, куда вы сохранили C++ классы. Вы должны увидеть там все созданные классы.
3.  **(Опционально) Создание Blueprint-Наследников:** Вы можете создать Blueprint-классы, унаследованные от этих C++ классов, чтобы настраивать их в редакторе и добавлять BP-специфичную логику или визуал.
4.  **Настройка GameMode в Проекте:** Перейдите в `Edit -> Project Settings -> Maps & Modes`. В разделе `Default Modes` выберите ваш `APolyeGameModeBase` (или его Blueprint-наследника) в качестве `Default GameMode` для вашей игровой карты. Вы также можете установить его глобально, если это основной режим.
5.  **Настройка Default Classes в GameMode:** Если вы используете C++ классы напрямую, конструктор `APolyeGameModeBase` уже настроен. Если вы создали Blueprint-наследники (например, `BP_PolyePlayerController`), откройте ваш `APolyeGameModeBase.cpp` (или Blueprint-наследник GameMode) и измените строки в конструкторе, чтобы они указывали на ваши Blueprint-классы, используя `ConstructorHelpers::FClassFinder` (как показано в закомментированном примере в `APolyeGameModeBase.cpp`).
