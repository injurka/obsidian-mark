**Основной Принцип:** Быстрые итерации, функциональность важнее визуала. Используются только базовые ассеты UE5 (кубы, сферы, стандартный манекен). Весь фокус — на коде, логике и ощущениях от геймплея.

### **Майлстоун 1: Создание Фундамента и Тестового Полигона (Недели 1-4)**

**Цель:** Подготовить рабочую среду и протестировать самую базовую, но определяющую механику — строительство без терраформинга.

#### **Неделя 1: Настройка и Базовый Игрок**
*   **Задачи:**
    1.  **Создание Проекта (Программист):** Создать чистый проект на C++ в Unreal Engine 5.
    2.  **Контроль Версий (Программист):** Настроить систему контроля версий (Perforce предпочтительнее для UE5, но Git LFS тоже подойдет).
    3.  **Базовый Игрок (Программист):** Создать `PlayerController` и `Character` на C++. Реализовать базовое перемещение от третьего лица (можно взять за основу стандартный `ThirdPersonCharacter` из шаблона UE5).
    4.  **Система Взаимодействия (Программист):** Создать простой интерфейс на C++ (`I_Interactable`) с функциями `BeginFocus`, `EndFocus`, `Interact`. Это позволит любому объекту в мире (Архониду, Мультиферме, растению) быть интерактивным.
*   **Результат:** Игрок может бегать по пустому уровню и наводить курсор на объекты, которые подсвечиваются при "фокусе".

#### **Неделя 2: Создание Тестового Полигона**
*   **Задачи:**
    1.  **Проектирование Карты (Геймдизайнер/Художник):** Нарисовать простую схему тестового уровня, который содержит ключевые элементы рельефа для проверки строительства.
    2.  **Создание Карты (Художник/Тех. Художник):** С помощью стандартного инструмента **Landscape** в UE5 создать тестовую карту. Она должна включать:
        *   Ровную площадку.
        *   Пологий холм.
        *   Крутой утес/скалу, на которую нельзя взобраться пешком.
        *   Небольшое ущелье или овраг (2-3 ширины игрока).
        *   Маленькую пещеру.
*   **Результат:** Тестовый уровень, на котором можно проверять все аспекты строительства и навигации.

#### **Недели 3-4: Прототип Строительства (Нулевое Терраформирование)**
*   **Задачи:**
    1.  **Логика Предпросмотра (Программист):**
        *   Реализовать систему, которая постоянно делает `Line Trace` от камеры игрока вперед.
        *   В точке попадания луча отображать "призрак" строительного блока (простой полупрозрачный куб).
        *   Этот призрак должен привязываться к глобальной сетке (например, 100x100x100 юнитов).
        *   Самое важное: призрак должен **выравниваться по нормали поверхности**. То есть на склоне он должен стоять под тем же углом, что и земля под ним.
    2.  **Логика Размещения и Ограничений (Программист/Геймдизайнер):**
        *   По клику мыши на месте призрака спавнится статичный блок (непрозрачный куб).
        *   Добавить проверку: если угол наклона поверхности слишком большой или если призрак пересекается с другим объектом, он должен становиться красным, и строить нельзя.
    3.  **Прототип Структурной Целостности (Программист):**
        *   Реализовать очень простую проверку: каждый новый блок должен либо касаться земли (Landscape), либо другим, уже установленным блоком, который имеет "фундамент" (то есть связан с землей).
        *   Если игрок пытается построить блок "в воздухе", призрак должен быть красным.
*   **Результат Майлстоуна 1:** Играбельная сборка, где игрок может бегать по тестовой карте и строить "лесенки" на холм, "мосты" через ущелье и "платформы" на утесе. Команда может оценить, насколько эта механика интуитивна и креативна.

### **Майлстоун 2: Ядро Био-инженерии v0.1 (Недели 5-8)**

**Цель:** Создать и связать воедино самые примитивные версии систем Флоры и Фауны. Доказать, что их взаимозависимость понятна и работает.

#### **Недели 5-6: Структуры Данных и Базовый UI**
*   **Задачи:**
    1.  **Data Tables (Геймдизайнер/Программист):** Создать в UE5 таблицы данных (`Data Tables`) для хранения информации. Это основа для будущего баланса.
        *   `DT_Items`: Список всех предметов (ID, Название, Описание, Иконка-плейсхолдер). Примеры: "Семена Простого Растения", "Еда", "Воск".
        *   `DT_ArkhonidSpecies`: Список видов Архонидов с их базовыми параметрами (что едят, что производят).
        *   `DT_Genes`: Таблица с генами (ID, Название, Эффект).
    2.  **Система Инвентаря (Программист):** Создать базовый компонент инвентаря на C++, который может хранить предметы из `DT_Items`.
    3.  **UI-прототипы (Программист/Тех. Художник):** С помощью **UMG** создать уродливые, но функциональные окна-плейсхолдеры:
        *   `WBP_PlayerInventory`: Окно инвентаря игрока.
        *   `WBP_Container`: Окно инвентаря для любого контейнера (Улей, Мультиферма).
*   **Результат:** Готова вся "бумажная" и интерфейсная основа. Можно добавлять геймплейные объекты.

#### **Недели 7-8: Прототип Полного Цикла**
*   **Задачи:**
    1.  **Мультиферма (Программист):**
        *   Создать актор `BP_Multifarm` (на базе Blueprint). Это простой куб, с которым можно взаимодействовать.
        *   У него есть свой инвентарь. Если в него положить "Семена Простого Растения", запускается таймер.
        *   По окончании таймера в его инвентаре появляется 1 "Еда".
    2.  **Архонид и Улей (Программист):**
        *   Создать актор `BP_Arkhonid_Proto`. Это просто сфера, которая медленно движется по земле. При взаимодействии (нажатии "Е") он исчезает и добавляется как предмет "Пойманный Архонид" в инвентарь игрока.
        *   Создать актор `BP_Hive`. Игрок может "использовать" предмет "Пойманный Архонид" на Улье, чтобы поместить его туда.
        *   Логика Улья: каждую секунду он проверяет: `ЕСЛИ` "внутри есть Архонид" `И` "в инвентаре есть 'Еда'", `ТО` запустить таймер.
        *   По окончании таймера: удалить 1 "Еду" из инвентаря и добавить 1 "Воск".
*   **Результат Майлстоуна 2:** Играбельная сборка, где игрок должен:
    1.  Найти и подобрать "семена" с земли.
    2.  Посадить их в Мультиферму.
    3.  Дождаться урожая и забрать "Еду".
    4.  Найти и поймать "Архонида".
    5.  Посадить его в Улей.
    6.  Перенести "Еду" из Мультифермы в Улей, чтобы получить "Воск".
    **Команда собственными руками проходит весь основной производственный цикл и может оценить его понятность.**

### **Майлстоун 3: Прототип Управляемого Риска и Финализация (Недели 9-12)**

**Цель:** Протестировать механику опасных мутаций и собрать все прототипы в единую сборку для финального обзора.

#### **Недели 9-10: Прототип "Хищной Лозы"**
*   **Задачи:**
    1.  **Логика Роста (Программист/Тех. Художник):**
        *   Создать актор `BP_PredatoryVine`.
        *   При его спавне (пока можно спавнить по нажатию debug-кнопки рядом с Мультифермой) он начинает "расти".
        *   Использовать `Spline Component`: каждые 1-2 секунды добавлять новую точку к сплайну в случайном направлении или в сторону ближайшего строения/игрока.
        *   Использовать `Spline Mesh Component`, чтобы отрисовать толстый "кабель" (простой цилиндр) вдоль сплайна. Это создаст эффект ползущей лозы.
    2.  **Логика Угрозы (Программист):**
        *   Использовать `PawnSensing` компонент или простую проверку дистанции. Если игрок подходит слишком близко к "голове" лозы, наносить ему урон (пока что можно просто выводить сообщение на экран: "ВАС АТАКОВАЛИ!").
        *   Если лоза "касается" другого строительного блока, она его "уничтожает" (удаляет актор).
    3.  **Логика Уничтожения (Программист):** Игрок может несколько раз "ударить" (нажать "Е") по лозе, чтобы уничтожить ее.
*   **Результат:** Возможность в любой момент превратить мирную ферму в поле боя с динамически растущей и разрушающей угрозой.

#### **Недели 11-12: Сборка, Тестирование и Ревью**
*   **Задачи:**
    1.  **Интеграция (Вся команда):** Собрать все три прототипа на одной тестовой карте. Убедиться, что они не конфликтуют друг с другом.
    2.  **Плейтест (Вся команда):** Несколько полных игровых сессий. Каждый член команды должен построить базу, запустить цикл производства и намеренно вызвать мутацию, чтобы пережить ее.
    3.  **Сбор Фидбэка (Вся команда):** Провести итоговое совещание по Фазе 0. Ответить на ключевые вопросы:
        *   **Строительство:** Достаточно ли оно гибкое? Чувствуется ли креативность? Что расстраивает больше всего?
        *   **Био-инженерия:** Понятен ли цикл? Увлекательно ли им заниматься на ручном уровне? Что можно улучшить для наглядности?
        *   **Риск:** Является ли "Лоза" интересным вызовом или несправедливым наказанием? Как можно дать игроку больше контроля/предупреждений?
    4.  **Документация и Планирование (Геймдизайнер/Программист):** Задокументировать все выводы. Составить список конкретных задач и улучшений, которые необходимо реализовать в **Фазе 1 (Вертикальный срез)**.
*   **Финальный Результат Фазы 0:** Не просто набор прототипов, а **подтвержденная и проверенная концепция игры**. Команда уверена в своих ключевых механиках и имеет четкий, основанный на реальном опыте план для следующего, более затратного этапа разработки.
