**Статус Эффекты (Горение, Заморозка, Замедление)** с использованием Gameplay Effects.

**Задача:** Создать `GameplayEffect` (GE) для представления различных статус-эффектов, таких как горение (DoT), заморозка (стан/неподвижность), замедление (снижение скорости) и т.д. Эти GE будут иметь конечную длительность и либо напрямую модифицировать атрибуты, либо предоставлять `GameplayTag`, на который могут реагировать другие системы.

**Зачем:** Добавить тактическую глубину в бой, позволяя игроку и врагам накладывать на цели временные ослабления, урон по времени или эффекты контроля.

**GAS Компоненты и Механизмы UE:** `UGameplayEffect`, `DurationPolicy`, `Period`, `Modifiers`, `GrantedTags`, `GameplayTag`, `ScalableFloat`.

---

**Подробная Реализация Шага:**

**Шаг 15.1: Определение Gameplay Tags для Статусов (в Редакторе)**

1.  **Откройте Unreal Editor -> Project Settings -> Gameplay Tags**.
2.  Создайте родительский тег `State`.
3.  Под ним создайте теги для каждого статус-эффекта, который вы хотите отслеживать с помощью тегов:
    *   `State.Debuff.Burning` (Для обозначения состояния горения)
    *   `State.Debuff.Frozen` (Для обозначения состояния заморозки - полная неподвижность)
    *   `State.Debuff.Chilled` (Для обозначения состояния охлаждения/замедления от холода)
    *   `State.Debuff.Slowed` (Общий тег замедления, если не от холода)
    *   `State.Debuff.Stunned` (Общий тег оглушения)
    *   `State.Debuff.Poisoned` (Если будет яд)
    *   `State.Buff.SpeedBoost` (Пример тега для баффа скорости)
    *   *(Добавьте другие по необходимости)*
4.  Создайте родительский тег `Damage` (если еще нет). Под ним `Damage.Type` (если еще нет). Под `Damage.Type` добавьте теги для типов урона DoT:
    *   `Damage.Type.Fire` (Уже должен быть)
    *   `Damage.Type.Poison` (Если будет яд)
5.  **Сохраните Project Settings.**

**Шаг 15.2: Создание Ассетов `GameplayEffect` для Статус-Эффектов (в Редакторе)**

Создадим GE для каждого эффекта в соответствующих папках (например, `Content/Features/Items/GAS/GameplayEffects/Status/Debuffs/` и `/Buffs/`).

**A. Горение (Burning - DoT и Состояние)**

1.  **Создайте GE:** ПКМ -> Blueprint Class -> Родитель: `GameplayEffect`. Имя: `GE_Status_Burning_DOT`.
2.  **Настройте `GE_Status_Burning_DOT`:**
    *   **Duration Policy:** `Has Duration`.
    *   **Duration Magnitude:** `Scalable Float`. Установите `Value` = длительность горения (например, `5.0` секунд).
    *   **Period:** `Scalable Float`. Установите `Value` = интервал нанесения урона (например, `0.5` секунды). Установите `Execute Periodic Effect On Application` = `true` (нанести урон сразу при применении).
    *   **Modifiers:** Нажмите `+`.
        *   **Attribute:** `BaseAttributeSet.Damage` (Мета-атрибут).
        *   **Modifier Op:** `Override`.
        *   **Magnitude Calculation Type:** `Scalable Float`.
        *   **Magnitude (Scalable Float):** Установите `Value` = урон за один "тик" (например, `4.0`).
    *   **Executions:** Нажмите `+` рядом с `Periodic Execution Calculations`.
        *   Выберите ваш `FrameForgeDamageExecCalculation`. Это гарантирует, что периодический урон будет учитывать сопротивления огню.
    *   **Granted Tags:** Нажмите `+` рядом с `Granted Tags` -> `Added`. Выберите тег `State.Debuff.Burning`. Пока этот эффект активен, цель будет иметь этот тег.
    *   **Asset Tags:** Добавьте `Status.Debuff.Burning`, `Damage.DOT`.
3.  **Сохраните `GE_Status_Burning_DOT`.**

**B. Заморозка (Frozen - Стан и Состояние)**

1.  **Создайте GE:** Имя: `GE_Status_Frozen_Stun`.
2.  **Настройте `GE_Status_Frozen_Stun`:**
    *   **Duration Policy:** `Has Duration`.
    *   **Duration Magnitude:** `Scalable Float`. `Value` = длительность заморозки (например, `3.0` секунды).
    *   **Period:** Оставьте `0.0`. Эффект не периодический.
    *   **Modifiers:** Оставьте пустым (мы не меняем атрибуты напрямую, используем тег).
    *   **Granted Tags:** Нажмите `+` -> `Added`. Выберите тег `State.Debuff.Frozen`.
    *   **Asset Tags:** Добавьте `Status.Debuff.Frozen`, `Status.Control.Stun`.
3.  **Сохраните `GE_Status_Frozen_Stun`.**
    *   *Примечание:* Другие системы (Анимация, AI, Способности) должны будут проверять наличие тега `State.Debuff.Frozen` или `State.Stunned` (если вы добавите и его) и блокировать действия/менять анимацию соответственно. Например, в `CanActivateAbility` можно добавить проверку `ActorInfo->AbilitySystemComponent->HasMatchingGameplayTag(FrozenTag)`. В AnimBP можно использовать `HasMatchingGameplayTag` для перехода в анимацию заморозки.

**C. Замедление (Slowed - Модификатор Атрибута и Состояние)**

1.  **Создайте GE:** Имя: `GE_Status_Slowed_Movement`.
2.  **Настройте `GE_Status_Slowed_Movement`:**
    *   **Duration Policy:** `Has Duration`.
    *   **Duration Magnitude:** `Scalable Float`. `Value` = длительность замедления (например, `4.0` секунды).
    *   **Modifiers:** Нажмите `+`.
        *   **Attribute:** `BaseAttributeSet.MovementSpeed`.
        *   **Modifier Op:** `Multiply` (Умножаем текущую скорость).
        *   **Magnitude Calculation Type:** `Scalable Float`.
        *   **Magnitude (Scalable Float):** Установите `Value` = множитель скорости. Например, `-0.5` для замедления на 50% (т.е. скорость станет `Base * (1 - 0.5)`). Или `0.75` для скорости 75% от базовой (если Multiply работает на базовое значение). *Тестируйте, как именно работает Multiply в вашей версии UE/GAS, возможно, лучше использовать `Add` с отрицательным значением или GEEC.* Для простоты используем `-0.5` как множитель, предполагая, что он применяется к текущей скорости (хотя это не всегда так в GAS по умолчанию). **Безопаснее использовать `Add` с отрицательным значением, рассчитанным от базовой скорости, если возможно.**
            *   *Альтернатива с Add:* Modifier Op: `Add`. Magnitude Calculation Type: `Attribute Based`. Attribute: `MovementSpeed`. Coefficient: `-0.5`. Это вычтет 50% от *текущего* значения MovementSpeed.
    *   **Granted Tags:** Нажмите `+` -> `Added`. Выберите тег `State.Debuff.Slowed` (или `State.Debuff.Chilled`, если замедление от холода).
    *   **Asset Tags:** Добавьте `Status.Debuff.Slowed`, `Status.Control.Movement`.
3.  **Сохраните `GE_Status_Slowed_Movement`.**

**D. Оглушение (Stunned - Состояние)**

1.  **Создайте GE:** Имя: `GE_Status_Stunned_Control`.
2.  **Настройте `GE_Status_Stunned_Control`:**
    *   **Duration Policy:** `Has Duration`.
    *   **Duration Magnitude:** `Scalable Float`. `Value` = длительность оглушения (например, `1.5` секунды).
    *   **Modifiers:** Оставьте пустым.
    *   **Granted Tags:** Нажмите `+` -> `Added`. Выберите тег `State.Debuff.Stunned`.
    *   **Asset Tags:** Добавьте `Status.Debuff.Stunned`, `Status.Control.Stun`.
3.  **Сохраните `GE_Status_Stunned_Control`.**
    *   *Примечание:* Как и с заморозкой, другие системы должны реагировать на тег `State.Debuff.Stunned`, блокируя способности, атаки, движение.

**Шаг 15.3: Применение Статус-Эффектов из Способностей/Оружия**

Теперь нужно обновить способности или GE урона, чтобы они применяли эти статус-эффекты.

**Вариант 1: Применение Статуса вместе с Уроном (в GE Урона)**

Этот подход подходит, если статус *всегда* накладывается при нанесении урона определенного типа (например, огненный урон всегда поджигает).

1.  **Откройте GE урона** (например, `GE_Damage_Weapon_SomeFireGun`).
2.  **Class Defaults:**
    *   **Conditional Gameplay Effects:** Найдите эту секцию. Нажмите `+`.
        *   **Effect Class:** Выберите GE статус-эффекта (например, `GE_Status_Burning_DOT`).
        *   **Required Source Tags:** Добавьте тег типа урона, который должен вызвать этот статус (например, `Damage.Type.Fire`).
        *   **Required Target Tags:** (Опционально) Теги, которые должны быть у цели для применения статуса (например, `State.Vulnerable.Fire`).
3.  **Сохраните GE урона.**
    *   *Недостаток:* Сложнее контролировать шанс наложения статуса или применять статус без урона.

**Вариант 2: Применение Статуса из Способности (в GA)**

Этот подход более гибкий, позволяет контролировать шанс и применять статус отдельно от урона.

1.  **Откройте Event Graph** способности, которая должна накладывать статус (например, `GA_Ability_FreezeBlast`).
2.  В месте, где определяется попадание по цели (после трассировки, оверлапа и т.д.):
    *   Получите `TargetASC` (Ability System Component цели).
    *   **(Опционально) Проверка Шанса:** Сгенерируйте `Random Float in Range` (0.0 - 1.0). Сравните с шансом наложения статуса (переменная, например, `FreezeChance = 0.75`). Если шанс не сработал, пропустите применение эффекта.
    *   **Создайте и Примените GE Статуса:**
        *   `Make Outgoing Gameplay Effect Spec`: `Gameplay Effect Class` = `GE_Status_Frozen_Stun`. `Level` = 1.
        *   `Assign Tag Set by Caller Magnitude`: (Опционально) Если длительность статуса зависит от чего-то (например, уровня способности), установите магнитуду здесь по тегу `Data.Duration`. В GE длительность должна быть `Set By Caller`.
        *   `Apply Gameplay Effect Spec to Target`: `Spec Handle` = (из Make Spec), `Target` = `TargetASC`.
3.  **Сохраните GA.**

**Вариант 3: Применение Статуса через Gameplay Cue (Косметический + Логика)**

Можно использовать Gameplay Cue не только для эффектов, но и для применения логики, включая GE.

1.  **Создайте Gameplay Cue Notify Actor/Static** (например, `GCN_Status_ApplyFreeze`).
2.  В этом GCN (например, в `OnExecute` или `OnActive`):
    *   Получите цель (`Parameters.TargetActor`).
    *   Получите `TargetASC`.
    *   Создайте и примените GE статуса (`GE_Status_Frozen_Stun`) к `TargetASC`.
3.  **В способности или GE урона:**
    *   Вместо прямого применения GE статуса, вызовите Gameplay Cue: `Execute Gameplay Cue on Actor` или добавьте тег `GameplayCue.Status.ApplyFreeze` к эффекту урона.

**Шаг 15.4: Настройка Реакции Систем на Теги Статусов**

Это выходит за рамки чисто GAS, но критически важно для работы статусов.

1.  **Анимация (`AnimBP`):**
    *   В Event Graph AnimBP получите `Owner Pawn` -> `Get Ability System Component`.
    *   Используйте ноду `Has Matching Gameplay Tag` для проверки тегов `State.Debuff.Frozen`, `State.Debuff.Stunned`, `State.Debuff.Burning`, `State.Debuff.Slowed`.
    *   Используйте результаты проверок для управления переменными стейт-машины (например, `bIsFrozen`, `bIsStunned`) или для прямого перехода в нужные состояния/проигрывания монтажей (анимация заморозки, стана, горения).
    *   Для замедления можно использовать значение атрибута `MovementSpeed` для управления скоростью анимации ходьбы/бега.
2.  **Способности (`GameplayAbility`):**
    *   В Class Defaults -> `Activation Blocked Tags` добавьте теги контроля (`State.Debuff.Frozen`, `State.Debuff.Stunned`), чтобы эти способности нельзя было использовать во время действия статуса.
    *   В Class Defaults -> `Cancel Abilities with Tag` можно добавить теги статусов, если начало нового статуса должно отменять текущие действия (например, заморозка отменяет атаку).
3.  **Искусственный Интеллект (`Behavior Tree`):**
    *   Создайте `BTDecorator_HasGameplayTag`.
    *   Используйте этот декоратор в Behavior Tree, чтобы проверять наличие тегов `State.Debuff.Frozen`, `State.Debuff.Stunned` у AI. Если тег есть, переходите в ветку "Ничего не делать" или "Проиграть анимацию стана".
4.  **Визуальные Эффекты (`GameplayCueNotify`):**
    *   Создайте GCN для каждого статуса (например, `GCN_Status_Burning_Loop`, `GCN_Status_Frozen_Effect`).
    *   В Class Defaults -> `Gameplay Cue Tag` укажите соответствующий тег состояния (`State.Debuff.Burning`, `State.Debuff.Frozen`).
    *   В логике GCN (`OnActive`, `WhileActive`, `OnRemoved`) спавните/уничтожайте партикл-системы (огонь на персонаже, ледяная корка), меняйте параметры материала (замороженный шейдер).

**Шаг 15.5: Компиляция и Тестирование**

1.  **Пересоберите C++ проект**, если вносили изменения.
2.  **Запустите игру.**
3.  **Тестирование:**
    *   **Применение:** Используйте способность/оружие, которое должно накладывать статус.
    *   **`showdebug abilitysystem`:** Проверьте цель:
        *   Появился ли соответствующий тег статуса (`State.Debuff...`)?
        *   Появился ли активный GE статуса (`GE_Status_...`) с правильной длительностью?
        *   Если статус меняет атрибут (замедление), изменилось ли значение атрибута (`MovementSpeed`)?
        *   Если статус наносит DoT (горение), уменьшается ли `Health` периодически?
    *   **Реакция Систем:**
        *   Проигрывается ли правильная анимация (стана, горения)?
        *   Блокируются ли способности/атаки/движение во время стана/заморозки?
        *   Замедляется ли персонаж/AI?
        *   Появляются ли визуальные эффекты статуса?
    *   **Окончание Эффекта:** Дождитесь окончания длительности статуса. Проверьте `showdebug abilitysystem` - тег и GE должны исчезнуть. Атрибуты должны вернуться к норме. Анимация/поведение должны нормализоваться.
