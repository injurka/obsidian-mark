## Фаза 1: [[Закладываем Фундамент GAS]]

1.  **Интеграция GAS:**
    *   **Задача:** Подключить модуль Gameplay Ability System к вашему проекту Unreal Engine.
    *   **Зачем:** Это базовый шаг, без которого ничего не будет работать.
    *   **GAS Компоненты:** Модуль в `Build.cs`.

2.  **Создание Базовых Классов (C++):**
    *   **Задача:** Создать базовые C++ классы для Персонажа (`AFrameForgeCharacter`), Контроллера Игрока (`AFrameForgePlayerController`), Состояния Игрока (`AFrameForgePlayerState`), и, возможно, GameMode (`AFrameForgeGameMode`) и GameState (`AFrameForgeGameState`).
    *   **Зачем:** Обеспечить надежную основу для блюпринтов и правильное владение/инициализацию GAS компонентов. Рекомендуется, чтобы `PlayerState` владел `AbilitySystemComponent` и `AttributeSet` для лучшей работы в мультиплеере.
    *   **GAS Компоненты:** Подготовка классов для добавления `AbilitySystemComponent` и `AttributeSet`.

3.  **Добавление Компонентов GAS:**
    *   **Задача:** Добавить `UAbilitySystemComponent` (ASC) и базовый `UAttributeSet` к вашим C++ классам (вероятно, `AFrameForgePlayerState` для ASC и Атрибутов). Реализовать интерфейс `IAbilitySystemInterface` на Персонаже (`AFrameForgeCharacter`), который будет возвращать ASC из `PlayerState`.
    *   **Зачем:** Дать вашему Шасси "мозг" GAS и базовые характеристики.
    *   **GAS Компоненты:** `AbilitySystemComponent`, `AttributeSet`, `IAbilitySystemInterface`.

4.  **Определение Базовых Атрибутов:**
    *   **Задача:** В вашем базовом `UAttributeSet` (C++) определить основные атрибуты, общие для всех Шасси (даже если их стартовые значения будут разными): `Health`, `MaxHealth`, `Armor`, `Energy`, `MaxEnergy`, `MovementSpeed`, `Stamina` (если будет), `AttackPower` (базовый), `CritChance` (базовый) и т.д. Реализовать логику `PreAttributeChange` / `PostGameplayEffectExecute` для зависимостей (например, зажим `Health` между 0 и `MaxHealth`).
    *   **Зачем:** Создать числовые характеристики Шасси, на которые будут влиять способности, предметы и урон.
    *   **GAS Компоненты:** `AttributeSet` (с `FGameplayAttributeData`), макросы `ATTRIBUTE_ACCESSORS`.

5.  **Настройка Репликации:**
    *   **Задача:** Убедиться, что `AttributeSet` и `AbilitySystemComponent` правильно настроены для репликации (в C++). У `PlayerState` это обычно происходит автоматически при правильной настройке.
    *   **Зачем:** Основа для работы в мультиплеере.
    *   **GAS Компоненты:** Настройки репликации для ASC и Атрибутов.

##  Фаза 2: [[Базовая Функциональность Шасси]]

6.  **Инициализация GAS и Атрибутов:**
    *   **Задача:** Реализовать логику инициализации GAS на сервере (например, в `PossessedBy` контроллера или при спавне персонажа) и на клиенте (`OnRep_PlayerState` контроллера). Применить базовые `GameplayEffect` для установки начальных значений атрибутов в зависимости от выбранного Шасси (например, `GE_Chassis_Typhon_Stats`).
    *   **Зачем:** Убедиться, что каждый игрок стартует с правильными характеристиками для своего Шасси.
    *   **GAS Компоненты:** `AbilitySystemComponent::InitAbilityActorInfo`, `GameplayEffect`.

7.  **Привязка Ввода (Input Binding):**
    *   **Задача:** Настроить Unreal Enhanced Input. Создать `InputAction` для основных действий (Move, Look, Jump, Interact, Fire, Ability1, Ability2, Utility, MovementAbility) и `InputMappingContext`. В блюпринте Персонажа или Контроллера привязать эти `InputAction` к функциям `AbilitySystemComponent::AbilityLocalInputPressed/Released`, используя перечисление (Enum) `EAbilityInputID` для идентификации.
    *   **Зачем:** Связать нажатия кнопок игроком с активацией способностей в GAS.
    *   **GAS Компоненты:** `AbilitySystemComponent::AbilityLocalInputPressed/Released`, `EAbilityInputID` (нужно создать).

8.  **Базовые Способности Шасси (не от модулей):**
    *   **Задача:** Создать базовые `GameplayAbility` (GA) для действий, доступных всегда:
        *   `GA_Character_Jump`: Способность прыжка (если не используется стандартная логика `ACharacter`).
        *   `GA_Character_Interact`: Способность для взаимодействия с миром (сундуки, станции). Активируется по `InputID_Interact`.
        *   `GA_Chassis_BaseAttack_[Type]`: Слабые базовые атаки для каждого Шасси (активируются по `InputID_Fire`, если не экипировано оружие).
    *   **Задача:** Предоставить (Grant) эти способности Шасси при инициализации.
    *   **Зачем:** Обеспечить базовую интерактивность и функциональность персонажа до нахождения модулей.
    *   **GAS Компоненты:** `GameplayAbility`, `AbilitySystemComponent::TryActivateAbilityByClass/Handle`, `GrantAbility`.

##  Фаза 3: [[Реализация Модульной Системы через GAS]]

9.  **Система Выдачи Способностей Предметами:**
    *   **Задача:** Разработать механизм, при котором подбор или экипировка Предмета (Модуля, Оружия, Компонента) вызывает выдачу (Grant) соответствующей `GameplayAbility` или `GameplayEffect` (пассивного) персонажу. При снятии предмета — способность/эффект удаляются (`ClearAbility`, `RemoveActiveGameplayEffect`). Это можно реализовать через компонент инвентаря или систему слотов Шасси.
    *   **Зачем:** Ключевая механика игры — способности приходят от предметов.
    *   **GAS Компоненты:** `GrantAbility`, `ClearAbility`, `ApplyGameplayEffectToSelf`, `RemoveActiveGameplayEffectWithGrantedTags`, `GameplayTag` (для идентификации эффектов/способностей от конкретных предметов).

10. **Реализация Пассивных Компонентов:**
    *   **Задача:** Создать `GameplayEffect` для каждого пассивного компонента из GDD (Титановая Обшивка, Сервоприводы и т.д.). Эти GE должны модифицировать атрибуты (`Add`, `Multiply`, `Override`) или предоставлять теги. Они выдаются персонажу при экипировке компонента и имеют бесконечную длительность (`DurationPolicy = Infinite`), но удаляются при снятии.
    *   **Зачем:** Реализовать систему пассивных улучшений от компонентов.
    *   **GAS Компоненты:** `GameplayEffect` (Modifiers, GrantedTags, DurationPolicy).

11. **Реализация Модулей Активных Способностей:**
    *   **Задача:** Для каждого активного модуля (Репульсор, Фазовый Сдвиг и т.д.) создать свою `GameplayAbility`. Каждая GA будет привязана к своему `EAbilityInputID` (Ability1, Ability2, Utility). GA должна содержать логику способности (применение эффектов, спавн акторов), стоимость (Cost GE), кулдаун (Cooldown GE). Способность выдается при экипировке модуля.
    *   **Зачем:** Реализовать активные умения, получаемые "на лету".
    *   **GAS Компоненты:** `GameplayAbility` (с `InputID`), `CommitAbility`, `ApplyGameplayEffectToOwner/Target`, `GameplayEffect` (Cost, Cooldown).

12. **Реализация Модулей Передвижения:**
    *   **Задача:** Аналогично активным модулям, создать `GameplayAbility` для каждого модуля передвижения (Крюк-Кошка, Ранец, Лазание, Подкат). Привязать их к `InputID_MovementAbility` или специфическим кнопкам (как Прыжок). Реализовать логику передвижения внутри GA или через вызов функций `MovementComponent`. Способность выдается при экипировке модуля.
    *   **Зачем:** Сделать продвинутое передвижение наградой за исследование, как указано в GDD.
    *   **GAS Компоненты:** `GameplayAbility` (с `InputID`), взаимодействие с `CharacterMovementComponent`.

13. **Реализация Оружейных Систем:**
    *   **Задача:** Для каждой Оружейной Системы создать свою `GameplayAbility` (например, `GA_Weapon_Fire_Razor`, `GA_Weapon_Fire_Wave`). Эта GA будет основной атакой, активируемой по `InputID_Fire`. Она заменит базовую атаку Шасси. Логика GA будет включать проверку патронов/перегрева, создание снаряда или выполнение HitScan, применение урона (через GE), применение Cooldown (скорострельность). Способность выдается при экипировке оружия.
    *   **Задача:** Создать GE для урона каждого оружия.
    *   **Задача:** Реализовать Модификаторы Оружия как пассивные `GameplayEffect`, которые выдаются вместе с GA оружия (или применяются к владельцу при наличии модификатора) и изменяют поведение GA/GE оружия (например, добавляя тег "Ricochet" для проверки в GA, или применяя дополнительный GE_Damage_Burn).
    *   **Зачем:** Реализовать сменное основное оружие и его модификацию.
    *   **GAS Компоненты:** `GameplayAbility` (с `InputID_Fire`), `GameplayEffect` (Damage, Cooldown, Modifiers), `GameplayTag`.

##  Фаза 4: [[Урон, Статусы и Взаимодействие]]

14. **Система Урона и Типов Урона:**
    *   **Задача:** Определить GE для различных типов урона (Physical, Energy, Fire, Cold и т.д.). Использовать `GameplayTag` для представления типов урона. Модифицировать базовый `AttributeSet` для реагирования на разные типы урона (например, через `PostGameplayEffectExecute` или Gameplay Effect Execution Calculation), учитывая броню/сопротивления.
    *   **Зачем:** Гибкая система расчета урона.
    *   **GAS Компоненты:** `GameplayEffect`, `GameplayTag`, `AttributeSet::PostGameplayEffectExecute`, `GameplayEffectExecutionCalculation` (опционально).

15. **Статус Эффекты (Горение, Заморозка, Замедление):**
    *   **Задача:** Реализовать статус-эффекты с помощью `GameplayEffect` с конечной длительностью (`DurationPolicy = Has Duration`). Эффекты могут напрямую менять атрибуты (скорость) или применять `GameplayTag` (Stunned, Burning, Frozen). Другие системы (анимация, AI) могут реагировать на наличие этих тегов.
    *   **Зачем:** Добавить глубину в бой через контроль и DoT.
    *   **GAS Компоненты:** `GameplayEffect` (Duration, Period, Modifiers, GrantedTags), `GameplayTag`.

16. **Интеграция с Анимацией:**
    *   **Задача:** Связать GAS с Animation Blueprint. Использовать `GameplayTag` для запуска анимационных монтажей (`PlayMontageAndWait` в GA). Использовать `AnimNotify` для отправки `GameplayEvent` обратно в GAS (например, для момента нанесения урона в ближнем бою). Реагировать на изменение атрибутов (скорость) и наличие тегов (заморозка) в AnimBP.
    *   **Зачем:** Визуальное представление способностей и состояний.
    *   **GAS Компоненты:** `GameplayTag`, `AbilityTask_PlayMontageAndWait`, `SendGameplayEventToActor`, `AnimNotifyState`.

##  Фаза 5: [[Полировка и Дополнительные Системы]]

17. **Gameplay Cues (Визуальные и Звуковые Эффекты):**
    *   **Задача:** Создать `GameplayCueNotify_Actor` и `GameplayCueNotify_Static` для воспроизведения VFX и SFX в ответ на события GAS (применение GE, активация способности, получение урона). Привязать их к соответствующим `GameplayTag` (`GameplayCue.Damage.Physical`, `GameplayCue.Ability.Repulsor.Activate`).
    *   **Зачем:** Сделать способности и эффекты "живыми" и понятными.
    *   **GAS Компоненты:** `GameplayCueManager`, `GameplayCueNotify_Actor/Static`, `GameplayTag` (с префиксом `GameplayCue.`).

18. **Система Эволюции/Комбинации (Обновление Способностей):**
    *   **Задача:** При Эволюции/Комбинации предмета система должна корректно удалить старые способности/эффекты, связанные с исходными предметами, и выдать новые способности/эффекты от созданного предмета. Использовать `GameplayTag` для идентификации, что удалять.
    *   **Зачем:** Реализовать ядро прогрессивной системы предметов.
    *   **GAS Компоненты:** `ClearAbility`, `RemoveActiveGameplayEffectWithGrantedTags`, `GrantAbility`, `ApplyGameplayEffectToSelf`, `GameplayTag`.

19. **UI Интеграция:**
    *   **Задача:** Связать элементы UI (полосы здоровья/энергии, иконки способностей) с данными из GAS. Использовать `AbilitySystemComponent::GetGameplayAttributeValueChangeDelegate` для обновления полос здоровья/энергии. Получать информацию о кулдаунах и зарядах способностей из ASC для отображения на иконках. Отображать иконки активных пассивных эффектов/баффов/дебаффов, читая теги/эффекты на ASC.
    *   **Зачем:** Отображение состояния персонажа и готовности способностей игроку.
    *   **GAS Компоненты:** `AbilitySystemComponent` (получение атрибутов, делегаты, информация о способностях).

20. **Мультиплеерные Аспекты (Revive):**
    *   **Задача:** Реализовать механику "Тяжело Ранен" (DBNO) и воскрешения. Создать GE, который применяется при `Health <= 0`, дает тег `State.Dead` или `State.DBNO` и, возможно, запускает таймер "bleedout". Создать `GA_Character_Revive`, которая может быть активирована союзником на персонаже с тегом `State.DBNO`.
    *   **Зачем:** Реализация ключевой кооперативной механики.
    *   **GAS Компоненты:** `GameplayEffect`, `GameplayTag`, `GameplayAbility`.

## [[Важные примечания]]:

*   **Итеративность:** Этот roadmap — не жесткий план. Будьте готовы возвращаться к предыдущим шагам, рефакторить и изменять решения по мере разработки и тестирования.
*   **Теги, Теги, Теги:** Активно используйте `GameplayTag` для всего: идентификации способностей, эффектов, состояний, типов урона, кулдаунов, событий. Это сделает систему гибкой и расширяемой.
*   **Баланс:** Балансировка (урон, кулдауны, стоимость, характеристики) будет происходить на протяжении всей разработки, в основном через настройку `GameplayEffect` и данных способностей.
*   **Чистота:** Старайтесь держать логику способностей внутри `GameplayAbility`, а изменение атрибутов и применение тегов — внутри `GameplayEffect`. Избегайте прямой модификации атрибутов вне GAS.
