# Zero Runtime CSS

## Суть концепции
Zero-Runtime CSS-in-JS — это архитектурный подход к стилизации, объединяющий Developer Experience (удобство разработки) из мира CSS-in-JS и производительность статического CSS. Вы пишете стили внутри JavaScript (TypeScript) рядом с компонентом, но во время сборки (build-time) специальный плагин (Babel, Vite, Webpack) анализирует ваш код, вырезает все стили, генерирует уникальные хэши классов и сохраняет их в обычный `.css` файл.

В браузере (runtime) не выполняется никакого JavaScript-кода для работы со стилями. Браузер просто скачивает статический CSS, как если бы вы писали его руками.

Популярные инструменты: **Vanilla Extract**, **Panda CSS**, **Linaria**, **Kuma UI**.

## Какую боль мы решаем
Библиотеки первого поколения (Emotion, Styled Components) работают в рантайме. При каждом рендере компонента они: парсят строку стилей, высчитывают хэш, проверяют, есть ли он в DOM, и если нет — вставляют `<style>`. В сложных приложениях это съедает огромную долю CPU, вызывая фризы. 
Вторая боль — **React Server Components (RSC)**. Серверные компоненты не имеют состояния (Context) и не могут использовать хуки, поэтому Runtime CSS-in-JS в них просто ломается. Zero-Runtime решает обе проблемы.

## Как это работает

```mermaid

    A[JSX File with Styles] --> B[Build Process (Webpack/Vite)]

    C --> E[Clean JS: <div class='hash-123'>]

    E --> F
```

## Примеры кода (на примере Panda CSS)

**❌ Антипаттерн: Полная динамика в Runtime**
```jsx
// Так можно было в Emotion, но в Zero-Runtime это вызовет ошибку билда,
// так как `Math.random()` неизвестен во время компиляции.
const boxStyle = css`
  width: ${Math.random() * 100}px;
`;
```

**✅ Правильное решение: Zero-Runtime (Panda CSS)**
```tsx
import { css } from '../styled-system/css';

// Этот код будет проанализирован при сборке.
// Строка 'red.500' будет найдена AST-парсером и превратится в статический CSS-класс.
const Box = () => (
  <div className={css({ 
    bg: 'red.500', 
    padding: '4', 
    borderRadius: 'md',
    _hover: { bg: 'red.600' }
  })}>
    Hello
  </div>
);

// Если нужна рантайм-динамика, используются инлайн-переменные:
// <div style={{ '--dynamic-width': width }} className={css({ width: 'var(--dynamic-width)' })} />
```

## Неочевидные нюансы и границы применимости
- **Сложность настройки:** Главный минус подхода. Вам всегда нужен сборщик. Вы не можете просто подключить библиотеку через `<script>`-тег. Если у вас монорепозиторий со сложной архитектурой (Storybook, Jest, Next.js), настроить плагины экстракции для всех сред бывает очень больно.
- **Статический анализ кода:** Экстракторы работают, анализируя AST (Абстрактное синтаксическое дерево) вашего кода. Если вы попытаетесь вычислять стили сложными динамическими функциями, парсер не сможет понять, какой CSS нужно сгенерировать, и выдаст ошибку.
- **Tailwind как альтернатива:** Технически, Tailwind CSS с его JIT-компилятором тоже является формой Zero-Runtime (он сканирует HTML/JS и генерирует статический CSS при билде), но использует синтаксис классов в разметке, а не JS-объекты.
