# Cascade Layers (Каскадные слои)

## Суть концепции
Cascade Layers (`@layer`) — это нативная функция CSS, которая позволяет разработчикам явно определять **слои приоритета** для стилей. Она меняет фундаментальное правило CSS: теперь приоритет зависит не от того, насколько "тяжелый" селектор (Specificty) или в каком порядке подключены файлы, а от того, в каком **слое** находится правило.

## Какую боль мы решаем
До появления слоев мы были заложниками специфичности. Если вы подключили стороннюю UI-библиотеку (например, Bootstrap), и там написано `#app .btn { background: blue; }`, вы не могли переопределить это простым классом `.my-btn { background: red; }`, потому что ID (`#app`) весит больше. Приходилось либо писать еще более безумные селекторы (`#app body .my-btn`), либо использовать `!important`.
Слои решают эту проблему раз и навсегда.

## Как это работает

```mermaid
graph TD
    A[CSS Layers Declaration Order]
    A --> B(@layer reset;)
    A --> C(@layer bootstrap;)
    A --> D(@layer components;)
    A --> E(@layer utilities;)
    A --> F(Unlayered Styles - Без слоя)
    
    style F fill:#f8d7da,stroke:#dc3545
    
    B -.->|Lowest Priority| C
    C -.-> D
    D -.-> E
    E -.->|Highest Layer Priority| F
```
Порядок объявления слоев задает их приоритет. Тот слой, что объявлен позже — сильнее.

## Примеры кода

**❌ Антипаттерн: Война специфичности (До `@layer`)**
```css
/* Сторонняя библиотека */
#sidebar .nav-link.active { color: blue; }

/* Наш кастомный стиль (не сработает, вес меньше) */
.text-red { color: red; }

/* Приходится делать хак */
.text-red { color: red !important; }
```

**✅ Правильное решение: Cascade Layers**
```css
/* 1. Декларируем порядок слоев (от слабых к сильным) */
@layer framework, custom-utilities;

/* 2. Загружаем библиотеку в слабый слой */
@layer framework {
  #sidebar .nav-link.active { color: blue; } /* Специфичность огромная, но слой слабый */
}

/* 3. Пишем свой код в сильный слой */
@layer custom-utilities {
  .text-red { color: red; } /* Специфичность минимальная, но слой сильный. ОН ПОБЕДИТ! */
}
```

## Неочевидные нюансы и границы применимости
- **Стили без слоев (Unlayered Styles) всегда побеждают:** Если вы написали стили вне всяких `@layer`, они будут иметь максимальный приоритет над любыми слоями. Это сделано специально для обратной совместимости старого кода.
- **!important инвертирует слои:** Это самое взрывоопасное поведение. Если использовать `!important` внутри слоев, приоритет слоев разворачивается задом наперед. `!important` в *самом слабом* слое (например, `reset`) победит `!important` в *самом сильном* слое.
- **Вложенность слоев:** Слои можно вкладывать друг в друга: `@layer framework.bootstrap { ... }`.
- Поддержка браузерами отличная (с начала 2022 года).
