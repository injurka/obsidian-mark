Антикоррупционный слой (Anti Corruption Layer, ACL) — это глухой оборонительный барьер между вашим кристально чистым фронтендом и "грязным" внешним миром: унаследованным (legacy) бэкендом, сторонними кривыми API или просто сервисами с чужеродной архитектурой.

**Какую боль мы решаем?**
Часто бэкенд возвращает структуры данных, которые очень удобны для реляционной базы данных, но просто ужасны для использования в UI. Если пропустить этот сырой JSON напрямую в React-компоненты, "коррупция" мгновенно распространится по всему фронтенду. Ваши компоненты обрастут проверками `if (data.usr_flg_actv === 'Y')`, а при любом изменении схемы API всё приложение рухнет как карточный домик.

ACL перехватывает чужие данные на границе инфраструктуры и бережно переводит их в термины вашего [[Ubiquitous Language]].

**История из жизни:**
Бэкенд-монолит из 2010-х присылает спагетти:
```json
{
  "u_id": 105,
  "f_nm": "John",
  "l_nm": "Doe",
  "d_bth": "1990-01-01T00:00:00Z"
}
```

**ACL в действии (часто живет внутри [[Repository]]):**
```typescript
// Этот маппер — наш щит от плохого дизайна бэкенда
function userAntiCorruptionMapper(dto: LegacyUserDto): User {
  return new User({
    id: dto.u_id.toString(),
    fullName: `${dto.f_nm} ${dto.l_nm}`,
    // Конвертируем дату в удобный для домена формат
    age: calculateAge(new Date(dto.d_bth)) 
  });
}
```

**Трейдоффы и границы применимости:**
ACL требует написания огромного количества мапперов-переводчиков. Это рутинный, скучный и объемный код. Каждое добавление нового поля требует обновления DTO, изменения маппера и расширения доменной модели. 

Это оправдано только тогда, когда внешний API действительно далек от идеала, или когда вы находитесь в мучительном процессе переезда со старого бэкенда на новый. Если же ваш бэкенд разрабатывается той же командой (Fullstack), гораздо дешевле и эффективнее договориться о контрактах (например, использовать паттерн BFF - Backend For Frontend) и избежать написания громоздкого ACL вовсе.
