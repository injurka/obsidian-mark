Мы часто сталкиваемся с тем, что разработчики, менеджеры и бизнес говорят на разных языках. Менеджер просит "заблокировать недобросовестного клиента", а разработчик пишет в коде `state.users.find(u => u.id === id).status = 2`. Через полгода никто не помнит, что значит `status = 2` и почему оно вообще меняется именно так. 

Единый язык (Ubiquitous Language) — это договоренность о том, что термины, которые использует бизнес, один в один отражаются в коде. Это не просто словарик терминов в Confluence, это буквально имена классов, переменных и методов. Повествование в коде должно читаться как рассказ о бизнес-процессе.

**Пример антипаттерна:**
```typescript
function updateUser(user: User, data: any) {
  // Что мы делаем? Меняем email? Блокируем? Даем админку?
  // Техническое описание вместо бизнес-намерения
  user.data = { ...user.data, ...data };
}
```

**Как надо:**
```typescript
class Client {
  // Название метода четко отражает бизнес-намерение
  banForPolicyViolation(reason: string) {
    this.status = ClientStatus.Banned;
    this.banReason = reason;
  }
}
```

Единый язык позволяет читать код как бизнес-требования. Но у него есть граница применимости — он ограничен рамками конкретного [[Bounded Context]]. Одно и то же слово "Заказ" для отдела продаж и для отдела логистики означает совершенно разные вещи и обладает разным набором полей. Попытка создать универсальный глоссарий для всей компании приведет к созданию неповоротливых монстров-сущностей с сотнями свойств. Стройте язык вокруг конкретной решаемой задачи, а не пытайтесь охватить весь мир.
