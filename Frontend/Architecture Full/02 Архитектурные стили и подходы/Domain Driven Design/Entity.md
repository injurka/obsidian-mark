Сущность (Entity) — это центральный строительный блок доменной модели, чья индивидуальность (идентичность) фундаментально важнее его атрибутов. Если человек меняет имя или фамилию, он всё равно остается тем же самым человеком. Мы отличаем одну сущность от другой исключительно по её уникальному идентификатору (ID).

В мире фронтенда большинство сложных объектов — пользователи, оформленные заказы, задачи в канбан-доске — являются сущностями.

**Почему концепция идентичности так важна на фронтенде?**
В современных UI-фреймворках (React, Vue) мы часто работаем с иммутабельностью. При обновлении данных мы создаем новые объекты-копии. Если мы будем сравнивать сложные объекты просто по ссылкам (`objA === objB`) или по глубокому равенству всех полей, мы потеряем логическую связь. Понимание Entity заставляет нас явно управлять идентификаторами и использовать именно их для поиска и обновления данных в сторе.

**Пример из жизни:**
```typescript
class User {
  constructor(
    public readonly id: string, // Идентификатор — фундамент сущности
    private name: string,
    private status: UserStatus
  ) {}

  activate() {
    this.status = UserStatus.Active;
  }

  // Бизнес-логика сравнения всегда опирается на ID
  equals(other: User): boolean {
    return this.id === other.id;
  }
}
```

В отличие от [[Value Object]], сущности имеют длительный жизненный цикл: они создаются, переживают множество трансформаций и мутаций своего состояния (или возвращают новую копию с тем же ID), и со временем могут быть удалены. Относитесь к сущностям как к главным актерам вашей бизнес-истории.
