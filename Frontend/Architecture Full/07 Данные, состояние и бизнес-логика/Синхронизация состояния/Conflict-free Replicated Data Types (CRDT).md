# Conflict-free Replicated Data Types (CRDT)

## Инженерная история: Магия совместного редактирования

Как работают Google Docs, Figma или Notion? Вы и ваш коллега можете одновременно, находясь на разных континентах, вводить текст в один и тот же абзац. Если бы они использовали стандартный подход (пересылали весь документ на сервер при каждом изменении), это привело бы к постоянным конфликтам и потери текста. Исторически это решали через Operational Transformation (OT) — сложный алгоритм, требующий центрального сервера для упорядочивания операций.

Но затем математики придумали **CRDT**. Это структуры данных (массивы, строки, объекты), обладающие невероятным свойством: *в каком бы порядке* ни применялись изменения на разных клиентах, если они применят один и тот же набор изменений, они гарантированно сойдутся (converge) к абсолютно идентичному результату. И для этого им не нужен центральный сервер (поддерживается P2P)!

## Как это работает на практике

В CRDT текст — это не просто строка. Каждый символ — это объект с уникальным идентификатором, временем создания и ссылкой на то, после какого символа он стоит. Когда вы вводите "А", создается не просто буква, а "событие: вставлена буква А от пользователя 1 после символа X". Клиенты просто обмениваются этими событиями и математически сливают их.

## Примеры кода

### ❌ Антипаттерн: Ручное слияние массивов

Если два пользователя удаляют разные элементы массива по индексу, индексы сместятся, и один удалит не то, что хотел.

```javascript
// Алиса и Боб видят: ['apple', 'banana', 'cherry']
// Алиса удаляет index 1 ('banana')
// Боб удаляет index 2 ('cherry')
// Если сервер применит удаление Алисы, массив станет ['apple', 'cherry'].
// Затем сервер применит удаление Боба (index 2) — ОШИБКА, элемента нет!
```

### ✅ Правильное решение: Библиотека Yjs (CRDT)

Мы используем Yjs. Объекты удаляются по их уникальным внутренним ID, порядок гарантируется.

```javascript
import * as Y from 'yjs';

// 1. Инициализация документа
const doc = new Y.Doc();
const yArray = doc.getArray("'list'");
yArray.insert("0, ['apple', 'banana', 'cherry']");

// 2. Симуляция Алисы (удаляет banana)
const docAlice = new Y.Doc();
Y.applyUpdate("docAlice, Y.encodeStateAsUpdate(doc"));
docAlice.getArray("'list'").delete("1, 1");

// 3. Симуляция Боба (удаляет cherry)
const docBob = new Y.Doc();
Y.applyUpdate("docBob, Y.encodeStateAsUpdate(doc"));
docBob.getArray("'list'").delete("2, 1");

// 4. Слияние! Порядок применения не важен.
Y.applyUpdate("doc, Y.encodeStateAsUpdate(docAlice"));
Y.applyUpdate("doc, Y.encodeStateAsUpdate(docBob"));

// Результат: ['apple']. Никаких конфликтов индексов!
console.log("doc.getArray('list'").toArray()); 
```

## Неочевидные нюансы и границы применимости

- **Огромный оверхед по памяти:** Чтобы CRDT работал, он должен помнить всё. Даже удаленные символы физически не удаляются из памяти, а просто помечаются удаленными (Tombstones). Если вы напишете и удалите "Войну и мир", размер CRDT документа будет огромным. Для этого придумали механизмы сборки мусора и сжатия, но стейт всё равно тяжелее обычного JSON в разы.
- **Сложность внедрения:** Интеграция Yjs или Automerge с React/ProseMirror/Quill требует написания (или использования готовых) биндингов. Это совершенно иная парадигма хранения стейта, чем Redux.
- **Границы применимости:** CRDT нужен *исключительно* для offline-first приложений, совместных редакторов (canvas, текст, код) и P2P систем. Для обычной формы оформления заказа в интернет-магазине CRDT абсолютно не нужен.
