# Metrics (Метрики)

## Что это и какую боль мы решаем?
Метрики — это числовые показатели состояния системы с привязкой ко времени (Time-Series Data). 
**Боль:** Логи и ошибки — это события. Их много, они тяжелые. Если вы хотите понять "Сколько в среднем загружается страница?" или "Какой процент API запросов падает с 500?", агрегировать миллионы логов будет слишком медленно и дорого. Метрики решают эту боль: они компактны, быстро агрегируются и идеально подходят для построения дашбордов и алертинга.

## Как это работает

Метрики бывают трех основных типов:
1. **Counters (Счетчики):** Только растут. (Например, количество загрузок страницы, количество кликов по кнопке).
2. **Gauges (Уровни):** Могут идти вверх и вниз. (Например, размер кэша в MB).
3. **Histograms (Гистограммы / Дистрибуции):** Используются для измерения длительности и перцентилей. (Например, время ответа API: p50, p95, p99).

## Примеры реализации на фронтенде

Чаще всего на фронтенде собирают бизнес-метрики (Performance метрики выделены в Web Vitals) и метрики надежности (Reliability).

**Антипаттерн:** Использование средних значений (Averages) для измерения времени. Среднее значение скроет выбросы: если у 9 пользователей страница грузится 1 секунду, а у одного — 20 секунд, среднее будет 2.9с. Все вроде хорошо, но один пользователь страдает.

**Правильное решение:** Использование гистограмм и перцентилей (p90, p95, p99).

```typescript
// ✅ ПРАВИЛЬНО: Запись длительности в виде гистограммы
import { measureDuration } from '@/lib/metrics';

async function fetchProducts() {
  const stopTimer = measureDuration('api.products.latency', { region: 'eu-west-1' });
  try {
    const res = await api.get('/products');
    return res;
  } finally {
    stopTimer(); // Отправит длительность для расчета p95 в дашборде
  }
}
```

## Неочевидные нюансы и границы применимости
- **Кардинальность (High Cardinality):** В метриках используются "теги" (или лейблы). Например, `region="eu"`. Если вы добавите тег с бесконечным количеством уникальных значений (например, `user_id` или `url` с параметрами), Time-Series база данных ляжет от переполнения индексов. Метрики — это агрегированные данные, в них не должно быть уникальных идентификаторов.
- **Оверхед отправки:** Аналогично логам, метрики нельзя отправлять по одной. Они должны накапливаться в памяти и отправляться пакетами раз в 10-30 секунд.
- **Ограниченность контекста:** Увидев на графике, что p95 `api.latency` выросло, вы не сможете из графика понять *почему*. Метрики показывают "Что сломалось", а для ответа "Почему сломалось" нужны Логи и Трейсы (Tracing).
