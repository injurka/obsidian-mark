# Статический хостинг (Static Hosting)

Не каждому приложению нужен мощный сервер. Если ваш проект — это React/Vue SPA или собранный Gatsby/Astro сайт, результатом сборки являются просто файлы: `index.html`, `.js`, `.css` и картинки.

Боль: запускать для таких файлов целый Docker-контейнер с Nginx или Node.js — это пустая трата денег и усложнение архитектуры. Статический хостинг (Amazon S3, GitHub Pages, Netlify) позволяет просто "положить файлы в корзину" и раздавать их миру.

```mermaid
graph LR
    User[Пользователь] --> CDN[CDN / Edge]
    CDN -->|Запрос файла| Bucket[(S3 Bucket / Object Storage)]
    Bucket -.->|HTML/JS/CSS| CDN
```

**Неочевидные нюансы:**
- **Роутинг SPA:** На статическом хостинге нет сервера, который обработает запрос к `/dashboard`. Вы должны настроить хостинг так, чтобы все 404 ошибки перенаправлялись на `index.html` (Rewrite rules), чтобы React Router сам разобрался с URL.
- **Безопасность:** В статике невозможно скрыть ключи API. Всё, что вы положите в статику, будет доступно в браузере пользователя.

**Антипаттерн:**
Арендовать VPS (Droplet), ставить туда Ubuntu, Nginx, настраивать SSL сертификаты через Certbot только для того, чтобы показать лендинг.

**Правильное решение:**
Использовать готовые платформы вроде Vercel/Netlify, которые заберут код из GitHub, соберут его и бесплатно раскидают статику по своим глобальным CDN.
