# Внутреннее устройство сборщиков (Webpack, Vite, Rollup)

Сборщики (Bundlers) решают задачу превращения сотен изолированных файлов с кодом (JS, TS, CSS, изображения) в оптимизированный набор файлов, пригодных для быстрой загрузки и выполнения в браузере. Подходы к сборке у Webpack, Rollup и Vite принципиально различаются.

---

## 1. Webpack: Статический сборщик графа зависимостей

Webpack — классический индустриальный стандарт. Он рассматривает любой ресурс (не только JS, но и CSS, картинки, шрифты) как модуль.

```text
Webpack Build:
[Entry File] ──► 1. Resolution ──► 2. Loaders (TS -> JS) ──► 3. AST (Парсинг) ──► 4. Dependency Graph ──► 5. Plugins ──► [Bundle]
```

### Этапы работы Webpack:
1.  **Resolution (Разрешение):** Webpack начинает с входных точек (`entry`) и определяет физические пути к импортируемым файлам.
2.  **Loaders (Загрузчики):** Нативно Webpack понимает только JS и JSON. Для обработки других файлов используются лоадеры (`ts-loader`, `css-loader`, `file-loader`). Они последовательно трансформируют исходные файлы в валидный JavaScript-код.
3.  **AST и графы зависимостей:** Webpack парсит полученный JS-код в абстрактное синтаксическое дерево (AST) для поиска директив `import`, `export` и `require`. На основе найденных связей строится единый **граф зависимостей (Dependency Graph)**.
4.  **Plugins (Плагины):** После построения графа плагины вмешиваются в процесс оптимизации. Они выполняют минимизацию кода (Terser), разделение на чанки (Code Splitting), инъекцию переменных и генерацию HTML.
5.  **Output (Вывод):** Генерация готовых чанков и запись файлов на диск.

---

## 2. Rollup: Чистый ESM Сборщик для библиотек

Rollup создавался с упором на поддержку стандарта **ES Modules (ESM)**. Он ориентирован на создание максимально чистых и легковесных бандлов (идеально для библиотек).

### Ключевые фичи Rollup:
*   **Tree Shaking под капотом:** Поскольку ESM статичен (импорты нельзя делать динамически на основе условий, в отличие от CommonJS `require`), Rollup анализирует граф импортов/экспортов на этапе сборки и полностью удаляет неиспользуемый код (мертвый код).
*   **Scope Hoisting (Слияние областей видимости):** Rollup не оборачивает каждый модуль в индивидуальную функцию-замыкание с рантайм-загрузчиком (как это делает Webpack). Вместо этого он помещает код всех модулей в одну общую область видимости, что ускоряет выполнение JS в браузере и уменьшает размер бандла.

## 3. Vite: Разделение Dev и Production сред

Vite кардинально изменил подход к разработке, разделив процесс запуска dev-сервера и финальной сборки приложения.

```text
Dev Server (Vite):
[Браузер] ──(Запрос по Native ESM)──► [Vite Dev Server] ──► (Трансформация файла на лету через esbuild) ──► Отдача в браузер

Production Build (Vite):
[Исходный код] ──► [Rollup] ──► [Оптимизированный бандл]
```

### 3.1. Как работает Dev-сервер Vite
Традиционные сборщики (Webpack) перед запуском сервера разработки должны полностью собрать весь проект в бандл в памяти. Чем больше проект, тем дольше старт (может занимать минуты).

Vite запускает сервер **мгновенно**, потому что он ничего не собирает:
1.  **Native ESM:** Vite полагается на нативную поддержку ES-модулей в современных браузерах. Браузер сам парсит `import` в коде и отправляет HTTP-запросы на сервер за каждым файлом.
2.  **Трансформация на лету:** Vite выступает в роли умного прокси-сервера. Он перехватывает запросы браузера, на лету компилирует запрошенный файл (например, конвертирует TS в JS или CSS-модуль) и отдает его клиенту. Неиспользуемые в данный момент файлы страниц вообще не обрабатываются.

### 3.2. Пре-бандлинг зависимостей (Dependency Pre-bundling) через esbuild
Если импортировать библиотеку (например, `lodash-es`), которая состоит из 600 мелких ESM файлов, браузер при старте отправит 600 сетевых запросов, что вызовет лаги сети.
*   **Решение:** При первом запуске Vite находит все тяжелые зависимости в `node_modules` и с помощью сверхбыстрого компилятора **esbuild** (написанного на Go) собирает их в единые крупные ESM-модули. Esbuild работает в 10–100 раз быстрее сборщиков на JS.

### 3.3. Финальная сборка (Production Build)
Для сборки продакшен-бандла Vite использует **Rollup**. В продакшене Native ESM использовать нельзя из-за сетевых задержек (запросы по цепочке зависимостей), поэтому сборка в оптимизированные чанки с минимизацией и Tree Shaking по-прежнему необходима.
