
Монорепозиторий — это подход к организации кодовой базы, при котором несколько независимых проектов (приложений, библиотек, бэкендов) хранятся в одном Git-репозитории. Это упрощает совместное использование кода (code sharing) и позволяет проводить сквозной рефакторинг.

---

## 1. Сравнение современных инструментов

Современный стек монорепозиториев делится на **диспетчеры пакетов** (низкоуровневые инструменты) и **сборщики/системы сборки** (надстройки для оркестрации задач).

```text
┌────────────────────────────────────────────────────────┐
│          Оркестраторы сборки (Turborepo, Nx)           │
│   (Кэширование, параллелизация задач, графы связей)     │
├────────────────────────────────────────────────────────┤
│          Диспетчеры пакетов (pnpm workspaces)          │
│   (Установка зависимостей, линкование пакетов)         │
└────────────────────────────────────────────────────────┘
```

### 1.1. pnpm workspaces
Базовый инструмент для создания монорепозитория. 
*   **Что делает:** Позволяет линковать локальные пакеты друг с другом без публикации в npm. `pnpm` использует жесткие ссылки (hard links) для хранения пакетов, благодаря чему установка зависимостей в монорепозитории происходит в разы быстрее, чем у npm или yarn.
*   **Итог:** Это фундамент монорепозитория. Для сборки и кэширования поверх него ставят Turborepo или Nx.

### 1.2. Turborepo (Vercel)
Легковесный, быстрый сборщик для монорепозиториев, написанный на Rust.
*   **Философия:** Настройка через один конфигурационный файл `turbo.json`. Простой порог входа.
*   **Ключевая фича:** Локальное и облачное кэширование задач (Remote Caching). Если файлы в пакете не изменились, `turbo` мгновенно берет результаты сборки или тестов из кэша.
*   **Подходит для:** Средних проектов, где нужно быстро ускорить сборку без усложнения архитектуры.

### 1.3. Nx
Полноценная расширяемая корпоративная система сборки.
*   **Философия:** Nx глубоко анализирует зависимости проекта и строит подробный граф связей. Имеет систему генераторов (командная строка Nx создает готовые шаблоны приложений и библиотек).
*   **Ключевая фича:** Вычисление затронутых проектов (`affected`). Nx запустит тесты/сборку только для тех пакетов, которые были изменены в текущей ветке (или зависят от изменившихся пакетов).
*   **Подходит для:** Крупных enterprise-проектов со сложными связями, сотнями библиотек и мультиязычным кодом.

### 1.4. Lerna
Один из старейших инструментов управления монорепозиториями.
*   **Статус:** Был на грани закрытия, но сейчас поддерживается компанией Nrwl (создателями Nx). Lerna интегрировала движок Nx под капот для ускорения задач.
*   **Фокус:** Главная ценность Lerna сегодня — удобная публикация пакетов (версионирование, автоматическое создание тегов в гит и релиз нескольких npm-пакетов одновременно).

## 2. Сравнительная таблица

| Критерий                | pnpm workspaces      | Turborepo                   | Nx                                |
| :---------------------- | :------------------- | :-------------------------- | :-------------------------------- |
| **Основная роль**       | Линковка пакетов.    | Кэширование, оркестрация.   | Глубокий анализ, генераторы, кэш. |
| **Язык движка**         | Go / JS              | Rust                        | TS / Rust                         |
| **Сложность настройки** | Минимальная.         | Низкая.                     | Высокая.                          |
| **Скорость сборки**     | Зависит от скриптов. | Сверхбыстрая (кэш на Rust). | Сверхбыстрая (граф affected).     |
| **Генерация кода**      | Нет.                 | Нет.                        | Да (плагины и кодогенерация).     |

### Детальный разбор плюсов и минусов

#### 1. pnpm workspaces
**Плюсы (➕):**
* **Минимальная сложность настройки:** Начать использовать `pnpm workspaces` очень просто (достаточно одного файла `pnpm-workspace.yaml`).
* **Эффективное управление зависимостями:** Отлично справляется со своей главной задачей — локальной линковкой пакетов (symlinks/hardlinks), предотвращая дублирование `node_modules`.
* **Универсальная основа:** Идеально работает в связке с любыми надстройками (с тем же Turborepo или Nx).

**Минусы (➖):**
* **Отсутствие кэширования и умной оркестрации:** `pnpm` не умеет кэшировать результаты сложных задач (например, сборки) или понимать, какие именно пакеты были затронуты изменениями.
* **Скорость сборки ограничена:** Скорость зависит исключительно от скриптов, каждый раз проекты собираются заново.

#### 2. Turborepo
**Плюсы (➕):**
* **Низкий порог входа:** Настройка сводится к понятному файлу `turbo.json`. Внедрить можно за считанные минуты.
* **Сверхбыстрая сборка:** Движок на Rust. Главное преимущество — мощное локальное и облачное кэширование.
* **Отличная параллелизация:** Умеет строить граф зависимостей задач и запускать независимые задачи параллельно.

**Минусы (➖):**
* **Отсутствие генераторов кода:** Turborepo не умеет создавать бойлерплейт для новых библиотек/приложений из коробки.
* **Меньше enterprise-фич:** Не проводит глубокий анализ AST для выявления тонких связей в коде, как это делает Nx.

#### 3. Nx
**Плюсы (➕):**
* **Интеллектуальный граф связей (affected):** Глубоко анализирует код и при коммите может запустить тесты и сборку *только* для затронутых частей системы.
* **Мощная кодогенерация:** Встроенные плагины позволяют одной командой сгенерировать готовое приложение или библиотеку со всеми настройками.
* **Глубокая экосистема:** Огромное количество официальных и комьюнити плагинов.

**Минусы (➖):**
* **Высокая сложность настройки и поддержки:** Высокий порог входа, конфигурация может стать перегруженной.
* **Избыточность для малых проектов:** В небольших монорепозиториях возможности Nx избыточны.

## 3. Рекомендация по выбору стека (Lead Guideline)

*   Для классического full-stack TS проекта (например, Next.js приложение, Nest.js бэкенд и общая библиотека типов `@my-app/shared-types`):
    *   **Стек:** `pnpm workspaces` (управление зависимостями) + `Turborepo` (сборка, тесты, кэширование). Это даст максимальную скорость настройки и предсказуемую работу.
*   Для крупных команд с сотнями переиспользуемых UI-компонентов и микрофронтендами:
    *   **Стек:** `Nx`. Он окупает свою сложность за счет интеллектуального графа зависимостей и мощных CLI-генераторов.
