# Синтаксис классов в JavaScript

Классы в JavaScript, добавленные в стандарте ECMAScript 2015 (ES6), предоставляют удобный, интуитивно понятный синтаксис для реализации объектно-ориентированного программирования (ООП). На первый взгляд они напоминают классы в классических языках вроде Java или C++, однако под капотом в JavaScript сохраняется прототипная модель наследования. В этом руководстве подробно рассматривается синтаксис классов, их свойства, методы, геттеры/сеттеры, а также их внутреннее устройство и отличия от традиционных функций-конструкторов.

---

## 1. Базовый синтаксис классов (Basic Class Syntax)

Классы служат шаблонами для создания объектов с общим набором свойств и методов. 

### Объявление класса, конструктор и методы

Для объявления класса используется ключевое слово `class`. Пример базового класса пользователя:

```javascript
class User {
  // Конструктор инициализирует начальное состояние объекта при его создании
  constructor(name, role) {
    this.name = name;
    this.role = role;
  }

  // Метод класса (будет автоматически записан в прототип)
  sayHi() {
    console.log(`Привет, меня зовут ${this.name}, моя роль: ${this.role}`);
  }
}

// Создание экземпляра класса с помощью ключевого слова new
const user = new User("Алексей", "Администратор");
user.sayHi(); // Выведет: "Привет, меня зовут Алексей, моя роль: Администратор"
```

### Ключевые особенности базового синтаксиса:

1. **Ключевое слово `class`**: Задает декларативное определение класса.
2. **Метод `constructor()`**:
   - Это специальный метод, предназначенный для инициализации создаваемого объекта.
   - Вызывается автоматически в момент выполнения конструкции `new ClassName(...)`.
   - В теле класса может быть объявлен только один метод с именем `constructor`. Если он не объявлен явно, JavaScript создаст пустой конструктор по умолчанию: `constructor() {}`.
3. **Объявление методов**:
   - Методы записываются непосредственно в тело класса.
   - Для объявления методов не требуется ключевое слово `function`.
   - **Разделители отсутствуют**: В отличие от обычных объектов, методы класса не разделяются запятыми. Попытка поставить запятую между методами приведет к синтаксической ошибке (`SyntaxError`).

## 2. Свойства классов (Class Fields)

Свойства классов (поля классов, или *Class Fields*) — это синтаксическая возможность, которая позволяет объявлять свойства экземпляра непосредственно внутри тела класса, без привязки к конструктору.

```javascript
class Button {
  // 1. Простое свойство класса со значением по умолчанию
  type = "submit";
  state = "active";

  constructor(label) {
    this.label = label;
  }

  // 2. Стрелочная функция как свойство класса (сохраняет контекст this)
  click = () => {
    console.log(`Кликнули по кнопке: ${this.label}, тип: ${this.type}`);
  }
}

const submitBtn = new Button("Отправить");
console.log(submitBtn.type); // "submit"

// Обычный метод потерял бы контекст this при передаче в коллбэк,
// но стрелочное свойство сохраняет его:
const callback = submitBtn.click;
callback(); // Выведет: "Кликнули по кнопке: Отправить, тип: submit" (this сохранен!)
```

### Различия между свойствами в конструкторе и свойствами класса:

* **Место объявления**: Свойства класса объявляются непосредственно внутри класса, повышая читаемость кода.
* **Расположение в памяти**: Поля класса (включая свойства со стрелочными функциями) создаются **на самом экземпляре объекта** (например, `this.type` и `this.click` будут лежать прямо на `submitBtn`), а не на его прототипе (`Button.prototype`).
* **Стрелочные функции**:
  - Когда метод объявляется как стрелочная функция-свойство класса (`click = () => { ... }`), он автоматически привязывается к текущему экземпляру. Это решает классическую проблему потери контекста `this` при передаче методов в качестве коллбэков (например, в обработчики событий DOM или `setTimeout`).
  - *Важно помнить*: Поскольку стрелочные функции записываются непосредственно на каждый создаваемый экземпляр, для каждого объекта будет выделяться отдельная память под свою копию функции. Обычные методы классов хранятся в единственном экземпляре в прототипе (`Button.prototype`), что более экономично по памяти.

## 3. Геттеры и сеттеры (Getters & Setters)

Классы поддерживают объявление геттеров (получателей) и сеттеров (установщиков), которые позволяют перехватывать обращения к свойствам объекта, валидировать входные данные или вычислять значения динамически.

```javascript
class User {
  constructor(name) {
    // При вызове конструктора неявно вызывается сеттер name
    this.name = name;
  }

  // Геттер: вызывается автоматически при чтении user.name
  get name() {
    return this._name;
  }

  // Сеттер: вызывается автоматически при присвоении значения (user.name = ...)
  set name(value) {
    if (value.trim().length < 3) {
      console.warn("Имя слишком короткое! Должно быть не менее 3 символов.");
      return;
    }
    this._name = value;
  }
}

const user = new User("Илья");
console.log(user.name); // "Илья"

user.name = "Ян"; // Выведет в консоль предупреждение, значение не обновится
console.log(user.name); // "Илья"
```

### Важные нюансы использования:

* **Защита от бесконечной рекурсии (переполнение стека)**:
  Если в геттере или сеттере свойства `name` обратиться к `this.name`, произойдет бесконечный цикл вызовов метода, что приведет к ошибке `RangeError: Maximum call stack size exceeded`. Чтобы этого избежать, реальное значение записывают в техническое ("скрытое") свойство с нижним подчеркиванием в начале названия (например, `this._name`).
* **Синтаксис**:
  Снаружи геттеры и сеттеры выглядят как обычные свойства объекта (к ним обращаются через точку, без круглых скобок `()`), но внутри они работают как методы.
* **Место хранения**:
  В отличие от обычных полей классов, геттеры и сеттеры помещаются на прототип объекта (`User.prototype`).

## 4. Под капотом: Синтаксический сахар над прототипами

Несмотря на внешнее сходство классов в JS с классами в других языках программирования, под капотом сохраняется привычная **прототипная модель**. Классы в JavaScript — это по большей части удобный "синтаксический сахар" над функциями-конструкторами и прототипами.

### Что происходит при объявлении `class User`?

Когда движок JavaScript разбирает объявление класса, он выполняет следующие шаги:

1. Создается функция с именем `User`. Тело этой функции берется из метода `constructor()`.
2. Все методы, объявленные в теле класса (за исключением полей класса и статических методов), записываются в прототип этой функции — `User.prototype`.

### Доказательства прототипной природы классов:

```javascript
class User {
  constructor(name) {
    this.name = name;
  }
  
  sayHi() {
    console.log(this.name);
  }
}

// 1. Класс — это функция
console.log(typeof User); // "function"

// 2. Конструктор на прототипе ссылается на саму функцию класса
console.log(User === User.prototype.constructor); // true

// 3. Метод sayHi расположен в прототипе User.prototype
console.log(User.prototype.sayHi); // [Function: sayHi]

// 4. Список собственных свойств прототипа
console.log(Object.getOwnPropertyNames(User.prototype)); // ["constructor", "sayHi"]
```

### Эквивалентный код в стиле ES5 (без класса):

Чтобы лучше понять, как работают классы, рассмотрим аналогичную реализацию на базе функций-конструкторов ES5:

```javascript
// 1. Создание функции-конструктора (аналог constructor)
function UserES5(name) {
  this.name = name;
}

// 2. Добавление метода на прототип
UserES5.prototype.sayHi = function() {
  console.log(this.name);
};

const userES5 = new UserES5("Иван");
userES5.sayHi(); // "Иван"
```

## 5. Различия между классом и функцией-конструктором

Хотя классы построены поверх прототипов, они не являются полной копией функций-конструкторов. Движок JavaScript вводит несколько критических различий для повышения безопасности и предсказуемости кода:

### 1. Обязательность вызова с `new`
* **Функция-конструктор**: Может быть вызвана без ключевого слова `new` (например, `UserES5()`). В этом случае `this` сошлется на глобальный объект `window` (или `global`), что приведет к загрязнению глобальной области видимости.
* **Класс**: Попытка вызвать класс без `new` приведет к ошибке: `TypeError: Class constructor User cannot be invoked without 'new'`. Движок помечает класс внутренним свойством `[[IsClassConstructor]]: true`.

### 2. Перечисляемость методов (Enumerability)
* **Функция-конструктор**: По умолчанию методы, добавленные на прототип (`UserES5.prototype.sayHi = ...`), являются *перечисляемыми* (enumerable: true). Они будут всплывать в циклах `for...in`.
* **Класс**: Все методы, объявленные внутри класса, автоматически получают свойство `enumerable: false` в дескрипторе свойств. Это избавляет от необходимости вручную скрывать методы от обхода циклом.

### 3. Строгий режим (Strict Mode)
* **Класс**: Весь код внутри тела класса по умолчанию выполняется в строгом режиме (`"use strict"`), даже если эта директива не была объявлена явно в файле.
* **Функция-конструктор**: Работает в обычном (нестрогом) режиме, пока `"use strict"` не будет явно прописан.

### 4. Хойстинг (Поднятие)
* **Функция-конструктор**: Объявления функций (Function Declarations) поднимаются. Вызывать конструктор через `new` можно до места его объявления в файле.
* **Класс**: Не поднимается аналогично обычным функциям. Объявления классов подчиняются тем же правилам временной мертвой зоны (Temporal Dead Zone, TDZ), что и переменные `let`/`const`. Создать экземпляр класса до его объявления в коде невозможно.

### 5. Конструируемость методов класса (Constructability)
* **Методы класса**: Методы, объявленные внутри класса, не имеют собственного свойства `prototype` и не могут быть вызваны как конструкторы с помощью `new` (попытка сделать `new user.sayHi()` вызовет ошибку).
* **Методы конструктора**: Традиционные функции на прототипе конструктора ES5 могут быть вызваны с ключевым словом `new`, что потенциально порождает баги.

## Резюме для самопроверки

1. **Синтаксический сахар**: Классы в JavaScript — это обертка над прототипным наследованием, делающая синтаксис чище и безопаснее.
2. **Конструктор**: Метод `constructor` инициализирует новые объекты и вызывается автоматически.
3. **Методы на прототипе**: Все стандартные методы класса записываются в `prototype` и не являются перечисляемыми (`enumerable: false`).
4. **Поля классов**: Свойства (переменные класса) создаются на самом экземпляре, а не на прототипе. Поля со стрелочными функциями надежно привязывают контекст `this` к экземпляру, но расходуют больше памяти.
5. **Безопасность**: Классы требуют обязательного использования оператора `new`, не подвержены обычному хойстингу и автоматически включают строгий режим (`"use strict"`).
