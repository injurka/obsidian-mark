# Делегирование событий

В современной веб-разработке интерфейсы часто содержат множество интерактивных элементов (списки, таблицы, галереи). Назначение отдельного обработчика событий каждому из них снижает производительность приложения и усложняет управление памятью. 

**Делегирование событий (Event Delegation)** — это паттерн проектирования, который позволяет обрабатывать события на множестве дочерних элементов с помощью одного-единственного обработчика, установленного на их общем родителе (или даже на `document`). 

Этот паттерн основан на стандартном механизме **всплытия событий (event bubbling)**: когда на дочернем элементе происходит событие, оно поднимается вверх по дереву DOM, проходя через всех его родителей.

Для более подробного понимания работы событий ознакомьтесь с материалами [[Введение в события]] и [[Всплытие и погружение]].

---

## Механизм работы: Всплытие и Погружение

Делегирование событий опирается на фазы жизненного цикла события в DOM.

### Использование фазы всплытия (по умолчанию)
В 99% случаев делегирование реализуется на **фазе всплытия (bubbling)**. Алгоритм выглядит следующим образом:
1. Мы вешаем обработчик события на общего предка (контейнер).
2. Пользователь взаимодействует с дочернем элементом (например, кликает на пункт списка `<li>`).
3. Событие всплывает от целевого элемента до общего предка.
4. На предке срабатывает обработчик. Внутри него мы анализируем, где именно произошло событие, используя объект события `event`.

### Использование фазы погружения (capturing)
Иногда требуется перехватить события, которые **не всплывают** (например, `focus` и `blur`). В этом случае делегирование настраивают на **фазу погружения (capturing)**, передавая третий параметр `{ capture: true }` в `addEventListener`:

```javascript
// Делегирование событий focus на уровне контейнера формы
const form = document.querySelector('form');
form.addEventListener('focus', (event) => {
  event.target.classList.add('focused');
}, { capture: true });
```

## Преимущества делегирования событий

Использование делегирования предоставляет три ключевых преимущества:

1. **Экономия оперативной памяти:** Вместо создания сотен функций-обработчиков (по одной для каждого элемента) создается и хранится в памяти всего одна функция на родительском элементе.
2. **Динамические элементы:** Если в контейнер динамически добавляются новые элементы (например, при подгрузке данных с сервера или создании пользователем), они **автоматически** получают ту же логику обработки событий. Нам не нужно вручную вешать на них новые обработчики или удалять старые при их удалении (что также предотвращает утечки памяти).
3. **Упрощение кода:** Меньше вызовов `addEventListener` and `removeEventListener`. Код инициализации интерфейса становится более лаконичным и централизованным.

## `event.target` vs `event.currentTarget`

При делегировании критически важно различать два свойства объекта события:

* **`event.target`** — это *целевой элемент*, на котором непосредственно произошло действие (самый глубокий вложенный элемент, по которому кликнули). В процессе всплытия это свойство **не меняется**.
* **`event.currentTarget`** — это *текущий элемент*, на котором сработал обработчик (тот, к которому был привязан метод `addEventListener`). В контексте делегирования это всегда **элемент-контейнер**.

### Таблица сравнения

| Свойство | Описание | Меняется при всплытии? | Роль в делегировании |
| :--- | :--- | :--- | :--- |
| `event.target` | Инициатор события (самый глубокий элемент) | Нет | Используется для определения того, на каком конкретно дочернем элементе произошло действие |
| `event.currentTarget` | Слушатель события (элемент с обработчиком) | Да (соответствует текущему узлу) | Представляет контейнер, в рамках которого мы делегируем события (часто используется для ограничения поиска) |

## Метод `element.closest(selector)` для работы со сложной вложенностью

В реальных интерфейсах дочерние элементы редко бывают плоскими текстовыми узлами. Например, кнопка может содержать иконку, текст и бейдж:

```html
<button class="action-btn">
  <svg class="icon">...</svg>
  <span>Сохранить</span>
</button>
```

Если пользователь кликнет по иконке `<svg>`, то значением `event.target` станет элемент `<svg>` (или его `<path>`). Если мы будем проверять только `event.target.tagName === 'BUTTON'`, наше условие не выполнится, и клик будет проигнорирован.

Для решения этой проблемы используется метод **`element.closest(selector)`**. 

### Как работает `closest`?
Метод `closest(selector)` ищет ближайший родительский элемент (начиная с самого элемента), который соответствует указанному CSS-селектору. Если элемент сам соответствует селектору, он возвращает его. Если ничего не найдено, возвращается `null`.

```javascript
const container = document.querySelector('.container');
container.addEventListener('click', (event) => {
  // Находим кнопку, даже если кликнули по иконке или тексту внутри нее
  const button = event.target.closest('.action-btn');

  // Если клик был вне кнопки или кнопки нет в этом контейнере, игнорируем
  if (!button) return;

  // Важно: проверяем, что найденная кнопка находится внутри нашего контейнера-делегата
  if (!event.currentTarget.contains(button)) return;

  console.log('Кликнули по кнопке:', button);
});
```

## Паттерн «Поведение» (Behavior Pattern)

Делегирование событий позволяет использовать декларативный подход к программированию интерфейсов, называемый **паттерном «Поведение»**. 

Вместо написания JS-кода для каждого нового интерактивного элемента мы описываем его поведение с помощью HTML-атрибутов (обычно `data-*`), а глобальный обработчик на уровне `document` (или крупного блока) считывает эти атрибуты и выполняет соответствующие действия.

### Преимущества паттерна:
* **Декларативность:** Чтобы добавить новое поведение (например, счетчик кликов или сворачивающийся блок), достаточно просто написать нужный `data-` атрибут в HTML.
* **Масштабируемость:** Добавление новых элементов с таким поведением на страницу не требует написания ни одной строчки JavaScript-кода.

## Тонкие моменты и подводные камни (Pitfalls)

1. **Влияние `event.stopPropagation()`**
   Если на каком-то из дочерних элементов внутри обработчика вызывается `event.stopPropagation()`, событие прекращает всплытие. Это означает, что оно никогда не достигнет родительского элемента-делегата, и делегированный обработчик **не сработает**. 
   *Рекомендация:* Избегайте использования `stopPropagation()` без крайней необходимости.

2. **События, которые не всплывают**
   Некоторые события не поддерживают фазу всплытия. При работе с ними стандартное делегирование не сработает:
   * **`focus` / `blur`** — не всплывают. 
     * *Решение:* Используйте события **`focusin` / `focusout`** (которые всплывают) или вешайте обработчик на фазу погружения (`{ capture: true }`).
   * **`mouseenter` / `mouseleave`** — не всплывают и не реагируют на переходы между дочерними элементами.
     * *Решение:* Используйте события **`mouseover` / `mouseout`** (которые всплывают).
   * **`load`, `unload`, `error`** (на картинках/скриптах) — не всплывают.

3. **Избыточная нагрузка на CPU**
   Если установить делегированный обработчик на часто генерируемые события (например, `mousemove`, `scroll` или `pointermove`) на уровне `document`, то при каждом движении мыши JS будет выполнять проверки соответствия селекторов (`closest`, `matches`). Это может привести к просадке FPS (frame drop).
   *Рекомендация:* Ограничивайте область делегирования ближайшим общим родителем вместо `document` и используйте приемы *Throttling / Debouncing*.

## Примеры практической реализации

Ниже приведены три полноценных примера использования делегирования событий.

### Пример 1: Базовое делегирование для списка (List Container Delegation)

Простой пример отслеживания кликов по элементам списка. При клике на элемент списка мы меняем его состояние (добавляем класс активности) и считываем данные.

```javascript
// HTML-структура:
// <ul id="category-list">
//   <li data-id="1">Электроника</li>
//   <li data-id="2">Книги</li>
//   <li data-id="3">Одежда</li>
// </ul>

const categoryList = document.getElementById('category-list');

categoryList.addEventListener('click', function(event) {
  // Нам интересны только клики по элементам LI
  if (event.target.tagName !== 'LI') {
    return;
  }

  // Сбрасываем класс активности у всех элементов списка
  const items = event.currentTarget.querySelectorAll('li');
  items.forEach(item => item.classList.remove('active'));

  // Добавляем класс активности выбранному элементу
  const clickedItem = event.target;
  clickedItem.classList.add('active');

  // Получаем данные из data-атрибута
  const categoryId = clickedItem.dataset.id;
  console.log(`Выбрана категория с ID: ${categoryId}`);
});
```

### Пример 2: Сложная вложенность и `closest()`

Сценарий с таблицей пользователей. В каждой строке таблицы есть кнопка удаления со вложенной иконкой. При клике мы должны удалить всю строку таблицы (`<tr>`), определив ID пользователя.

```javascript
// HTML-структура:
// <table id="users-table">
//   <tr data-user-id="101">
//     <td>Иван Иванов</td>
//     <td>
//       <button class="delete-btn" aria-label="Удалить">
//         <svg class="icon"><path d="..."/></svg>
//         <span>Удалить</span>
//       </button>
//     </td>
//   </tr>
// </table>

const usersTable = document.getElementById('users-table');

usersTable.addEventListener('click', (event) => {
  // Находим кнопку удаления с помощью closest()
  const deleteButton = event.target.closest('.delete-btn');

  // Если клик был не по кнопке удаления, игнорируем его
  if (!deleteButton) {
    return;
  }

  // Убеждаемся, что кнопка находится в пределах нашей таблицы
  if (!event.currentTarget.contains(deleteButton)) {
    return;
  }

  // Находим родительскую строку таблицы для удаления
  const tableRow = deleteButton.closest('tr');
  if (tableRow) {
    const userId = tableRow.dataset.userId;
    
    // Выполняем действие
    console.log(`Удаление пользователя с ID: ${userId}`);
    tableRow.remove(); // Удаляем строку из DOM
  }
});
```

### Пример 3: Паттерн «Поведение» (Счетчик и Переключатель)

Пример декларативного программирования. Мы вешаем единый обработчик на `document`, который обслуживает все элементы со специальными `data-` атрибутами на странице.

```javascript
// HTML-структура:
// <!-- Декларативные счетчики -->
// <button data-counter>0</button>
// <button data-counter>5</button>
// 
// <!-- Декларативные переключатели видимости (toggles) -->
// <button data-toggle-target="secret-info">Показать/Скрыть секрет</button>
// <div id="secret-info" style="display: none;">Секретная информация!</div>

document.addEventListener('click', (event) => {
  const target = event.target;

  // 1. Поведение: Счетчик (data-counter)
  // Ищем элемент с атрибутом data-counter
  const counterBtn = target.closest('[data-counter]');
  if (counterBtn) {
    let currentValue = parseInt(counterBtn.textContent, 10) || 0;
    counterBtn.textContent = currentValue + 1;
    return; // Завершаем обработку события
  }

  // 2. Поведение: Переключатель (data-toggle-target)
  // Ищем кнопку, которая управляет видимостью другого элемента
  const toggleBtn = target.closest('[data-toggle-target]');
  if (toggleBtn) {
    const targetId = toggleBtn.dataset.toggleTarget;
    const targetElement = document.getElementById(targetId);

    if (targetElement) {
      const isHidden = targetElement.style.display === 'none';
      targetElement.style.display = isHidden ? 'block' : 'none';
    }
  }
});
```
