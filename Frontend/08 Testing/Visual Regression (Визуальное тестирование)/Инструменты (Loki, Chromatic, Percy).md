# Инструменты визуального регрессионного тестирования (Loki, Chromatic, Percy)

Визуальное регрессионное тестирование (Visual Regression Testing) проверяет, как интерфейс выглядит на самом деле. В отличие от обычных тестов DOM, визуальные тесты рендерят компоненты и попиксельно сравнивают скриншоты "до" (эталон) и "после" (текущий билд).

---

## 1. Сравнительный анализ инструментов

Выбор инструмента зависит от бюджета проекта, инфраструктуры и используемого стека.

| Параметр | Loki | Percy | Chromatic |
| :--- | :--- | :--- | :--- |
| **Тип** | Локальный (Open-Source) | Облачный (Коммерческий) | Облачный (Коммерческий) |
| **Платформа** | Только Storybook | Любой сайт, Storybook, E2E | Строго интегрирован со Storybook |
| **Движок рендера** | Локальный Headless Chrome | Облачные инстансы Chrome/Safari/Firefox | Облачные инстансы Chrome/Safari/Firefox |
| **Дашборд аппрувов**| Нет (только локальные диффы) | Отличный облачный интерфейс | Отличный облачный интерфейс |
| **Цена** | **Бесплатно** | Есть бесплатный лимит, далее платно | Есть бесплатный лимит, далее платно |

### 1.1. Loki
Самый популярный бесплатный инструмент для визуального тестирования Storybook.
*   *Плюс:* Не требует отправки кода в облака, работает локально на машине разработчика.
*   *Минус:* Рендеринг шрифтов зависит от операционной системы. Если разработчик на macOS сгенерирует эталоны, у разработчика на Linux/Windows тесты упадут из-за субпиксельных отличий рендеринга шрифтов.
*   *Решение:* Запускать Loki строго внутри идентичных Docker-контейнеров локально и в CI.

### 1.2. Percy (BrowserStack)
Мощный облачный сервис. Вы можете делать скриншоты как отдельных историй Storybook, так и целых страниц во время прохождения E2E-тестов (например, в Cypress или Playwright).
*   *Плюс:* Тестирование реальных браузеров в облаке (включая рендеринг в Safari на iOS).

### 1.3. Chromatic
Разработан создателями Storybook, поэтому имеет идеальную интеграцию. Он не просто делает скриншоты, а анализирует зависимости. Если компонент `Button` не менялся и компоненты, его использующие, тоже — Chromatic пропустит их рендеринг, сэкономив лимиты скриншотов.

## 2. Борьба с ложными срабатываниями (Flaky Visual Tests)

Попиксельное сравнение крайне чувствительно к малейшим изменениям. Чтобы тесты не падали без реальных причин, необходимо стабилизировать рендеринг.

### 2.1. Динамические даты и текст
Если на странице отображается текущее время (например, "Создано 2 минуты назад"), тест будет падать постоянно.
*   *Решение:* Мокайте глобальный объект `Date` в тестах или Storybook (используйте библиотеки вроде `timekeeper` или `sinon.useFakeTimers()`).

### 2.2. Мигающий курсор ввода (Caret)
Мигающая палочка курсора в текстовом инпуте попадет на скриншот в случайной фазе (видимая/невидимая).
*   *Решение:* Скрывайте курсор ввода с помощью CSS во время тестов:
    ```css
    input {
      caret-color: transparent !important;
    }
    ```

### 2.3. Анимации и GIF-изображения
Анимации загрузки (спиннеры) или CSS-transitions сдвинут элементы на скриншоте в зависимости от миллисекунды создания снимка.
*   *Решение:* Принудительно отключайте все CSS-анимации и переходы для тестового окружения:
    ```css
    *, *::before, *::after {
      transition: none !important;
      animation: none !important;
      animation-duration: 0s !important;
    }
    ```
