# Контекст выполнения и ключевое слово this в JavaScript

Понимание работы контекста (`this`) — одна из важнейших тем в JavaScript. В отличие от лексической области видимости (которая определяется при написании кода), контекст `this` является **динамическим** и определяется непосредственно в момент вызова функции.

---

## 1. Что такое контекст выполнения и динамический `this`

Контекст выполнения (Execution Context) — это внутреннее окружение, в котором выполняется код JavaScript. Каждый раз, когда вызывается функция, для нее создается новый контекст выполнения, частью которого является значение `this`.

Ключевое слово `this` ссылается на объект, который «владеет» текущим исполняемым кодом или связан с ним в момент вызова. 

> **Главное правило:** Значение `this` определяется не тем, *где* функция была объявлена, а тем, *как* она была вызвана.

---

## 2. Поведение `this` в разных сценариях вызова

### Глобальный контекст

На самом верхнем уровне (вне каких-либо функций) `this` указывает на глобальный объект:
* В браузере глобальным объектом является `window`.
* В среде Node.js на уровне модуля `this` ссылается на объект экспорта модуля `module.exports`.

```javascript
// В браузере
console.log(this === window); // true (в браузере)

// В Node.js (внутри файла/модуля)
console.log(this === module.exports); // true
```

### Простой вызов функции (Regular Function Call)

При обычном вызове функции значение `this` зависит от использования строгого режима (`use strict`):

1. **Без строгого режима (Non-strict mode):** `this` автоматически ссылается на глобальный объект (`window` в браузере или `global` в Node.js).
2. **В строгом режиме (Strict mode):** `this` равен `undefined`. Это защищает глобальный объект от случайного изменения данных внутри функций.

```javascript
// Нестрогий режим
function showThis() {
  return this;
}
console.log(showThis()); // window (в браузере) или global (в Node.js)

// Строгий режим
function showThisStrict() {
  'use strict';
  return this;
}
console.log(showThisStrict()); // undefined
```

### Вызов метода объекта (Object Method Call)

Когда функция вызывается как метод объекта (через точку), `this` указывает на объект перед точкой.

```javascript
const person = {
  name: 'Алексей',
  greet() {
    return `Привет, я ${this.name}`;
  }
};

console.log(person.greet()); // "Привет, я Алексей" (this ссылается на person)
```

Контекст динамичен. Если скопировать этот метод в другой объект, `this` изменится:

```javascript
const anotherPerson = {
  name: 'Елена'
};

// Копируем ссылку на функцию
anotherPerson.greet = person.greet;

// Теперь вызываем метод у anotherPerson
console.log(anotherPerson.greet()); // "Привет, я Елена" (this ссылается на anotherPerson)
```

## 3. Стрелочные функции и лексический `this`

Стрелочные функции (Arrow functions) были введены в ES6 и работают с контекстом принципиально иначе: **у них нет собственного контекста `this`**.

* Стрелочные функции берут `this` из внешнего (лексического) окружения в момент своего создания.
* Контекст стрелочной функции невозможно изменить с помощью методов `call()`, `apply()` или `bind()`.
* Стрелочные функции нельзя вызывать с ключевым словом `new` (они не могут быть конструкторами).

```javascript
const group = {
  title: 'Фронтенд-разработка',
  students: ['Анна', 'Игорь'],
  showStudents() {
    // Стрелочная функция наследует `this` из showStudents (который указывает на group)
    this.students.forEach((student) => {
      console.log(`${this.title}: ${student}`);
    });
  }
};

group.showStudents();
// Выведет:
// "Фронтенд-разработка: Анна"
// "Фронтенд-разработка: Игорь"
```

## 4. Проблема потери контекста (Lost Context)

Потеря контекста — частая ошибка при передаче метода объекта в качестве колбэка или при копировании метода в переменную.

### Пример 1: Копирование метода в переменную
Когда метод присваивается переменной, теряется связь с объектом. Происходит обычный вызов функции, и `this` становится `undefined` (в строгом режиме).

```javascript
const user = {
  firstName: 'Дмитрий',
  sayHi() {
    return `Привет, ${this.firstName}!`;
  }
};

const greet = user.sayHi; // копируем ссылку на метод
// console.log(greet()); // Ошибка! TypeError: Cannot read properties of undefined
```

### Пример 2: Передача в качестве колбэка (setTimeout)
Когда метод передается в `setTimeout`, планировщик вызывает функцию отдельно от объекта, что приводит к потере контекста.

```javascript
const clock = {
  time: '12:00',
  showTime() {
    console.log(`Текущее время: ${this.time}`);
  }
};

// Контекст потерян, выведет: "Текущее время: undefined"
setTimeout(clock.showTime, 1000);
```

### Способы решения проблемы:
1. **Использование обертки (стрелочной функции):**
   ```javascript
   setTimeout(() => clock.showTime(), 1000); // Обертка вызывает метод через точку
   ```
2. **Явное связывание контекста с помощью `bind()`:**
   ```javascript
   setTimeout(clock.showTime.bind(clock), 1000); // Создает новую функцию с привязанным clock
   ```
