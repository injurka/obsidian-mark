UMD представляет собой паттерн для создания JavaScript-модулей, которые могут работать в различных окружениях, включая браузеры (как с AMD, так и без модульной системы) и серверные среды (например, Node.js с CommonJS) 3. UMD пытается объединить лучшие черты CommonJS и AMD, а также обеспечить возможность использования модуля в качестве глобальной переменной, если ни одна из модульных систем не обнаружена 3.

UMD обычно реализуется как самовызывающаяся анонимная функция (IIFE), которая проверяет наличие окружения AMD (`typeof define === 'function' && define.amd`) или CommonJS (`typeof module === 'object' && module.exports`) и соответствующим образом определяет и экспортирует модуль 26. Если ни одна из этих систем не обнаружена, модуль обычно прикрепляется к глобальному объекту (`window` в браузере, `global` в Node.js) 26.

UMD был полезен для создания библиотек, которые должны были быть максимально совместимыми с различными JavaScript-окружениями. Однако с широкой поддержкой ESM и развитием сборщиков модулей, которые могут обрабатывать различные форматы, необходимость в UMD снижается. Тем не менее, UMD все еще можно встретить в некоторых старых библиотеках.
