# Всплытие и погружение (Event Bubbling and Capturing)

## 1. Введение / Описание темы

В браузерном окружении события (такие как `click`, `keydown`, `submit` и др.) не происходят изолированно на одном единственном элементе. Браузер должен определить, какие именно элементы интерфейса реагируют на действие пользователя и в каком порядке. Процесс прохождения события через иерархию элементов DOM-дерева называется **распространением события (Event Propagation)**.

Основной принцип распространения событий заключается в том, что если пользователь кликает по кнопке, находящейся глубоко внутри контейнеров, клик физически происходит не только по самой кнопке, но и по всем родительским элементам, в которые она вложена, вплоть до самого верха — тегов `<body>`, `<html>`, объекта `document` и, наконец, объекта `window`.

Понимание жизненного цикла события позволяет эффективно управлять поведением интерфейса, реализовывать паттерн делегирования событий, оптимизировать производительность и избегать труднонаходимых багов.

---

## 2. Фазы распространения события (Event Propagation Phases)

Согласно спецификации DOM Events, стандартный жизненный цикл события делится на три основные последовательные фазы:

1.  **Фаза погружения (Capturing phase / Перехват):** Событие начинает свой путь от самого корня — объекта `window` — и опускается вниз по иерархии DOM-дерева через `document`, `<html>`, `<body>` и промежуточные родительские узлы, пока не достигнет элемента, на котором произошло действие.
2.  **Фаза цели (Target phase / Фаза цели):** Событие достигает целевого элемента (самого глубокого элемента в дереве, вызвавшего событие). На этой фазе срабатывают обработчики, зарегистрированные непосредственно на самой цели.
3.  **Фаза всплытия (Bubbling phase / Всплытие):** Событие начинает подниматься обратно по цепочке родителей: от целевого элемента наверх через всех его предков к `document` и `window`.

### Визуальная схема распространения события (ASCII-диаграмма)

```
          [ Window ]
           │      ▲
1. Фаза    │      │  3. Фаза
погружения │      │  всплытия
(Capture)  ▼      │  (Bubble)
        [ Document ]
           │      ▲
           ▼      │
         [ <html> ]
           │      ▲
           ▼      │
         [ <body> ]
           │      ▲
           ▼      │
      [ <div> (Родитель) ]
           │      ▲
           ▼      │
    =========================
    2. Фаза цели (Target Phase)
         [ <button> ]
    =========================
```

*Примечание:* Хотя фаза цели выделена отдельно, в большинстве современных браузеров обработчики на фазе погружения и фазе всплытия срабатывают последовательно при прохождении через целевой элемент, и разработчики редко разделяют фазу цели как изолированный этап в прикладном коде.

## 3. Всплытие событий (Bubbling)

Всплытие — это наиболее часто используемый этап жизненного цикла события. 

**Детальное объяснение:**
Когда на каком-либо элементе происходит событие, обработчики (слушатели) сначала запускаются на самом этом элементе. Затем событие поднимается на один уровень вверх, вызывая обработчики на его непосредственном родителе. Этот процесс продолжается до тех пор, пока событие не дойдет до объекта `document`, а от него — до `window`.

Рассмотрим пример. Для наглядности HTML-структура представлена в виде комментария внутри JavaScript-кода:

```javascript
// Ниже приведена HTML-структура, для которой мы назначим обработчики событий:
/*
<div id="ancestor" style="padding: 20px; background: red;">
  Ancestor
  <div id="parent" style="padding: 20px; background: yellow;">
    Parent
    <button id="child">Кликни меня</button>
  </div>
</div>
*/

// Получаем ссылки на элементы DOM:
const ancestor = document.getElementById('ancestor');
const parent = document.getElementById('parent');
const child = document.getElementById('child');

// Назначаем обработчики клика (по умолчанию они работают на фазе всплытия):
ancestor.addEventListener('click', () => console.log('Клик на Ancestor'));
parent.addEventListener('click', () => console.log('Клик на Parent'));
child.addEventListener('click', () => console.log('Клик на Child'));

// Если пользователь кликнет по кнопке с id="child", в консоли поочередно появится:
// 1. "Клик на Child"
// 2. "Клик на Parent"
// 3. "Клик на Ancestor"
```

### Исключения (события, которые не всплывают)

Большинство событий в веб-интерфейсе всплывают, но есть важные исключения. Некоторые события слишком специфичны для конкретного элемента или ресурсные ограничения делают их всплытие нецелесообразным:
*   **`focus`** и **`blur`**: События фокусировки элемента не всплывают. Если вам нужно отслеживать фокус на уровне родительского контейнера, следует использовать их всплывающие аналоги: **`focusin`** и **`focusout`**.
*   **`mouseenter`** и **`mouseleave`**: События наведения мыши не всплывают и не реагируют на переходы между дочерними элементами внутри родителя. Если требуется всплытие, используйте события **`mouseover`** и **`mouseout`**.
*   **`load`**, **`unload`**, **`abort`**, **`error`**: Эти события связаны с загрузкой внешних ресурсов (изображений, скриптов, фреймов) и происходят локально на конкретном элементе, не поднимаясь по дереву DOM.

## 4. Погружение событий (Capturing)

Погружение (или перехват) — это первая фаза жизненного цикла события, когда оно движется от корня DOM вниз к цели. Хотя на практике логику чаще привязывают к фазе всплытия, фаза погружения незаменима, когда нужно перехватить событие до того, как оно достигнет целевого элемента и дочерних обработчиков.

### Регистрация обработчика на фазе погружения

По умолчанию метод `addEventListener` настраивает слушатель на фазу всплытия. Чтобы зарегистрировать обработчик для фазы погружения, необходимо передать дополнительный третий аргумент:
1.  **Булевое значение `true`** (классический способ):
    ```javascript
    elem.addEventListener('click', handler, true);
    ```
2.  **Объект настроек `{ capture: true }`** (более современный способ, позволяющий передавать и другие опции, например `{ once: true }`):
    ```javascript
    elem.addEventListener('click', handler, { capture: true });
    ```
Если передать `false` или опустить параметр, слушатель будет работать на фазе всплытия.

### Правильное удаление обработчика через `removeEventListener`

Если вы зарегистрировали обработчик событий на фазе погружения, то при его удалении методом `removeEventListener` вы **обязаны** указать тот же флаг перехвата. В противном случае браузер не сможет сопоставить удаляемый слушатель и он останется активным в памяти.

```javascript
// Объявляем функцию-обработчик:
function handleEvent(event) {
  console.log('Событие перехвачено на погружении');
}

// Правильная регистрация и удаление:
elem.addEventListener('click', handleEvent, true);
elem.removeEventListener('click', handleEvent, true); // Обработчик успешно удален

// Если удалить без флага true, обработчик НЕ удалится:
elem.addEventListener('click', handleEvent, true);
elem.removeEventListener('click', handleEvent); // Обработчик останется активным!
```

## 5. Свойства `event.target` и `event.currentTarget`

При обработке событий крайне важно понимать разницу между свойствами `event.target` и `event.currentTarget` (также доступным как `this` внутри стандартных функций).

*   **`event.target`** — это целевой элемент, который является непосредственным инициатором события (самый глубокий вложенный элемент, на котором произошло действие, например, конкретный клик). Значение `event.target` остается **неизменным** на всех фазах распространения события.
*   **`event.currentTarget`** — это элемент, на котором в данный момент выполняется текущий обработчик. Это тот самый элемент, к которому был привязан слушатель через `addEventListener`. Значение `event.currentTarget` **динамически меняется** по мере того, как событие перемещается по дереву DOM и триггерит обработчики на разных родительских элементах.

### Пример разграничения свойств

```javascript
// Представим форму со вложенной кнопкой:
/*
<form id="registrationForm">
  <button id="submitBtn">Отправить</button>
</form>
*/

const form = document.getElementById('registrationForm');

form.addEventListener('click', function(event) {
  // Если пользователь кликнул по кнопке submitBtn:
  console.log(event.target);        // Выведет: <button id="submitBtn">
  console.log(event.currentTarget); // Выведет: <form id="registrationForm">
  console.log(this === event.currentTarget); // Выведет: true (в обычной функции)
});
```

### Сравнительная таблица

| Свойство | Что означает | Меняется ли при прохождении DOM? | Совпадение с `this` |
| :--- | :--- | :--- | :--- |
| **`event.target`** | Источник события (цель) | Нет (всегда указывает на инициатора) | Только если событие обрабатывается на самой цели |
| **`event.currentTarget`** | Текущий обрабатывающий элемент | Да (принимает значение элемента, чей обработчик выполняется) | Всегда совпадает (для обычных функций) |

## 6. Прекращение распространения (Stopping Propagation)

В некоторых сценариях требуется прервать дальнейшее движение события по дереву DOM. Для этого используются методы объекта события `stopPropagation` и `stopImmediatePropagation`.

### `event.stopPropagation()`

Этот метод останавливает дальнейшее распространение события вверх (при всплытии) или вниз (при погружении).
*   **Важная деталь:** Метод `stopPropagation()` останавливает движение события по дереву к другим элементам, но **все остальные обработчики, назначенные на текущий элемент для этого же события, все равно выполнятся**.

### `event.stopImmediatePropagation()`

Если на одном элементе зарегистрировано несколько слушателей для одного и того же события, и один из них вызывает `stopImmediatePropagation()`, то:
1.  Останавливается дальнейшее распространение события по дереву DOM (как и при `stopPropagation()`).
2.  Отменяется выполнение всех оставшихся (еще не сработавших) обработчиков этого события на текущем элементе.

### Пример сравнения методов

```javascript
const button = document.getElementById('button');
const button2 = document.getElementById('button2');

// Пример с stopPropagation():
button.addEventListener('click', (event) => {
  console.log('Первый обработчик на button');
  event.stopPropagation(); // Препятствует всплытию к родителям
});

button.addEventListener('click', () => {
  console.log('Второй обработчик на button'); // СРАБОТАЕТ, так как висит на том же элементе
});

// Пример с stopImmediatePropagation():
button2.addEventListener('click', (event) => {
  console.log('Первый обработчик на button2');
  event.stopImmediatePropagation(); // Полностью блокирует всплытие и другие обработчики
});

button2.addEventListener('click', () => {
  console.log('Второй обработчик на button2'); // НЕ сработает
});
```

### Почему прекращение распространения нужно использовать с осторожностью?

Частый и необоснованный вызов `stopPropagation()` является плохой практикой и может привести к трудноуловимым багам в больших приложениях. Вот основные проблемы, которые это создает:

1.  **Создание «мертвых зон»:** Клик по элементу с остановленным всплытием скрыт от всех вышестоящих родителей. Это ломает логику родительских компонентов, которые ожидают услышать события от своих потомков.
2.  **Поломка систем аналитики и метрик:** Системы сбора статистики (такие как Яндекс.Метрика, Google Analytics, Hotjar и др.) часто вешают глобальные слушатели на `document` или `window` для отслеживания кликов и действий пользователей. Если на пути события вызывается `stopPropagation()`, клик по элементу не будет учтен аналитикой.
3.  **Поломка глобальных интерфейсных фич:** Например, закрытие выпадающего меню (dropdown) или модального окна при клике в любое место экрана обычно реализуется через глобальный слушатель на `document`. Если кликнуть внутри меню на элемент, вызывающий `stopPropagation()`, то глобальный обработчик на `document` не сработает, и меню не закроется.

**Альтернатива:** Вместо жесткой остановки события используйте паттерн **делегирования событий**, либо проверяйте `event.target` в обработчике на родителе, чтобы отсекать нежелательные клики.
