
Наследование классов позволяет создавать новые классы на основе уже существующих, расширяя или частично изменяя их поведение. В стандарте ES6 (ECMAScript 2015) для этого используется ключевое слово `extends`. Под капотом классов JavaScript по-прежнему лежит прототипная модель наследования, однако синтаксис классов предлагает дополнительные правила и возможности, такие как ключевое слово `super` и автоматическая привязка статических методов.

---

## 1. Базовый синтаксис и ключевое слово `extends`

Для наследования одного класса от другого используется синтаксис `class Child extends Parent`.

Пример базового наследования:

```javascript
class Animal {
  constructor(name) {
    this.name = name;
  }

  run(speed) {
    console.log(`${this.name} бежит со скоростью ${speed} км/ч.`);
  }
}

// Класс Rabbit наследует свойства и методы класса Animal
class Rabbit extends Animal {
  hide() {
    console.log(`${this.name} прячется!`);
  }
}

const rabbit = new Rabbit("Белый кролик");
rabbit.run(5); // Выведет: "Белый кролик бежит со скоростью 5 км/ч."
rabbit.hide(); // Выведет: "Белый кролик прячется!"
```

При наследовании методы родительского класса автоматически становятся доступными для экземпляров дочернего класса.

## 2. Устройство под капотом (Двойная цепочка прототипов)

Когда мы используем ключевое слово `extends`, движок JavaScript устанавливает две связи прототипов:

1. **Связь прототипов экземпляров**:
   `Rabbit.prototype.__proto__` указывает на `Animal.prototype`. Это позволяет экземплярам дочернего класса искать обычные методы в прототипе родителя.
2. **Связь самих классов**:
   `Rabbit.__proto__` указывает на `Animal`. Благодаря этому статические методы родительского класса автоматически наследуются дочерним классом (например, если у `Animal` есть статический метод `Animal.compare()`, его можно вызвать как `Rabbit.compare()`).

Пример проверки прототипов в JS:

```javascript
class Animal {
  static compare(animalA, animalB) {
    return animalA.name.localeCompare(animalB.name);
  }
}

class Rabbit extends Animal {}

// 1. Проверяем связь прототипов методов экземпляра
console.log(Object.getPrototypeOf(Rabbit.prototype) === Animal.prototype); // true

// 2. Проверяем связь самих классов (наследование статических методов)
console.log(Object.getPrototypeOf(Rabbit) === Animal); // true
console.log(Rabbit.compare({ name: "A" }, { name: "B" })); // -1 (работает!)
```

## 3. Конструктор и ключевое слово `super`

В наследовании классов JavaScript есть строгие правила инициализации объектов, связанные со встроенным свойством `[\[ConstructorKind\]]`.

### Обязательный вызов `super()` в конструкторе

Если дочерний класс имеет собственный конструктор `constructor()`, он **обязан** вызвать `super(...)` перед тем, как обратиться к ключевому слову `this`.

Пример правильного вызова:

```javascript
class Animal {
  constructor(name) {
    this.name = name;
  }
}

class Rabbit extends Animal {
  constructor(name, earLength) {
    // console.log(this.name); // Ошибка ReferenceError: Must call super constructor in derived class before accessing 'this'
    super(name); // Вызов родительской реализации. Инициализирует this
    this.earLength = earLength; // Теперь this доступен
  }
}

const rabbit = new Rabbit("Банни", 10);
console.log(rabbit.name); // "Банни"
```

### Почему необходимо вызывать `super()`?

В JavaScript конструкторы делятся на два типа:
- **Базовый конструктор** (`\[\[ConstructorKind\]]: "base"`): вызывается при создании обычного (не наследующего) класса. Он сам выделяет память под объект и записывает ссылку в `this`.
- **Производный конструктор** (`\[\[ConstructorKind\]]: "derived"`): вызывается при создании унаследованного класса. Он не создает объект самостоятельно, а ожидает, что это сделает родительский класс. Поэтому вызов `super()` является точкой создания объекта. Без вызова `super()` память под экземпляр не будет выделена, и обращение к `this` приведет к ошибке.

### Автоматический конструктор по умолчанию

Если в наследуемом классе не объявить конструктор явно, движок JavaScript сгенерирует его автоматически. Данный конструктор просто передает все аргументы в родительский класс:

```javascript
class Rabbit extends Animal {
  // Автоматически генерируемый конструктор при его отсутствии в дочернем классе
  constructor(...args) {
    super(...args);
  }
}
```

## 4. Переопределение методов (Method Overriding)

Дочерний класс может переопределять методы родительского класса. При этом он может полностью заменить реализацию или использовать ключевое слово `super` для обращения к родительскому методу внутри дочернего.

Пример расширения родительского метода:

```javascript
class Animal {
  constructor(name) {
    this.name = name;
  }

  say() {
    console.log(`${this.name} издает звук.`);
  }
}

class Dog extends Animal {
  say() {
    super.say(); // Вызов родительской реализации
    console.log(`${this.name} лает: Гав-гав!`); // Добавление новой логики
  }
}

const dog = new Dog("Шарик");
dog.say();
// Выведет:
// "Шарик издает звук."
// "Шарик лает: Гав-гав!"
```

## 5. Внутреннее устройство `super` и свойство `[\[HomeObject\]]`

В JavaScript работа `super` устроена сложнее, чем простое обращение к `this.__proto__`. Если бы `super` работал через `this.__proto__`, то при многоуровневом наследовании возникали бы бесконечные циклы вызовов.

Для корректной работы `super` движок использует скрытое внутреннее свойство функции — `[\[HomeObject\]]`.

* **`[\[HomeObject\]]`** — это ссылка на объект или прототип, в котором метод был объявлен.
* Когда в методе встречается вызов `super.say()`, JavaScript берет прототип объекта `[\[HomeObject\]]` (то есть `Object.getPrototypeOf([\[HomeObject\]])`) и вызывает его метод `say` с текущим контекстом `this`.

Пример, иллюстрирующий поведение `[\[HomeObject\]]` и ограничение при копировании методов:

```javascript
const animal = {
  name: "Животное",
  say() {
    console.log(this.name);
  }
};

const rabbit = {
  __proto__: animal,
  name: "Кролик",
  say() {
    super.say(); // HomeObject жестко привязан к объекту rabbit
  }
};

const longEar = {
  __proto__: rabbit,
  name: "Длинноухий кролик",
  say() {
    super.say(); // HomeObject жестко привязан к объекту longEar
  }
};

longEar.say(); // Выведет "Длинноухий кролик" (все работает корректно)

// Попытка скопировать метод в другой объект:
const otherObject = {
  name: "Посторонний объект",
  say: rabbit.say // У скопированной функции HomeObject по-прежнему указывает на rabbit
};

// otherObject.say(); // Вызовет ошибку TypeError, так как super.say() пытается найти метод на прототипе rabbit (то есть в animal), но контекст this будет otherObject.
```

*Важное следствие*: Методы, использующие `super`, привязаны к своему `[\[HomeObject\]]` и не могут быть перенесены в другие объекты без потери связи. Это работает только для методов, объявленных в синтаксисе классов или через сокращенную запись методов объектов `method() {}` (для обычных стрелочных функций или свойств-функций вроде `method: function() {}` свойство `[\[HomeObject\]]` не создается).

## 6. Особенности переопределения свойств (полей классов)

Свойства классов (Class Fields) ведут себя иначе, чем методы. Они инициализируются непосредственно на экземпляре объекта, а не на прототипе. Из-за этого порядок их инициализации критически важен.

### Порядок инициализации свойств при наследовании:
1. Поля базового класса инициализируются до вызова его конструктора.
2. Поля дочернего класса инициализируются сразу после выполнения `super()` в его конструкторе.

Это приводит к классической проблеме: если конструктор родительского класса вызывает метод, который переопределен в дочернем классе, дочерний метод выполнится, но обратится к еще не проинициализированным свойствам дочернего класса!

Пример ловушки с инициализацией полей:

```javascript
class Parent {
  name = "Parent";

  constructor() {
    this.showName();
  }

  showName() {
    console.log(`Parent class: ${this.name}`);
  }
}

class Child extends Parent {
  name = "Child";

  showName() {
    console.log(`Child class: ${this.name}`);
  }
}

// Создаем экземпляр Child
const child = new Child(); // Выведет: "Child class: Parent"
child.showName();          // Выведет: "Child class: Child"
```

### Пошаговый разбор выполнения:
1. Вызывается `new Child()`.
2. Начинает работать конструктор класса `Child`, который сразу вызывает `super()`.
3. Выполнение переходит в конструктор класса `Parent`.
4. В классе `Parent` инициализируются его поля: создается свойство `this.name = "Parent"`.
5. Конструктор `Parent` вызывает `this.showName()`.
6. Поскольку метод `showName` переопределен в `Child`, вызывается реализация из класса `Child`.
7. Метод `showName` дочернего класса считывает `this.name`. На этот момент поля `Child` еще **не** проинициализированы (потому что `super()` еще не завершился). Объект содержит только свойство `this.name` со значением `"Parent"`, установленным на шаге 4. Поэтому выводится `"Child class: Parent"`.
8. Вызов `super()` завершается.
9. Теперь инициализируются поля `Child`: свойству `this.name` присваивается значение `"Child"`.
10. Последующие вызовы `child.showName()` будут выводить ожидаемое `"Child class: Child"`.

**Рекомендация**: Избегайте вызова переопределяемых методов внутри конструкторов, так как это может привести к работе с недоинициализированными данными наследников.

## Резюме для самопроверки

1. **`extends`**: Создает двойную цепочку прототипов: для связи прототипов экземпляров (`Child.prototype.__proto__ === Parent.prototype`) и для связи самих классов (`Child.__proto__ === Parent`).
2. **`super`**:
   - В конструкторе: вызывает родительский конструктор. Должен быть вызван до обращения к `this`.
   - В методах: обращается к методам родительского класса.
3. **`[\[HomeObject\]]`**: Скрытое свойство метода, связывающее его с объектом объявления. Используется движком для поиска прототипа в вызовах `super`.
4. **Порядок инициализации полей**: Поля родителя инициализируются до выполнения тела конструктора родителя. Поля наследника инициализируются только после возврата из `super()`. Вызов методов наследника из конструктора родителя может прочитать старые или неинициализированные значения свойств.
