# Zero-runtime (Vanilla Extract, Linaria)

## 1. Концепция Zero-runtime CSS-in-JS

**Zero-runtime CSS-in-JS** — это подход к стилизации, совмещающий удобство написания стилей внутри JavaScript/TypeScript кода (Developer Experience) с производительностью статического CSS (User Experience). 

В отличие от классического CSS-in-JS (Styled Components, Emotion), который генерирует стили в браузере клиента, инструменты Zero-runtime полностью **компилируют стили в обычные `.css` файлы на этапе сборки проекта (build time)**. В готовом бандле для клиента не остается никакого JS-кода библиотеки стилизации.

Наиболее популярные решения: **Linaria** и **Vanilla Extract**.

---

## 2. Как это работает под капотом (Архитектура сборки)

Каждый инструмент решает задачу компиляции по-своему:

```text
[Исходный код: JS/TS]
        │
        ├─► [Linaria]: Парсинг Babel-плагином ──► Извлечение CSS-строк ──► Замена на хэши классов
        │
        └─► [Vanilla Extract]: Выполнение .css.ts в Node.js sandbox ──► Генерация статического CSS + типов (TS)
                                                                                  │
                                                                                  ▼
                                                                     [Финальный бандл: static.css]
```

### 2.1. Linaria
Linaria использует плагин для Babel, чтобы парсить файлы во время сборки. 
*   Babel находит шаблонные строки `css` или `styled.div` и вычисляет их содержимое (если это возможно статически).
*   Заменяет эти вызовы на сгенерированные имена классов (например, `class="header_1x8a8sd"`).
*   Извлеченный CSS записывается в отдельный временный файл `.css`, который затем подхватывается стандартным загрузчиком (например, `mini-css-extract-plugin` в Webpack или встроенным CSS-обработчиком в Vite).

### 2.2. Vanilla Extract
Vanilla Extract полностью построен на TypeScript и не использует парсинг строк через Babel. Стили пишутся в специальных файлах с расширением `.css.ts`.
*   Во время сборки интеграционный плагин (для Vite, Webpack, esbuild) запускает файлы `.css.ts` в изолированном контексте Node.js.
*   Функции вроде `style()` или `createVar()` выполняются и регистрируют CSS-правила.
*   На выходе генерируется статический `.css` файл, а в JS-код импортируются только строковые названия классов и TypeScript-типы.

## 3. Сравнительный анализ: Linaria vs Vanilla Extract

| Критерий | Linaria | Vanilla Extract |
| :--- | :--- | :--- |
| **Синтаксис** | Похож на Styled Components (шаблонные строки / CSS-синтаксис). | Объектный синтаксис (TypeScript API). |
| **Механизм** | Babel-плагин для статического анализа и парсинга JS. | Node.js среда выполнения во время сборки. |
| **Типизация** | Базовая поддержка TS. | Полная строгая типизация (Type-Safe) из коробки. |
| **Динамика** | Встроенная генерация CSS Variables из интерполяций. | Требует явного создания переменных через `createVar()`. |
| **Экосистема** | Менее развита. | Богатая: `Recipes` (варианты), `Sprinkles` (утилиты), `Themes`. |

## 4. Как реализуется динамическая стилизация?

Так как CSS компилируется на этапе сборки и больше не может меняться на лету, динамическое изменение стилей (например, на основе пользовательского ввода или состояния) реализуется через **CSS Custom Properties (CSS-переменные)**.

### Пример на Vanilla Extract:

1.  **Создание стилей и переменных (`button.css.ts`):**
    ```typescript
    import { style, createVar } from '@vanilla-extract/css';

    // Создаем строго типизированную CSS-переменную
    export const buttonBgColor = createVar();

    export const buttonClass = style({
      padding: '12px 24px',
      border: 'none',
      borderRadius: '4px',
      // Привязываем переменную к свойству background-color
      backgroundColor: buttonBgColor,
      color: '#fff',
      transition: 'background-color 0.2s ease',
    });
    ```

2.  **Использование в React-компоненте (`Button.tsx`):**
    ```tsx
    import { buttonClass, buttonBgColor } from './button.css.ts';

    interface ButtonProps {
      customColor: string;
      children: React.ReactNode;
    }

    export function Button({ customColor, children }: ButtonProps) {
      return (
        <button
          className={buttonClass}
          // Передаем динамическое значение в inline-стили через CSS-переменную
          style={{ [buttonBgColor]: customColor }}
        >
          {children}
        </button>
      );
    }
    ```

## 5. Преимущества и недостатки Zero-runtime

### Преимущества:
*   **0 Кб в JS-бандле:** Нет runtime-кода библиотеки, который нужно скачивать и парсить клиенту.
*   **Максимальная производительность:** CSS-файлы загружаются параллельно с JS, кэшируются браузером и обрабатываются нативным быстрым CSS-движком.
*   **Совместимость с React Server Components (RSC):** Стили можно без ограничений использовать внутри серверных компонентов, так как они не требуют гидратации рантайма на клиенте.
*   **Type Safety (для Vanilla Extract):** TypeScript проверяет, что вы не ошиблись в написании свойств (например, `paddingTop` вместо `padding-top` или невалидные значения).

### Недостатки и ограничения:
*   **Сложность настройки:** Требуется интеграция плагинов в сборщик (Vite, Webpack, Turborepo).
*   **Ограниченная динамика:** Любое динамическое изменение должно быть спроектировано через CSS-переменные. Напрямую прокинуть пропс в CSS-объект, как в Emotion, нельзя.
*   **Скорость HMR (Hot Module Replacement):** При изменении стилей сборщик должен перегенерировать CSS-файл на диске, что может работать чуть медленнее во время разработки по сравнению с моментальной инъекцией в DOM у Styled Components.
