# View Transitions API

## 1. Революция в анимации интерфейсов

До появления **View Transitions API** создание плавных переходов между страницами или состояниями DOM требовало подключения тяжелых JavaScript-библиотек (Framer Motion, GSAP, React Transition Group) и написания сложной логики отслеживания жизненного цикла элементов.

View Transitions API — это нативный браузерный API, который берет на себя всю грязную работу по анимации переходов. Он позволяет анимировать изменения DOM (как в Single Page Applications, так и при переходе между физическими страницами в Multi-Page Applications) с помощью стандартного CSS.

---

## 2. Как это работает под капотом (Алгоритм браузера)

Когда мы запускаем переход с помощью JS-метода `document.startViewTransition(updateCallback)`:

```text
[Текущий DOM] ──► 1. Снимок Старого состояния (::view-transition-old)
                        │
                        ▼ (Вызов updateCallback)
[Новый DOM]     ──► 2. Снимок Нового состояния (::view-transition-new)
                        │
                        ▼
                  3. Наложение CSS-анимации (Cross-fade по умолчанию)
```

1.  **Заморозка экрана:** Браузер делает скриншот (растровый снимок) текущего состояния страницы.
2.  **Изменение DOM:** Браузер выполняет переданную функцию `updateCallback` (например, меняет контент, удаляет/добавляет узлы).
3.  **Новый снимок:** Браузер делает скриншот нового состояния страницы.
4.  **Создание дерева псевдоэлементов:** Браузер генерирует временную структуру псевдоэлементов в DOM.
5.  **Анимация:** GPU проигрывает CSS-анимацию перехода от старого снимка к новому (по умолчанию применяется плавное перекрестное затухание — `cross-fade`).

## 3. Дерево псевдоэлементов View Transition

Для кастомизации анимации браузер временно встраивает в корень документа специальное дерево псевдоэлементов:

```text
::view-transition
 └── ::view-transition-group(root)
      └── ::view-transition-image-pair(root)
           ├── ::view-transition-old(root)  /* Снимок старого DOM */
           └── ::view-transition-new(root)  /* Снимок нового DOM */
```

Мы можем переопределить стандартные CSS-анимации для этих псевдоэлементов:

```css
/* Кастомная анимация для старого состояния (уход влево) */
::view-transition-old(root) {
  animation: 0.4s ease-out both slide-out-left;
}

/* Кастомная анимация для нового состояния (приход справа) */
::view-transition-new(root) {
  animation: 0.4s ease-out both slide-in-right;
}

@keyframes slide-out-left {
  to { transform: translateX(-100%); }
}
@keyframes slide-in-right {
  from { transform: translateX(100%); }
}
```

## 4. Морфинг элементов: Свойство `view-transition-name`

Самая мощная фича API — возможность связать конкретный элемент на старой странице с элементом на новой. Браузер автоматически рассчитает изменение их размера, положения и плавно перенесет (сморфирует) один элемент в другой.

### Пример (клик по превью товара открывает детальную страницу):

1.  **На странице списка товаров (HTML):**
    ```html
    <!-- Превью товара -->
    <img src="phone.jpg" class="product-thumb" style="view-transition-name: product-hero;" />
    ```

2.  **На детальной странице товара (HTML):**
    ```html
    <!-- Главное фото товара -->
    <img src="phone.jpg" class="product-large" style="view-transition-name: product-hero;" />
    ```

Когда происходит переход, браузер видит элементы с одинаковым `view-transition-name: product-hero` и автоматически анимирует движение и изменение масштаба картинки из списка в шапку детальной карточки.

> [!IMPORTANT]
> **Уникальность имен:**
> Значение `view-transition-name` должно быть **уникальным** на странице в момент выполнения перехода. Если у вас на странице списка товаров будет 10 картинок с одинаковым именем `product-hero`, браузер выдаст ошибку и проигнорирует переход.
> *Решение:* Динамически вешать уникальное имя (например, `product-hero-ID`) на кликнутый элемент прямо перед запуском `startViewTransition`.

## 5. Использование в SPA (Single Page Applications)

В React или Vanilla JS переход выглядит следующим образом:

```javascript
function navigateToPage(pageId) {
  // Проверка поддержки браузером
  if (!document.startViewTransition) {
    updateDOM(pageId); // Обычное обновление без анимации
    return;
  }

  // Запуск нативного перехода
  document.startViewTransition(() => {
    // Внутри колбэка обновляем DOM синхронно или возвращаем Promise
    updateDOM(pageId);
  });
}
```

---

## 6. Использование в MPA (Multi-Page Applications)

Начиная с Chrome 126, View Transitions API поддерживает нативные переходы между физическими HTML-страницами (без SPA).

Чтобы включить эту фичу, обе страницы (старая и новая) должны содержать CSS-правило `@view-transition`:

```css
@view-transition {
  navigation: auto; /* Включает переходы при стандартной навигации в браузере */
}
```

При переходе по ссылкам браузер автоматически выполнит плавный transition между страницами, сохраняя историю переходов ("Назад" / "Вперед").

---

## 7. Доступность (a11y)

Как и любые другие анимации, переходы страниц могут вызывать дискомфорт у людей с вестибулярными расстройствами. Переопределяйте или отключайте переходы для медиа-запроса `prefers-reduced-motion`:

```css
@media (prefers-reduced-motion: reduce) {
  ::view-transition-group(*),
  ::view-transition-old(*),
  ::view-transition-new(*) {
    animation: none !important;
  }
}
```
