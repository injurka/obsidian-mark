# Селектор :has() (Родительский селектор)

Псевдокласс **`:has()`** — это одно из самых революционных нововведений в CSS за последние годы. Он представляет собой долгожданный «родительский селектор», позволяющий стилизовать элемент в зависимости от того, какие дочерние элементы или состояния потомков находятся внутри него.

---

## 1. Зачем нужен :has()?

Исторически CSS умел двигаться по DOM-дереву только сверху вниз и вправо (к последующим соседям). Выбрать родителя на основе ребенка или предыдущего соседа было невозможно.

*   *Раньше (на JS):* Приходилось вешать слушатели событий в React/JS, чтобы при фокусе инпута добавлять класс `.is-focused` на его родительскую обертку.
*   *Сейчас (на чистом CSS):* Мы пишем `.wrapper:has(input:focus)` и стилизуем обертку.

---

## 2. Практические кейсы использования

### 2.1. Стилизация родительского контейнера на основе его детей
Мы можем менять раскладку карточки, если внутри нее есть изображение:

```css
/* Дефолтная карточка без картинки */
.card {
  background: white;
  padding: 16px;
}

/* Если внутри карточки есть тег <img>, делаем её темной с другими отступами */
.card:has(img) {
  background: black;
  color: white;
  padding: 0;
}
```

### 2.2. Стилизация форм на основе состояния полей ввода
Подсветка всей секции формы, если пользователь сфокусирован на инпуте или если в форме есть ошибка:

```css
/* Стилизуем блок группы полей, когда инпут внутри него получает фокус */
.form-group:has(input:focus) {
  border-color: #3b82f6;
  box-shadow: 0 0 0 3px rgba(59, 130, 246, 0.15);
}

/* Красим рамку карточки в красный цвет, если чекбокс внутри нее содержит ошибку (invalid) */
.card:has(input:invalid) {
  border: 2px solid red;
}
```

### 2.3. Стилизация предыдущих соседей (Previous Sibling)
В CSS есть селектор последующего соседа `A + B`. Но нет селектора предыдущего соседа. С помощью `:has()` мы можем его имитировать:

```css
/* Стилизуем заголовок h1, только если сразу за ним следует параграф p */
h1:has(+ p) {
  margin-bottom: 8px;
}
```

### 2.4. Реактивная сетка (Grid Layout)
Смена раскладки всей сетки, если в ней появляется хотя бы один крупный элемент:

```css
/* Если внутри сетки есть хотя бы одна большая карточка, меняем алгоритм авторазмещения */
.grid:has(.card--large) {
  grid-template-columns: repeat(auto-fit, minmax(350px, 1fr));
}
```

---

## 3. Влияние на производительность (Performance)

Долгое время разработчики браузеров отказывались внедрять родительский селектор из-за потенциальных проблем с производительностью. Движок рендеринга CSS должен пересчитывать стили при каждом изменении DOM. Поиск «снизу вверх» (от ребенка к родителю) теоретически мог вызывать лаги при динамическом обновлении страницы.

### Современный статус:
Разработчики браузеров (Blink, WebKit, Gecko) оптимизировали алгоритмы инвалидации стилей. `:has()` работает быстро и поддерживается во всех современных браузерах (Chrome 105+, Safari 15.4+, Firefox 121+). 

Тем не менее, старайтесь не использовать слишком глубокие и общие конструкции вроде `html:has(*)`, так как это заставит браузер анализировать все дерево при любых изменениях. Фокусируйте селектор: `.class:has(.child)`.
