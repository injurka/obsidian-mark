# Container Queries (@container)

**Container Queries (Контейнерные запросы)** — это современный инструмент CSS, позволяющий стилизовать дочерний элемент на основе размеров его ближайшего родительского контейнера, а не всей ширины экрана (Viewport), как в классических `@media`.

---

## 1. Зачем нужны Container Queries?

В компонентном дизайне (UI-kit) один и тот же компонент карточки товара может отображаться в разных частях сайта: в широкой центральной колонке (где под него выделено 800px) и в узком сайдбаре (где под него выделено 250px).

```text
 viewport = 1200px
┌───────────────────────────┬────────────────────────┐
│  Сайдбар (250px)          │  Основная лента (950px)│
│  [Карточка товара (узка)] │  [Карточка товара]     │  ◄── Один и тот же компонент
│  (Изображение сверху)     │  (Изображение сбоку)   │
└───────────────────────────┴────────────────────────┘
```

Раньше для реализации этого приходилось писать модификаторы классов на JS (например, `<Card size="small" />`) или анализировать размеры контейнера через `ResizeObserver`. Container Queries позволяют решить эту задачу нативно средствами CSS.

---

## 2. Синтаксис и объявление контейнера

Чтобы дочерний элемент мог реагировать на размеры родителя, этот родитель должен быть объявлен как **контейнер**.

### Шаг 1: Объявляем контекст контейнера на родителе
```css
.card-wrapper {
  /* Указываем тип контейнера: inline-size отслеживает только ширину */
  container-type: inline-size;
  
  /* Опционально задаем имя контейнера для точечного обращения */
  container-name: product-grid;
}
```

### Доступные значения `container-type`:
*   `inline-size` — отслеживает изменения размера по инлайновой (горизонтальной) оси. Самый популярный вариант.
*   `size` — отслеживает размер по обеим осям (ширину и высоту). Требует жестко заданных размеров самого контейнера.
*   `normal` — элемент больше не является контейнером запросов по размеру, но остается контейнером для запросов стилей (Style Queries).

---

### Шаг 2: Пишем запросы для дочерних элементов
Используем директиву `@container`:

```css
/* Дефолтный стиль карточки (узкий вид) */
.product-card {
  display: flex;
  flex-direction: column;
}

/* Если ширина родителя .card-wrapper превышает 400px */
@container (min-width: 400px) {
  .product-card {
    flex-direction: row;
    align-items: center;
    gap: 16px;
  }
}
```

Мы также можем нацелиться на конкретный именованный контейнер:
```css
@container product-grid (min-width: 600px) {
  .product-card {
    grid-column: span 2;
  }
}
```

## 3. Новые единицы измерения (Container Query Units)

Вместо `vw` (1% Viewport Width) и `vh` (1% Viewport Height) Container Queries вводят новые относительные единицы измерения:

*   **`cqw`** — 1% от ширины контейнера.
*   **`cqh`** — 1% от высоты контейнера.
*   **`cqi`** — 1% от инлайнового размера контейнера (ширины при горизонтальном письме).
*   **`cqb`** — 1% от блочного размера контейнера (высоты).
*   **`cqmin`** — наименьшее значение между `cqi` и `cqb`.
*   **`cqmax`** — наибольшее значение между `cqi` и `cqb`.

**Пример (Адаптивный размер текста относительно размера карточки):**
```css
.product-card-title {
  /* Шрифт будет увеличиваться вместе с увеличением ширины карточки */
  font-size: clamp(1rem, 5cqi, 2.5rem);
}
```
