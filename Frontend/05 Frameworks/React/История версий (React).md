
В этом документе подробно описаны основные изменения в мажорных версиях React с примерами кода и интересными фактами.

## React 19 (2024)

React 19 сфокусирован на автоматизации оптимизации производительности и упрощении работы с данными и формами.

### 1. React Compiler (Автоматическая мемоизация)
Революционное изменение. Компилятор автоматически мемоизирует компоненты и хуки, устраняя необходимость вручную писать `useMemo`, `useCallback` и `React.memo`.
* **Пример:**
  Раньше для предотвращения лишних рендеров приходилось делать так:
  ```jsx
  const memoizedValue = useMemo(() => computeExpensiveValue(a, b), [a, b]);
  ```
  В React 19 вы просто пишете обычный код:
  ```jsx
  const value = computeExpensiveValue(a, b);
  ```
  Компилятор сам понимает, когда нужно пересчитать значение.
* **Интересность:** React Compiler начинался как исследовательский проект "React Forget", анонсированный еще в 2021 году. Его цель была сделать React по-настоящему реактивным без лишнего ручного труда.

### 2. React Server Components (RSC)
Серверные компоненты позволяют рендерить UI на сервере. Это уменьшает размер бандла JavaScript, который отправляется клиенту, и улучшает SEO.
* **Пример:**
  Компонент может напрямую обращаться к базе данных, так как выполняется на сервере:
  ```jsx
  // Этот компонент не отправляется в клиентский JS-бандл!
  async function Article({ id }) {
    const article = await db.articles.get(id);
    return <h1>{article.title}</h1>;
  }
  ```
* **Интересность:** RSC стирают грань между бэкендом и фронтендом. Они позволяют передавать не просто HTML, а сериализованное дерево компонентов, которое клиентский React объединяет с интерактивными клиентскими компонентами.

### 3. Actions API и новые хуки для форм
Значительно упрощена работа с мутациями данных и отправкой форм.
* **Новые хуки:**
  - `useActionState` (ранее `useFormState`): управляет состоянием ответа от Action.
  - `useFormStatus`: позволяет дочерним компонентам формы (например, кнопкам) узнать, отправляется ли форма сейчас.
  - `useOptimistic`: позволяет мгновенно обновить UI еще до ответа сервера.
* **Пример:**
  ```jsx
  function SubmitButton() {
    const { pending } = useFormStatus();
    return <button disabled={pending}>Submit</button>;
  }

  function Form() {
    const [error, submitAction] = useActionState(updateName, null);
    return (
      <form action={submitAction}>
        <input name="name" />
        <SubmitButton />
        {error && <p>{error}</p>}
      </form>
    );
  }
  ```

### 4. Универсальный хук `use`
Новый хук, позволяющий "читать" ресурсы (например, Promises или Context) прямо в теле компонента (в том числе условно, внутри `if`, что запрещено для обычных хуков).
* **Пример:**
  ```jsx
  function Message({ messagePromise }) {
    // React приостановит рендер (Suspense), пока promise не разрешится
    const message = use(messagePromise); 
    return <p>{message}</p>;
  }
  ```

### 5. Упрощение работы с Refs и Метаданными
Отказ от `forwardRef`. Теперь `ref` передается как обычный проп. Также добавлена нативная поддержка метатегов (`<title>`, `<meta>`, `<link>`), которые автоматически переносятся в `<head>`.
* **Пример:**
  ```jsx
  // Больше никакого forwardRef!
  function MyInput({ placeholder, ref }) {
    return <input placeholder={placeholder} ref={ref} />;
  }
  ```

## React 18 (2022)

Главной темой React 18 стало конкурентное выполнение (Concurrent Rendering).

### 1. Concurrent Rendering (Конкурентный рендеринг)
Фундаментальное изменение, позволяющее React прерывать, приостанавливать или возобновлять рендеринг компонентов для обеспечения плавности UI.
* **Интересность:** Раньше процесс рендеринга в React был синхронным и блокирующим: начав рендер дерева, React не мог остановиться, пока не закончит. Конкурентный режим работает как продвинутая операционная система, переключаясь между задачами.

### 2. Automatic Batching (Автоматическое пакетирование)
Оптимизация производительности: React объединяет несколько обновлений состояния в один рендер, даже если они происходят в асинхронном коде (например, в `setTimeout` или после `fetch`).
* **Пример:**
  ```jsx
  setTimeout(() => {
    setCount(c => c + 1);
    setFlag(f => !f);
    // React 17 сделал бы 2 рендера. React 18 делает только 1 рендер!
  }, 1000);
  ```

### 3. Transitions (Переходы)
Новое API (`startTransition`, `useTransition`) для разделения срочных обновлений состояния (ввод текста) и несрочных (тяжелая фильтрация списка).
* **Пример:**
  ```jsx
  const [isPending, startTransition] = useTransition();
  const [query, setQuery] = useState('');
  
  function handleChange(e) {
    // Срочное обновление (чтобы инпут не тормозил)
    setInputValue(e.target.value);
    
    // Несрочное обновление (фильтрация большого списка)
    startTransition(() => {
      setQuery(e.target.value);
    });
  }
  ```

### 4. Suspense на сервере
Поддержка `<Suspense>` при серверном рендеринге (SSR). Позволяет отправлять HTML клиенту по частям по мере загрузки данных.
* **Интересность:** Это решило проблему SSR: раньше нужно было дождаться загрузки всех данных на сервере, прежде чем отдать хотя бы байт HTML. Теперь можно сразу отдать "скелет" страницы, а контент "дослать" позже по тому же HTTP-соединению.

### 5. Новые API: `createRoot` и `useId`
Замена `ReactDOM.render` на `createRoot`. Хук `useId` для генерации уникальных ID (особенно полезно для доступности `aria-` атрибутов).
* **Пример:**
  ```jsx
  const id = useId();
  return (
    <>
      <label htmlFor={id}>Name:</label>
      <input id={id} type="text" />
    </>
  );
  ```

## React 17 (2020)

React 17 был назван "релизом без новых фич". Это был мост для постепенного обновления.

### 1. Изменение Event Delegation (Делегирование событий)
React перестал вешать слушатели событий на `document`. Теперь они вешаются на корневой элемент приложения (`root`).
* **Интересность:** Это изменение позволило безопасно встраивать несколько разных версий React на одну страницу, что стало спасением для микрофронтендов.

### 2. Новый JSX Transform
Позволил использовать JSX без импорта React.
* **Пример:**
  Раньше в каждом файле требовалось: `import React from 'react';`
  Начиная с React 17, Babel и TypeScript компилируют JSX с помощью новых точек входа, и ручной импорт больше не нужен.

### 3. Улучшение очистки эффектов
Очистка `useEffect` (функция, которую он возвращает) стала запускаться асинхронно после отрисовки экрана, что ускорило размонтирование.

## React 16 (2017-2019)

Одна из самых масштабных версий в истории React, представившая Хуки и Fiber.

### 1. React Hooks (16.8)
Позволили использовать состояние и жизненный цикл в функциональных компонентах.
* **Пример:**
  ```jsx
  function Counter() {
    const [count, setCount] = useState(0);
    return <button onClick={() => setCount(count + 1)}>{count}</button>;
  }
  ```
* **Интересность:** До хуков функциональные компоненты назывались "Stateless Components". Хуки полностью изменили способ написания React-приложений, сделав классы устаревшими.

### 2. Fiber Architecture (16.0)
Полное переписывание алгоритма согласования (Reconciler).
* **Интересность:** Проект переписывания ядра длился около 2 лет. Разработчики React создали механизм, который разбивал работу на мелкие куски (fibers), что в будущем (в React 18) позволило реализовать Concurrent Mode.

### 3. Context API (16.3)
Официальное решение проблемы prop-drilling.
* **Пример:**
  ```jsx
  const ThemeContext = React.createContext('light');
  ```
* **Интересность:** До 16.3 существовал "старый" (legacy) Context, но он был нестабильным, и команда React предупреждала не использовать его. 16.3 дал официальный зеленый свет.

### 4. Error Boundaries (Предохранители)
Позволили перехватывать ошибки JS в дочернем дереве, предотвращая падение всего приложения.
* **Пример:** Использование метода жизненного цикла `componentDidCatch` (только в классах) для рендера запасного UI.

### 5. Portals и Fragments
- **Portals:** `ReactDOM.createPortal` позволил рендерить элементы вне родительского DOM-узла (идеально для модалок).
- **Fragments:** `<></>` позволили возвращать несколько элементов без лишних оберток `<div>`.

## React 15 (2016)

Важные улучшения работы с DOM.

### 1. document.createElement
Отказ от генерации HTML-строк и `innerHTML` при монтировании в пользу прямого использования `document.createElement`.
* **Интересность:** Это значительно улучшило производительность и закрыло потенциальные уязвимости XSS.

### 2. Поддержка SVG
React начал полномасштабно поддерживать теги и атрибуты SVG.

### 3. Отказ от лишних `<span>`
Раньше текстовые узлы в React оборачивались в `<span data-reactid="...">`, что сильно загрязняло DOM. В React 15 они стали рендериться как чистые текстовые узлы браузера.
