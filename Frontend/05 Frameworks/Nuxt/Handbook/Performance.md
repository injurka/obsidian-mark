# Оптимизация производительности

Nuxt из коробки предлагает множество решений для оптимизации, но разработчику важно знать основные подходы для достижения максимальной скорости.

## Гибридный рендеринг (Route Rules)

Не всем страницам нужен динамический SSR. `routeRules` в `nuxt.config.ts` позволяют кешировать ответы сервера (SWR) или пререндерить статику (SSG) на уровне отдельных маршрутов.

```ts
export default defineNuxtConfig({
  routeRules: {
    // Главная страница пререндерится при сборке (SSG)
    '/': { prerender: true },
    // API ответы кешируются на 60 секунд (SWR)
    '/api/**': { swr: 60 },
    // Панель управления работает как SPA (без SSR)
    '/dashboard/**': { ssr: false }
  }
})
```

## Lazy Loading (Ленивая загрузка)

Для отложенной загрузки компонентов достаточно добавить префикс `Lazy` к их имени:

```vue
<template>
  <div>
    <Header />
    <!-- Этот компонент загрузится только если v-if станет true -->
    <LazyHeavyChart v-if="showChart" />
  </div>
</template>
```

## Nuxt Image (@nuxt/image)

Официальный модуль для оптимизации изображений. Он автоматически конвертирует форматы (WebP, AVIF), изменяет размер на сервере и предоставляет атрибут `loading="lazy"`.

```vue
<NuxtImg src="/photo.jpg" width="800" height="600" format="webp" />
```

## Исключение страниц из бандла (ClientOnly и ServerOnly)

- `<ClientOnly>` - компонент внутри отрендерится только в браузере (полезно для тяжелых клиентских библиотек).
- `<ServerOnly>` - компонент отрендерится на сервере, клиентская гидратация и JS для него будут удалены (полезно для статических блоков).

## Оптимизация шрифтов

Рекомендуется использовать модуль `@nuxt/fonts` для автоматического скачивания, локального кеширования и инлайнинга веб-шрифтов, что предотвращает сдвиги макета (CLS).
