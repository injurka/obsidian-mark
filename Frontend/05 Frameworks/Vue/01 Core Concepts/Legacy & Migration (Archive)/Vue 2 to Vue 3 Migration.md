
В **Vue 2** реактивность строилась на методе `Object.defineProperty`. При инициализации компонента фреймворк рекурсивно обходил весь объект `data` и превращал каждое свойство в пару геттер/сеттер. 

В **Vue 3** используется объект `Proxy` — встроенная возможность JavaScript создавать невидимую «обертку» вокруг целевого объекта, перехватывающую любые операции с ним.

Это изменение решило 3 фундаментальные проблемы Vue 2.

---

## 1. Проблема добавления и удаления свойств

**В Vue 2 (defineProperty):**
Геттеры и сеттеры привязываются к **конкретным ключам**. Если при инициализации свойства `user.age` не было в объекте, Vue не мог повесить на него сеттер.
```javascript
// Vue 2
const user = { name: 'Иван' }; // Vue вешает сеттер только на 'name'
user.age = 30; // Изменение не вызовет перерисовку экрана!
```
Чтобы обойти это, разработчикам приходилось использовать специальные костыли: `Vue.set(user, 'age', 30)` или `this.$delete(user, 'name')`.

**В Vue 3 (Proxy):**
Proxy оборачивает **сам объект**, а не его ключи. Любая операция (даже обращение к несуществующему ключу, его добавление или удаление через оператор `delete`) проходит через перехватчики (traps) Прокси.
```javascript
// Vue 3
const user = reactive({ name: 'Иван' });
user.age = 30; // Proxy перехватывает добавление нового ключа. Реактивность работает из коробки!
delete user.name; // Proxy перехватывает удаление.
```

---

## 2. Боль с Массивами и Коллекциями (Map/Set)

**В Vue 2 (defineProperty):**
Механизм геттеров/сеттеров ужасно работал с массивами. Vue 2 не мог отследить изменение по индексу или изменение длины:
```javascript
// Vue 2
this.items[0] = 'Новое значение'; // НЕ РЕАКТИВНО
this.items.length = 0; // НЕ РЕАКТИВНО
```
Под капотом Vue 2 приходилось подменять («манки-патчить») стандартные методы массивов (`push`, `pop`, `splice`), чтобы они вызывали обновление экрана. Также Vue 2 не поддерживал реактивность для структур данных `Map`, `Set` и `WeakMap`.

**В Vue 3 (Proxy):**
Для Proxy массив — это просто объект, а индексы — это его ключи. Proxy нативно перехватывает операцию `items[0] = ...` и изменение свойства `length`. Также Vue 3 обеспечивает полноценную реактивную поддержку для `Map` и `Set`.

---

## 3. Производительность: Жадная vs Ленивая инициализация

Это самое важное отличие, влияющее на скорость работы приложения.

**В Vue 2 (Жадная инициализация):**
Если вы загрузили с сервера массив из 1000 сложных объектов и положили его в `data`, Vue 2 был вынужден **немедленно**, рекурсивно обойти каждый вложенный объект и массив, вызвав `Object.defineProperty` для тысяч свойств. Это блокировало основной поток (Main Thread) и замедляло рендеринг тяжелых страниц.

**В Vue 3 (Ленивая инициализация):**
Proxy работает «лениво». Когда вы делаете объект реактивным через `reactive()`, Vue 3 создает Proxy только для верхнего уровня.
Если внутри есть вложенный объект, он **не становится реактивным до тех пор, пока вы к нему не обратитесь**. 

Под капотом это работает так:
```javascript
// Упрощенный код Proxy из Vue 3
const proxy = new Proxy(target, {
  get(obj, key) {
    const value = obj[key];
    // Отслеживаем зависимость (кто сейчас читает свойство)
    track(obj, key);
    
    // ЛЕНИВАЯ РЕАКТИВНОСТЬ: Если значение - объект, мы оборачиваем его в Proxy 
    // только в момент чтения, а не заранее!
    if (typeof value === 'object') {
      return reactive(value);
    }
    return value;
  }
});
```
Благодаря этому стартовая загрузка (особенно для больших списков данных) в Vue 3 стала в разы быстрее, а потребление памяти — существенно ниже.

---

## 4. Изоляция системы реактивности

**В Vue 2:** Реактивность была намертво привязана к контексту компонента (к `this`). Вы не могли просто создать реактивный стейт в отдельном `.js` файле без костылей вроде `new Vue({ data: ... })`.

**В Vue 3:** Поскольку Proxy позволили сделать реактивность прозрачной, команда Vue выделила её в отдельный независимый пакет `@vue/reactivity`. 
Именно это сделало возможным появление **Composition API** (`ref`, `reactive`, `computed`), который позволяет описывать и переиспользовать реактивную логику вообще без привязки к компонентам.

---

## Резюме для самопроверки

1. **Суть:** Vue 2 переписывал ключи через `Object.defineProperty` (геттеры/сеттеры). Vue 3 оборачивает объекты в `Proxy`.
2. **Добавление свойств:** В Vue 3 больше не нужны `$set` и `$delete`. Вы просто работаете с объектом как с обычным JS.
3. **Массивы:** Vue 3 нативно отслеживает изменение массивов по индексу (`arr[0] = 1`) и изменение `length`.
4. **Скорость:** Vue 2 парсил всё дерево данных сразу (жадно). Vue 3 делает глубокие объекты реактивными «на лету» (лениво), когда вы их читаете. Это экономит CPU и память.
