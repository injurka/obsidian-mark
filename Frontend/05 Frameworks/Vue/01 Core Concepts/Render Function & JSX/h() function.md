
# Render-функции и функция `h()` (Hyperscript)

В Vue.js мы привыкли описывать интерфейс с помощью HTML-подобных шаблонов (`<template>`). Однако под капотом браузер не понимает эти шаблоны. При сборке проекта (или прямо в браузере) компилятор Vue парсит ваш `<template>` и превращает его в **Render-функцию** — обычный JavaScript-код, который возвращает дерево виртуального DOM (Virtual DOM). 

Функция **`h()`** (сокращение от *Hyperscript* — скрипт, генерирующий HTML) — это публичный инструмент, позволяющий вам пропустить этап компиляции и создавать узлы Virtual DOM (VNodes) напрямую с помощью JavaScript.

---

## 1. Что такое VNode и зачем нужен `h()`?

Функция `h()` **не создает реальные DOM-элементы** (вроде `document.createElement`). Она возвращает **VNode (Virtual Node)** — легковесный JavaScript-объект, который описывает, как должен выглядеть реальный узел. Vue собирает эти объекты в дерево, сравнивает его с предыдущим состоянием (Diffing) и точечно обновляет реальный DOM.

**Когда использовать `h()` вместо `<template>`?**
1. **Высокодинамичные компоненты:** Когда теги или структура зависят от сложной JS-логики. (Например, компонент `<Heading level="2">`, который должен рендерить `<h1...h6>` в зависимости от пропса. Через `h()` это пишется в одну строку, а в `<template>` потребовалось бы 6 `v-if`).
2. **Библиотеки компонентов и Headless UI:** Разработчики библиотек часто используют render-функции для максимальной гибкости абстракций, создания оберток и управления слотами без привязки к HTML-разметке.

---

## 2. Анатомия функции `h()`

Сигнатура функции очень гибкая и подстраивается под переданные аргументы:
```javascript
h(type, propsOrChildren?, children?)
```

1. **`type` (Обязательно):** Что рендерим? Строка (например, `'div'`), объект компонента Vue или асинхронный компонент.
2. **`props` (Опционально):** Объект с атрибутами (`id`, `class`), пропсами компонента и слушателями событий (`onClick`).
3. **`children` (Опционально):** Вложенные элементы. Может быть строкой (текстовый узел), массивом других VNodes (вызовов `h()`) или объектом для передачи слотов в компоненты.

---

## 3. Отказ от директив: Шаблоны превращаются в JS

Поскольку вы пишете на чистом JavaScript, встроенные директивы Vue (`v-if`, `v-for`, `v-model`) здесь не работают. Всю эту логику вы реализуете нативными средствами языка.

### Условный рендеринг (`v-if` / `v-show`)
Вместо `v-if` используются `if/else` или тернарные операторы:
```javascript
// v-if="isReady"
return () => isReady.value ? h('div', 'Готово') : null; // null не отрендерит ничего
```

### Рендеринг списков (`v-for`)
Вместо `v-for` используется метод `Array.prototype.map()`:
```javascript
// <li v-for="item in list" :key="item.id">{{ item.text }}</li>
return () => h('ul', list.value.map(item => {
  return h('li', { key: item.id }, item.text)
}))
```

### События и двустороннее связывание (`v-on` и `v-model`)
События передаются как свойства в `props`, начиная с `on` и с заглавной буквы.
Для `v-model` магия Vue исчезает: вы должны вручную передать значение (`modelValue`) и обработать событие его изменения (`onUpdate:modelValue`):
```javascript
// <input v-model="text" />
return () => h('input', {
  value: text.value,
  'onUpdate:modelValue': (newValue) => text.value = newValue
})
```

## 4. Сложный уровень: Компоненты и Слоты

Самая частая трудность при переходе на `h()` — работа с вложенными компонентами и их слотами. 

Если в `children` передать массив VNodes — они попадут в `default` слот дочернего компонента. Для именованных слотов `children` должен быть **объектом с функциями**, возвращающими VNodes:

```javascript
import { h, defineComponent } from 'vue'
import CustomCard from './CustomCard.vue' // Обычный .vue компонент

export default defineComponent({
  setup() {
    return () => h(CustomCard, 
      // Пропсы для CustomCard
      { theme: 'dark' }, 
      
      // Объект со слотами (каждый слот - это функция)
      {
        header: () => h('h1', 'Заголовок карточки'),
        default: () => [h('p', 'Основной контент'), h('p', 'Еще текст')],
        footer: (slotProps) => h('span', `Футер. Данные из слота: ${slotProps.text}`)
      }
    )
  }
})
```

## 5. Альтернатива: JSX / TSX

Писать многоэтажные вложенные вызовы `h()` вручную («hyperscript-лапшу») очень тяжело читать. Поэтому в экосистеме Vue, как и в React, активно используется **JSX** — синтаксический сахар, который позволяет писать HTML-подобный код прямо в JavaScript.

Специальный плагин для Babel (или встроенный сборщик в Vite) на лету компилирует этот JSX:
```jsx
// Ваш код на JSX:
const vnode = <div id="app"><span class="text">Привет</span></div>

// То, во что он скомпилируется под капотом (вызовы h):
const vnode = h('div', { id: 'app' }, [ h('span', { class: 'text' }, 'Привет') ])
```

---

## Резюме для самопроверки

1. **Суть:** `h()` создает VNode (объект описания), а не реальный DOM-узел. Шаблоны Vue под капотом компилируются в вызовы `h()`.
2. **Аргументы:** `(тег_или_компонент, пропсы_и_события, вложенные_элементы)`.
3. **Директивы:** В Render-функциях нет магии директив. `v-if` — это тернарный оператор, `v-for` — это `.map()`, `v-model` — это ручная передача `value` и обработка `onUpdate`.
4. **Слоты:** Передаются в дочерние компоненты как объект функций, где ключ — имя слота, а значение — функция, возвращающая массив VNodes.
5. **JSX:** Синтаксический сахар над вызовами `h()`, делающий код Render-функций читаемым.
