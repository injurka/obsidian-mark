# TanStack Query (React Query)

До появления React Query (теперь TanStack Query), разработчики использовали Redux для хранения данных, пришедших с сервера. Это было ошибкой.
Главная идея TanStack Query: **Разделение клиентского состояния (UI, модалки, фильтры) и серверного состояния (данные из базы).** 

TanStack Query — это не просто библиотека для `fetch`, это мощный **асинхронный стейт-менеджер** для серверного состояния.

## 1. Stale-Time vs Garbage Collection Time (Cache Time)
Это **самый популярный вопрос** на собеседованиях по React Query. Что означают эти две настройки?

- **`staleTime` (Время свежести):** Время, в течение которого данные считаются "свежими". Если вы вызовете хук `useQuery` для тех же данных до истечения этого времени, библиотека **вообще не будет делать запрос на сервер**, а просто мгновенно отдаст кэш. *(По умолчанию: 0 миллисекунд)*.
- **`gcTime` (Время жизни в кэше, ранее `cacheTime`):** Время, которое данные хранятся в оперативной памяти после того, как ВСЕ компоненты, использовавшие их, были размонтированы. Если пользователь вернется на страницу до истечения этого времени, он мгновенно увидит старые данные (пока в фоне идет новый запрос). Если время истекло — сборщик мусора удалит их, и пользователь увидит спиннер загрузки. *(По умолчанию: 5 минут)*.

## 2. Инвалидация кэша (Мутации)
Когда вы отправляете данные на сервер (создаете пост), вы хотите, чтобы список постов обновился. Вместо того, чтобы вручную манипулировать массивами, вы просто говорите React Query: "Кэш для постов устарел".

```tsx
import { useMutation, useQueryClient } from '@tanstack/react-query';

function useCreatePost() {
  const queryClient = useQueryClient();

  return useMutation({
    mutationFn: (newPost) => axios.post('/posts', newPost),
    onSuccess: () => {
      // Это заставит ВСЕ компоненты, у которых есть useQuery(['posts']), 
      // немедленно сделать фоновый fetch-запрос и перерисоваться!
      queryClient.invalidateQueries({ queryKey: ['posts'] });
    },
  });
}
```

## 3. ⚠️ Edge Case: Зависимые запросы (Dependent Queries)
Что если запрос B должен выполниться **только после того**, как завершится запрос A (например, нам нужен `userId`, чтобы запросить его проекты)?

Если вы попытаетесь сделать это через `useEffect` или вызовете два запроса подряд, вы получите ошибки или ненужные рендеры. 
В TanStack Query это решается ключом `enabled`:

```tsx
// 1. Получаем пользователя
const { data: user } = useQuery({
  queryKey: ['user', email],
  queryFn: getUserByEmail,
});

// 2. Получаем проекты, ТОЛЬКО если у нас уже есть user.id
const { data: projects } = useQuery({
  queryKey: ['projects', user?.id],
  queryFn: () => getProjectsByUser(user.id),
  // Запрос не полетит на сервер, пока enabled === false
  enabled: !!user?.id, 
});
```

## 4. Оптимистичные обновления (Optimistic Updates)
TanStack Query позволяет обновить интерфейс мгновенно при клике, еще до того, как сервер ответит "ОК". 
Для этого в `useMutation` используются методы `onMutate` (в котором вы вручную меняете кэш) и `onError` (в котором вы откатываете кэш назад, если запрос упал). Это золотой стандарт для лайков, добавления в корзину и галочек "Выполнено".
