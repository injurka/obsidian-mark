# E2E Testing (End-to-End)

В отличие от юнит-тестов (где мы мокаем базу данных и API) и компонентных тестов (где мы рендерим кнопку изолированно), **E2E тесты проверяют систему целиком**.
Они поднимают реальный браузер (Chromium, WebKit, Firefox), переходят по реальному URL, кликают по кнопкам и проверяют, что данные реально записались в настоящую (обычно тестовую) базу данных.

## 1. Playwright vs Cypress (Расклад сил в 2026)
Долгое время **Cypress** был бесспорным королем E2E тестирования. Но к 2026 году **Playwright** (разрабатываемый Microsoft) выиграл эту гонку и стал стандартом.

**Почему Playwright победил?**
1. **Параллелизация из коробки:** Cypress долгое время запускал тесты в одном потоке локально. Playwright с первого дня запускает тесты в несколько потоков (workers), сокращая время прогона с 20 минут до 2-3.
2. **Никаких ограничений iFrame:** Cypress работает внутри самого браузера как веб-приложение, поэтому у него огромные проблемы с iframe, несколькими вкладками (tabs) и попапами (alert/confirm). Playwright общается с браузером через протокол DevTools, поэтому может контролировать всё устройство (включая геолокацию, права на микрофон и несколько страниц).
3. **Настоящий WebKit (Safari):** В отличие от Cypress, Playwright позволяет честно тестировать баги специфичные для Safari (iOS).

## 2. Главная проблема E2E: Flaky Tests (Нестабильные тесты)
Flaky test (моргающий тест) — это тест, который то проходит успешно, то падает на одной и той же версии кода. Это проклятие E2E.

**Причины:**
- Сетевые задержки (вчера API ответило за 100мс, сегодня за 2000мс).
- Анимации интерфейса (тест попытался кликнуть на кнопку, которая еще "выезжала" из-за экрана).
- Конфликт данных в базе (параллельные тесты изменили одного и того же пользователя).

## 3. Как Playwright решает проблему Flaky Tests (Auto-waiting)
В старых фреймворках (Selenium) разработчики постоянно писали `sleep(2000)` — "подожди 2 секунды, чтобы кнопка точно появилась". Это ужасный антипаттерн, делающий тесты очень долгими.

Playwright использует **Auto-waiting (Автоматическое ожидание)**.
Когда вы пишете команду клика:
```javascript
await page.locator('button.submit').click();
```
Под капотом Playwright перед кликом автоматически проверяет целый чек-лист:
1. Элемент прикреплен к DOM?
2. Элемент видимый (visible)?
3. Элемент не анимируется прямо сейчас (перестал двигаться)?
4. Элемент не перекрыт другим элементом (например, z-index модалкой)?

Если хоть одно условие не выполнено, Playwright будет молча ждать (до таймаута, например, 30 секунд), и только когда всё "успокоится", он совершит клик. Это делает тесты невероятно стабильными.

## 4. Паттерн Page Object Model (POM)
В E2E, если у вас 50 тестов взаимодействуют со страницей Логина, и завтра вы измените ID кнопки с `#login` на `#signin`, вам придется переписывать 50 тестов.

**POM** — это паттерн ООП, где вы выносите логику страницы в отдельный класс.

```javascript
// loginPage.ts
export class LoginPage {
  constructor(public page: Page) {}

  async login(user, pass) {
    await this.page.fill('#username', user);
    await this.page.fill('#password', pass);
    await this.page.click('.submit-btn');
  }
}

// Тест
test('Успешный логин', async ({ page }) => {
  const loginPage = new LoginPage(page);
  await loginPage.login('admin', '12345');
  await expect(page.locator('.dashboard')).toBeVisible();
});
```
Теперь, при изменении селекторов, вы меняете код только в одном месте!
