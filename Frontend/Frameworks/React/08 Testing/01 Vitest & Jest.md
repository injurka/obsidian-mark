
Тест-раннеры (Test Runners) отвечают за поиск тестовых файлов, их выполнение и вывод результатов (успешно/провалено) в консоль. Они предоставляют глобальные функции, такие как `describe`, `it`, `test` и `expect`.

## 1. Jest (Старая школа)
Долгие годы Jest от Facebook был монополистом в мире React.
**Особенности:**
- Поставляется "все в одном" (runner, assertion library, mocking).
- Встроенный JSDOM (эмулятор браузера в Node.js).
**Почему теряет позиции к 2026 году?**
Jest плохо работает с ESM (ECMAScript Modules) "из коробки", требует сложных настроек Babel/Webpack для трансформации кода перед запуском тестов и медленно стартует на больших проектах.

## 2. Vitest (Новый стандарт)
Vitest — это современный тест-раннер, построенный на базе сборщика **Vite**. В 2026 году это выбор по умолчанию для большинства новых React-проектов.

**Преимущества Vitest:**
1. **Невероятная скорость:** Работает на тех же модульных графах, что и Vite, что делает запуск и HMR (Hot Module Replacement) в тестах мгновенными.
2. **Нулевая конфигурация:** Если ваш проект уже использует `vite.config.ts`, Vitest автоматически прочитает ваши алиасы, плагины и переменные окружения.
3. **API-совместимость с Jest:** Чтобы переехать с Jest на Vitest, достаточно поменять `jest.fn()` на `vi.fn()` в 99% случаев.

## 3. Mocks & Spies (Моки и Шпионы)
Изоляция — ключевой принцип юнит-тестирования. Если ваша функция делает запрос к API, тест **не должен** реально стучаться в интернет.

```javascript
import { vi, expect, test } from 'vitest';
import { fetchUserData } from './api';

// Мокаем весь модуль './api'
vi.mock('./api', () => ({
  fetchUserData: vi.fn(),
}));

test('должен корректно обрабатывать данные', async () => {
  // Настраиваем мок на возврат конкретных данных
  fetchUserData.mockResolvedValue({ name: 'Alex' });

  // Вызываем нашу логику, которая внутри использует fetchUserData...
  
  // Проверяем (Шпион), что функция была вызвана 1 раз
  expect(fetchUserData).toHaveBeenCalledTimes(1); 
});
```

## 4. ⚠️ Edge Case: Асинхронные тесты и "Ложноположительные" результаты (False Positives)
Одной из самых частых ошибок новичков в тестировании является неправильная работа с асинхронностью. Тест проходит успешно (зеленый свет), хотя в коде баг.

**❌ ПЛОХО:**
```javascript
test('тестируем API', () => {
  fetchData().then(data => {
    // Если fetchData упадет с ошибкой до выполнения then,
    // эта строчка никогда не выполнится. 
    // Тест завершится синхронно и покажет УСПЕХ!
    expect(data).toBe('some data'); 
  });
});
```

**✅ ХОРОШО (Используем async/await):**
```javascript
test('тестируем API', async () => {
  const data = await fetchData();
  expect(data).toBe('some data'); 
});
```
Если `fetchData` выкинет ошибку, промис будет отклонен, тест это перехватит и честно покажет провал (Красный свет).
