# Micro-frontends (Микрофронтенды)

Архитектурный подход, при котором монолитное фронтенд-приложение разбивается на мелкие, независимые приложения (микрофронтенды), которые выглядят для пользователя как единый цельный продукт.
Это калька с концепции Микросервисов в бэкенде.

## 1. Зачем это нужно?
Паттерн применяется исключительно в **Enterprise-проектах** с огромной кодовой базой и десятками команд разработки.

**Преимущества:**
- **Независимые релизы:** Команда "Корзины" может деплоить свой код каждый день, не дожидаясь, пока команда "Каталога" закончит тестирование своего функционала.
- **Технологическая независимость:** Теоретически, "Корзина" может быть написана на Vue, а "Каталог" на React (хотя на практике в 2026 году стараются использовать единый стек, например React, чтобы не грузить браузер пользователя тремя разными фреймворками).

## 2. Как это реализуется: Module Federation
**Module Federation** (появился в Webpack 5, сейчас активно используется в Rspack и Vite) — это индустриальный стандарт для микрофронтендов.

Он позволяет одному JavaScript-приложению динамически загружать код из другого JavaScript-приложения в рантайме (прямо в браузере), при этом **разделяя общие зависимости**.

### Архитектура
1. **Host (Shell / Хост-приложение):** Каркас приложения (Хедер, Футер, Роутинг).
2. **Remote (Удаленное приложение):** Отдельно развернутое приложение (например, `CartApp` на `cart.domain.com`), которое предоставляет свои компоненты.

**Пример конфигурации Webpack/Vite на стороне Remote:**
```javascript
// Мы "выставляем" наружу компонент корзины
new ModuleFederationPlugin({
  name: 'cartApp',
  filename: 'remoteEntry.js',
  exposes: {
    './CartWidget': './src/components/CartWidget',
  },
  shared: { react: { singleton: true }, 'react-dom': { singleton: true } },
});
```

**Пример использования в Host:**
```jsx
import React, { lazy, Suspense } from 'react';

// Динамически качаем код компонента с другого домена!
const RemoteCartWidget = lazy(() => import('cartApp/CartWidget'));

function App() {
  return (
    <div>
      <Header />
      <Suspense fallback="Загрузка корзины...">
        <RemoteCartWidget />
      </Suspense>
    </div>
  );
}
```

## 3. ⚠️ Критические недостатки и Edge Cases
На собеседованиях на сеньорские позиции любят спрашивать, *почему микрофронтенды — это боль*.

1. **Глобальный State Management:** Как передать токен авторизации из Host-приложения в Remote-корзину? (Решение: кастомные события браузера `CustomEvent` или шаринг Zustand стора через глобальный объект `window`).
2. **Конфликты версий библиотек (Dependency Clash):** Что если Host использует React 18, а Remote использует React 19? Если в `shared` настройках стоит `singleton: true`, приложение просто упадет (React запрещает иметь две копии себя на одной странице).
3. **Сложность CI/CD:** Дебажить баги, когда приложение состоит из 10 микрофронтендов, раскиданных по разным репозиториям — настоящий кошмар.
4. **Конфликты стилей:** Глобальные CSS классы из Remote могут "перекрасить" элементы в Host приложении. (Решение: CSS Modules, Tailwind со строгими префиксами или Web Components/Shadow DOM).
