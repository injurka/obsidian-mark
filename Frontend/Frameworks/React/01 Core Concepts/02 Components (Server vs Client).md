# Components (Server vs Client)

Компонент — это основной строительный блок любого React-приложения. С эволюцией React (вплоть до RSC — React Server Components) парадигма того, *где* и *как* выполняются компоненты, кардинально изменилась.

## 1. Исторический контекст
До появления Server Components мы делили компоненты на **Классовые (Class)** и **Функциональные (Functional)**. 
- Классовые управляли состоянием и жизненным циклом.
- С приходом хуков (React 16.8) функциональные компоненты стали стандартом де-факто, полностью вытеснив классы.
- **В 2026 году классовые компоненты — это исключительно legacy-код**, хотя их знания иногда проверяют на собеседованиях.

## 2. Современная архитектура: RSC (React Server Components)
Архитектура RSC делит компоненты по среде их выполнения: на клиенте (в браузере) или на сервере (во время рендера или сборки).

### Server Components (Серверные компоненты)
В Next.js App Router (и других современных мета-фреймворках) **по умолчанию все компоненты являются серверными**.

**Особенности:**
- Выполняются **только на сервере** (или на этапе сборки).
- Их код и зависимости не попадают в бандл JavaScript, который скачивается браузером (нулевой размер бандла).
- Могут быть асинхронными (`async/await`) и напрямую обращаться к базам данных или серверным API.
- **Ограничения**: В них нельзя использовать стейт (`useState`), эффекты (`useEffect`), контекст (`useContext`) и браузерные API (например, `window` или прослушиватели событий `onClick`).

**Пример серверного компонента:**
```tsx
// Это Server Component по умолчанию
import db from '@/lib/db';

export default async function UserProfile({ userId }) {
  // Прямой запрос к базе данных внутри компонента!
  const user = await db.user.findUnique({ where: { id: userId } });

  return (
    <div>
      <h1>{user.name}</h1>
      <p>{user.email}</p>
    </div>
  );
}
```

### Client Components (Клиентские компоненты)
Чтобы сделать компонент клиентским, в начале файла пишется директива `"use client"`.

**Особенности:**
- Рендерятся на сервере (для SSR - начальный HTML) и затем **гидратируются** на клиенте.
- Могут использовать интерактивность, хуки состояния, жизненного цикла и браузерные API.
- Код компонента попадает в итоговый JS-бандл.

**Пример клиентского компонента:**
```tsx
'use client'; // Директива обязательна

import { useState } from 'react';

export default function Counter() {
  const [count, setCount] = useState(0);
  // На сервере 'onClick' не имеет смысла, поэтому этот компонент должен быть клиентским
  return <button onClick={() => setCount(count + 1)}>Clicks: {count}</button>;
}
```

## 3. Взаимодействие (Interleaving) и Паттерны

### Граница "use client"
Директива `"use client"` не делает один компонент клиентским, она объявляет **границу (boundary)**. Все компоненты, импортируемые в файл с `"use client"`, автоматически становятся клиентскими.

### Важное правило (Edge Case & Подводные камни)
**❌ Нельзя напрямую импортировать Server Component внутрь Client Component.**
Если вы это сделаете, серверный компонент автоматически превратится в клиентский (или выдаст ошибку, если в нем используются Node.js API вроде `fs`).

**✅ Как правильно: Передача через Props (Children)**
Серверный компонент может передать другой серверный компонент в качестве `children` в клиентский.

```tsx
// ClientWrapper.tsx
'use client';
export default function ClientWrapper({ children }) {
  const [isOpen, setIsOpen] = useState(false);
  return (
    <div>
      <button onClick={() => setIsOpen(!isOpen)}>Toggle</button>
      {isOpen && children}
    </div>
  );
}

// ServerPage.tsx (Server Component)
import ClientWrapper from './ClientWrapper';
import HeavyServerComponent from './HeavyServerComponent';

export default function Page() {
  return (
    <ClientWrapper>
      {/* HeavyServerComponent рендерится на сервере, а клиентский компонент только управляет его видимостью! */}
      <HeavyServerComponent />
    </ClientWrapper>
  );
}
```

### Сериализация Props
Когда Server Component передает пропсы в Client Component, эти пропсы должны быть сериализуемыми (преобразуемыми в JSON).
*Необычная ситуация:* Вы **не можете** передать обычную функцию, `Date` или инстанс класса как пропс от сервера к клиенту. 
Исключение составляют **Server Actions** — специальные серверные функции, которые можно передавать клиенту для вызова мутаций.
