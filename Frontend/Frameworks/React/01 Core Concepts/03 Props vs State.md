# Props vs State

Эти две концепции управляют потоком данных в React. Несмотря на то, что они обе хранят информацию, влияющую на то, что видит пользователь, их назначение и поведение кардинально отличаются.

## 1. Ограничения и определения

### Props (Свойства)
- **Что это:** Входящие данные, которые компонент получает от своего родителя (по аналогии с аргументами функции).
- **Мутабельность:** Строго **Read-Only** (Только для чтения). Компонент *никогда* не должен изменять свои собственные пропсы. Попытка изменить пропс (например, `props.title = 'New'`) — это антипаттерн и нарушение чистой функции.
- **Цель:** Переиспользование компонентов и настройка их внешнего вида или поведения извне.

### State (Состояние)
- **Что это:** Локальные данные, которые принадлежат самому компоненту и управляются им (через `useState`, `useReducer`).
- **Мутабельность:** Изменяемо (но только через специальные функции-сеттеры, такие как `setCount`). Изменение состояния — это **основной триггер для ре-рендера** компонента в React.
- **Цель:** Хранение данных, которые меняются во времени (ввод пользователя, таймеры, данные с сервера).

---

## 2. Подъем состояния (Lifting State Up)
Так как данные в React текут сверху вниз (однонаправленный поток данных), дочерние компоненты не могут передавать данные друг другу напрямую (брату/сестре). 

Если двум компонентам нужны одни и те же данные, состояние "поднимается" к их ближайшему общему родителю.

```jsx
// ❌ Разрозненное состояние: Панель и Кнопка не могут синхронизироваться
function Panel() { const [isOpen, setIsOpen] = useState(false); ... }
function Button() { ... }

// ✅ Lifting state up
function Parent() {
  const [isOpen, setIsOpen] = useState(false);
  return (
    <>
      <Button onClick={() => setIsOpen(!isOpen)} />
      <Panel isOpen={isOpen} />
    </>
  );
}
```

## 3. Props Drilling (Просверливание пропсов)
Когда состояние поднимается слишком высоко, его приходится передавать через множество промежуточных компонентов, которым эти данные не нужны. Это называется **Props Drilling**.

**Решения проблемы:**
1. Использование **Composition (Композиции)**: Передача компонентов через `children` или другие пропсы (Render Props).
2. Использование **Context API**.
3. Использование глобальных менеджеров состояний (Zustand, Redux).

## 4. Глубокое понимание: State как Snapshot (Снимок)
Один из самых частых вопросов на собеседованиях и источник багов — понимание того, как React работает с замыканиями (closures) при изменении состояния.

**State в React работает как моментальный снимок (snapshot) для конкретного рендера.** 
Переменная состояния не меняется прямо внутри текущей выполняемой функции.

> **Пример (Edge case с асинхронностью):**

```jsx
function Counter() {
  const [count, setCount] = useState(0);

  const handleClick = () => {
    setCount(count + 1);
    setCount(count + 1);
    setCount(count + 1);
    // Что будет в console.log?
    console.log(count); // Выведет 0, а не 3!
  };

  // После рендера count станет равен 1, а не 3!
}
```
**Почему 1, а не 3?**
Потому что для текущего рендера `count` — это константа (`0`). Каждый вызов `setCount(count + 1)` читает из замыкания текущее значение и говорит React: "На следующем рендере сделай count равным 0 + 1". В итоге React просто три раза планирует установить `count` в `1`.

**Как решить? Использовать updater function (функцию обновления):**
```jsx
const handleClick = () => {
  setCount(prev => prev + 1);
  setCount(prev => prev + 1);
  setCount(prev => prev + 1);
  // Теперь после рендера count будет 3, так как мы берем актуальное состояние из очереди React.
};
```

### Deriving State (Вычисляемое состояние)
**Антипаттерн:** Дублирование пропсов в стейт.
Если данные можно вычислить из пропсов или существующего стейта, *не создавайте* для них отдельный стейт.

```jsx
// ❌ ПЛОХО
function Form({ user }) {
  const [firstName, setFirstName] = useState(user.firstName);
  const [lastName, setLastName] = useState(user.lastName);
  // Нарушение единого источника истины (SSOT). При изменении user.firstName извне, стейт не обновится!
}

// ✅ ХОРОШО
function Form({ user }) {
  const fullName = `${user.firstName} ${user.lastName}`; // Вычисляется на лету
}
```
