# Accessibility (a11y) - Доступность

К 2026 году знание базовых принципов доступности (a11y от a-11-y: "accessibility") — строгое требование во многих западных и крупных СНГ компаниях (во многом из-за судебных исков за нарушение законов вроде ADA).

## 1. Семантический HTML — основа основ
Худшее, что можно сделать в React — это построить интерфейс на одних `<div>`. 
Скринридеры (VoiceOver, NVDA), которыми пользуются слабовидящие люди, не знают, как взаимодействовать с `<div>`.

```jsx
// ❌ ПЛОХО: Кнопка на дивах. Скринридер скажет просто "Отправить" и пойдет дальше.
// Пользователь не сможет нажать её пробелом или Enter.
<div onClick={submit} className="button-style">Отправить</div>

// ✅ ХОРОШО: Нативный тег. Скринридер скажет "Отправить, кнопка".
// Клавиатурный фокус и нажатия работают "из коробки".
<button onClick={submit}>Отправить</button>
```

## 2. ARIA атрибуты в React
Если нативный HTML не может описать сложность вашего виджета (например, вы делаете кастомный Dropdown или Slider), вам нужно использовать `aria-*` атрибуты.

- `aria-expanded={isOpen}`: Сообщает, раскрыто ли в данный момент выпадающее меню.
- `aria-label="Закрыть модальное окно"`: Озвучивает текст для кнопки, внутри которой только иконка `X` (крестик). Без этого скринридер скажет просто "Кнопка".

## 3. Управление фокусом и Focus Trap
Слепые пользователи или люди с нарушениями моторики не используют мышь. Они перемещаются по сайту клавишей **Tab**.

**Сценарий:** Пользователь открывает модальное окно. 
**Проблема:** Если он продолжит нажимать Tab, фокус "улетит" за пределы модалки на скрытые элементы заднего фона (под модалкой). Пользователь потеряется.
**Решение:** Имплементация **Focus Trap (Ловушка фокуса)**. Фокус должен "зацикливаться" внутри открытого модального окна, пока оно не будет закрыто (клавишей Escape). Большинство Headless UI библиотек (Radix, MUI) делают это за вас.

## 4. ⚠️ Edge Case в React: Анонс динамических изменений (aria-live)
В обычном интернете загрузка новой страницы — это событие, о котором скринридер уведомляет пользователя.
В React (Single Page Application) контент меняется *динамически*, без перезагрузки. Скринридер об этом **не знает**.

Представьте: пользователь нажимает кнопку "Сохранить профиль". Рядом появляется зеленый текст "Успешно сохранено". Зрячий это увидит. Слепой — нет, для него ничего не произошло.

**Решение: `aria-live` (Живые регионы)**
```jsx
// Этот компонент должен присутствовать в DOM всегда (изначально пустой)
// "polite" означает, что скринридер дочитает текущее предложение, а потом анонсирует это сообщение.
<div aria-live="polite" className="sr-only">
  {notificationText} 
</div>
```
Класс `sr-only` (Screen Reader Only) — это специальный CSS, который прячет элемент визуально (через clipping), но оставляет его в DOM для "прочтения" скринридерами (в отличие от `display: none`).

## 5. Инструменты тестирования
Никто не пишет a11y идеально с нуля. Настройте инструменты:
- **eslint-plugin-jsx-a11y**: Линтер будет ругаться в IDE, если вы добавите `onClick` на `<div>` без атрибута `role="button"`.
- **Axe DevTools**: Расширение браузера, которое сканирует страницу на наличие проблем контрастности и семантики.
