# Internationalization (i18n) - Локализация

Создание мультиязычных React-приложений — это не просто замена текста "Hello" на "Привет". Это сложная экосистема работы с плюрализацией (окончаниями), форматированием дат, валют и направлением текста (RTL - Right to Left, например для арабского языка).

Индустриальный стандарт в React экосистеме — библиотека **`i18next`** (в связке с `react-i18next`).

## 1. Базовое использование (Словари)
Тексты хранятся в JSON-файлах (словарях).
```json
// en.json
{
  "header": {
    "welcome": "Welcome back, {{name}}!"
  }
}
```

В компоненте мы используем хук `useTranslation`:
```jsx
import { useTranslation } from 'react-i18next';

function Header({ userName }) {
  const { t } = useTranslation();
  
  // Вставит имя переменной вместо {{name}}
  return <h1>{t('header.welcome', { name: userName })}</h1>; 
}
```

## 2. Плюрализация (Склонения - Боль и слезы)
Один из самых сложных аспектов i18n, особенно для русского языка (1 яблоко, 2 яблока, 5 яблок). В английском их всего два (apple / apples).

Современные библиотеки используют **ICU Message Format** (стандарт интернационализации).
```json
// ru.json
{
  "apples_count_one": "{{count}} яблоко",
  "apples_count_few": "{{count}} яблока",
  "apples_count_many": "{{count}} яблок"
}
```
Библиотека `i18next` сама определит правильный суффикс на основе переданного числа.

```jsx
// Выведет "5 яблок"
<p>{t('apples_count', { count: 5 })}</p> 
```

## 3. ⚠️ Edge Case: Cumulative Layout Shift (CLS)
Перевод текста часто ломает верстку. Немецкий текст может быть на 30-50% длиннее английского.
Если ваша кнопка имела фиксированную ширину `width: 150px`, в немецкой локализации текст просто вылезет за её пределы (Overflow).

**Решение:**
Никогда не задавайте фиксированную ширину и высоту текстовым контейнерам. Используйте `padding`, `min-width`, `flex` и `max-content`, чтобы UI "дышал" и растягивался под контент.

## 4. Server-Side i18n (В Next.js App Router)
К 2026 году перевод страниц на клиенте (когда грузится английская версия, а потом JS-скрипт меняет её на русскую) считается плохой практикой из-за проблем с SEO и мерцанием.

В Next.js локализация работает на уровне роутинга:
URL выглядит как `example.com/en/about` или `example.com/ru/about`.
Папка `app` оборачивается в динамический сегмент `[locale]`.

```tsx
// app/[locale]/page.tsx
// Server Component принимает локаль из URL и рендерит готовую статику нужного языка!
export default async function Page({ params: { locale } }) {
  // Читаем словарь на сервере
  const dict = await import(`@/dictionaries/${locale}.json`); 
  
  return <h1>{dict.welcome}</h1>;
}
```
Поисковики (Google, Яндекс) получают чистый HTML на правильном языке.
