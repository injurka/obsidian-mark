# React Compiler (ранее React Forget)

Одним из самых мощных обновлений React 19 (и стандарта 2026 года) стало внедрение **React Compiler**.

## 1. Проблема ручной мемоизации
Годами разработчики страдали, вручную расставляя `useMemo`, `useCallback` и `React.memo` по всему проекту. 
Это приводило к двум проблемам:
1. **Загрязнение кода:** Код становится трудно читать.
2. **Ошибки:** Забыли добавить переменную в массив зависимостей хука — получили Stale Closure. Добавили слишком много — мемоизация ломается.

## 2. Что делает React Compiler?
Это инструмент сборки (Babel-плагин), который анализирует ваш код и **автоматически добавляет мемоизацию под капотом**.

Вам больше не нужно писать это:
```jsx
// ❌ Старый подход (ДО компилятора)
const Header = React.memo(({ user, onLogout }) => { ... });

function App() {
  const handleLogout = useCallback(() => logout(), []);
  const config = useMemo(() => ({ theme: 'dark' }), []);
  return <Header user={user} onLogout={handleLogout} config={config} />;
}
```

Вы просто пишете обычный, чистый JavaScript:
```jsx
// ✅ Новый подход (С компилятором)
function Header({ user, onLogout }) { ... }

function App() {
  const handleLogout = () => logout();
  const config = { theme: 'dark' };
  // Компилятор САМ поймет, что эти объекты не меняются, и закэширует их на уровне Fiber-дерева!
  return <Header user={user} onLogout={handleLogout} config={config} />;
}
```

## 3. Как это работает под капотом
Компилятор анализирует потоки данных (Data Flow) внутри компонента. Если он видит, что создание массива или объекта зависит только от определенных пропсов, он генерирует кэширующий код (используя новые внутренние хуки, недоступные разработчикам напрямую, например `useMemoCache`). 
Он способен мемоизировать даже отдельные куски JSX (например, если внутри компонента изменился один `<div>`, а соседний `<ul>` не изменился, React Compiler закэширует результат выполнения `<ul>`).

## 4. Что Компилятор НЕ решает (Edge Cases)
Важно понимать на собеседовании, что React Compiler — это не "волшебная палочка", которая исправит плохую архитектуру.

1. **Глобальный стейт (Context):** Если вы используете один гигантский `useContext`, и его значение поменялось, компилятор не спасет от каскадного ре-рендера всех подписанных компонентов.
2. **"Грязные" функции:** Компилятор полагается на то, что ваши компоненты и функции — это **Чистые Функции (Pure Functions)**. Если вы мутируете внешние переменные (Side Effects) прямо в теле рендера компонента, компилятор либо сломает вам приложение, либо откажется его оптимизировать.
3. **Отказ от мемоизации:** Если по какой-то причине автоматическая мемоизация ломает логику (что бывает крайне редко), вы можете добавить директиву `"use no memo"` в начале функции, чтобы компилятор ее проигнорировал.
