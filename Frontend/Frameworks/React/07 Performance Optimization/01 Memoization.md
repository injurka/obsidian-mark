# Memoization (Мемоизация)

Мемоизация — это техника оптимизации, при которой сохраняется (кэшируется) результат дорогостоящей функции, и при повторном вызове с теми же аргументами возвращается закэшированный результат.

В React есть три главных инструмента для этого: `useMemo`, `useCallback` (описаны в разделе Hooks) и `React.memo`.

## 1. React.memo (HOC)
По умолчанию в React, если рендерится родительский компонент, **БЕЗУСЛОВНО** рендерятся и все его дочерние компоненты, даже если их пропсы не изменились.

Обернув компонент в `React.memo`, вы говорите React: *"Перед тем как рендерить этот компонент, проверь его пропсы. Если они строго равны предыдущим, пропусти рендер и используй старый результат"*.

```jsx
const ExpensiveChild = React.memo(({ title }) => {
  console.log('Рендер ExpensiveChild');
  return <div>{title}</div>;
});

// Если в Parent изменится count, ExpensiveChild НЕ перерисуется (title остался тем же).
function Parent() {
  const [count, setCount] = useState(0);
  return (
    <>
      <ExpensiveChild title="Статика" />
      <button onClick={() => setCount(c => c + 1)}>Клик {count}</button>
    </>
  );
}
```

## 2. ⚠️ Главная ошибка: Нарушение ссылочной идентичности (Referential Equality)
Мемоизация компонента ломается, если вы передаете в него объекты, массивы или функции, созданные "на лету" внутри родителя.

**❌ ПЛОХО: React.memo бесполезен**
```jsx
// Каждый рендер Parent создает НОВУЮ функцию в памяти.
// React.memo сравнивает (старая функция === новая функция) -> false.
// И компонент перерисовывается.
<ExpensiveChild onClick={() => console.log('Клик!')} /> 

// Аналогично с объектами:
<ExpensiveChild config={{ theme: 'dark' }} />
```

**✅ ХОРОШО: Использование useCallback и useMemo**
```jsx
const handleClick = useCallback(() => console.log('Клик!'), []);
const config = useMemo(() => ({ theme: 'dark' }), []);

<ExpensiveChild onClick={handleClick} config={config} />
```

## 3. Антипаттерн: Налог на мемоизацию (Overhead)
Частый вопрос на собеседованиях: *"Почему бы не обернуть ВСЕ компоненты в React.memo?"*
Потому что сравнение пропсов не бесплатно. 
Функция `Object.is()`, которая проходится по всем ключам пропсов (`Shallow Compare`), занимает процессорное время. Если ваш компонент очень легкий (например, простой `<span>`), то затраты времени на сравнение пропсов будут **больше**, чем время на его просто перерисовку.

**Когда использовать `React.memo`:**
1. Компонент реально "тяжелый" (рисует сложный график, огромный список).
2. Компонент рендерится часто с одними и теми же пропсами.
