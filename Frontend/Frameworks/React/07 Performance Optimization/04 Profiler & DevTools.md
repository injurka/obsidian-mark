# Profiler & React DevTools

Знание того, как измерять производительность — отличительная черта Senior разработчика. React предоставляет для этого мощные встроенные инструменты.

## 1. React DevTools Extension (Расширение для браузера)
Это ваш главный инструмент при отладке "тормозов". Во вкладке **Profiler** нужно нажать запись (Record), выполнить действие на сайте (например, набрать текст в поиске) и остановить запись.

### Основные фичи Profiler:
1. **Flamegraph (Огненный граф):** Показывает дерево компонентов. Ширина блока означает, сколько времени занял рендер. Цвет блока (от зеленого до желтого/красного) показывает, насколько рендер был "тяжелым". Удобно для поиска "бутылочных горлышек".
2. **Ranked Chart:** Сортирует все отрендеренные компоненты по времени рендера от самого долгого к самому быстрому. Идеально для поиска одного виновника лагов.
3. **"Why did this render?" (Почему произошел рендер?):** Потрясающая функция! Если включить опцию записи причин рендера в настройках DevTools, вы можете кликнуть на компонент в Profiler, и он напишет: *"Пропс `user` изменился. State 1 изменился."* Это лучший способ отловить потерянную ссылочную идентичность (когда кто-то передает `style={{ color: 'red' }}` прямо в пропс).

## 2. `<Profiler>` API (Программное измерение)
Вы можете измерять рендер программно прямо в коде, чтобы, например, отправлять логи на сервер аналитики.

```jsx
import { Profiler } from 'react';

function onRenderCallback(
  id, // id профайлера ('Navigation')
  phase, // 'mount' или 'update'
  actualDuration, // Время, затраченное на рендер
  baseDuration, // Оценочное время без мемоизации
  startTime,
  commitTime,
) {
  if (actualDuration > 16) { 
    // 16ms - это предел для 60 FPS. Если дольше - кадр выпал.
    console.warn(`Компонент ${id} рендерился слишком долго: ${actualDuration}ms`);
  }
}

function App() {
  return (
    <Profiler id="Navigation" onRender={onRenderCallback}>
      <HeavyNavigation />
    </Profiler>
  );
}
```

## 3. ⚠️ КРИТИЧЕСКИЙ Edge Case: Dev vs Prod Mode
Самая грубая ошибка, которую можно совершить — это пытаться измерять **абсолютную скорость** рендера (в миллисекундах) в режиме разработки (Development mode).

В режиме разработки React:
- Выполняет кучу валидаций пропсов (PropTypes).
- Записывает предупреждения в консоль.
- Вызывает компоненты **дважды** в StrictMode, чтобы помочь вам найти побочные эффекты.

Из-за этого приложение работает в разы медленнее. **DevTools Profiler нужен для поиска относительных проблем** (почему отрендерилось то, что не должно было; какой компонент самый тяжелый *относительно других*).
Если вам нужно узнать, за сколько миллисекунд реально рендерится страница у пользователя, вы обязаны **собрать проект в Production Mode** и использовать вкладку `Performance` браузера (или специальный Production-билд React DevTools).
