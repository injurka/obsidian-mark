# useMemo & useCallback

Эти два хука предназначены исключительно для **оптимизации производительности** за счет **Мемоизации** (кэширования результатов). 

> **Важно для 2026 года:** С выходом **React Compiler (ранее React Forget)** в React 19, во многих случаях компилятор автоматически мемоизирует код под капотом, делая ручное написание `useMemo` и `useCallback` избыточным. Тем не менее, понимание этих хуков **обязательно** для прохождения собеседований и поддержки кода, написанного без компилятора.

## 1. useMemo
Кэширует **результат** вычислений. Принимает функцию-вычислитель и массив зависимостей.

### Когда использовать?
1. **Тяжелые вычисления**: Парсинг больших массивов данных, сложные математические операции.
   ```jsx
   // filter и map для 10 000 элементов больше не будут запускаться на каждый чих (например, если пользователь просто вводит текст в другой инпут)
   const filteredUsers = useMemo(() => {
     return users.filter(u => u.name.includes(searchQuery)).map(formatUser);
   }, [users, searchQuery]); 
   ```
2. **Сохранение стабильности ссылок (Referential Equality)**: Чтобы объект или массив не пересоздавался при каждом рендере и не вызывал ре-рендер дочерних компонентов (которые обернуты в `React.memo`) или ложных срабатываний `useEffect`.

## 2. useCallback
Кэширует **саму функцию**. По сути, `useCallback(fn, deps)` — это синтаксический сахар для `useMemo(() => fn, deps)`.

### Когда использовать?
Практически единственный валидный случай использования — передача функции в качестве пропса дочернему компоненту, который обернут в `React.memo`.

```jsx
// Родитель
function Parent() {
  const [text, setText] = useState('');
  const [count, setCount] = useState(0);

  // Без useCallback эта функция пересоздается при каждом изменении `text` (при вводе в инпут).
  // Из-за этого <HeavyButton> будет постоянно перерисовываться, даже если `count` не менялся!
  const handleIncrement = useCallback(() => {
    setCount(c => c + 1);
  }, []);

  return (
    <>
      <input value={text} onChange={e => setText(e.target.value)} />
      <HeavyButton onClick={handleIncrement} count={count} />
    </>
  );
}

// Дочерний (обернут в React.memo, то есть рендерится только при изменении пропсов)
const HeavyButton = React.memo(({ onClick, count }) => {
  // Очень долгий рендер...
  return <button onClick={onClick}>{count}</button>;
});
```

## 3. Антипаттерны и Edge Cases (Оверхед мемоизации)

### ❌ Использование useMemo/useCallback ВЕЗДЕ
Мемоизация не бесплатна. У `useMemo` и `useCallback` есть свой налог на производительность:
1. Вызов самого хука стоит времени.
2. Проверка массива зависимостей при каждом рендере стоит времени.
3. Хранение закэшированных значений занимает оперативную память.

**Антипаттерн:** Оборачивать простые функции или примитивные вычисления в `useMemo`.
```jsx
// ❌ ПЛОХО: Оверхед на мемоизацию дороже самой операции
const total = useMemo(() => a + b, [a, b]);
const handleClick = useCallback(() => console.log('click'), []); // Передается в обычный <button>, useCallback тут БЕСПОЛЕЗЕН
```

**✅ Золотое правило:** 
- `useCallback` нужен ТОЛЬКО если вы передаете функцию в дочерний компонент, обернутый в `React.memo`, или если эта функция является зависимостью для `useEffect`. Во всех остальных случаях (передача в `div`, `button` и т.д.) — он не нужен.
