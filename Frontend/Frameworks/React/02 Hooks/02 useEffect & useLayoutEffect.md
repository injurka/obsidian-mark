# useEffect & useLayoutEffect

Оба хука используются для выполнения побочных эффектов, но кардинально различаются по **времени выполнения**.

## 1. useEffect
**Назначение:** Синхронизация React-компонента с внешней системой (сеть, подписки, сторонние библиотеки). 
**Выполнение:** Асинхронно, **ПОСЛЕ** того как браузер отрисовал кадр (Paint). Это означает, что он не блокирует визуальные обновления интерфейса.

### Массив зависимостей (Dependency Array)
- `[]` — выполнить только при монтировании.
- `[state1, prop2]` — выполнить при монтировании и когда изменятся эти значения.
- `Без массива` — выполнять после КАЖДОГО рендера (почти всегда плохая идея).

### Cleanup-функция (Функция очистки)
Возвращаемая из эффекта функция. Она вызывается:
1. Перед следующим запуском этого же эффекта (для очистки предыдущего состояния).
2. При размонтировании (unmount) компонента.

```jsx
useEffect(() => {
  const timer = setInterval(() => console.log('Tick'), 1000);
  // Обязательно очищаем, иначе при каждом ре-рендере будут плодиться новые интервалы (Утечка памяти)
  return () => clearInterval(timer);
}, []);
```

### ⚠️ Edge Case: Stale Closure (Устаревшее замыкание)
Частый баг в React. Происходит, когда эффект "захватывает" переменную из старого рендера и не обновляется.

```jsx
const [count, setCount] = useState(0);

useEffect(() => {
  const timer = setInterval(() => {
    // ❌ Stale Closure: count всегда будет 0, потому что эффект не зависит от count
    console.log(count); 
  }, 1000);
  return () => clearInterval(timer);
}, []); // <-- Забыли добавить count в зависимости!
```

### ⚠️ Edge Case: Infinite Loop (Бесконечный цикл)
Возникает, если в зависимости передать объект или функцию, создаваемые внутри компонента (без мемоизации), и при этом эффект обновляет стейт.
```jsx
const userQuery = { name: 'Alex' }; // При каждом рендере ссылка новая!

useEffect(() => {
  fetchData(userQuery).then(setData); // Обновляет стейт -> ре-рендер -> новая ссылка userQuery -> запуск эффекта -> бесконечный цикл!
}, [userQuery]);
```

## 2. useLayoutEffect
**Выполнение:** Синхронно, **СРАЗУ ПОСЛЕ** мутаций DOM, но **ДО** того, как браузер их нарисует (Paint).

### Когда использовать?
Исключительно для **чтения размеров/позиций из DOM** и синхронного применения изменений, чтобы избежать "мерцания" (Flickering).

> **Пример:** Вам нужно отрендерить тултип и позиционировать его точно над кнопкой.
Если использовать `useEffect`:
1. Тултип рендерится в (0, 0).
2. Браузер рисует это. Пользователь видит тултип в левом верхнем углу (на миллисекунду).
3. Запускается `useEffect`, читает позицию, смещает тултип на (100, 100).
4. Браузер перерисовывает. **Результат: мерцание**.

Если использовать `useLayoutEffect`:
1. Тултип рендерится в (0, 0).
2. Запускается `useLayoutEffect`, читает позицию, смещает на (100, 100).
3. **Браузер рисует первый раз**. Пользователь сразу видит тултип в правильном месте. Без мерцаний.

### ⚠️ Ограничения Server-Side Rendering (SSR)
`useLayoutEffect` нельзя выполнить на сервере (там нет DOM). Next.js выдаст предупреждение. Для обхода этого можно использовать проверку на окно: `typeof window !== 'undefined' ? useLayoutEffect : useEffect`.
