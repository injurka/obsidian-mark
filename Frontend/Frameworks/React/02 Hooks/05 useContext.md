
Хук `useContext` позволяет читать данные из React Context и подписываться на их изменения. Основная цель контекста — решение проблемы **Props Drilling** (передачи пропсов сквозь множество слоев компонентов).

## 1. Как это работает (3 шага)
1. **Создание:** `const ThemeContext = createContext('light');`
2. **Провайдер:** Обернуть часть дерева в `<ThemeContext.Provider value="dark">`
3. **Потребление:** Вызвать `const theme = useContext(ThemeContext);` в любом дочернем компоненте.

## 2. ⚠️ Главная проблема Контекста (Edge Case: Рендер-шторм)
Контекст — это отличный инструмент для редко меняющихся данных (тема, язык, авторизация пользователя). Но он **плохо подходит для часто меняющегося состояния**.

**Почему?** 
Потому что **ЛЮБОЙ** компонент, вызывающий `useContext(MyContext)`, будет **ре-рендериться каждый раз**, когда изменяется `value` в Провайдере, независимо от того, какая именно часть значения изменилась.

```jsx
const AppContext = createContext();

function App() {
  const [theme, setTheme] = useState('light');
  const [user, setUser] = useState({ name: 'Alex' });

  // ❌ ПЛОХО: Изменение theme вызовет пересоздание всего объекта value!
  return (
    <AppContext.Provider value={{ theme, user, setTheme, setUser }}>
      <Navbar /> {/* Использует только user */}
      <ThemeToggle /> {/* Использует только theme */}
    </AppContext.Provider>
  );
}
```
В примере выше, если вы переключите тему, `<Navbar />` все равно сделает ре-рендер, хотя `user` не изменился!

## 3. Способы оптимизации Context
Чтобы избежать лишних ре-рендеров и проблем с производительностью, применяются следующие архитектурные подходы:

### 1. Мемоизация Value (Базовая оптимизация)
Оборачивание передаваемого значения в `useMemo`, а функций-обработчиков — в `useCallback`. Это гарантирует, что объект `value` не будет создаваться заново при каждом ре-рендере родительского компонента, если сами данные остались прежними.
```jsx
const value = useMemo(() => ({ theme, user }), [theme, user]);
```

### 2. Разделение контекстов по доменам (Сплиттинг)
Не храните всё в одном глобальном контексте. Создавайте независимые провайдеры для разных логических частей приложения: `<ThemeProvider>` и `<UserProvider>`. Если изменится тема, компоненты, подписанные только на данные пользователя, не будут ре-рендериться.

### 3. Разделение состояния и функций (State & Dispatch)
Создание двух отдельных контекстов для одной сущности: один для самих данных, другой для функций их изменения (сеттеров). Компоненты (например, кнопки переключения), которым нужно только вызывать функцию, подписываются на `DispatchContext` и не ре-рендерятся при изменении самих данных.
```jsx
<ThemeStateContext.Provider value={theme}>
  <ThemeDispatchContext.Provider value={setTheme}>
    {children}
  </ThemeDispatchContext.Provider>
</ThemeStateContext.Provider>
```

### 4. Использование паттерна `children` (Оптимизация дерева)
Вынесение стейта и Провайдера в отдельный компонент-обертку, который принимает `children`. Изменение состояния внутри такого Провайдера вызовет ре-рендер только его самого, но не затронет вложенное дочернее дерево (так как проп `children` останется тем же ссылочно).
```jsx
function ThemeProvider({ children }) {
  const [theme, setTheme] = useState('light');
  const value = useMemo(() => ({ theme, setTheme }), [theme]);
  
  return (
    <ThemeContext.Provider value={value}>
      {children}
    </ThemeContext.Provider>
  );
}
```

### 5. Использование сторонних стейт-менеджеров (Zustand, Redux)
Если у вас сложное, часто меняющееся состояние (много полей, частые обновления), правильным решением будет отказаться от React Context. Библиотеки вроде Zustand позволяют компонентам подписываться только на конкретный "кусочек" (slice) состояния с помощью селекторов, полностью избегая лишних ре-рендеров.

## 4. Использование `use` (React 19) вместо `useContext`
В React 19 появился новый хук `use()`, который может заменить `useContext`. 

**Главная особенность `use(Context)`:**
Его **МОЖНО** вызывать внутри условий (`if`) и циклов! Обычный `useContext` должен строго подчиняться правилам хуков и вызываться только на самом верхнем уровне компонента.

```jsx
import { use } from 'react';

function Header({ isPremium }) {
  if (isPremium) {
    // В React 18 с useContext это вызвало бы ошибку! В React 19 с use() это работает.
    const premiumData = use(PremiumContext); 
    return <div>{premiumData.badge}</div>;
  }
  return <div>Standard</div>;
}
```
