
Эти два хука отвечают за локальное управление состоянием компонента. Под капотом `useState` на самом деле реализован через `useReducer`.

## 1. useState

Самый базовый хук для добавления состояния. Возвращает кортеж `[состояние, функция_обновления]`.

### Ленивая инициализация (Lazy Initialization)
Если начальное состояние требует тяжелых вычислений, передайте в `useState` функцию, а не само значение. Эта функция выполнится **только один раз** при первом рендере.

```jsx
// ❌ ПЛОХО: Вычисление происходит при КАЖДОМ рендере, хотя используется только один раз
const [data, setData] = useState(heavyComputation());

// ✅ ХОРОШО: Ленивая инициализация
const [data, setData] = useState(() => heavyComputation());
```

### Автоматический батчинг (Automatic Batching)
Начиная с React 18, React группирует (batches) несколько обновлений состояния в один ре-рендер для повышения производительности, даже если они находятся внутри таймаутов, промисов или нативных обработчиков событий (раньше батчинг работал только в React-событиях).

```jsx
setTimeout(() => {
  setCount(c => c + 1);
  setFlag(f => !f);
  // React 18: Вызовет только 1 ре-рендер
}, 1000);
```

### ⚠️ Edge Case: Мутация объектов напрямую
React сравнивает объекты и массивы по **ссылке** (`Object.is()`). Если вы измените свойство объекта и передадите тот же объект в сеттер, React **не сделает ре-рендер**.

```jsx
// ❌ ПЛОХО: Изменение существующего объекта
user.name = 'Alex';
setUser(user); // Ре-рендера не будет, ссылка та же!

// ✅ ХОРОШО: Создание нового объекта (Иммутабельность)
setUser({ ...user, name: 'Alex' });
```

## 2. useReducer

Идеален для **сложной логики состояния**, когда следующее состояние сильно зависит от предыдущего, или когда несколько полей состояния обновляются вместе.

```tsx
const initialState = { count: 0, error: null };

function reducer(state, action) {
  switch (action.type) {
    case 'increment':
      return { ...state, count: state.count + 1, error: null };
    case 'error':
      return { ...state, error: action.payload };
    default:
      return state;
  }
}

function Counter() {
  const [state, dispatch] = useReducer(reducer, initialState);
  return <button onClick={() => dispatch({ type: 'increment' })}> +1 </button>;
}
```

### Когда использовать `useReducer` вместо `useState`?
1. **Сложные объекты состояния**: Если у вас есть 3-4 `useState`, которые часто обновляются одновременно, лучше объединить их в один `useReducer`.
2. **Избежание зависимости от замыканий (Stale Closures)**: Сеттер от `useState` или сама переменная могут устареть в эффектах. Функция `dispatch` от `useReducer` **стабильна** — она никогда не меняется в течение жизни компонента, поэтому ее безопасно передавать в эффекты или дочерние компоненты.
3. **Паттерн "Отправка намерений"**: В `useState` вы говорите компоненту *"что сделать"* (`setCount(5)`). В `useReducer` вы говорите *"что произошло"* (`dispatch({ type: 'user_clicked' })`), а редьюсер сам решает, как это обработать.
