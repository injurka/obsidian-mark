
Tailwind CSS к 2026 году стал абсолютным стандартом индустрии для стилизации React-приложений. Это **Utility-first** фреймворк, где вы собираете дизайн из атомарных классов прямо в разметке.

## 1. Главные преимущества
- **Отсутствие Context Switching (Переключения контекста):** Вам не нужно прыгать между `Component.tsx` и `Component.css`. Вы пишете стили там же, где и разметку.
- **Встроенная дизайн-система:** Tailwind ограничивает вас "магическими числами". Вы не можете просто написать `padding: 13px`, вы используете шкалу `p-3` или `p-4`, что делает дизайн всего приложения консистентным.
- **Производительность:** Компилятор Tailwind сканирует ваш код и оставляет в финальном CSS-файле **только те классы, которые вы реально использовали**.

## 2. Проблема длинных строк (Уродливый HTML)
Главная претензия к Tailwind — это мешанина из классов:
```html
<button className="bg-blue-500 hover:bg-blue-700 text-white font-bold py-2 px-4 rounded focus:outline-none focus:shadow-outline transition duration-150 ease-in-out">
  Кнопка
</button>
```
**Как это решается в React:**
Созданием маленьких, изолированных компонентов! Вы прячете эти классы внутрь компонента `<Button>` один раз, и дальше используете красивый и чистый API.

## 3. Edge Case: Динамические классы и Конфликты
Часто в React нужно склеивать классы в зависимости от пропсов или состояния. 
Новичковая ошибка — строковая конкатенация:
```jsx
// ❌ ПЛОХО: Если isError === false, в классе останется "undefined" или "false"
<div className={`p-4 ${isError && 'bg-red-500'}`}>...</div>
```

**Индустриальный стандарт (Утилита `cn`):**
В современных проектах (особенно с Shadcn UI) всегда используется комбинация двух библиотек: `clsx` (для логического склеивания) и `tailwind-merge` (для разрешения конфликтов Tailwind-классов).

```jsx
import { clsx } from "clsx";
import { twMerge } from "tailwind-merge";

// Эту утилиту обычно кладут в lib/utils.ts
export function cn(...inputs) {
  return twMerge(clsx(inputs));
}

// ✅ ХОРОШО: 
// Если мы передадим className="px-2", twMerge поймет, что "px-2" перекрывает "p-4", 
// и удалит "p-4", оставив только финальный результат без CSS-конфликтов!
function Alert({ isError, className }) {
  return (
    <div className={cn("p-4 rounded-md", isError ? "bg-red-500" : "bg-gray-100", className)}>
      Внимание
    </div>
  );
}
```

## 4. Ограничения компилятора
Tailwind не может исполнять JavaScript. Если вы попытаетесь сгенерировать имя класса динамически, компилятор его не найдет, и стиль не применится.

```jsx
// ❌ ПЛОХО: Tailwind не найдет этот класс при сборке!
const color = 'red';
<div className={`bg-${color}-500`}>...</div>

// ✅ ХОРОШО: Прописывать полные классы
const colorVariants = {
  red: 'bg-red-500',
  blue: 'bg-blue-500',
};
<div className={colorVariants[color]}>...</div>
```
