# MobX

MobX предлагает совершенно иной подход к управлению состоянием по сравнению с Redux, Zustand или Jotai. Если другие библиотеки пропагандируют **Функциональное программирование и Иммутабельность** (неизменяемость), то MobX построен на **Объектно-ориентированном программировании (ООП) и Мутабельности**.

## 1. Концепция: Прозрачная реактивность (Transparent Reactivity)
В MobX вы создаете классы (или объекты), помечаете их свойства как "наблюдаемые" (observable), и можете изменять их напрямую, как обычные переменные `user.name = 'Alex'`. 
Под капотом MobX использует **Proxy API**, чтобы перехватить это изменение и автоматически перерисовать те компоненты, которые читают это свойство.

### Базовый пример
```javascript
import { makeAutoObservable } from "mobx";
import { observer } from "mobx-react-lite";

// 1. Создаем стор в стиле ООП
class TimerStore {
  secondsPassed = 0; // Наблюдаемое состояние (State)

  constructor() {
    // Автоматически делает все свойства observable, а методы - action
    makeAutoObservable(this); 
  }

  // Действие (Action) - только экшены имеют право мутировать состояние
  increase() {
    this.secondsPassed += 1; // Жесткая мутация!
  }

  // Вычисляемое значение (Computed) - аналог селекторов, кэшируется
  get displayTime() {
    return `${this.secondsPassed} сек.`;
  }
}

const myTimer = new TimerStore();

// 2. Оборачиваем компонент в HOC observer
// Это заставляет компонент следить за всеми observable свойствами, которые он рендерит
const TimerView = observer(({ timer }) => (
  <button onClick={() => timer.increase()}>
    Время: {timer.displayTime}
  </button>
));
```

## 2. Главное преимущество
MobX невероятно точен в своих оптимизациях. Компонент ре-рендерится ТОЛЬКО если изменилось конкретное свойство, которое было прочитано (accessed) внутри его функции рендера. Вам не нужно писать `useSelector` или мемоизировать пропсы.

## 3. ⚠️ Главный подвох (Edge Case): Раннее разыменование (Early Dereference)
Это самая частая причина, почему "MobX не работает" у новичков.

Поскольку MobX отслеживает обращения к свойствам (`timer.secondsPassed`) **через геттеры Proxy во время рендера**, вы должны "читать" свойство именно внутри компонента-обозревателя (`observer`).

**❌ ПЛОХО: Потеря реактивности**
```jsx
// Родитель достает примитив из стора и передает его вниз
const App = observer(() => {
  const seconds = myTimer.secondsPassed; // Считали примитив здесь
  return <Child seconds={seconds} />; // Передали обычное число
});

// Если Child НЕ observer, он НЕ перерисуется, так как он получил просто число `0`, 
// и у него нет связи с Proxy от MobX!
const Child = ({ seconds }) => <div>{seconds}</div>; 
```

**✅ ХОРОШО: Передача ссылки на объект**
```jsx
// Передаем весь объект-стор вниз
const App = observer(() => <Child timer={myTimer} />);

// Дочерний компонент сам является observer и "читает" свойство внутри себя
const Child = observer(({ timer }) => <div>{timer.secondsPassed}</div>);
```
