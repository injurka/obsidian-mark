# Next.js

К 2026 году Next.js (от компании Vercel) является абсолютным лидером среди React-фреймворков. На собеседованиях знание Next.js требуется почти так же часто, как и знание самого React.

## 1. App Router vs Pages Router
Next.js предлагает две архитектуры роутинга:
- **Pages Router (Legacy):** Роутинг на основе папки `pages`. Использовал функции `getServerSideProps` и `getStaticProps` для получения данных. На 2026 год считается устаревшим, но активно поддерживается.
- **App Router (Стандарт):** Роутинг на основе папки `app`. Построен **целиком на React Server Components (RSC)**. Вместо `getServerSideProps` вы просто пишете `async/await` прямо внутри компонента.

## 2. Стратегии рендеринга (SSR, SSG, ISR)
Это самый частый вопрос на собеседованиях по Next.js:

1. **SSR (Server-Side Rendering - Динамический рендер):**
   Страница генерируется на сервере **при каждом запросе** пользователя. Подходит для дашбордов, лент новостей.
   *(Как включить: использовать `fetch` с `cache: 'no-store'` или читать куки/заголовки через `cookies()`).*
2. **SSG (Static Site Generation - Статический рендер):**
   Страница генерируется **один раз во время сборки (build)**. Сервер отдает готовый HTML (очень быстро) через CDN. Подходит для блогов, документации.
   *(Включено по умолчанию для всех страниц, где нет динамических функций).*
3. **ISR (Incremental Static Regeneration):**
   Компромисс. Страница генерируется статически, но имеет "срок годности". Например, раз в 60 секунд. Если кто-то зайдет на страницу через 61 секунду, он увидит старую кэшированную версию, но в фоне сервер перегенерирует страницу для следующих посетителей.
   *(Как включить: `export const revalidate = 60` или `fetch(..., { next: { revalidate: 60 } })`).*

## 3. ⚠️ Четырехуровневое кэширование (Edge Case)
Самая большая боль разработчиков Next.js — это агрессивное кэширование. Next.js кэширует всё по умолчанию на 4 уровнях:

1. **Request Memoization:** Дедупликация одинаковых запросов `fetch` в течение ОДНОГО рендера (живет доли секунды).
2. **Data Cache:** Кэширование ответов от `fetch` (сохраняется между рендерами и деплоями).
3. **Full Route Cache:** Кэширование сгенерированного HTML на сервере (тот самый SSG).
4. **Router Cache (Client-side):** Кэш в браузере. Если вы перешли с Главной на Профиль, а потом нажали "Назад", Next.js не пойдет на сервер за Главной страницей, он достанет ее из памяти браузера (живет около 30 секунд или до ручной инвалидации).

**Как сбросить кэш?**
Использовать серверные функции `revalidatePath('/blog')` или `revalidateTag('posts')` внутри Server Actions.

## 4. Edge Computing (Граничные вычисления)
Next.js позволяет запускать код (например, Middleware) не на центральном сервере (Node.js), а на Edge-нодах (серверах CDN, раскиданных по всему миру, V8 Isolates).
**Ограничения Edge:** Там нет полного Node.js API (нельзя использовать модуль `fs` для файлов или тяжелые криптографические библиотеки). Код должен быть очень легким и выполняться за миллисекунды.
