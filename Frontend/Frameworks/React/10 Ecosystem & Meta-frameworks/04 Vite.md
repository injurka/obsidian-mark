# Vite

К 2026 году **Vite** ("Вить" — по-французски "быстрый") полностью уничтожил и заменил Webpack и Create React App (CRA) в роли инструмента для создания SPA (Single Page Applications) и бандлера.

## 1. Как работал Webpack (Проблема)
Когда вы запускали `npm start` в старом React-приложении, Webpack брал **весь** ваш проект (тысячи файлов), сканировал все импорты, собирал из этого один огромный JS-бандл и отдавал его браузеру.
Чем больше рос проект, тем дольше он запускался (иногда старт локального сервера занимал 2-3 минуты!).

## 2. Как работает Vite (Решение)
Vite использует фичу современных браузеров — **Native ESM** (нативные ECMAScript модули через `<script type="module">`).

Vite делит код на две категории:
1. **Зависимости (Dependencies):** Код из `node_modules`. Он меняется редко. При первом запуске Vite использует **Esbuild** (написан на Go, работает в 100 раз быстрее JS-сборщиков), чтобы предварительно собрать их ("Pre-bundling") и закешировать.
2. **Ваш код (Source code):** Исходники проекта. Vite **вообще не собирает их** при старте сервера! 

Сервер Vite запускается за **0.5 секунд**, независимо от того, 10 файлов у вас в проекте или 10 000. 
Когда браузер запрашивает файл (например, `App.jsx`), Vite на лету компилирует его (и только его!) и отдает браузеру.

### HMR (Мгновенное обновление)
Если вы измените один файл, Vite отправит в браузер только этот измененный модуль. Интерфейс обновится мгновенно без перезагрузки всей страницы (Hot Module Replacement).

## 3. Сборка для Production
Vite использует **Rollup** для финальной сборки (команда `npm run build`). В продакшене код все равно должен быть объединен в бандлы (с Code Splitting), чтобы оптимизировать сетевые запросы для конечного пользователя.

## 4. ⚠️ Edge Case: Совместимость с CJS (CommonJS)
Хотя Vite великолепен с современными ESM-пакетами (`import / export`), в `node_modules` всё ещё лежит много старых библиотек, использующих CJS (`require / module.exports`).
Часто при запуске проекта Vite может выдать ошибку *"does not provide an export named 'default'"*.

**Почему это происходит?** Esbuild пытается конвертировать старый CJS-пакет в ESM на лету, но пакет может быть написан нестандартно.
**Решение:** Добавить пакет в секцию `optimizeDeps.include` в `vite.config.js`, чтобы принудительно заставить Esbuild обработать его корректно.
