# Пользовательские ошибки и расширение класса Error

## 1. Зачем создавать свои классы ошибок?
При разработке сложных приложений стандартных типов ошибок (таких как `TypeError` или `SyntaxError`) часто недостаточно. Нам важно отличать ошибки валидации данных (`ValidationError`), ошибки авторизации (`AuthError`), ошибки отсутствия ресурсов (`NotFoundError`) и другие бизнес-ошибки от системных ошибок рантайма. Создание кастомных классов позволяет разделять стратегии обработки ошибок в зависимости от их типа.

---

## 2. Шаблон создания пользовательского класса ошибки
В современном JavaScript пользовательские ошибки создаются путем наследования от встроенного класса `Error`.

### Анатомия кастомного класса
```javascript
class MyCustomError extends Error {
  constructor(message) {
    super(message); // Вызов конструктора родительского класса Error
    this.name = this.constructor.name; // Автоматическое присвоение имени текущего класса
    
    // Поддержка красивого стека вызовов в V8-движках (Node.js, Chrome)
    if (Error.captureStackTrace) {
      Error.captureStackTrace(this, this.constructor);
    }
  }
}
```

### Важные нюансы реализации:
1. **Вызов `super(message)`**: Вызов родительского конструктора обязателен. Он инициализирует свойство `message` и устанавливает стек вызовов.
2. **Свойство `this.name`**: По умолчанию `super` устанавливает `this.name = "Error"`. Чтобы в логах и стеке отображалось имя нашего класса, мы явно перезаписываем его. Использование динамического `this.constructor.name` избавляет от необходимости хардкодить имя при наследовании.
3. **`Error.captureStackTrace`**: Этот метод исключает вызов самого конструктора нашей кастомной ошибки из стека вызовов, делая трассировку более чистой.

## 3. Построение иерархии ошибок
В больших приложениях принято создавать базовый класс для всех ошибок приложения (или определенного модуля), а затем наследоваться от него.

```javascript
// Базовый класс для ошибок валидации/парсинга данных
class AppError extends Error {
  constructor(message) {
    super(message);
    this.name = this.constructor.name;
    if (Error.captureStackTrace) {
      Error.captureStackTrace(this, this.constructor);
    }
  }
}

// Конкретная ошибка валидации
class ValidationError extends AppError {
  constructor(message, property) {
    super(message);
    this.property = property; // Дополнительное свойство для отладки
  }
}

// Ошибка отсутствия обязательного свойства
class PropertyRequiredError extends ValidationError {
  constructor(property) {
    super(`Отсутствует обязательное свойство: ${property}`, property);
  }
}
```

## 4. Обработка пользовательских ошибок через `instanceof`
Оператор `instanceof` позволяет проверять принадлежность ошибки к конкретному классу или его родителю. Это дает возможность тонко настраивать логику обработки ошибок в одном блоке `catch`.

```javascript
function readUser(json) {
  let user;
  try {
    user = JSON.parse(json);
  } catch (err) {
    throw new ValidationError("Невалидный JSON-формат", "json");
  }

  if (!user.name) {
    throw new PropertyRequiredError("name");
  }
  if (!user.age) {
    throw new PropertyRequiredError("age");
  }

  return user;
}

// Использование и перехват
try {
  const badJson = '{ "age": 25 }';
  const user = readUser(badJson);
  console.log(user);
} catch (error) {
  if (error instanceof PropertyRequiredError) {
    console.error(`Ошибка формы: Заполните обязательное поле "${error.property}"`);
  } else if (error instanceof ValidationError) {
    console.error(`Ошибка валидации данных: ${error.message} (Поле: ${error.property})`);
  } else if (error instanceof SyntaxError) {
    console.error(`Критическая синтаксическая ошибка: ${error.message}`);
  } else {
    console.error("Неизвестная системная ошибка. Проброс...");
    throw error; // Системные ошибки пробрасываем выше
  }
}
```

## 5. Оборачивание ошибок (Error Wrapping) и свойство `cause` (ES2022)
Иногда на верхних слоях приложения нам нужно выбросить общую ошибку (например, `DatabaseError`), но при этом сохранить исходную причину (например, `ConnectionTimeoutError`), которая ее вызвала. Для этого используется опция `{ cause }` при создании ошибки.

```javascript
class DatabaseError extends Error {
  constructor(message, options) {
    super(message, options);
    this.name = this.constructor.name;
  }
}

function connectToDatabase() {
  try {
    // Имитация низкоуровневой сетевой ошибки
    throw new TypeError("Failed to resolve host 'db.local'");
  } catch (rawError) {
    // Оборачиваем низкоуровневую ошибку в понятную высокоуровневую
    throw new DatabaseError("Не удалось подключиться к базе данных", { cause: rawError });
  }
}

try {
  connectToDatabase();
} catch (error) {
  console.error(`Ошибка: ${error.message}`); // Ошибка: Не удалось подключиться к базе данных
  if (error.cause) {
    console.error(`Первопричина (cause): ${error.cause.name} -> ${error.cause.message}`);
    // Первопричина (cause): TypeError -> Failed to resolve host 'db.local'
  }
}
```
