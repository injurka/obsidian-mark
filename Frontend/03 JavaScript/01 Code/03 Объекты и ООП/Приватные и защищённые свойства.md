
В объектно-ориентированном программировании (ООП) одним из ключевых принципов является **инкапсуляция** — разделение интерфейса класса на внешний (публичный) и внутренний (скрытый от внешнего мира). Это позволяет защитить внутреннее состояние объекта от некорректного вмешательства извне, а также свободно изменять внутреннюю реализацию класса, не нарушая работу внешнего кода, который от него зависит.

В JavaScript свойства и методы классов по умолчанию являются публичными. Однако язык предоставляет механизмы для создания защищенных (по соглашению) и приватных (на уровне спецификации) свойств и методов.

---

## 1. Введение: Публичный и внутренний интерфейсы

Публичный интерфейс класса (Public Interface) — это набор свойств и методов, которые доступны для использования из любого места программы. Внутренний интерфейс (Internal Interface) — это детали реализации, которые должны быть доступны только внутри самого класса.

Для понимания концепции инкапсуляции можно представить обычную кофеварку:
* **Публичный интерфейс**: кнопка включения, селектор выбора напитка, индикатор готовности. Вы нажимаете на кнопку снаружи, и вам не нужно знать, что происходит внутри.
* **Внутренний интерфейс**: нагревательный элемент, трубки для подачи воды, насос. Все это скрыто под корпусом. Если пользователь попытается залезть внутрь работающей кофеварки отверткой, он может ее сломать или получить удар током.

Точно так же в программировании: скрытие внутренних деталей реализации позволяет избежать случайных ошибок и упрощает поддержку кода.

## 2. Защищенные свойства и соглашение «_»

Защищенные свойства (Protected Properties) должны быть доступны внутри самого класса и его дочерних классов (наследников), но не должны быть видны из внешнего кода.

В JavaScript нет встроенной поддержки защищенных полей на уровне синтаксиса. Вместо этого в сообществе разработчиков принято соглашение: свойства и методы, имя которых начинается с символа подчеркивания `_`, считаются защищенными. Движок JavaScript никак не ограничивает доступ к ним, но программисты понимают, что обращаться к таким полям извне класса крайне нежелательно.

Часто защищенные свойства сочетают с геттерами и сеттерами, чтобы организовать доступ «только для чтения» или контролировать корректность записываемых данных.

### Пример реализации защищенных свойств:

```javascript
class CoffeeMachine {
  _waterAmount = 0; // Защищенное свойство

  constructor(power) {
    this._power = power; // Мощность кофемашины (только для чтения)
  }

  // Сеттер позволяет валидировать количество воды
  set waterAmount(value) {
    if (value < 0) {
      throw new Error("Количество воды не может быть отрицательным");
    }
    this._waterAmount = value;
  }

  // Геттер предоставляет доступ к свойству
  get waterAmount() {
    return this._waterAmount;
  }

  // Геттер без сеттера делает свойство _power доступным только для чтения
  get power() {
    return this._power;
  }
}

const machine = new CoffeeMachine(100);
machine.waterAmount = 50; // Запись значения через сеттер
console.log(`Количество воды: ${machine.waterAmount}, мощность: ${machine.power}`);
// Выведет: Количество воды: 50, мощность: 100
```

Защищенные свойства автоматически наследуются дочерними классами, и те могут свободно читать и изменять их.

## 3. Приватные свойства на уровне языка

Приватные свойства и методы (Private Properties) доступны исключительно внутри того класса, в котором они были объявлены. Ни внешний код, ни дочерние классы-наследники не имеют к ним прямого доступа.

Начиная со спецификации ES2020, в JavaScript добавлена нативная поддержка приватных полей. Для их обозначения используется префикс решетки `#` перед именем свойства или метода.

### Важные правила работы с приватными полями:
1. **Обязательное объявление**: Все приватные поля должны быть явно объявлены в теле класса. Их нельзя создать динамически «на лету» в конструкторе, как это можно сделать с публичными или защищенными полями.
2. **Отсутствие динамического доступа**: Обратиться к приватным полям через квадратные скобки (например, `this['#waterLimit']`) невозможно. Доступ осуществляется строго через синтаксис точки (`this.#waterLimit`).
3. **Инкапсуляция в наследниках**: Классы-наследники не наследуют прямой доступ к приватным полям родителя. Попытка обратиться к приватным свойствам родительского класса вызовет синтаксическую ошибку `SyntaxError` на этапе компиляции кода.

### Пример реализации приватных свойств и методов:

```javascript
class CoffeeMachine {
  #waterLimit = 200; // Приватное свойство

  // Приватный метод для внутренней проверки
  #checkWater(value) {
    if (value < 0) throw new Error("Отрицательное количество воды");
    if (value > this.#waterLimit) throw new Error("Слишком много воды");
  }

  // Публичный метод для изменения воды
  setWater(value) {
    this.#checkWater(value);
    this.water = value;
  }
}

class MegaCoffeeMachine extends CoffeeMachine {
  // Дочерний класс не имеет прямого доступа к приватным свойствам родителя.
  // Например, вызов return this.#waterLimit вызовет SyntaxError во время компиляции.
  // Но можно взаимодействовать через унаследованные публичные методы (setWater).
}

const machine = new CoffeeMachine();
machine.setWater(150); // Успешно работает
// machine.#checkWater(100); // Ошибка SyntaxError во время компиляции
```

## 4. Сравнение приватных и защищенных свойств

| Критерий | Защищенные свойства (`_`) | Приватные свойства (`#`) |
| :--- | :--- | :--- |
| **Нативная поддержка** | Отсутствует (только соглашение) | Есть (начиная с ES2020) |
| **Доступ снаружи класса** | Возможен физически (но нарушает соглашение) | Невозможен (вызывает синтаксическую ошибку) |
| **Доступ из классов-наследников** | Возможен и приветствуется | Невозможен |
| **Обязательное объявление в классе** | Не требуется | Обязательно |

---

## 5. Резюме и лучшие практики

1. **Защищенные поля (`_`)** подходят в тех случаях, когда вы планируете расширять логику класса в дочерних классах и наследникам требуется доступ к внутреннему состоянию родителя.
2. **Приватные поля (`#`)** обеспечивают максимальную степень инкапсуляции и гарантируют, что ни одна внешняя часть программы, включая наследников, не сможет нарушить целостность внутренних данных класса.
3. Избегайте прямого обращения к защищенным полям с префиксом `_` вне класса. Создавайте публичные методы (интерфейс) для взаимодействия со свойствами объекта.
