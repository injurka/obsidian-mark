# Стек вызовов и контекст выполнения в JavaScript

Понимание стека вызовов (Call Stack) и контекста выполнения (Execution Context) является фундаментальным для понимания того, как движок JavaScript выполняет код, управляет памятью и определяет области видимости.

---

## 1. Введение в Стек вызовов (Call Stack)

Стек вызовов — это механизм, который используется интерпретатором JavaScript для отслеживания вызовов функций в программе. Он работает по принципу **LIFO** (Last In, First Out — «последним пришёл, первым ушёл»).

Поскольку JavaScript является однопоточным языком программирования, он имеет только один стек вызовов. Это означает, что движок может выполнять только одну задачу в конкретный момент времени.

---

## 2. Контекст выполнения (Execution Context)

Каждый раз, когда JavaScript-код запускается на выполнение, он выполняется внутри контекста выполнения. Существует два основных типа контекстов:

1. **Глобальный контекст выполнения (Global Execution Context)** — создаётся по умолчанию при первом запуске скрипта. В любой программе существует только один глобальный контекст. Он создает глобальный объект (например, `window` в браузере) и устанавливает значение `this` равным этому глобальному объекту.
2. **Контекст выполнения функции (Function Execution Context)** — создаётся каждый раз, когда происходит вызов функции. У каждой функции есть свой собственный контекст выполнения, который создаётся динамически в момент вызова.

---

## 3. Жизненный цикл контекста выполнения

Создание и выполнение контекста происходит в две фазы:

### Фаза создания (Creation Phase)
На этом этапе движок подготавливает всё необходимое для выполнения кода:
* **Создание LexicalEnvironment и VariableEnvironment:** Создаются объекты для хранения переменных, констант и объявлений функций.
* **Инициализация поднятия (Hoisting):** Переменные, объявленные через `var`, инициализируются значением `undefined`, а объявления функций (Function Declarations) полностью помещаются в память. Переменные `let` и `const` остаются неинициализированными (находятся в "временной мертвой зоне").
* **Создание цепочки областей видимости (Scope Chain):** Каждый контекст получает ссылку на лексическое окружение своего родителя (внешнее окружение).
* **Определение значения `this`:** Устанавливается контекст вызова функции.

### Фаза выполнения (Execution Phase)
На этой фазе движок выполняет код построчно: присваивает переменным их реальные значения и осуществляет вызовы функций.

---

## 4. Анатомия кадра стека (Stack Frame)

Каждая запись в стеке вызовов представляет собой кадр стека (Stack Frame). Кадр хранит информацию, необходимую для выполнения конкретной функции:
* **Аргументы функции:** Локальные копии параметров, переданных при вызове.
* **Локальные переменные:** Переменные и константы, объявленные внутри функции.
* **Ссылка на внешнее окружение (Outer Environment reference):** Ссылка, используемая для поиска переменных выше по цепочке областей видимости (Scope Chain).
* **Контекст вызова (`this`):** Ссылка на объект, с которым связан текущий вызов.
* **Адрес возврата:** Точка в коде (строка), куда управление должно вернуться после завершения функции.

---

## 5. Связь с оперативной памятью (Stack vs Heap)

Движок JavaScript использует два типа хранилища в памяти:
* **Стек (Stack):** Быстрая и структурированная область памяти фиксированного размера. В стеке хранятся кадры вызовов функций, примитивные значения (числа, строки, логические значения) и ссылки на объекты.
* **Куча (Heap):** Неструктурированная область памяти большого объема, предназначенная для динамического выделения памяти под объекты, массивы и функции. Кадр стека содержит лишь указатель (ссылку) на адрес объекта в куче.

---

## Пошаговый разбор выполнения кода

Рассмотрим простой пример:

```javascript
const globalVar = 'global';

function second() {
  const b = 'second';
  console.log(b);
}

function first() {
  const a = 'first';
  second();
}

first();
```

### Как меняется стек вызовов во времени:

1. **Запуск скрипта:** В стек помещается Глобальный контекст выполнения `[Global]`. В куче создаются функции `first` и `second`.
2. **Вызов `first()`:** Движок приостанавливает выполнение глобального кода, создаёт контекст `[first]` и помещает его на вершину стека поверх `[Global]`.
3. **Вызов `second()`:** Внутри функции `first` вызывается `second`. Движок создаёт контекст `[second]` и помещает его на вершину стека поверх `[first]`.
4. **Выполнение `second()`:** Выводится строка `'second'`. Функция завершается. Её контекст `[second]` удаляется с вершины стека.
5. **Возврат в `first()`:** Управление возвращается на адрес после вызова `second()`. Функция `first` завершается, её контекст `[first]` удаляется из стека.
6. **Возврат в глобальный контекст:** Стек снова содержит только `[Global]`. После завершения программы глобальный контекст удаляется.

# Стек вызовов: переполнение, отладка и стектрейс

Стек вызовов (Call Stack) в JavaScript служит не только для последовательного выполнения функций, но и является важнейшим инструментом при отладке приложений, поиске ошибок и оптимизации производительности.

Подробнее о внутреннем устройстве контекстов выполнения и кадров стека читайте в: [[Область видимости и память/Cтек вызовов|Стек вызовов и контекст выполнения]].

---

## 1. Переполнение стека (Stack Overflow)

Поскольку размер стека вызовов ограничен оперативной памятью, выделенной под поток выполнения, существует предел глубины стека (обычно от 10 000 до 50 000 вызовов в зависимости от браузера и движка JavaScript).

Если функции вызывают друг друга без остановки, стек заполняется до своего предела. Как только лимит превышен, рантайм выбрасывает ошибку:
`RangeError: Maximum call stack size exceeded`

---

## 2. Методы предотвращения переполнения стека

При работе со сложными рекурсивными алгоритмами применяются следующие подходы для защиты от переполнения:

### Правильный базовый случай рекурсии
Каждая рекурсивная функция должна иметь четкое условие выхода, которое гарантированно будет достигнуто при выполнении.

### Асинхронные вызовы (Event Loop)
Если перенести вызов функции в очередь макрозадач (с помощью `setTimeout`) или микрозадач (через `Promise`), текущий кадр стека завершится и будет удален из стека вызовов. Следующий шаг рекурсии выполнится уже в новом, чистом стеке вызовов.

### Шаблон "Трамплин" (Trampoline)
Трамплин — это паттерн, который преобразует рекурсию в обычный цикл. Вместо того чтобы вызывать функцию рекурсивно напрямую, функция возвращает другую функцию (обертку — thunk), а внешний цикл последовательно запускает эти обертки, пока не получит итоговое нефункциональное значение.

---

## 3. Стектрейс (Stack Trace) и отладка

Стектрейс — это снимок стека вызовов на момент возникновения ошибки или создания объекта `Error`. Он показывает цепочку вызовов функций, которые привели к текущей строчке кода.

### Чтение стектрейса
Стектрейс читается снизу вверх:
* Самая нижняя строка — это точка входа в программу (например, глобальный вызов или обработчик события).
* Самая верхняя строка — место, где непосредственно произошел сбой.

### Инструменты разработчика
В браузере (Chrome, Firefox) при остановке на точке останова (breakpoint) во вкладке **Sources** доступна панель **Call Stack**. Она позволяет визуально исследовать стек, перемещаться по кадрам и просматривать значения локальных переменных на каждом уровне.

## Примеры кода

### Пример 1: Демонстрация бесконечной рекурсии и обработка RangeError

```javascript
function recursiveHelper(count) {
  recursiveHelper(count + 1);
}

try {
  recursiveHelper(1);
} catch (error) {
  console.error('Ошибка поймана:', error.message);
  // Выведет сообщение об ошибке переполнения стека
}
```

### Пример 2: Использование асинхронности для очистки стека

```javascript
function asyncRecursive(count) {
  if (count > 20000) {
    console.log('Выполнение успешно завершено!');
    return;
  }
  // Переносим выполнение в конец очереди событий, стек очищается
  setTimeout(() => asyncRecursive(count + 1), 0);
}

asyncRecursive(1);
```

### Пример 3: Реализация паттерна "Трамплин"

```javascript
function trampoline(fn) {
  return function(...args) {
    let result = fn(...args);
    while (typeof result === 'function') {
      result = result();
    }
    return result;
  };
}

function factorialThunk(n, acc = 1) {
  if (n <= 1) return acc;
  return () => factorialThunk(n - 1, n * acc);
}

const safeFactorial = trampoline(factorialThunk);
console.log(safeFactorial(10000)); // Выполнится без RangeError
```

### Пример 4: Получение и вывод стектрейса через объект Error

```javascript
function traceFunction() {
  const err = new Error('Локальный снимок стека');
  console.log(err.stack);
}

function runTrace() {
  traceFunction();
}

runTrace();
```
