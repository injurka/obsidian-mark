# Fixed Versioning (Единое версионирование)

**Fixed Versioning (или Lockstep Versioning)** — это стратегия управления версиями в монорепозитории, при которой **все** опубликованные пакеты проекта всегда имеют строго одинаковую версию (например, `v18.2.0`). Самые известные примеры — React (`react`, `react-dom`, `react-test-renderer`), Angular и Babel.

## Боль, которую мы решаем

Представьте экосистему из 10 тесно связанных пакетов (ядро, роутер, стейт-менеджер, утилиты). Если мы позволим каждому пакету иметь свою версию (Независимое версионирование), пользователю придется собирать пазл: "Так, у меня ядро версии `2.4.1`. Какая версия роутера с ним совместима? `1.8.0` или уже `2.0.0`?". Возникает "Ад зависимостей" (Dependency Hell) и фрагментация экосистемы.

## Как это работает на практике

При едином версионировании монорепозиторий трактуется как единый продукт. Если разработчик добавил новую фичу (minor) только в пакет `@org/router`, при релизе версия поднимается до `1.5.0` **вообще у всех** пакетов, даже если в них не изменилось ни строчки кода.

```mermaid
graph TD
    subgraph Monorepo Release v2.0.0
        A[@org/core v2.0.0]
        B[@org/router v2.0.0]
        C[@org/cli v2.0.0]
    end
    
    A -. "Ensures 100% compatibility" .- B
    B -. "No version guessing" .- C
```

**Плюсы для потребителей (DX):**
Разработчик, использующий вашу библиотеку, просто обновляет все пакеты с префиксом `@org/*` до версии `2.0.0` и уверен, что они гарантированно работают вместе. 

## Неочевидные нюансы и трейдоффы

1. **Спам релизами:** Главный минус Fixed Versioning — это "пустые" обновления. Если вы исправили баг в `cli`, пользователям прилетит обновление пакета `core`, в котором ничего не поменялось. Это сбивает с толку, заставляет системы CI у пользователей скачивать новые пакеты и может инвалидировать кеши.
2. **Психологический барьер мажорных версий:** Если в одном крошечном пакете утилит вы изменили API (ломающее изменение, Major bump), вы обязаны выпустить новую мажорную версию (напр. `v3.0.0`) для всего огромного проекта. Сообщество может подумать: "Ого, React 3.0 вышел, надо всё переписывать!", хотя реально поменялась лишь одна утилита. Из-за этого разработчики монореп с Fixed Versioning панически боятся делать ломающие изменения.
3. **Инструментарий:** Lerna исторически была королевой Fixed Versioning (режим по умолчанию). Сегодня этот подход легко реализуется через Changesets (с помощью фичи `linked` packages).
