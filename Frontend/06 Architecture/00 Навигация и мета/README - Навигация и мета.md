# 00. Навигация и мета — Общий обзор базы знаний

Добро пожаловать в структурированную базу знаний по архитектуре фронтенда. Этот репозиторий представляет собой полную карту архитектурного проектирования веб-приложений: от базовых принципов чистого кода до масштабных распределенных систем уровня Enterprise.

---

## 🗺️ Общая структура базы знаний

Материалы разделены на последовательные тематические блоки, позволяющие изучать тему от простого к сложному:

1. **Разделы 00–01: Основы и мета-информация**
   * Введение, чек-листы, глоссарии, фундаментальные принципы проектирования (SOLID, DRY, KISS, YAGNI, GRASP) и метрики качества кода (Cohesion & Coupling).
2. **Разделы 02–04: Методологии и границы**
   * Сравнение подходов (Clean Architecture, DDD, FSD, Atomic Design), правила выстраивания модульных границ, контроль импортов и контракты.
3. **Разделы 05–07: Внутренняя архитектура клиента**
   * Проектирование компонентов, дизайн систем, темизация, управление стейтом и бизнес-логикой.
4. **Разделы 08–10: Сетевое взаимодействие и доставка**
   * Работа с API, BFF, стратегии кэширования, оффлайн-архитектура, роутинг и стратегии рендеринга (SSR, CSR, SSG, Island Architecture).
5. **Разделы 11–12: Производительность и стили**
   * Архитектура стилизации, оптимизация критического пути рендеринга (Critical Rendering Path), оптимизация JS/Bundle, Core Web Vitals.
6. **Разделы 13–14: Масштабирование и сборка**
   * Микрофронтенды, монорепозитории (Nx, Turborepo), сборщики (Vite, Webpack, Rspack) и стратегии публикации.
7. **Разделы 15–18: Инструменты качества**
   * TypeScript как инструмент проектирования, веб-безопасность (XSS, CSRF, CSP), стратегии тестирования, Observability, логирование и Feature Flags.
8. **Разделы 19–22: Инфраструктура и управление**
   * CI/CD, хостинг, System Design для фронтенда, Accessibility (a11y), процессы ревью, ADR, RFC и практики эволюции легаси.

---

## 🎯 Цели этой базы знаний

* **Стандартизация процессов:** Задать единые рамки и терминологию для проектирования систем внутри команды.
* **Быстрый онбординг:** Помочь новым разработчикам быстро понять подходы к кодовой базе.
* **Повышение качества кода:** Уменьшить количество технического долга и внедрить практику осознанных компромиссов (trade-offs).
* **Подготовка к System Design:** Служить настольной книгой для прохождения и проведения секций системного проектирования.
