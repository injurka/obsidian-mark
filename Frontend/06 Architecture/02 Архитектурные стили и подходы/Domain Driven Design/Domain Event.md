Доменное событие (Domain Event) — это почтовый голубь вашей системы. Это сообщение о том, что в домене произошло нечто, что имеет важное значение для бизнеса: "Заказ успешно оформлен", "Товар добавлен в корзину", "Пользователь заблокирован за спам".

**Зачем это нужно фронтенду?**
События помогают развязать (декаплинговать) различные части системы, чтобы они не превратились в запутанный клубок зависимостей. Вместо того чтобы агрегат при выполнении своего действия дергал сторонние сервисы, он просто публикует факт свершения. А те, кому этот факт интересен, самостоятельно реагируют на него.

**Боль жесткой связности (Антипаттерн):**
```typescript
class Cart {
  addItem(item: Item) {
    this.items.push(item);
    // Домен внезапно знает про инфраструктуру аналитики и UI!
    AnalyticsService.track('item_added'); 
    ToastNotification.show('Item added successfully!');        
  }
}
```

**Элегантное решение через события:**
```typescript
class Cart {
  addItem(item: Item) {
    this.items.push(item);
    // Модель просто констатирует факт
    EventBus.publish(new ItemAddedToCartEvent(item.id, item.price));
  }
}

// Где-то в слое приложения (Application Layer)
EventBus.subscribe(ItemAddedToCartEvent, (event) => {
  AnalyticsService.track('item_added', event.price);
  ToastNotification.show('Item added successfully!');
});
```

**Неочевидный оверхед:**
Доменные события делают поток управления неявным (implicit). Если в коде с прямыми вызовами можно нажать `Cmd+Click` и по цепочке увидеть всю логику, то с событиями вам придется искать обработчики по всему проекту (а иногда их может не быть вовсе, или их может быть десять). 

Используйте доменные события как мосты между независимыми [[Bounded Context]] (например, когда модуль корзины хочет неявно сообщить модулю рекомендаций о предпочтениях пользователя). Внутри одного контекста, где важна прозрачность логики, предпочитайте обычные явные вызовы функций.
