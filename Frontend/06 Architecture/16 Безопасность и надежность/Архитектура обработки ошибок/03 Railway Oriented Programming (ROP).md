# Функциональное связывание (Railway Oriented Programming)

## 1. Основная идея

Railway Oriented Programming (железнодорожно-ориентированное программирование) — это концепция, популяризированная Скоттом Влашиным (Scott Wlaschin). Она является логической эволюцией Result-контейнеров и решает проблему накапливания однотипных проверок `if (!result.ok) return result.error;`.

Представьте себе железнодорожные пути с двумя параллельными колеями:
1. **Зеленая колея (Успех):** По ней едут успешные результаты (`Success` / `Ok`).
2. **Красная колея (Ошибка):** По ней едут ошибки (`Failure` / `Err`).

Каждая функция в вашей бизнес-логике — это железнодорожная стрелка. Она принимает данные с зеленой колеи, выполняет свою работу и решает: 
- Оставить поезд на **зеленой** колее (вернуть успешный Result).
- Перевести поезд на **красную** колею (вернуть Result с ошибкой).

**Самое главное правило ROP:** Если поезд (поток выполнения) попал на красную колею, все последующие функции бизнес-логики **игнорируются**. Ошибка просто "катится" по красной колее до самого конца, где её ждет финальный обработчик.

## 2. Проблема, которую мы решаем

Допустим, у нас есть три функции, каждая из которых возвращает `Result`:
1. Распарсить входящие данные (`parseData`).
2. Провалидировать их (`validateUser`).
3. Сохранить в базу (`saveToDb`).

При ручной распаковке контейнеров код выглядит громоздко:

```javascript
function registerUser(rawData) {
  // Шаг 1
  const parseResult = parseData(rawData);
  if (!parseResult.ok) return parseResult; // Ручной выход

  // Шаг 2
  const validationResult = validateUser(parseResult.value);
  if (!validationResult.ok) return validationResult; // Ручной выход

  // Шаг 3
  const saveResult = saveToDb(validationResult.value);
  if (!saveResult.ok) return saveResult; // Ручной выход

  return saveResult; // Успех
}
```

---

## 3. Решение: Автоматическое проталкивание (Chaining/Piping)

Чтобы избавиться от `if`, мы наделяем наш Result-контейнер специальными методами-адаптерами. Чаще всего они называются `map`, `bind` (или `flatMap`, `chain`) и `match`.

### Схематичная реализация контейнера:

```javascript
class Result {
  constructor(ok, value, error) {
    this.ok = ok;
    this.value = value;
    this.error = error;
  }

  static success(value) { return new Result(true, value, null); }
  static failure(error) { return new Result(false, null, error); }

  // Метод BIND (Связывание)
  // Принимает функцию, которая САМА возвращает Result.
  bind(fn) {
    if (!this.ok) {
      // Если мы уже на красной колее (ошибка), мы ПРОПУСКАЕМ выполнение 
      // новой функции и просто катим текущую ошибку дальше.
      return this; 
    }
    // Если на зеленой — выполняем функцию и возвращаем её Result
    return fn(this.value);
  }

  // Метод MATCH (Финальная распаковка)
  // Принимает два обработчика. Выполняет один в зависимости от итоговой колеи.
  match(onFailure, onSuccess) {
    if (this.ok) return onSuccess(this.value);
    return onFailure(this.error);
  }
}
```

## 4. Применение Railway Oriented Programming на практике

Перепишем функцию `registerUser`, используя методы `bind` и `match`:

```javascript
// Представим, что наши функции возвращают инстансы умного Result:
const parseData = (raw) => raw ? Result.success(raw) : Result.failure("No data");
const validateUser = (user) => user.age > 18 ? Result.success(user) : Result.failure("Too young");
const saveToDb = (user) => Result.success({ id: 1, ...user });

// Наша главная функция превращается в изящный пайплайн!
function handleRegistration(rawData) {
  
  // Выстраиваем цепочку ("железнодорожные пути")
  parseData(rawData)
    .bind(validateUser) // Передаст данные дальше, если parseData успешен
    .bind(saveToDb)     // Передаст данные дальше, если validateUser успешен
    .match(
      // Обработчик красной колеи (сработает один раз для любой ошибки из цепочки)
      (error) => {
        console.error("Регистрация провалена. Причина:", error);
        ui.showError(error);
      },
      // Обработчик зеленой колеи (сработает, если ВСЕ шаги были успешны)
      (savedUser) => {
        console.log("Регистрация успешна!", savedUser);
        ui.showSuccess("Добро пожаловать!");
      }
    );
}
```

### Как это работает под капотом?
Если `parseData` вернула ошибку, метод `.bind(validateUser)` увидит, что `ok: false`, и даже **не будет вызывать** функцию `validateUser`. Он просто вернет ту же самую ошибку. Следующий `.bind` сделает то же самое. В итоге ошибка "докатится" прямиком до блока `.match`, где отработает `onFailure`.

> *В реальном продакшене используют библиотеки `neverthrow`, `fp-ts` или `sweet-monads`.*

## 5. Плюсы и минусы ROP

### Плюсы:
* **Декларативность:** Вы описываете *что* должно произойти (последовательность шагов), а не *как* управлять состоянием через `if / else`.
* **Изоляция ошибок:** Обработка всех ошибок юзкейса собрана в одном месте (в методе `.match` в самом конце), а сама цепочка состоит только из "счастливого пути".
* **Никакого дублирования:** Вы полностью избавляетесь от рутинных проверок контейнеров на промежуточных этапах.

### Минусы:
* **Высокий порог входа:** Парадигма монадических операций (`bind`, `map`, `flatMap`) требует привыкания разработчикам из ООП / императивного мира.
* **Сложность дебага:** При передаче функций по ссылке (`.bind(validateUser)`) иногда сложнее отследить по стеку вызовов, на каком именно этапе произошел сбой.
* **Синтаксис в JS:** Без нативного оператора пайплайна (`|>`) или паттерн-матчинга код строится через цепочки методов или функции-помощники (`pipe()`).
