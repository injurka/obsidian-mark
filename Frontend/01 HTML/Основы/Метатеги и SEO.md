# Метатеги и SEO

**Метатеги (Meta tags)** — это специальные (одиночные) HTML-теги, которые предоставляют структурированные метаданные о веб-странице. Они всегда располагаются внутри технического контейнера `<head>` и не отображаются визуально в окне браузера. 

Их главная целевая аудитория — это **браузеры** (как правильно отображать контент), **поисковые системы** (Google, Yandex, Bing) и **социальные сети/мессенджеры** (как отображать ссылку при шеринге).

Правильное использование метатегов — фундамент **SEO** (Search Engine Optimization — поисковой оптимизации). Без них поисковым роботам крайне сложно понять суть страницы, а значит, она не получит высоких позиций в выдаче.

---

## 1. Базовые (технические) метатеги

Эти теги критически важны для корректного отображения сайта и косвенно влияют на SEO, так как поисковики пессимизируют (понижают в выдаче) сайты с техническими ошибками.

### Кодировка (Charset)
Обязательный тег, который указывает браузеру, как правильно декодировать текст страницы. Должен стоять в самом начале `<head>`.
```html
<meta charset="UTF-8">
```

### Адаптивность (Viewport)
Критически важный тег для SEO. В Google действует алгоритм **Mobile-First Indexing** — поисковик в первую очередь оценивает мобильную версию сайта. Без этого тега сайт не будет считаться адаптированным под мобильные устройства.
```html
<meta name="viewport" content="width=device-width, initial-scale=1.0">
```

## 2. Основные SEO-теги контента

Эти элементы напрямую видят пользователи в поисковой выдаче (SERP — Search Engine Results Page).

### Тег Title (Заголовок страницы)
Строго говоря, это не `<meta>`-тег, а отдельный HTML-элемент `<title>`, но в SEO-контексте его всегда рассматривают первым. Это **самый важный фактор** ранжирования.
* **Что делает:** Отображается как синяя кликабельная ссылка в поиске и как название вкладки в браузере.
* **Ограничения:** Рекомендуемая длина — **50–60 символов**. Если сделать длиннее, поисковик обрежет его многоточием.
* **Правило:** Должен содержать главное ключевое слово страницы и быть уникальным для каждого URL.
```html
<title>Купить ноутбук в Москве — Недорого, с доставкой | StoreName</title>
```

### Метатег Description (Описание)
* **Что делает:** Краткое описание страницы. Формирует серый текст-сниппет под заголовком в поиске. Напрямую не влияет на позиции в Google, но **критически влияет на CTR** (кликабельность). Если текст привлекательный, на ссылку нажмут чаще.
* **Ограничения:** Рекомендуемая длина — **140–160 символов** для десктопа и ~120 для мобилок.
```html
<meta name="description" content="Широкий выбор игровых и офисных ноутбуков. Гарантия 2 года, бесплатная доставка по Москве при заказе от 10 000 руб. Скидки студентам!">
```

### Метатег Keywords (Ключевые слова) — 💀 МЕРТВ
Исторически использовался для перечисления ключевых слов через запятую.
> [!WARNING] Важно
> Google официально игнорирует метатег `keywords` с 2009 года, Яндекс — также не учитывает его при ранжировании. Использование этого тега **бессмысленно**, а жесткий переспам ключами (keyword stuffing) в нем может привести к наложению фильтров (штрафам). Лучше вообще не добавлять его в код.

## 3. Управление индексацией (Метатег Robots)

Тег `robots` — это пульт управления поисковым роботом. Он говорит краулерам (Googlebot, YandexBot), что можно делать со страницей, а что нельзя.

```html
<meta name="robots" content="index, follow">
```

### Основные директивы атрибута `content`:
| Директива | Действие |
| :--- | :--- |
| `index` | Разрешает поисковику добавлять страницу в базу данных (индексировать). *Включено по умолчанию.* |
| `noindex` | **Запрещает** добавление страницы в поисковую выдачу. Используется для служебных страниц (корзина, админка, страница успешной оплаты). |
| `follow` | Разрешает поисковику переходить по ссылкам на этой странице и передавать им "вес". *Включено по умолчанию.* |
| `nofollow` | Запрещает переходить по ссылкам на странице. |
| `noarchive` | Запрещает поисковику показывать сохраненную (кэшированную) копию страницы. |
| `nosnippet` | Запрещает поисковику выводить сниппет (description) в результатах поиска. |

*Пример (Скрыть страницу из поиска, но разрешить ходить по ее ссылкам):*
```html
<meta name="robots" content="noindex, follow">
```

## 4. Социальные метатеги (SMO и Микроразметка)

Когда пользователь кидает ссылку на ваш сайт в Telegram, VK, Slack или Twitter, мессенджер автоматически подтягивает красивую карточку с картинкой, заголовком и описанием. За это отвечают протоколы **Open Graph** (разработан Facebook) и **Twitter Cards**. Без них ссылка будет выглядеть как скучный серый текст.

### Open Graph (Универсальный стандарт)
Использует атрибут `property="og:..."`. Поддерживается практически всеми платформами.
```html
<!-- Тип контента (website, article, product) -->
<meta property="og:type" content="website">

<!-- Заголовок для соцсетей -->
<meta property="og:title" content="Заголовок для красивой карточки">

<!-- Описание для соцсетей -->
<meta property="og:description" content="Текст, который появится под заголовком в Телеграме.">

<!-- URL страницы -->
<meta property="og:url" content="https://mysite.com/page">

<!-- Картинка-превью (рекомендуемый размер 1200x630 px) -->
<meta property="og:image" content="https://mysite.com/assets/og-image.jpg">
```

### Twitter Cards
Специфичные метатеги для платформы X (Twitter).
```html
<meta name="twitter:card" content="summary_large_image">
<meta name="twitter:title" content="Заголовок">
<meta name="twitter:description" content="Описание">
<meta name="twitter:image" content="https://mysite.com/assets/twitter-img.jpg">
```

## 5. Важные SEO-связи: тег `<link>`

Хотя это не `<meta>`-теги, они играют критическую роль в техническом SEO и всегда размещаются в `<head>`.

### Canonical (Каноническая ссылка)
Часто один и тот же контент доступен по разным URL (например, `site.com/catalog?sort=price` и `site.com/catalog`). Поисковики ненавидят **дублирование контента** и могут понизить сайт в выдаче.
Тег `canonical` указывает поисковику, какой URL считать главным (оригиналом).
```html
<link rel="canonical" href="https://mysite.com/catalog">
```

### Hreflang (Мультиязычность)
Если ваш сайт переведен на несколько языков, атрибут `hreflang` подскажет Google, какую версию страницы показывать пользователю в зависимости от его региона и языка браузера.
```html
<link rel="alternate" hreflang="ru" href="https://mysite.com/ru/page">
<link rel="alternate" hreflang="en" href="https://mysite.com/en/page">
<link rel="alternate" hreflang="x-default" href="https://mysite.com/en/page"> <!-- Язык по умолчанию -->
```

## 6. Современный фронтенд (SPA, SSR и Метатеги)

В классическом HTML-документе метатеги просто прописываются в файле. Но в современных Single Page Applications (SPA), написанных на Vue или React, `<head>` документа изначально пуст, а контент генерируется JavaScript-ом на лету. 

Поисковые роботы (особенно Яндекс) плохо справляются с асинхронным рендерингом метатегов через JavaScript (Client-Side Rendering). Именно поэтому для SEO-оптимизированных проектов применяют **SSR (Server-Side Rendering)** или **SSG (Static Site Generation)** с помощью фреймворков Nuxt или Next.js.

*Пример того, как в Nuxt 3 (фреймворк из вашей базы знаний) динамически управляются SEO-метатеги с помощью композитного API:*
```vue
<script setup>
useSeoMeta({
  title: 'Моя крутая страница',
  description: 'Это динамическое описание, пришедшее из базы данных',
  ogTitle: 'Моя крутая страница',
  ogDescription: 'Это динамическое описание, пришедшее из базы данных',
  ogImage: 'https://mysite.com/dynamic-image.png',
  twitterCard: 'summary_large_image',
})
</script>
```

### Главные правила SEO для разработчика:
1. **Уникальность:** У каждой страницы сайта должен быть уникальный `<title>` и `<meta name="description">`.
2. **Семантика:** Правильное использование тегов заголовков (`<h1>`-`<h6>`). На странице должен быть строго один `<h1>`.
3. **Скорость (Core Web Vitals):** Поисковики пессимизируют медленные сайты (плохие показатели LCP, CLS, INP).
4. **Доступность (A11y):** Заполненные атрибуты `alt` у изображений критически важны для поиска по картинкам.
