# Вкладка Memory (Chrome DevTools)

Вкладка **Memory** предназначена для анализа использования оперативной памяти веб-приложением. Это главный инструмент для поиска и устранения **утечек памяти (Memory Leaks)**.

## Основные режимы профилирования:

### 1. Heap Snapshot (Снапшот кучи)
Создает "фотографию" всей памяти, которую использует страница в текущий момент времени.
*   Показывает распределение памяти между объектами JavaScript и DOM-узлами.
*   **Сравнение снапшотов (Comparison):** Самый частый сценарий поиска утечек. 
    1. Делаем первый снапшот.
    2. Выполняем действие (например, открываем и закрываем модальное окно).
    3. Делаем второй снапшот.
    4. Сравниваем их, чтобы найти объекты (например, Detached DOM tree), которые должны были быть удалены сборщиком мусора, но почему-то остались в памяти.

### 2. Allocation instrumentation on timeline (Распределение по времени)
Показывает создание новых объектов в реальном времени во время записи.
*   Удобно для поиска участков кода, которые генерируют слишком много временных объектов (что заставляет сборщик мусора работать слишком часто и приводит к подвисаниям — Garbage Collection pauses).
*   Синие полоски означают выделение памяти, серые — что память была освобождена сборщиком мусора.

### 3. Allocation sampling (Семплирование)
Облегченный вариант профилирования памяти. Показывает, какие функции (стеки вызовов) выделяют больше всего памяти. Менее точный, чем Timeline, но создает минимальную нагрузку на систему во время записи.

## Ключевые термины для понимания:
*   **Shallow Size:** Размер памяти, который занимает сам объект (строки, числа).
*   **Retained Size:** Размер памяти, который освободится, если удалить этот объект (и все другие объекты, на которые ссылается только он). Именно этот размер важен при поиске утечек.
*   **Detached DOM elements:** DOM-узлы, которые были удалены из документа, но остались в памяти, потому что на них все еще ссылается переменная в JavaScript или обработчик событий. Самая частая причина утечек.
