# types

> [!info]
> Опция **`types`** в `tsconfig.json` управляет тем, какие именно пакеты из директорий `typeRoots` (или стандартной `@types`) будут загружены компилятором в **глобальную область видимости**.

## Суть концепции

В то время как `typeRoots` указывает компилятору, *где* искать папки с типами, опция `types` ограничивает, *какие* именно пакеты из этих папок будут неявно доступны (как ambient-декларации) без явного импорта в файлах проекта.

По умолчанию TypeScript автоматически подключает все видимые пакеты из `node_modules/@types` глобально. Однако, это не всегда желательно. Например, в проекте может быть настроен Jest (тестирование), и типы для глобальных функций `describe` и `it` протекут в код приложения, маскируя потенциальные ошибки (например, случайное использование глобальной переменной `test`).

### Пример настройки

Использование опции `types` позволяет создать "white-list" разрешенных глобальных типов:

```json
{
  "compilerOptions": {
    "types": ["node", "jest"]
  }
}
```
В этом примере в глобальном контексте будут доступны только модули Node.js (`process.env`) и функции Jest. Типы для пакетов, которые импортируются явно (например, `import * as React from "react"`), будут работать нормально, так как они подтягиваются через модульную систему, а не глобально.

Если указать пустой массив:
```json
{
  "compilerOptions": {
    "types": []
  }
}
```
Это полностью отключит автоматическое добавление типов из `@types` в глобальную область, что часто полезно для строго изолированных frontend-сборок.

### Важность для Strict Mode и Ambient Declarations
Опция `types` работает в симбиозе с концепцией ambient-контекста (`declare`). Регулируя список глобально доступных типов, вы улучшаете изоляцию и предсказуемость вашего кода. В **Strict Mode** отключение ненужных глобальных типов помогает избежать конфликтов имен глобальных переменных и делает зависимости проекта прозрачными.
