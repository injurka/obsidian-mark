> [!info]
> **Продвинутые паттерны декораторов** — это архитектурные приемы использования декораторов в TypeScript для создания гибкого, переиспользуемого и чистого кода. К ним относятся фабрики декораторов, композиция декораторов и автоматическая обработка ошибок.

## Суть концепции

По мере усложнения приложения простые декораторы перестают справляться с комплексной бизнес-логикой. Разработчики прибегают к продвинутым паттернам, которые позволяют:
- Настраивать поведение декораторов (Фабрики).
- Комбинировать несколько декораторов на одном элементе (Композиция).
- Инкапсулировать повторяющуюся логику (например, `try...catch` блоки) прямо на уровне метаданных.

### Legacy декораторы (experimentalDecorators) vs Новые декораторы (TS 5.0)
При использовании продвинутых паттернов важно учитывать, что порядок вызова (особенно при композиции) строго регламентирован в обоих стандартах. Однако новый стандарт (TS 5.0) добавляет новые возможности, такие как `addInitializer` в контексте, который позволяет прикреплять дополнительную логику инициализации после того, как класс или метод были определены. Это делает паттерны вроде Dependency Injection более надежными.

## Примеры кода на TypeScript (Новый стандарт TS 5.0+)

### Пример: Автоматический обработчик ошибок (Error Guard)

Часто методы классов содержат одинаковые блоки `try...catch`. С помощью декоратора можно вынести эту логику.

```typescript
function CatchError(errorHandler: (err: any) => void) {
  return function (originalMethod: any, context: ClassMethodDecoratorContext) {
    return function (this: any, ...args: any[]) {
      try {
        return originalMethod.apply(this, args);
      } catch (err) {
        errorHandler(err);
      }
    };
  };
}

class ApiService {
  @CatchError((err) => console.error('[API Error]:', err.message))
  fetchData() {
    // Симуляция ошибки
    throw new Error('Network timeout');
  }
}

const api = new ApiService();
api.fetchData(); // Безопасно перехватит ошибку и выведет: [API Error]: Network timeout
```
