# Best Practices

## Описание

> [!info] 
> Best Practices в TypeScript — это набор рекомендаций и паттернов, которые помогают писать чистый, масштабируемый и типобезопасный код. Они охватывают настройку компилятора, стиль написания типов, архитектурные решения и избегание частых антипаттернов.

Соблюдение лучших практик позволяет максимизировать пользу от статического анализатора и избежать "TypeScript-ада", когда типы становятся слишком сложными, нечитаемыми или когда разработчики начинают злоупотреблять костылями.

## Примеры использования

```typescript
// ❌ АНТИПАТТЕРНЫ
// 1. Использование any отключает проверку
const processData = (data: any) => { /* ... */ };

// 2. Использование enum (часто раздувает бандл и ведет себя странно)
enum Status { Open, Closed }

// 3. Ненужные Type Assertions
const el = document.getElementById('my-el') as HTMLInputElement;


// ✅ ЛУЧШИЕ ПРАКТИКИ
// 1. Использование unknown и валидации
const processDataSafe = (data: unknown) => {
    if (typeof data === 'string') {
        console.log(data.toUpperCase());
    }
};

// 2. Использование Union типов (POJO константы)
type StatusType = "Open" | "Closed";

// 3. Использование Optional Chaining и Type Guards
const inputEl = document.getElementById('my-el');
if (inputEl instanceof HTMLInputElement) {
    console.log(inputEl.value);
}
```

## Особенности и нюансы

- **Strict Mode**: Всегда включайте `"strict": true` в `tsconfig.json`. Это фундамент безопасного кода.
- **Предпочтение Интерфейсам**: Используйте `interface` для объявления структур данных объектов. Используйте `type` (Type Aliases) для примитивов, объединений (unions), кортежей (tuples) и сложных утилитарных типов.
- **Избегайте `any`**: Если тип неизвестен, используйте `unknown`. Если тип сложный, опишите его. `any` — это вирус, который отключает TS.
- **Return Types**: Явно указывайте возвращаемые типы для экспортируемых функций, чтобы избежать неожиданного вывода типов.
- **Utility Types**: Активно используйте встроенные типы-утилиты (`Partial`, `Pick`, `Omit`, `Record`), чтобы не дублировать код интерфейсов.
