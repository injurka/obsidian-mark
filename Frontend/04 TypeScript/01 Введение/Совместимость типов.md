# Совместимость типов

## Описание

> [!info] 
> Совместимость типов в TypeScript базируется на принципе структурной типизации (Structural Typing). Два типа считаются совместимыми, если их внутренние структуры (набор свойств и их типы) совпадают. Правило "утиной типизации": если это выглядит как утка и крякает как утка, то это утка.

В TypeScript объект типа `A` можно присвоить переменной типа `B`, если `A` содержит все обязательные свойства `B` с совместимыми типами. Лишние свойства в `A` при этом не мешают присвоению (за исключением объектных литералов, которые проверяются строже).

## Примеры использования

```typescript
interface Pet {
    name: string;
}

interface Dog {
    name: string;
    breed: string;
}

let pet: Pet;
let dog: Dog = { name: "Rex", breed: "Shepherd" };

// Совместимо! У dog есть свойство 'name' типа string
pet = dog; 

// Ошибка! У pet нет свойства 'breed'
// dog = pet; 

// Строгая проверка объектных литералов (Excess Property Checks)
// Если мы передаем литерал напрямую, TS выдаст ошибку на лишние поля:
// let anotherPet: Pet = { name: "Bella", breed: "Poodle" }; // Ошибка!
```

## Особенности и нюансы

- **Функции**: Совместимость функций зависит от параметров и возвращаемых типов. Функция с меньшим количеством параметров может быть присвоена функции с большим, если типы совпадают (отбрасывание параметров).
- **Ковариантность и Контравариантность**: В TS типы возврата функций ковариантны (можно вернуть более специфичный тип), а параметры функций бивариантны (до `strictFunctionTypes`) или контравариантны (в строгом режиме).
- **Избыточные проверки свойств (Excess Property Checks)**: Присваивание напрямую созданного объекта (литерала) интерфейсу вызывает строгую проверку — запрещены любые свойства, не описанные в интерфейсе.
- **Подводный камень**: При присваивании через промежуточную переменную лишние свойства "пропадают" из поля зрения TypeScript, но в рантайме они все еще есть в объекте.
