# Номинальная типизация и эмуляция

## Описание

> [!info] 
> TypeScript использует структурную типизацию (duck typing), а не номинальную. Номинальная типизация (как в Java или C#) проверяет совместимость по имени типа, тогда как структурная — по структуре (полям) объекта. Однако, иногда номинальная типизация необходима для безопасности, и её можно эмулировать (через брендирование / Opaque Types).

При структурной типизации, если у двух разных интерфейсов одинаковые поля, TypeScript будет считать их взаимозаменяемыми. Это может стать проблемой, когда у нас есть, например, `UserId` (string) и `OrderId` (string). Мы не хотим случайно передать ID заказа в функцию, ожидающую ID пользователя. Эмуляция номинальной типизации (Branded Types) решает эту проблему путем подмешивания фиктивного свойства.

## Примеры использования

```typescript
// ПРОБЛЕМА СТРУКТУРНОЙ ТИПИЗАЦИИ:
type UserId = string;
type OrderId = string;

function banUser(id: UserId) { /* ... */ }
const myOrder: OrderId = "order_123";
banUser(myOrder); // TS пропустит это, так как оба типа — string!

// РЕШЕНИЕ (Эмуляция номинальной типизации - Branding):
type Nominal<T, Brand> = T & { readonly __brand: Brand };

type BrandedUserId = Nominal<string, "UserId">;
type BrandedOrderId = Nominal<string, "OrderId">;

function banUserSafe(id: BrandedUserId) { /* ... */ }

// Функция создания Branded типа
const createUserId = (id: string) => id as BrandedUserId;
const createOrderId = (id: string) => id as BrandedOrderId;

const uId = createUserId("user_456");
const oId = createOrderId("order_789");

banUserSafe(uId); // OK
// banUserSafe(oId); // Ошибка: Argument of type 'BrandedOrderId' is not assignable to parameter of type 'BrandedUserId'.
```

## Особенности и нюансы

- **Брендирование (Branding)**: Использование пересечений (intersections `&`) с уникальными полями-маркерами (`__brand`), которых не существует в рантайме.
- **Безопасность**: Защищает от случайного смешивания примитивных типов с разной бизнес-логикой.
- **Управление состоянием**: Позволяет отличать "провалидированные" строки от сырых (например, `ValidatedEmail`).
- **Подводный камень**: Необходимы специальные функции-фабрики (или Type Assertions) для приведения сырого типа к брендированному, что добавляет немного бойлерплейта. Свойство `__brand` существует только для компилятора, в рантайме оно не создается (благодаря `as Type`).
