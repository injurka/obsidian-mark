# Стирание типов (Type Erasure)

## Описание

> [!info] 
> Стирание типов (Type Erasure) — это процесс, при котором компилятор TypeScript удаляет все конструкции, связанные с типами (интерфейсы, аннотации типов, алиасы), во время преобразования кода в JavaScript. В сгенерированном JS-коде не остается никаких следов типов.

TypeScript является языком со статической типизацией на этапе разработки, но с динамической типизацией на этапе выполнения. Компилятор лишь проверяет корректность типов, а затем "стирает" их. Это означает, что вы не можете использовать типы, интерфейсы или дженерики в качестве реальных значений или для проверок (например, `instanceof`) во время выполнения программы.

## Примеры использования

```typescript
// Код на TypeScript
interface Person {
    name: string;
    age: number;
}

function greet(person: Person): void {
    console.log(`Hello, ${person.name}`);
}
```

```javascript
// Скомпилированный код (JavaScript) после Type Erasure
// Интерфейс 'Person' полностью исчез
function greet(person) {
    console.log(`Hello, ${person.name}`);
}
```

## Особенности и нюансы

- **Нулевой overhead в рантайме**: Использование сложных типов в TS никак не влияет на размер бандла или производительность конечного JS-кода, так как все типы удаляются.
- **Невозможность проверки интерфейсов в рантайме**: Вы не можете написать `if (obj instanceof Person)` если `Person` — это интерфейс.
- **Подводный камень**: Из-за стирания типов, для валидации данных в рантайме (например, ответов от API) необходимо использовать Type Guards, пользовательские проверки (Custom Type Predicates) или сторонние библиотеки валидации схем (Zod, Joi, Yup).
- **Исключения**: `enum` и `namespace` не стираются полностью, а компилируются в реальные объекты JavaScript (если это не `const enum`). Классы также остаются, так как они существуют в JS.
