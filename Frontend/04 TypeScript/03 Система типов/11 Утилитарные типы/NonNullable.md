# NonNullable

## Описание

> [!info] NonNullable<Type>
> Утилитарный тип `NonNullable<Type>` создает новый тип, исключая `null` и `undefined` из переданного типа `Type`.

Он решает проблему "очистки" типов от возможных пустых значений. Если у вас есть переменная или результат функции, который может быть строкой, а может быть `null` или `undefined`, и вы передаете это значение в функцию, которая точно требует строку, вы можете использовать `NonNullable` для уточнения типа (совместно с проверками в рантайме).

## Примеры использования

```typescript
type T0 = NonNullable<string | number | undefined>;
// type T0 = string | number

type T1 = NonNullable<string[] | null | undefined>;
// type T1 = string[]
```

## Особенности и нюансы

- **Опция `strictNullChecks`**: `NonNullable` имеет смысл и работает должным образом только при включенном флаге `strictNullChecks` в `tsconfig.json`. Без него `null` и `undefined` неявно входят во все типы, и извлечь их не получится.
- **Под капотом**:
  До TypeScript 4.8 реализация выглядела так (с помощью условных типов):
  ```typescript
  type NonNullable<T> = T extends null | undefined ? never : T;
  ```
  Начиная с TypeScript 4.8, реализация была изменена для лучшей работы с пересечениями типов и теперь выглядит так:
  ```typescript
  type NonNullable<T> = T & {};
  ```
  В TypeScript `& {}` (пересечение с пустым объектом) эффективно удаляет `null` и `undefined`, так как они не могут быть пересечены с объектом, в то время как другие типы (включая примитивы) с ним совместимы (примитивы в TS могут быть автоупакованы).
