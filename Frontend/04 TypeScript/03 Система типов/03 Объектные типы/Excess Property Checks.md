# Excess Property Checks

## Описание

> [!info] 
> **Excess Property Checks (проверки избыточных свойств)** — это механизм TypeScript, который строго проверяет объектные литералы на наличие свойств, не описанных в целевом типе, при их непосредственном присваивании переменным или передаче в функции.

TypeScript применяет это правило только к свежим (fresh) объектным литералам. Если вы создаете объектный литерал и сразу же присваиваете его переменной с явным типом или передаете в качестве аргумента, TypeScript выдаст ошибку на любые дополнительные свойства. Это сделано для выявления опечаток и предотвращения передачи ненужных данных.

## Примеры использования

```typescript
interface UserSettings {
  theme: "dark" | "light";
  notifications: boolean;
}

// ❌ Ошибка: Object literal may only specify known properties, and 'volume' does not exist in type 'UserSettings'.
const settings: UserSettings = {
  theme: "dark",
  notifications: true,
  volume: 100 // Ошибка!
};

function applySettings(config: UserSettings) {
  // ...
}

// ❌ Ошибка: избыточное свойство 'color'
applySettings({ theme: "light", notifications: false, color: "blue" });
```

## Особенности и нюансы

- **Только для свежих объектных литералов**: Проверка избыточных свойств **не срабатывает**, если объектный литерал сначала присваивается промежуточной переменной, а затем передается туда, где ожидается другой тип (при условии, что обязательные свойства присутствуют - работает структурная типизация).
  ```typescript
  const mySettings = {
    theme: "dark" as const,
    notifications: true,
    volume: 100
  };
  
  // ✅ Ошибки нет, так как `mySettings` не является "свежим" литералом
  const validSettings: UserSettings = mySettings;
  applySettings(mySettings);
  ```
- **Обход проверки с помощью утверждения типа**: Если вы уверены, что избыточные свойства необходимы, можно использовать `as`.
  ```typescript
  const settings = {
    theme: "dark",
    notifications: true,
    volume: 100
  } as UserSettings;
  ```
- **Индексные сигнатуры (Index Signatures)**: Если тип может содержать любые другие дополнительные свойства, лучшим решением будет добавление индексной сигнатуры `[key: string]: any;` к интерфейсу.
- **Опечатки в опциональных свойствах**: Этот механизм крайне полезен для поиска опечаток, когда все свойства опциональны (Weak Types), предотвращая создание объектов, которые структурно удовлетворяют типу, но фактически не содержат нужных данных.
