# Interface vs Type

## Описание

> [!info] 
> `interface` и `type` — это два основных способа описания структур данных и типов в TypeScript. Во многих случаях они взаимозаменяемы, но имеют концептуальные различия, разные возможности расширения и поведение при пересечении.

- **`interface` (Интерфейс)** используется исключительно для описания формы объектов (object shapes) и классов.
- **`type` (Type Alias, Псевдоним типа)** может использоваться для объектов, но также поддерживает объединения (unions), пересечения (intersections), примитивы, кортежи (tuples) и утилиты типов.

Выбор между ними зависит от контекста и требований к расширяемости и композиции типов.

## Примеры использования

```typescript
// --- Описание объекта с помощью Type ---
type PointType = {
  x: number;
  y: number;
};

// --- Описание объекта с помощью Interface ---
interface PointInterface {
  x: number;
  y: number;
}

// --- Расширение интерфейсов (extends) ---
interface Animal {
  name: string;
}
interface Bear extends Animal {
  honey: boolean;
}

// --- Расширение типов (intersection) ---
type AnimalType = {
  name: string;
}
type BearType = AnimalType & { 
  honey: boolean 
};

// Оба могут быть имплементированы классом
class MyPoint implements PointInterface {
  x = 1;
  y = 2;
}
```

## Особенности и нюансы

1. **Декларативное слияние (Declaration Merging):**
   - **`interface`** поддерживает слияние деклараций. Если вы объявляете два интерфейса с одинаковым именем в одной области видимости, TypeScript объединит их свойства в один интерфейс. Это критически важно для расширения сторонних библиотек.
   - **`type`** не поддерживает слияние. Попытка объявить `type` с одним и тем же именем дважды вызовет ошибку.
   ```typescript
   interface Window { title: string; }
   interface Window { ts: typeof ts; } // Успешное объединение

   type WindowType = { title: string; }
   // type WindowType = { ts: typeof ts; } // Ошибка: Duplicate identifier
   ```

2. **Примитивы и Union типы:**
   - **`type`** может описывать объединения (`TypeA | TypeB`), примитивы (`type ID = string | number`) и кортежи (`type Point = [number, number]`).
   - **`interface`** может описывать только объекты (или сигнатуры функций/конструкторов).

3. **Разрешение конфликтов при расширении:**
   - Если два интерфейса имеют одноименное свойство с несовместимыми типами, `extends` выдаст ошибку.
   - Если вы используете пересечение `&` для типов с несовместимыми свойствами, TypeScript молча создаст тип `never` для этого свойства.

4. **Производительность компилятора:** В очень сложных системах типов интерфейсы часто компилируются и кэшируются быстрее, чем сложные пересечения типов (`&`), так как интерфейсы создают плоскую структуру при наследовании, а типы вычисляются рекурсивно.

**Рекомендация:**
Используйте `interface` для определения публичных API библиотек и структур объектов (из-за возможности расширения). Используйте `type` для объединений, примитивов, кортежей и сложных утилитных типов (mapped types, conditional types).
