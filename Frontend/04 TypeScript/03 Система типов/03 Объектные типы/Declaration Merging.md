# Declaration Merging

## Описание

> [!info]
> **Слияние объявлений (Declaration Merging)** — это механизм компилятора TypeScript, который объединяет два или более отдельных объявлений с одинаковым именем в одно единое определение. Полученная сущность обладает характеристиками всех исходных объявлений.

В TypeScript вы можете объявить интерфейс, пространство имен (namespace) или даже функцию несколько раз. Вместо того чтобы выдать ошибку о повторном объявлении (как это произошло бы с переменными `let` или `const`), компилятор аккуратно сливает эти объявления воедино. Это особенно полезно при расширении сторонних библиотек, типизации глобальных объектов (например, `window`) или при постепенном наращивании структуры данных.

Слиянию поддаются:
- Интерфейсы (Interfaces)
- Пространства имен (Namespaces)
- Перечисления (Enums)
- Пространства имен с классами, функциями или перечислениями

Классы и псевдонимы типов (`type`) **не могут** сливаться сами с собой.

## Примеры использования

### Слияние интерфейсов

Самый частый сценарий — расширение интерфейсов.

```typescript
interface User {
  name: string;
}

interface User {
  age: number;
}

// Теперь интерфейс User содержит оба поля
const john: User = {
  name: "John",
  age: 30
};
```

### Расширение глобального объекта Window

Часто при работе с браузерным API или добавлении глобальных переменных нужно расширить интерфейс `Window`.

```typescript
interface Window {
  myCustomPlugin: {
    init(): void;
  };
}

// Теперь TS знает, что myCustomPlugin существует на объекте window
window.myCustomPlugin = {
  init: () => console.log('Plugin initialized')
};
```

### Слияние пространств имен (Namespaces)

```typescript
namespace Animals {
  export class Zebra {}
}

namespace Animals {
  export interface Legged {
    numberOfLegs: number;
  }
  export class Dog {}
}

// Эквивалентно одному пространству имен с классами Zebra, Dog и интерфейсом Legged
```

## Особенности и нюансы

- **Порядок слияния методов:** При слиянии интерфейсов, если в них определены методы с одинаковыми именами, то те методы, которые объявлены позже, будут иметь больший приоритет (будут стоять выше в списке перегрузок). Исключением являются сигнатуры с параметрами строковых литералов — они всегда поднимаются на самый верх.
- **Отсутствие слияния для `type`:** В отличие от `interface`, псевдонимы типов (`type aliases`) не поддерживают слияние. Попытка объявить два `type` с одним именем вызовет ошибку.
- **Слияние классов и пространств имен:** Можно использовать пространства имен для добавления статических методов к классам. Для этого класс и пространство имен должны находиться в одном файле и класс должен быть объявлен перед пространством имен.
- **Невозможность слияния классов:** TypeScript не поддерживает слияние двух классов с одинаковым именем.
- **Расширение модулей (Module Augmentation):** Позволяет расширять типы сторонних библиотек без их изменения, используя синтаксис `declare module "module-name" { ... }`.
