# Брендированные и номинальные типы

## Описание

> [!info]
> **Брендированные типы (Branded Types)** — это паттерн в TypeScript для эмуляции номинальной типизации (Nominal Typing) поверх структурной. Он позволяет компилятору отличать типы, которые имеют одинаковую структуру (например, две разные строки или числа), защищая от ошибочного смешивания несовместимых данных.

TypeScript использует структурную типизацию: если два типа имеют одинаковую структуру, они считаются совместимыми, даже если у них разные имена. Однако в бизнес-логике часто возникает необходимость строго разделять сущности, которые под капотом представлены одним примитивом. Например, `UserId` и `PostId` могут быть числами, но передача `PostId` в функцию, ожидающую `UserId`, должна вызывать ошибку. 

Для решения этой задачи в TypeScript используют паттерн "Брендирования". К базовому типу с помощью пересечения (`&`) добавляется уникальная метка (бренд), которая не существует в рантайме, но позволяет компилятору различать типы.

## Примеры использования

### Создание базового утилитарного типа

```typescript
// Обобщенный тип для создания брендированных типов
type Brand<K, T> = K & { __brand: T };

// Либо более современный подход с использованием уникальных символов:
declare const brand: unique symbol;
type Branded<T, B> = T & { [brand]: B };
```

### Разделение идентификаторов

```typescript
type UserId = Brand<number, "UserId">;
type PostId = Brand<number, "PostId">;

function getUserById(id: UserId) {
  // Получение пользователя
}

const userId = 1 as UserId;
const postId = 1 as PostId;

getUserById(userId); // OK
// getUserById(postId); // Ошибка: Тип 'PostId' не может быть назначен типу 'UserId'.
```

### Валидация данных

Брендированные типы отлично подходят для гарантии того, что данные прошли валидацию.

```typescript
type ValidatedEmail = Brand<string, "Email">;

function isValidEmail(email: string): email is ValidatedEmail {
  return email.includes("@");
}

function sendEmail(email: ValidatedEmail) {
  console.log(`Sending email to ${email}`);
}

const userEmail = "test@example.com";

// sendEmail(userEmail); // Ошибка: Argument of type 'string' is not assignable to parameter of type 'ValidatedEmail'

if (isValidEmail(userEmail)) {
  sendEmail(userEmail); // OK: теперь TS знает, что это ValidatedEmail
}
```

## Особенности и нюансы

- **Отсутствие в рантайме:** Бренды существуют только на уровне типов. Во время выполнения это будут обычные строки, числа или объекты. Свойство `__brand` фактически никогда не добавляется к объекту.
- **Необходимость приведения типов (Type Casting):** Чтобы создать брендированное значение, обычно требуется использовать утверждение типа (`as UserId`) или написать специальную функцию-валидатор (Type Guard), так как напрямую присвоить примитив брендированному типу нельзя.
- **Уникальные символы:** Использование `declare const brand: unique symbol` вместо строк для брендов снижает вероятность случайного совпадения имен брендов и делает тип более чистым, так как символ не отображается в подсказках IDE так навязчиво, как строковое свойство.
- **Альтернативы (Flavoring):** Иногда используют "Flavors" — опциональные бренды (например, `{ __brand?: T }`). Они позволяют нестрогое присваивание, когда примитив можно передать туда, где ожидается Flavor, но два разных Flavor смешивать нельзя. Но классические брендированные типы обеспечивают более строгую защиту.
