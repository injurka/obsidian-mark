# Enums vs Union Types

## Описание

> [!info]
> Enums (Перечисления) и Union Types (Объединения) с литералами часто решают одну и ту же задачу — определение ограниченного набора возможных значений. Однако они работают по-разному и имеют свои плюсы и минусы.

В современном TypeScript-сообществе прослеживается сильный тренд на **отказ от Enums в пользу Union Types** (`"A" | "B"`), так как последние более предсказуемы, не добавляют рантайм-кода и проще в использовании.

## Сравнение

### Enums

**Плюсы:**
- Имеют собственное имя (пространство имен) при импорте.
- Могут быть легко итерированы (через `Object.keys`, если это не `const enum`).
- Понятны разработчикам, пришедшим из C# / Java.

**Минусы:**
- Добавляют код в рантайме (генерируют реальные JS-объекты).
- Строковые Enum-ы номинативны (нельзя передать обычную строку, даже если она совпадает, только `Enum.Value`).
- Числовые Enum-ы до TS 5.0 были небезопасны (позволяли передать любое число).
- `const enum` ломаются с некоторыми бандлерами (`--isolatedModules`).

### Union Types

```typescript
// Альтернатива Enum
type Direction = "Up" | "Down" | "Left" | "Right";

// Альтернатива итерируемому объекту (as const)
const DIRECTION = {
  Up: "Up",
  Down: "Down",
  Left: "Left",
  Right: "Right",
} as const;
type DirectionType = typeof DIRECTION[keyof typeof DIRECTION];
```

**Плюсы:**
- Не генерируют JS-код.
- Структурная типизация: можно передать обычную строку (например, `"Up"`), не импортируя ничего.
- Меньше проблем при сборке и бандлинге.

## Вывод

> [!tip]
> Используйте **Union Types** или объекты с **`as const`** в 95% случаев. Используйте **Enums**, только если вы работаете в команде, где это строгий стандарт, или если вам сильно нужно обратное отображение (Reverse Mapping) числовых значений.
