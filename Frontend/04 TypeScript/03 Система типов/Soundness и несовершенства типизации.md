# Soundness и несовершенства типизации

## Описание

> [!info] 
> Soundness (Надежность или Строгость) системы типов — это гарантия того, что если программа прошла проверку типов (compile-time), то в рантайме она никогда не выбросит ошибку, связанную с несоответствием типов.

TypeScript **не является полностью sound** (т.е. он unsound). Дизайн языка осознанно жертвует 100% надежностью в пользу удобства, гибкости и совместимости с существующими паттернами JavaScript.

## Основные компромиссы (Unsoundness)

Существуют определенные ситуации, когда TypeScript считает код безопасным, но в рантайме он может упасть.

### 1. Бивариантность методов (Method Bivariance)

Как было описано в статье о Variance, методы классов и интерфейсов бивариантны. Это означает, что вы можете передать менее специфичный тип туда, где ожидается более специфичный (что небезопасно).

### 2. Тип `any`

Использование `any` отключает все проверки типов. Значение `any` может быть присвоено чему угодно, и что угодно может быть присвоено `any`.

### 3. Type Assertions (Приведение типов)

Использование `as Type` или `<Type>` заставляет компилятор доверять вам, даже если вы ошибаетесь.

```typescript
const obj = {} as { name: string };
console.log(obj.name.toUpperCase()); // Упадет в рантайме (Cannot read property 'toUpperCase' of undefined)
```

### 4. Индексация массивов

По умолчанию TypeScript считает, что доступ по индексу в массиве всегда возвращает элемент.

```typescript
const nums: number[] = [1, 2, 3];
const x: number = nums[10]; // x = undefined, но тип number
// Ошибка в рантайме при x.toFixed(), хотя TS не ругается.
```
*Решение:* включить флаг компилятора `noUncheckedIndexedAccess` (тогда тип будет `number | undefined`).

## Вывод

TypeScript предоставляет инструменты для раннего обнаружения большинства ошибок, но не является панацеей от всех Runtime-ошибок. Разработчик должен понимать эти ограничения и использовать строгие настройки компилятора (`strict: true`, `noUncheckedIndexedAccess: true`), чтобы повысить надежность кода.
