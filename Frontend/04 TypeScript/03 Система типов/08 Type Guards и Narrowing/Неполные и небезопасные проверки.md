# Неполные и небезопасные проверки

## Описание

> [!info] 
> Неполные и небезопасные проверки возникают тогда, когда логика сужения типов (Type Guards) либо не охватывает все возможные ветвления, либо содержит ошибочные утверждения, которым доверяет компилятор.

TypeScript стремится соблюсти баланс между строгой типизацией и продуктивностью. В результате некоторые проверки (например, пользовательские предикаты типов или оператор `in` с объектами `any`) могут заставить компилятор "поверить" в безопасность, которой на самом деле нет, что приводит к ошибкам времени выполнения (runtime errors).

## Примеры использования

```typescript
// Пример 1: Небезопасный пользовательский предикат
function isString(val: any): val is string {
  // Ошибка в реализации! Мы проверяем на number, но утверждаем, что это string.
  // TypeScript нам поверит.
  return typeof val === "number"; 
}

// Пример 2: Проблемы с замыканиями (Control Flow Analysis limitations)
let value: string | null = "hello";

if (value !== null) {
  // Здесь value - string
  setTimeout(() => {
    // Внутри колбэка TypeScript может не знать, изменилось ли value где-то еще.
    // Если strictNullChecks включен, TS может пожаловаться, или, в более старых версиях, 
    // ошибочно сохранить суженный тип.
    console.log(value.toUpperCase());
  });
}
value = null; // Мы изменили значение синхронно, код упадет в таймауте!
```

## Особенности и нюансы

- **Ответственность за `is`**: Конструкции `val is Type` и `asserts val is Type` являются формами Type Assertions. Если вы ошибетесь в их реализации, TypeScript не сможет вас защитить.
- **Exhaustiveness checking**: Чтобы избежать неполных проверок в `switch`, используйте паттерн присваивания переменной типа `never` в блоке `default`. Если в Union будет добавлен новый тип, TS выдаст ошибку, так как этот новый тип нельзя присвоить `never`.
- **Проверки массивов**: `Array.isArray(x)` проверяет, что это массив, но не проверяет тип элементов внутри. Если `x` имеет тип `any`, вы получите `any[]`.
