# Const Type Parameters

## Описание

> [!info] 
> **Const-модификатор для параметров типа (Const Type Parameters)**, добавленный в TypeScript 5.0, позволяет компилятору выводить параметры типа функции как неизменяемые (литеральные и `readonly`) типы, так, как если бы при вызове функции использовалось утверждение `as const`.

При добавлении модификатора `const` перед параметром типа (`<const T>`), TypeScript меняет стратегию вывода типа. Вместо расширения типов (например, вывод `string[]` из `["a", "b"]`), компилятор выводит наиболее точный, узкий литеральный тип (например, `readonly ["a", "b"]`).

## Примеры использования

```typescript
// Обычная функция-дженерик (расширение типа)
function normal<T>(arg: T): T { return arg; }
const res1 = normal(["a", "b", "c"]); 
// Тип выводится как string[]

// Функция с const-параметром типа
function withConst<const T>(arg: T): T { return arg; }
const res2 = withConst(["a", "b", "c"]); 
// Тип выводится как readonly ["a", "b", "c"]

const objRes = withConst({ text: "hello", count: 42 });
// Тип выводится как { readonly text: "hello"; readonly count: 42; }
```

## Особенности и нюансы

- Это избавляет вызывающий код от необходимости писать `as const` при каждом вызове функции. Теперь разработчик библиотеки/функции может указать, что функция ожидает литеральные типы.
- Модификатор `const` влияет только на **вывод типов** при вызове функции, когда параметр типа выводится из переданного аргумента (объектов, массивов, примитивов).
- Нельзя использовать `const` с параметрами типов в классах, интерфейсах или алиасах — модификатор работает только с параметрами типов функций и методов.
- Если передать аргумент, который уже был типизирован широко (например, переменную типа `string[]`), `const` не сможет волшебным образом сузить её тип до литерального, так как тип уже утерян. Это работает только для литеральных значений, передаваемых напрямую в вызов.
