# Variance Annotations

## Описание

> [!info] 
> **Аннотации вариантности (Variance Annotations)** — это модификаторы `in` и `out`, добавляемые к параметрам типа в интерфейсах, типах и классах, которые явно указывают, как параметры типа влияют на подтипизацию (ковариантность и контравариантность).

До TypeScript 4.7 компилятор вычислял вариантность (variance) структурно, анализируя каждое использование параметра типа. Явные аннотации `in` и `out` позволяют ускорить проверку типов (отключив глубокий структурный анализ для этих типов) и строже контролировать дизайн типов.

- `out` означает **ковариантность**: параметр типа используется только как возвращаемое значение (на выход).
- `in` означает **контравариантность**: параметр типа используется только как аргумент (на вход).

## Примеры использования

```typescript
// out: Ковариантность (Producer)
// Тип T только "выходит" из интерфейса
interface Getter<out T> {
    get(): T;
}

let stringGetter: Getter<string> = { get: () => "hello" };
let unknownGetter: Getter<unknown> = stringGetter; // OK, string можно присвоить unknown

// in: Контравариантность (Consumer)
// Тип T только "входит" в интерфейс
interface Setter<in T> {
    set(value: T): void;
}

let unknownSetter: Setter<unknown> = { set: (v) => console.log(v) };
let stringSetter: Setter<string> = unknownSetter; // OK, функция, принимающая unknown, справится со string

// in out: Инвариантность
// Тип T и "входит", и "выходит"
interface State<in out T> {
    get(): T;
    set(value: T): void;
}
```

## Особенности и нюансы

- Использование `in` и `out` позволяет повысить производительность компилятора, так как ему не нужно рекурсивно обходить всю структуру типа, чтобы определить его вариантность.
- Если вы укажете модификатор `out`, но попробуете использовать `T` во входной позиции (например, в аргументе метода), TypeScript выдаст ошибку во время компиляции. Это помогает на ранних этапах выявлять ошибки проектирования архитектуры.
- Применимо к параметрам типа в `type`, `interface` и `class`.
