# Definite Assignment Assertion

## Описание

> [!info] 
> Definite Assignment Assertion (`!:` при объявлении) — это указание компилятору TypeScript на то, что переменная класса или локальная переменная точно будет инициализирована, даже если статический анализатор не может этого доказать.

TypeScript отслеживает инициализацию переменных, чтобы предотвратить их использование до присвоения значения (при включенном `strictPropertyInitialization`). Однако в некоторых случаях переменная может инициализироваться неявно (например, в декораторах, сторонних методах инициализации или в хуках фреймворков). Добавляя `!` после имени свойства, мы берем ответственность на себя.

## Примеры использования

```typescript
class MyComponent {
  // TypeScript выдаст ошибку: свойство 'name' не инициализировано в конструкторе
  // name: string; 
  
  // Мы используем '!', говоря компилятору: "Я обещаю, что оно будет инициализировано"
  name!: string;
  
  constructor() {
    this.init();
  }
  
  init() {
    this.name = "Hello World";
  }
}

// Пример с локальной переменной
let x!: number;
initialize();
console.log(x * 2); // Ок, мы утверждаем, что x инициализирован

function initialize() {
  x = 10;
}
```

## Особенности и нюансы

- **Только для статического анализа**: Оператор просто подавляет ошибку компилятора. Если переменная фактически не инициализируется до её использования, в рантайме вы получите значение `undefined`, что может привести к непредвиденным ошибкам.
- **Декораторы и DI**: Этот оператор крайне популярен при использовании внедрения зависимостей (Dependency Injection) в таких фреймворках, как Angular, или при работе с ORM (например, TypeORM, где поля инициализируются движком базы данных).
- **Лучшие практики**: Использовать только там, где стандартный Control Flow Analysis не может отследить инициализацию, а вы точно уверены, что она происходит.
