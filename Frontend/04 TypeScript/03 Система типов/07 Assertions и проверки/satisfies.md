# satisfies

## Описание

> [!info] 
> Оператор `satisfies` проверяет, что выражение соответствует заданному типу, не изменяя при этом (не расширяя) тип самого выражения.

В отличие от аннотации типа (`const x: Type = ...`), которая "забывает" специфичные детали объекта в угоду общему типу, и в отличие от утверждения `as` (`... as Type`), которое заставляет компилятор поверить вам, `satisfies` проверяет соответствие контракту, но сохраняет максимально точный (узкий) выведенный тип объекта.

## Примеры использования

```typescript
type Color = string | [number, number, number];
type Palette = Record<"red" | "green" | "blue", Color>;

// Использование аннотации типа (потеря точной информации)
const palette1: Palette = {
  red: [255, 0, 0],
  green: "#00ff00",
  blue: [0, 0, 255]
};
// Ошибка: palette1.red имеет тип Color (string | [number,number,number]), 
// поэтому методы массивов недоступны без сужения типа
// palette1.red.push(0); 

// Использование satisfies
const palette2 = {
  red: [255, 0, 0],
  green: "#00ff00",
  blue: [0, 0, 255]
} satisfies Palette;

// Успех! TS знает, что palette2.red это ИМЕННО кортеж [number, number, number]
palette2.red.push(0); 
// А palette2.green это строка
palette2.green.toUpperCase();
```

## Особенности и нюансы

- **Безопасность типов**: В отличие от `as`, `satisfies` не позволит вам указать неверные свойства. Он строго проверит соответствие типу `T`.
- **Точность и вывод**: Позволяет валидировать сложный объект, сохраняя при этом выведенные литеральные типы. Это невероятно полезно для конфигураций, роутинга и статических словарей.
- **Выявление опечаток**: Отличный инструмент для того, чтобы убедиться, что вы не забыли обязательные ключи и не написали лишних, при этом сохраняя максимально строгую типизацию значений.
