# Strict Mode и флаги строгости

> [!info]
> **Strict Mode (Строгий режим)** в TypeScript — это набор опций компилятора, которые включают самые строгие правила проверки типов, обеспечивая максимальную безопасность и предсказуемость кода.

## Суть концепции

Включение строгого режима происходит с помощью одного флага в `tsconfig.json` — `"strict": true`. Это активирует целую группу параметров проверки типов. Разработчики TypeScript рекомендуют всегда включать этот флаг в новых проектах.

### Основные флаги строгости

- `alwaysStrict`: Гарантирует, что каждый файл будет скомпилирован в режиме JavaScript `use strict`.
- `strictNullChecks`: Запрещает присваивать `null` и `undefined` переменным других типов. Это защищает от знаменитой ошибки "Cannot read property of undefined".
- `strictBindCallApply`: Проверяет, что аргументы, передаваемые в функции `bind`, `call`, и `apply`, соответствуют типам параметров оригинальной функции.
- `strictFunctionTypes`: Включает более строгую проверку типов аргументов функций (контравариантность аргументов).
- `strictPropertyInitialization`: Требует инициализации всех свойств класса в конструкторе (если они не помечены как опциональные).
- `noImplicitAny`: Запрещает неявное использование типа `any` (когда компилятор не может вывести тип и присваивает `any`).
- `noImplicitThis`: Выбрасывает ошибку при использовании ключевого слова `this`, если его тип неявно равен `any`.

### Пример `tsconfig.json`

```json
{
  "compilerOptions": {
    "strict": true,
    // В исключительных случаях можно отключать отдельные флаги:
    "noImplicitAny": false
  }
}
```

### Связь с Ambient-декларациями
При строгом режиме (особенно с `noImplicitAny`), TypeScript требует явного описания внешних модулей и библиотек. Если библиотека не предоставляет типы, разработчику необходимо написать ambient-декларацию (`declare module "my-lib"`) в файле `.d.ts`, иначе компилятор выдаст ошибку импорта.
