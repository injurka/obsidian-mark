# Linter Checks и качество кода

> [!info]
> **Linter Checks** в TypeScript — это набор опций компилятора, которые выполняют функции статического анализатора кода, выявляя логические неточности, мертвый код и потенциально опасные конструкции.

## Суть концепции

Хотя для проверки качества кода в экосистеме JavaScript чаще используется ESLint, встроенный компилятор TypeScript (`tsc`) имеет несколько собственных правил линтинга. В отличие от правил ESLint, которые работают на уровне абстрактного синтаксического дерева (AST), опции TypeScript имеют доступ к системе типов, что делает их проверки более глубокими.

### Ключевые опции проверок

- **`noUnusedLocals`**: Выдает ошибку, если в функции или модуле объявлена локальная переменная, которая никогда не используется (мертвый код).
- **`noUnusedParameters`**: Указывает на параметры функции, которые передаются, но не используются внутри ее тела.
- **`noImplicitReturns`**: Проверяет, что все пути выполнения функции (ветвления `if`/`else`, `switch`) возвращают значение. Защищает от ситуаций, когда функция неожиданно возвращает `undefined`.
- **`noFallthroughCasesInSwitch`**: Сообщает об ошибке в конструкции `switch`, если блок `case` содержит код, но не завершается `break` или `return` (предотвращает случайное "проваливание" в следующий `case`).
- **`exactOptionalPropertyTypes`**: (Относительно новая опция) Запрещает явное присвоение значения `undefined` опциональным свойствам интерфейса. Свойство либо отсутствует вовсе, либо соответствует заявленному типу.

### Пример использования

```json
{
  "compilerOptions": {
    "strict": true,
    "noUnusedLocals": true,
    "noUnusedParameters": true,
    "noImplicitReturns": true,
    "noFallthroughCasesInSwitch": true
  }
}
```

### Связь с другими концепциями
Эти флаги дополняют концепцию **Strict Mode**, делая код не просто типобезопасным, но и алгоритмически "чистым". При написании файлов деклараций `.d.ts` или использовании `declare` контекста, эти правила также могут играть роль: например, ambient-функции не могут содержать тела, поэтому правило `noImplicitReturns` к ним не применяется, что является нормальным поведением для типов окружения.
