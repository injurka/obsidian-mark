
**Code Splitting** — это архитектурная оптимизация веб-приложений, при которой весь исходный код JavaScript разбивается на несколько небольших файлов (чанков, *chunks*), а не склеивается в один гигантский `bundle.js`. 

Разделение кода позволяет браузеру загружать только тот JavaScript, который строго необходим для текущего экрана. Остальной код подгружается асинхронно по мере необходимости (Lazy Loading).

---

## 1. Зачем это нужно?

Проблема монолитного бандла не только в долгом скачивании по сети. Главный враг производительности — **парсинг и выполнение скриптов**. 
Когда браузер встречает JS-файл, он блокирует основной поток (Main Thread). Чем больше бандл, тем дольше страница остается нереспонсивной (не реагирует на клики и скролл).

* **Улучшение TTI (Time to Interactive) и TBT (Total Blocking Time):** Браузер компилирует и выполняет только критически важный код.
* **Эффективное кэширование (Long-term caching):** При изменении одной строчки кода инвалидируется кэш только маленького чанка, а не всего приложения. Пользователю не придется заново скачивать мегабайты кода.

---

## 2. Механика «под капотом»: Динамический импорт

Вся магия Code Splitting в современных сборщиках (Webpack, Vite/Rollup) базируется на стандарте ECMAScript — **динамическом импорте `import()`**.

* **Статический импорт** (`import { a } from './module'`) заставляет сборщик включить код модуля прямо в текущий бандл.
* **Динамический импорт** (`import('./module')`) возвращает **Promise**. Когда сборщик видит такой синтаксис, он понимает: *«Ага, это точка разделения (split point). Я вынесу этот модуль в отдельный `.js` файл и создам логику для его загрузки по сети»*.

```javascript
// Этот код не попадет в основной бандл
button.addEventListener('click', async () => {
  // Браузер сделает сетевой запрос за файлом math.js только в момент клика
  const { add } = await import('./math.js');
  console.log(add(2, 2));
});
```

## 3. Основные стратегии разделения

### 3.1. Route-based splitting (На уровне маршрутизации)
Это самый очевидный и эффективный шаг. Код изолируется постранично. Пользователь, зашедший на главную страницу, не должен качать код админ-панели или личного кабинета.

*Пример (Vue Router):*
```javascript
const routes = [
  { path: '/', component: Home }, // Входит в стартовый бандл
  { path: '/dashboard', component: () => import('./views/Dashboard.vue') } // Загрузится при переходе
]
```

### 3.2. Component/Interaction-based splitting (По взаимодействию)
Применяется для тяжелых UI-элементов, которые нужны не сразу или не всем пользователям (графики Chart.js, 3D-модели, сложные WYSIWYG-редакторы в модальных окнах).

*Пример (Vue 3 `defineAsyncComponent` / React `lazy`):*
```javascript
import { defineAsyncComponent } from 'vue'

// Файл HeavyChart.vue и библиотека для графиков скачаются только тогда, 
// когда компонент будет отрендерен (например, при переключении таба)
const HeavyChart = defineAsyncComponent(() => import('./HeavyChart.vue'))
```

### 3.3. Vendor splitting (Разделение зависимостей)
Код из `node_modules` (Vue, React, Lodash) меняется редко, а код вашего приложения — часто. Сборщики могут автоматически выделять сторонние библиотеки в отдельный чанк `vendor.[hash].js`. 
Благодаря этому браузер кэширует тяжелые фреймворки на месяцы, и при релизе новых фич скачивается только крошечный файл с логикой приложения.

## 4. Оптимизация разделения: Prefetch и Дедупликация

Code Splitting имеет обратную сторону: **сетевая задержка**. Если код страницы `/about` не скачан заранее, то при клике на ссылку пользователю придется ждать, пока JS скачается, распарсится и отрендерится.

### Prefetch (Предзагрузка)
Чтобы сгладить задержку, используется фоновая предзагрузка чанков, когда основной поток свободен.
В Webpack для этого существуют "магические комментарии":
```javascript
const About = () => import(
  /* webpackPrefetch: true */ 
  './views/About.vue'
);
```
Сборщик добавит в `<head>` страницы тег `<link rel="prefetch" href="about-chunk.js">`. Браузер тихо скачает файл в фоновом режиме в кэш. Когда пользователь кликнет на ссылку, код выполнится мгновенно. Современный Vite использует похожий механизм `modulepreload` автоматически.

### Дедупликация общих модулей (Shared Chunks)
Если страница А и страница Б обе динамически импортируют библиотеку `moment.js`, сборщик (например, через `SplitChunksPlugin` в Webpack) достаточно умен, чтобы не дублировать `moment.js` в оба чанка. Он создаст третий, **общий чанк**, который загрузится один раз и переиспользуется.

## Резюме для самопроверки

1. **Цель:** Уменьшить размер стартового бандла, чтобы освободить Main Thread и ускорить первый рендеринг (FCP, TTI).
2. **Основа:** Динамический импорт (`import()`), возвращающий Promise. Сборщик превращает его в отдельный физический файл (чанк).
3. **Route & Component Level:** Разделение чаще всего делается по страницам (роутам) или по тяжелым компонентам, скрытым за кликом пользователя.
4. **Вендоры:** Вынесение `node_modules` в отдельный файл необходимо для долгосрочного браузерного кэширования.
5. **Prefetching:** Позволяет загружать отложенные чанки в фоне до того, как они реально понадобятся пользователю, убирая сетевую задержку.
