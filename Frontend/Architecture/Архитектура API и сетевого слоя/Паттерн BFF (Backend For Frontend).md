# BFF (Backend for Frontend)

**BFF (Backend for Frontend)** — это архитектурный паттерн, при котором для каждого клиентского приложения (веб-версия, мобильное приложение на iOS, мобильное приложение на Android, смарт-ТВ) создается свой собственный, узконаправленный бэкенд.

## Зачем это нужно?
Часто микросервисы (или монолитный бэкенд) предоставляют универсальные API (General-purpose API). Фронтенду при этом приходится делать множество запросов, агрегировать данные на клиенте, фильтровать лишние поля или, наоборот, недополучать нужные данные с первого раза (проблемы Overfetching и Underfetching).

BFF решает эти проблемы, выступая прослойкой между клиентом и микросервисами.

## Обязанности BFF:
1. **Агрегация данных:** Сбор данных из нескольких микросервисов и отдача их на фронтенд одним запросом.
2. **Форматирование:** Преобразование данных в формат, идеально подходящий для конкретного интерфейса (очистка от ненужных полей).
3. **Безопасность (Auth):** Хранение сессий, токенов (например, http-only cookies), обработка авторизации, чтобы не отдавать токены на клиент.
4. **Кэширование:** Кэширование ответов от медленных сервисов.
5. **Адаптация протоколов:** Например, фронтенд общается с BFF по GraphQL или REST, а BFF общается с микросервисами по gRPC.

## Популярные инструменты для реализации BFF в JS/TS:
- Next.js (API Routes / Server Actions)
- NestJS
- Express / Fastify
- GraphQL Federation / Apollo Server
