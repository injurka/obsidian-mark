# Feature-Sliced Design (FSD)

**Feature-Sliced Design (FSD)** — это современная архитектурная методология проектирования фронтенд-приложений. Она решает проблему масштабируемости, хаоса в импортах и запутанности связей в крупных кодовых базах, разделяя проект на слои (layers), слайсы (slices) и сегменты (segments).

---

## 1. Иерархия Слоев (Layers)

Кодовая база делится на вертикальные слои, расположенные друг над другом. Каждый нижележащий слой является более абстрактным и переиспользуемым, чем вышележащий.

```text
▲ [app]        ──► Инициализация: провайдеры, глобальные стили, роутер
│ [pages]      ──► Композиция: страницы приложения, собранные из виджетов
│ [widgets]    ──► Крупные блоки: объединяют фичи и сущности (например, Header)
│ [features]   ──► Действия пользователя: приносят бизнес-ценность (например, AddToCart)
│ [entities]   ──► Бизнес-сущности: бизнес-логика (например, User, Product, Order)
▼ [shared]     ──► Базовые ресурсы: UI-кит, утилиты, API-клиент
```

### Разбор слоев:
1.  **shared:** Фундамент. Содержит UI-компоненты общего назначения (кнопки, инпуты), хелперы, типы API. Не знает ничего о бизнес-логике приложения.
2.  **entities (сущности):** Бизнес-сущности предметной области. Например, сущность `user` содержит аватар, карточку пользователя, селекторы профиля и методы получения данных пользователя.
3.  **features (фичи):** Интерактивные действия пользователя, которые приносят бизнес-ценность. Отвечают на вопрос: "Что делает пользователь?". Например: `add-to-cart` (добавление в корзину), `search-by-catalog` (поиск по каталогу).
4.  **widgets (виджеты):** Крупные самостоятельные UI-блоки, объединяющие фичи и сущности. Пример: `ProductCardList` (виджет списка товаров, который рендерит сетку сущностей `ProductCard` с внедренными кнопками фичи `AddToCartButton`).
5.  **pages (страницы):** Композиционный слой. Страницы не содержат логики, они лишь собирают виджеты в конкретный макет (layout).
6.  **app:** Точка входа. Настройка глобальных провайдеров (React Context, Redux Store), инициализация аналитики, подключение глобальных стилей.

## 2. Слайсы (Slices) и Сегменты (Segments)

Внутри каждого слоя (начиная с `shared` и выше) код делится на слайсы и сегменты.

*   **Слайсы (Slices):** Предметные области. Например, внутри `entities` будут слайсы `user`, `product`, `article`.
*   **Сегменты (Segments):** Техническое разделение кода внутри слайса. Стандартные сегменты:
    *   `ui` — визуальные компоненты.
    *   `model` — стейт-менеджмент, экшены, селекторы, бизнес-логика.
    *   `api` — функции запросов к бэкенду.
    *   `lib` — локальные хелперы и инфраструктурные хуки.

```text
entities/ (Слой)
  └── product/ (Слайс)
        ├── ui/ (Сегмент) ──► ProductCard.tsx
        ├── model/        ──► productSlice.ts
        └── api/          ──► getProductById.ts
```

## 3. Два главных закона FSD (Lead Guardrails)

Нарушение этих законов мгновенно разрушает FSD-архитектуру и превращает её в кашу.

### Закон №1: Направление импортов (Import Flow)
> Модуль может импортировать код только с **нижележащих** слоев. Импорты с вышележащих слоев или горизонтальные импорты (между слайсами одного слоя) строго **запрещены**.

*   *Разрешено:* Компонент из `features/add-to-cart` импортирует логику из `entities/product` (слой ниже).
*   *Запрещено:* Компонент из `entities/user` импортирует `features/login` (слой выше — циклическая зависимость).
*   *Запрещено:* Слайс `entities/product` импортирует `entities/user` (горизонтальный импорт). Если сущности связаны, их связь должна настраиваться на вышележащих слоях (в `features` или `widgets`).

### Закон №2: Публичный API (Public API фасады)
> Каждый слайс должен иметь один файл `index.ts` в своем корне. Этот файл является фасадом (Public API). Любой внешний импорт из этого слайса разрешен **только через этот файл**.

*   *Правильно:*
    ```typescript
    import { ProductCard } from '@/entities/product';
    ```
*   *Неправильно (глубокий импорт, ломающий инкапсуляцию слайса):*
    ```typescript
    import { ProductCard } from '@/entities/product/ui/ProductCard';
    ```
    Это позволяет безопасно рефакторить внутреннюю структуру слайса: вы можете переименовать папку `ui` в `components` или объединить файлы — внешние импорты не сломаются, пока обновлен `index.ts`.
