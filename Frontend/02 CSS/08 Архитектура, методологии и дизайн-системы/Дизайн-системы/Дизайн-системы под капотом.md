# Дизайн-системы под капотом

## 1. Архитектура Дизайн-системы: Токены и Слои

Дизайн-система на фронтенде — это не просто набор компонентов в Storybook. Это инженерный мост между дизайном и кодом, построенный на структурированных данных.

В основе современной дизайн-системы лежит концепция **Дизайн-токенов (Design Tokens)** — атомарных кусочков визуального стиля (цвета, размеры, шрифты, скругления, тени), хранящихся в едином источнике правды (SSOT — Single Source of Truth).

```text
Дизайнеры (Figma) ──► JSON-файл токенов ──► Style Dictionary ──► CSS / JS / iOS / Android
```

### Три уровня дизайн-токенов:
1.  **Глобальные токены (Global / Primitive):**
    Базовые, контекстно-независимые значения. Описывают палитру цветов и сетку размеров.
    *Пример:* `color-blue-500: #3b82f6`, `spacing-4: 16px`.
2.  **Семантические токены (Semantic / Alias):**
    Задают смысл и контекст использования глобальных токенов. Отвечают на вопрос: "Для чего используется этот цвет?". Именно на этом уровне настраивается темизация (светлая/темная тема).
    *Пример:* `background-brand: var(--color-blue-500)`, `text-primary: var(--color-gray-900)`.
3.  **Компонентные токены (Component-level):**
    Узкие токены, привязанные к конкретному компоненту. Изолируют внутренности компонента от глобальных изменений.
    *Пример:* `button-primary-bg: var(--background-brand)`.

## 2. Построение Theme Engine на CSS Custom Properties

Использование JS-контекста для темизации (например, `<ThemeProvider>` в CSS-in-JS) вызывает лишние ререндеры дерева React и замедляет работу. Современный стандарт — **нативные CSS-переменные**.

### 2.1. Реализация переключения тем
Для смены темы достаточно переопределить семантические токены под определенным классом или дата-атрибутом на самом верхнем уровне DOM (теге `<html>` или `<body>`).

```css
:root {
  /* Глобальные токены */
  --blue-500: #3b82f6;
  --gray-100: #f3f4f6;
  --gray-900: #111827;

  /* Семантические токены (Светлая тема по умолчанию) */
  --bg-app: var(--gray-100);
  --text-main: var(--gray-900);
  --color-primary: var(--blue-500);
}

[data-theme="dark"] {
  /* Семантические токены переопределяются для Темной темы */
  --bg-app: var(--gray-900);
  --text-main: var(--gray-100);
}

body {
  background-color: var(--bg-app);
  color: var(--text-main);
  transition: background-color 0.3s ease, color 0.3s ease;
}
```

### 2.2. HSL-подход для динамической прозрачности
Иногда компоненту нужно применить цвет токена, но сделать его полупрозрачным. Напрямую с HEX-переменной это сделать сложно. Решение — хранить цвета в виде HSL-компонентов (Hue, Saturation, Lightness):

```css
:root {
  /* Храним только каналы HSL без обертки hsl() */
  --primary-hsl: 220 90% 56%; 
}

.button-with-overlay {
  /* Теперь мы можем на ходу подставлять альфа-канал */
  background-color: hsla(var(--primary-hsl) / 0.15); /* 15% прозрачности */
  border: 1px solid hsl(var(--primary-hsl)); /* 100% непрозрачность */
}
```

## 3. Проектирование компонентного API (UI-Kit)

При создании компонентов дизайн-системы важно соблюдать баланс между жесткостью стандартов дизайна и гибкостью для разработчиков.

### 3.1. Полиморфизм (Компонент-хамелеон)
Компоненты должны уметь менять свой HTML-тег с сохранением стилей. Например, кнопка может визуально выглядеть как кнопка, но в DOM должна рендериться как ссылка `<a>` (если ведет на другую страницу) или как роутер-линк (`<Link>`).

Использование паттерна **`asChild`** (популяризированного библиотекой Radix UI):

```tsx
import React from 'react';
import { Slot } from '@radix-ui/react-slot';

interface ButtonProps extends React.ButtonHTMLAttributes<HTMLButtonElement> {
  asChild?: boolean;
}

export const Button = React.forwardRef<HTMLButtonElement, ButtonProps>(
  ({ asChild, ...props }, ref) => {
    // Если передан флаг asChild, мы рендерим Slot, который просто
    // передаст все стили и обработчики первому дочернему элементу.
    const Component = asChild ? Slot : 'button';
    return <Component ref={ref} {...props} className="btn-primary" />;
  }
);
```
*Использование:*
```tsx
// Рендерит тег <a> со стилями кнопки
<Button asChild>
  <a href="/login">Войти</a>
</Button>
```

### 3.2. Инкапсуляция Layout-правил (Правило отступов)
Компонент дизайн-системы **никогда** не должен иметь внешних отступов (`margin`).
*   **Почему?** Компонент не знает, в каком контексте он будет использоваться. Если кнопка содержит `margin-right: 16px`, её невозможно будет поставить вплотную к правому краю карточки.
*   **Решение:** Отступы между элементами контролируются родительскими структурными компонентами (например, `Stack`, `Grid`, `Flex`) или утилитарными классами разметки.

## 4. Сборка и дистрибуция токенов через Style Dictionary

Дизайнеры ведут токены в Figma (например, используя плагин Tokens Studio). Figma отдает JSON-файл с токенами. Для конвертации этого JSON во фронтенд-код используется **Style Dictionary** (библиотека от Amazon).

Пример конфигурации Style Dictionary (`config.json`):
```json
{
  "source": ["tokens/**/*.json"],
  "platforms": {
    "css": {
      "transformGroup": "css",
      "buildPath": "build/css/",
      "files": [{
        "destination": "_variables.css",
        "format": "css/variables"
      }]
    },
    "typescript": {
      "transformGroup": "js",
      "buildPath": "build/ts/",
      "files": [{
        "destination": "tokens.ts",
        "format": "javascript/es6"
      }]
    }
  }
}
```
Style Dictionary автоматически преобразует цвета Figma в CSS Custom Properties для веба, XML для Android и Swift для iOS, обеспечивая полную кроссплатформенную синхронизацию стилей.
