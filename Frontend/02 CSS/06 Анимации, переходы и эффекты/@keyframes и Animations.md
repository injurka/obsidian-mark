# Keyframes и Transitions (Глубокий разбор)

## 1. Transitions vs Animations: Когда что применять?

В CSS есть два способа заставить интерфейс двигаться: **Transitions (Переходы)** и **Animations (Анимации / @keyframes)**.

```text
Transitions:      [Состояние А] ──(Hover / Focus / JS класс)──> [Состояние Б]
Animations:       [Старт] ──(25%)──> [Шаг 1] ──(50%)──> [Шаг 2] ──> [Финиш] (Циклично)
```

| Параметр | Transitions | Animations / @keyframes |
| :--- | :--- | :--- |
| **Принцип** | Сглаживание перехода между **двумя** состояниями элемента. | Создание **многоэтапных** сценариев движения. |
| **Триггер** | Требует изменения свойств (hover, focus, добавление класса на JS). | Может запускаться автоматически при рендере элемента. |
| **Управление** | Простое (время, задержка, функция плавности). | Детализированное (направление, бесконечный цикл, пауза). |
| **Сложность** | Низкая (подходит для микро-взаимодействий вроде ховеров кнопок). | Высокая (сложные лоадеры, сценарии появления элементов). |

## 2. Глубокий разбор CSS Transitions

Синтаксис свойства:
```css
.element {
  transition: [property] [duration] [timing-function] [delay];
}
```

### Подводные камни производительности:
> [!WARNING]
> **Никогда не пишите `transition: all 0.3s;`**
> Браузер будет вынужден отслеживать изменения *всех* свойств элемента (включая цвет текста, тени, размеры). Если вы анимируете только прозрачность, пишите: `transition: opacity 0.3s;`. Это экономит ресурсы процессора.

### Анимация в `display: none`
Обычный transition не работает при переходе из `display: none` в `display: block`, так как `display` не является численным свойством и не может быть интерполирован.
*   *Решение:* Использовать связку `opacity` + `visibility` или современное свойство `@starting-style` (поддерживается в современных браузерах).

## 3. Глубокий разбор CSS Animations & `@keyframes`

Позволяет создавать сложные таймлайны. 

```css
@keyframes slideAndFade {
  0% {
    transform: translateY(20px);
    opacity: 0;
  }
  60% {
    transform: translateY(-5px);
    opacity: 0.8;
  }
  100% {
    transform: translateY(0);
    opacity: 1;
  }
}

.card {
  animation: slideAndFade 0.6s cubic-bezier(0.25, 1, 0.5, 1) forwards;
}
```

### Разбор критических свойств:
1.  **`animation-fill-mode`** — определяет, какие стили применяются к элементу до начала анимации (при задержке) и после ее завершения.
    *   `none` (дефолт) — после анимации элемент мгновенно возвращается к своим исходным стилям.
    *   `forwards` — элемент сохраняет стили последнего ключевого кадра (`100%` или `to`).
    *   `backwards` — элемент сразу (во время задержки `animation-delay`) принимает стили первого кадра (`0%` или `from`).
    *   `both` — совмещает оба режима (применяет стили первого кадра во время задержки и сохраняет стили последнего кадра после окончания).
2.  **`animation-play-state`** — позволяет ставить анимацию на паузу (`paused` / `running`). Очень полезно при наведении курсора:
    ```css
    .scrolling-ticker { animation-play-state: running; }
    .scrolling-ticker:hover { animation-play-state: paused; }
    ```

## 4. Тайминг-функции и Кривые Безье (`cubic-bezier`)

Тайминг-функция описывает **скорость** прохождения анимации на разных ее участках.

```text
Linear:       ════════════════ (равномерно)
Ease-In:      ── ── ──── ────── (медленный старт, быстрый конец)
Ease-Out:     ────── ──── ── ── (быстрый старт, медленный конец)
Cubic-Bezier: ── ── ────── ── ── (кастомное ускорение и замедление)
```

### 4.1. Кастомные кривые Безье
Определяются через координаты четырех точек: `cubic-bezier(x1, y1, x2, y2)`.
*   По осям `x1` и `x2` значения должны быть строго от `0` до `1` (время).
*   По осям `y1` и `y2` значения могут выходить за пределы `0` и `1` (выход за рамки финального значения — эффект отскока).

**Пример упругого отскока (Bouncy/Spring Effect):**
```css
.modal-window {
  /* y2 > 1 дает эффект вылета дальше цели и возвращения назад */
  transition: transform 0.5s cubic-bezier(0.175, 0.885, 0.32, 1.275);
}
```

### 4.2. Пошаговые функции: `steps()`
Вместо сглаживания `steps(N, start/end)` делит анимацию на дискретные шаги. Отлично подходит для анимации спрайтов.
```css
.sprite-character {
  width: 100px;
  background: url('sprite.png') no-repeat;
  /* Перемещаем фоновую картинку по 8 кадрам мгновенными шагами */
  animation: playSprite 0.8s steps(8) infinite;
}

@keyframes playSprite {
  from { background-position: 0px; }
  to { background-position: -800px; }
}
```

## 5. Производительность: Золотое правило FPS

Анимации должны работать с частотой **60 кадров в секунду (60 FPS)**. Это значит, что на отрисовку одного кадра у браузера есть всего **16.67 мс**.

Если анимировать свойства, влияющие на геометрию (Layout) или отрисовку (Paint), браузер начнет «лагать» (пропускать кадры / junk).

> [!IMPORTANT]
> **Правило высокой производительности:**
> Анимируйте только **`transform`** (scale, translate, rotate) и **`opacity`**. 
> Избегайте анимации `width`, `height`, `top`, `left`, `margin`, `box-shadow`. Они заставляют браузер пересчитывать сетку страницы (Reflow) на каждом кадре.
