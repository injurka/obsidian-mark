**Интеграция с Анимацией** с использованием GAS. Это важный шаг для визуализации способностей и состояний персонажа.

**Задача:** Связать Gameplay Ability System (GAS) с Animation Blueprint (AnimBP). Использовать `GameplayTag` для запуска анимационных монтажей из способностей. Использовать `AnimNotify` для отправки `GameplayEvent` обратно в GAS для точного тайминга. Заставить AnimBP реагировать на изменение атрибутов (скорость) и наличие тегов состояний (заморозка, оглушение).

**Зачем:** Обеспечить визуальную обратную связь для действий игрока и состояний персонажа, делая игру более понятной и живой. Анимация должна отражать использование способностей, скорость передвижения и различные статусы (стан, заморозка).

**GAS Компоненты и Механизмы UE:** `GameplayTag`, `UAbilityTask_PlayMontageAndWait`, `UAbilityTask_WaitGameplayEvent`, `UAbilitySystemComponent::SendGameplayEventToActor`, `UAnimNotify`, `UAnimNotifyState`, `UAnimInstance`, `IAbilitySystemInterface`.

**Подробная Реализация Шага:**

**Шаг 16.1: Подготовка Базового `AnimInstance` (C++)**

Чтобы эффективно взаимодействовать с GAS, лучше создать базовый C++ класс для вашего AnimBP. Это позволит кэшировать ссылки и добавлять вспомогательные функции.

1.  **Tools -> New C++ Class...**
2.  Родитель: `AnimInstance`.
3.  Имя: `FrameForgeAnimInstance`.
4.  Путь: `FrameForge/Source/FrameForge/Public/Features/Chassis/Animations/` (или аналогичный).
5.  **`FrameForgeAnimInstance.h`**:
    ```cpp
    #pragma once

    #include "CoreMinimal.h"
    #include "Animation/AnimInstance.h"
    #include "GameplayTagContainer.h" // Для тегов
    #include "FrameForgeAnimInstance.generated.h"

    class UAbilitySystemComponent; // Прямое объявление

    UCLASS()
    class FRAMEFORGE_API UFrameForgeAnimInstance : public UAnimInstance
    {
        GENERATED_BODY()

    public:
        virtual void NativeInitializeAnimation() override;
        virtual void NativeUpdateAnimation(float DeltaSeconds) override;

    protected:
        // --- Кэшированные Данные ---
        UPROPERTY(BlueprintReadOnly, Category = "Animation|GAS")
        TWeakObjectPtr<AActor> OwningActor; // Используем Weak Ptr для безопасности

        UPROPERTY(BlueprintReadOnly, Category = "Animation|GAS")
        TWeakObjectPtr<UAbilitySystemComponent> OwnerASC;

        // --- Переменные для Стейт-Машины и Блендспейсов ---
        // Эти переменные будут обновляться в NativeUpdateAnimation и использоваться в AnimGraph

        UPROPERTY(VisibleAnywhere, BlueprintReadOnly, Category = "Animation|State", meta = (AllowPrivateAccess = "true"))
        float GroundSpeed = 0.0f;

        UPROPERTY(VisibleAnywhere, BlueprintReadOnly, Category = "Animation|State", meta = (AllowPrivateAccess = "true"))
        bool bIsFalling = false;

        UPROPERTY(VisibleAnywhere, BlueprintReadOnly, Category = "Animation|State", meta = (AllowPrivateAccess = "true"))
        bool bIsCrouching = false; // Если будет приседание

        UPROPERTY(VisibleAnywhere, BlueprintReadOnly, Category = "Animation|State", meta = (AllowPrivateAccess = "true"))
        bool bIsDead = false;

        UPROPERTY(VisibleAnywhere, BlueprintReadOnly, Category = "Animation|State|Debuffs", meta = (AllowPrivateAccess = "true"))
        bool bIsStunned = false;

        UPROPERTY(VisibleAnywhere, BlueprintReadOnly, Category = "Animation|State|Debuffs", meta = (AllowPrivateAccess = "true"))
        bool bIsFrozen = false;

        // --- Вспомогательные Функции ---
        /** Получает и кэширует ASC от владельца */
        void InitializeReferences();

        /** Обновляет переменные состояния (скорость, падение и т.д.) */
        void UpdateMovementData(float DeltaSeconds);

        /** Обновляет переменные состояния на основе тегов GAS */
        void UpdateGASStateTags();

        /** Получает значение атрибута из кэшированного ASC (с проверкой) */
        UFUNCTION(BlueprintPure, Category = "Animation|GAS")
        float GetAttributeValue(FGameplayAttribute Attribute) const;

        /** Проверяет наличие тега в кэшированном ASC (с проверкой) */
        UFUNCTION(BlueprintPure, Category = "Animation|GAS")
        bool HasMatchingTag(FGameplayTag TagToCheck) const;
    };
    ```
6.  **`FrameForgeAnimInstance.cpp`**:
    ```cpp
    #include "Features/Chassis/Animations/FrameForgeAnimInstance.h" // Ваш путь
    #include "AbilitySystemComponent.h"
    #include "AbilitySystemInterface.h"       // Для получения ASC через интерфейс
    #include "GameFramework/Character.h"       // Для получения владельца-персонажа
    #include "GameFramework/CharacterMovementComponent.h" // Для получения скорости и состояния падения

    void UFrameForgeAnimInstance::NativeInitializeAnimation()
    {
        Super::NativeInitializeAnimation();
        InitializeReferences();
    }

    void UFrameForgeAnimInstance::NativeUpdateAnimation(float DeltaSeconds)
    {
        Super::NativeUpdateAnimation(DeltaSeconds);

        // Перепроверяем ссылки на случай, если владелец изменился (хотя обычно не должен для AnimInstance)
        if (!OwningActor.IsValid() || !OwnerASC.IsValid())
        {
            InitializeReferences();
        }

        // Если ссылки все еще невалидны, выходим
        if (!OwningActor.IsValid() || !OwnerASC.IsValid())
        {
            return;
        }

        // Обновляем данные о движении
        UpdateMovementData(DeltaSeconds);

        // Обновляем состояния на основе тегов GAS
        UpdateGASStateTags();
    }

    void UFrameForgeAnimInstance::InitializeReferences()
    {
        OwningActor = GetOwningActor();
        if (OwningActor.IsValid())
        {
            // Пытаемся получить ASC через интерфейс
            IAbilitySystemInterface* ASI = Cast<IAbilitySystemInterface>(OwningActor.Get());
            if (ASI)
            {
                OwnerASC = ASI->GetAbilitySystemComponent();
                // UE_LOG(LogTemp, Log, TEXT("FrameForgeAnimInstance: Found ASC for %s"), *OwningActor->GetName());
            }
            else
            {
                // UE_LOG(LogTemp, Warning, TEXT("FrameForgeAnimInstance: Owning actor %s does not implement IAbilitySystemInterface!"), *OwningActor->GetName());
            }
        }
    }

    void UFrameForgeAnimInstance::UpdateMovementData(float DeltaSeconds)
    {
        if (!OwningActor.IsValid()) return;

        // Получаем скорость
        GroundSpeed = OwningActor->GetVelocity().Size2D(); // Скорость по горизонтали

        // Получаем состояние падения из компонента движения
        ACharacter* OwnerCharacter = Cast<ACharacter>(OwningActor.Get());
        if (OwnerCharacter)
        {
             UCharacterMovementComponent* MoveComp = OwnerCharacter->GetCharacterMovement();
             if (MoveComp)
             {
                 bIsFalling = MoveComp->IsFalling();
                 bIsCrouching = MoveComp->IsCrouching(); // Если есть приседание
             }
        }
    }

    void UFrameForgeAnimInstance::UpdateGASStateTags()
    {
        if (!OwnerASC.IsValid()) return;

        // Проверяем наличие тегов состояний
        bIsDead = OwnerASC->HasMatchingGameplayTag(FGameplayTag::RequestGameplayTag(FName("State.Dead")));
        bIsStunned = OwnerASC->HasMatchingGameplayTag(FGameplayTag::RequestGameplayTag(FName("State.Debuff.Stunned")));
        bIsFrozen = OwnerASC->HasMatchingGameplayTag(FGameplayTag::RequestGameplayTag(FName("State.Debuff.Frozen")));
        // Добавьте проверки для других тегов, если нужно (Горение, Отравление и т.д.)
    }

    float UFrameForgeAnimInstance::GetAttributeValue(FGameplayAttribute Attribute) const
    {
        if (OwnerASC.IsValid())
        {
            return OwnerASC->GetNumericAttribute(Attribute);
        }
        return 0.0f;
    }

    bool UFrameForgeAnimInstance::HasMatchingTag(FGameplayTag TagToCheck) const
    {
        if (OwnerASC.IsValid())
        {
            return OwnerASC->HasMatchingGameplayTag(TagToCheck);
        }
        return false;
    }
    ```
7.  **Скомпилируйте C++ проект.**
8.  **Создайте или обновите ваш основной AnimBP** (например, `ABP_BaseChassis`), унаследовав его от `FrameForgeAnimInstance`.

**Шаг 16.2: Запуск Анимационных Монтажей из Способностей (GAS -> AnimBP)**

1.  **Подготовка Монтажа:**
    *   Создайте `Animation Montage` для вашей способности (например, `AM_Attack_Melee`, `AM_Ability_RepulsorCast`).
    *   В монтаже убедитесь, что вы используете подходящий Слот (Slot) в треке анимации (например, `DefaultSlot`, `UpperBody`, `FullBody`). Выберите слот в зависимости от того, должна ли анимация проигрываться на всем теле или только на его части.
2.  **Настройка AnimBP:**
    *   Откройте ваш `ABP_BaseChassis`.
    *   Перейдите в `AnimGraph`.
    *   В графе найдите место *после* вашей основной стейт-машины и блендспейсов.
    *   Добавьте ноду `Slot 'DefaultSlot'` (или другой слот, который вы используете в монтажах).
    *   Подключите выход вашей стейт-машины/блендспейса ко входу `Source` ноды `Slot`.
    *   Подключите выход ноды `Slot` к ноде `Output Pose`.
    *   *Объяснение:* Это позволяет анимациям из монтажей, использующих этот слот, переопределять базовую анимацию.
3.  **Использование AbilityTask в Способности (GA):**
    *   Откройте Event Graph вашей `GameplayAbility` (например, `GA_Chassis_BaseAttack_Typhon`).
    *   В логике после `Commit Ability`:
        *   Вызовите Ability Task `Play Montage and Wait`.
            *   `Montage to Play`: Выберите ваш `AM_Attack_Melee`.
            *   `Rate`: `1.0` (нормальная скорость).
            *   `Start Section`: (Оставьте пустым или укажите имя секции).
            *   `Anim Root Motion Translation Scale`: `1.0` (если монтаж использует Root Motion для перемещения).
            *   `Stop When Ability Ends`: `true` (Остановить монтаж, если способность прервется).
        *   Подключите выходы `On Completed`, `On Blend Out`, `On Interrupted`, `On Cancelled` к ноде `End Ability`.
        *   *Примечание:* Если вам нужно дождаться *события* из монтажа (как для урона в мили), используйте `Play Montage and Wait for Event` (см. Шаг 16.3).

**Шаг 16.3: Отправка Gameplay Events из Анимации в GAS (AnimBP -> GAS)**

Это используется для точного тайминга событий, например, нанесения урона в середине замаха.

1.  **Создание Кастомного AnimNotify (C++)**:
    *   **Tools -> New C++ Class...**
    *   Родитель: `AnimNotify`.
    *   Имя: `AnimNotify_SendGameplayEvent`.
    *   Путь: `FrameForge/Source/FrameForge/Public/Animation/Notifies/` (создайте папки).
    *   **`AnimNotify_SendGameplayEvent.h`**:
        ```cpp
        #pragma once

        #include "CoreMinimal.h"
        #include "Animation/AnimNotifies/AnimNotify.h"
        #include "GameplayTagContainer.h" // Для тега
        #include "AnimNotify_SendGameplayEvent.generated.h"

        UCLASS(meta = (DisplayName = "Send Gameplay Event to Owner")) // Имя в редакторе
        class FRAMEFORGE_API UAnimNotify_SendGameplayEvent : public UAnimNotify
        {
            GENERATED_BODY()

        public:
            // Тег события, который будет отправлен владельцу ASC
            UPROPERTY(EditAnywhere, BlueprintReadWrite, Category = "AnimNotify", meta = (DisplayName = "Event Tag"))
            FGameplayTag EventTagToSend;

        protected:
            virtual void Notify(USkeletalMeshComponent* MeshComp, UAnimSequenceBase* Animation, const FAnimNotifyEventReference& EventReference) override;
            virtual FString GetNotifyName_Implementation() const override; // Для отображения имени в редакторе
        };
        ```
    *   **`AnimNotify_SendGameplayEvent.cpp`**:
        ```cpp
        #include "Animation/Notifies/AnimNotify_SendGameplayEvent.h" // Ваш путь
        #include "AbilitySystemBlueprintLibrary.h" // Для GetAbilitySystemComponent
        #include "AbilitySystemComponent.h"

        void UAnimNotify_SendGameplayEvent::Notify(USkeletalMeshComponent* MeshComp, UAnimSequenceBase* Animation, const FAnimNotifyEventReference& EventReference)
        {
            Super::Notify(MeshComp, Animation, EventReference);

            if (!EventTagToSend.IsValid())
            {
                 UE_LOG(LogTemp, Warning, TEXT("AnimNotify_SendGameplayEvent: EventTagToSend is not valid on notify in %s"), *GetNameSafe(Animation));
                 return;
            }

            AActor* OwnerActor = MeshComp->GetOwner();
            if (!OwnerActor)
            {
                 UE_LOG(LogTemp, Warning, TEXT("AnimNotify_SendGameplayEvent: Could not get OwnerActor from MeshComp in %s"), *GetNameSafe(Animation));
                 return;
            }

            UAbilitySystemComponent* OwnerASC = UAbilitySystemBlueprintLibrary::GetAbilitySystemComponent(OwnerActor);
            if (!OwnerASC)
            {
                 UE_LOG(LogTemp, Warning, TEXT("AnimNotify_SendGameplayEvent: Could not get AbilitySystemComponent from OwnerActor %s in %s"), *OwnerActor->GetName(), *GetNameSafe(Animation));
                 return;
            }

            // Создаем данные события (можно добавить магнитуду и т.д., если нужно)
            FGameplayEventData EventData;
            EventData.EventTag = EventTagToSend;
            EventData.Instigator = OwnerActor; // Инициатор - владелец меша
            EventData.Target = OwnerActor;     // Цель по умолчанию - владелец меша

            // Отправляем событие
            OwnerASC->HandleGameplayEvent(EventTagToSend, &EventData);
             UE_LOG(LogTemp, Verbose, TEXT("AnimNotify_SendGameplayEvent: Sent event %s from %s"), *EventTagToSend.ToString(), *OwnerActor->GetName());
        }

        FString UAnimNotify_SendGameplayEvent::GetNotifyName_Implementation() const
        {
            if (EventTagToSend.IsValid())
            {
                return FString::Printf(TEXT("Send Event: %s"), *EventTagToSend.GetTagName().ToString());
            }
            return Super::GetNotifyName_Implementation();
        }
        ```
    *   **Скомпилируйте C++ проект.**
2.  **Добавление AnimNotify в Монтаж:**
    *   Откройте ваш `Animation Montage` (например, `AM_Attack_Melee`).
    *   Перейдите к таймлайну трека `Notifies`.
    *   Кликните правой кнопкой мыши в нужный момент времени (например, середина удара) -> `Add Notify...` -> `Send Gameplay Event to Owner`.
    *   Выделите добавленный нотифай. В панели `Details` найдите поле `Event Tag To Send`.
    *   Создайте и/или выберите тег, который будет сигнализировать о моменте нанесения урона, например, `Event.Montage.DamageTick`.
    *   Сохраните монтаж.
3.  **Ожидание События в Способности (GA):**
    *   Откройте Event Graph вашей `GameplayAbility` (например, `GA_Chassis_BaseAttack_Typhon`).
    *   Используйте Ability Task `Play Montage and Wait for Event`.
        *   `Montage to Play`: Ваш `AM_Attack_Melee`.
        *   `Event Tags`: Создайте `Gameplay Tag Container` и добавьте туда тег `Event.Montage.DamageTick`.
    *   От выхода `Event Received`:
        *   **(Здесь ваша логика нанесения урона):** Сделайте оверлап, найдите цели, примените `Damage GE`.
    *   От выходов `On Completed`, `On Blend Out`, `On Interrupted`, `On Cancelled`: Вызовите `End Ability`.

**Шаг 16.4: Реакция на Атрибуты в AnimBP (Скорость)**

Мы уже подготовили это в `FrameForgeAnimInstance`.

1.  **Откройте `ABP_BaseChassis`**.
2.  Перейдите в `AnimGraph`.
3.  Найдите ваш `Blend Space` для передвижения (например, `BS_Locomotion_Ground`).
4.  Подключите переменную `GroundSpeed` (которая обновляется в `NativeUpdateAnimation` из C++) ко входу скорости вашего Blend Space.
5.  *Результат:* Анимация ходьбы/бега будет автоматически меняться в зависимости от скорости персонажа, полученной из `CharacterMovementComponent`. Если вы хотите, чтобы сама *максимальная* скорость менялась из-за атрибута `MovementSpeed` GAS, это нужно делать отдельно (например, в `AFrameForgeCharacter` подписаться на изменение атрибута и обновлять `MaxWalkSpeed` у `CharacterMovementComponent`).

**Шаг 16.5: Реакция на Теги Состояний в AnimBP (Заморозка, Стан)**

Мы также подготовили это в `FrameForgeAnimInstance`.

1.  **Откройте `ABP_BaseChassis`**.
2.  Перейдите в `AnimGraph`.
3.  Найдите или создайте вашу основную `State Machine` (например, `Locomotion`).
4.  **Добавьте Новые Состояния:**
    *   Создайте состояние `FrozenState`. Внутри него зациклите анимацию заморозки (`A_Frozen_Idle_Loop`).
    *   Создайте состояние `StunnedState`. Внутри него зациклите анимацию оглушения (`A_Stunned_Idle_Loop`).
5.  **Настройте Переходы:**
    *   Создайте переход из `Any State` (или из базового состояния `Idle/WalkRun`) в `FrozenState`.
        *   В условии перехода (`Can Enter Transition`) используйте переменную `bIsFrozen` (которая обновляется в `NativeUpdateAnimation` из C++ через проверку тега `State.Debuff.Frozen`).
    *   Создайте переход из `FrozenState` обратно в базовое состояние.
        *   В условии перехода используйте `NOT bIsFrozen`.
    *   Аналогично настройте переходы для `StunnedState`, используя переменную `bIsStunned`.
6.  *Результат:* Когда к персонажу применяется GE, дающий тег `State.Debuff.Frozen` или `State.Debuff.Stunned`, переменная `bIsFrozen`/`bIsStunned` в AnimInstance станет `true`, и стейт-машина автоматически перейдет в соответствующее состояние, проигрывая нужную анимацию. Когда GE закончится и тег снимется, стейт-машина вернется в нормальное состояние.

**Шаг 16.6: Компиляция и Тестирование**

1.  **Пересоберите C++ проект.**
2.  **Запустите игру.**
3.  **Тестирование Монтажей:**
    *   Активируйте способности, использующие `Play Montage and Wait` / `Play Montage and Wait for Event`.
    *   Визуально проверьте, проигрывается ли нужная анимация.
    *   Проверьте, синхронизирована ли логика (урон) с анимацией через `AnimNotify` и `WaitGameplayEvent`. Используйте `slomo 0.1` для замедления и отладки таймингов.
4.  **Тестирование Атрибутов (Скорость):**
    *   Побегайте персонажем. Анимация должна соответствовать скорости.
    *   Примените к себе GE, изменяющий `MovementSpeed`. Персонаж должен начать двигаться быстрее/медленнее, и анимация в блендспейсе должна измениться соответственно.
5.  **Тестирование Тегов (Состояния):**
    *   Примените к себе GE `GE_Status_Frozen_Stun`. Персонаж должен перейти в анимацию заморозки. Способности должны блокироваться.
    *   Дождитесь окончания эффекта или удалите его командой. Персонаж должен вернуться в нормальное состояние.
    *   Повторите для `GE_Status_Stunned_Control`.

**Итог Шага:**

Вы успешно интегрировали Gameplay Ability System с системой анимации. Теперь ваши способности могут запускать анимационные монтажи для визуального представления (`PlayMontageAndWait`). Анимации могут точно по времени инициировать события в способностях (например, нанесение урона) с помощью кастомных `AnimNotify` и `WaitGameplayEvent`. Ваш Animation Blueprint теперь динамически реагирует на состояние персонажа, считывая скорость из `CharacterMovementComponent` и проверяя наличие тегов состояний (заморозка, стан) из `AbilitySystemComponent`, чтобы управлять стейт-машиной и блендспейсами. Это делает визуальное представление действий и состояний персонажа точным и синхронизированным с игровой логикой.
