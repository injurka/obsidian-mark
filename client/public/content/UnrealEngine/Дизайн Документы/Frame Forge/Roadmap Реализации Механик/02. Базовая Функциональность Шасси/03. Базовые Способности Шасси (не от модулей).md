**Базовые Способности Шасси (не от модулей)**.

**Задача:** Создать и выдать базовые `GameplayAbility` (GA), которые доступны Шасси всегда, независимо от найденных модулей: Прыжок, Взаимодействие и Базовая Атака (уникальная для каждого типа Шасси, активная только если не экипировано основное оружие).

**Зачем:** Обеспечить минимально необходимую функциональность и интерактивность персонажа с самого начала забега. Прыжок нужен для навигации, взаимодействие - для сбора лута и использования станций, базовая атака - для уничтожения простейших объектов и защиты на старте.

**GAS Компоненты и Механизмы UE:** `UGameplayAbility`, `AbilitySystemComponent::GiveAbility`, `FGameplayAbilitySpec`, `AbilitySystemComponent::TryActivateAbilityByInputID`, `AbilityTask_PlayMontageAndWait`, `AbilityTask_WaitGameplayEvent`, `GameplayTag`, `GameplayEffect`.

**Шаг 8.1: Создание Базового Класса `GameplayAbility` (C++)**

Для удобства и возможного добавления общей логики в будущем, создадим базовый C++ класс для наших способностей.

1.  **Tools -> New C++ Class...**
2.  Родительский класс: `GameplayAbility`.
3.  Имя: `FrameForgeGameplayAbility`.
4.  Путь: `FrameForge/Source/FrameForge/Public/Abilities/` (создайте папки Abilities, если нужно).
5.  Нажмите **Create Class**.
6.  **Откройте `FrameForgeGameplayAbility.h`**. Добавьте перечисление `EAbilityInputID` и, возможно, хелперы для получения владельца/аватара.

    ```cpp
    // FrameForge/Source/FrameForge/Public/Abilities/FrameForgeGameplayAbility.h

    #pragma once

    #include "CoreMinimal.h"
    #include "Abilities/GameplayAbility.h"
    #include "Core/AbilityInputID.h" // Включаем наше перечисление
    #include "FrameForgeGameplayAbility.generated.h"

    class AFrameForgeCharacter; // Прямое объявление для хелперов
    class AController;

    UCLASS(Abstract) // Abstract - нельзя создать экземпляр этого базового класса напрямую
    class FRAMEFORGE_API UFrameForgeGameplayAbility : public UGameplayAbility
    {
        GENERATED_BODY()

    public:
        UFrameForgeGameplayAbility();

        // --- Вспомогательные Функции ---

        UFUNCTION(BlueprintPure, Category = "Ability|Helpers")
        AFrameForgeCharacter* GetFrameForgeCharacterFromActorInfo() const;

        UFUNCTION(BlueprintPure, Category = "Ability|Helpers")
        AController* GetControllerFromActorInfo() const;

        // --- Свойства Способности ---

        // InputID, с которым эта способность будет связана. Устанавливается в FGameplayAbilitySpec при выдаче.
        // Мы не можем сделать это UPROPERTY напрямую редактируемым здесь, т.к. InputID задается при GiveAbility.
        // Но оставим комментарий как напоминание.
        // EAbilityInputID AbilityInputID = EAbilityInputID::None;

        // Тег, который будет автоматически применен к владельцу во время активации способности.
        // Полезно для блокировки других способностей или для анимации.
        UPROPERTY(EditDefaultsOnly, BlueprintReadOnly, Category = "Ability|Tags")
        FGameplayTagContainer ActivationOwnedTags;

    protected:
        // Переопределяем для автоматического применения ActivationOwnedTags
        virtual void ActivateAbility(const FGameplayAbilitySpecHandle Handle, const FGameplayAbilityActorInfo* ActorInfo, const FGameplayAbilityActivationInfo ActivationInfo, const FGameplayEventData* TriggerEventData) override;

        // Переопределяем для автоматического снятия ActivationOwnedTags
        virtual void EndAbility(const FGameplayAbilitySpecHandle Handle, const FGameplayAbilityActorInfo* ActorInfo, const FGameplayAbilityActivationInfo ActivationInfo, bool bReplicateEndAbility, bool bWasCancelled) override;
    };
    ```
7.  **Откройте `FrameForgeGameplayAbility.cpp`**. Реализуйте конструктор и хелперы.

    ```cpp
    // FrameForge/Source/FrameForge/Private/Abilities/FrameForgeGameplayAbility.cpp

    #include "Abilities/FrameForgeGameplayAbility.h"
    #include "FrameForgeCharacter.h"       // Включаем персонажа
    #include "GameFramework/Controller.h" // Включаем контроллер
    #include "AbilitySystemComponent.h"      // Для GetAbilitySystemComponentFromActorInfo

    UFrameForgeGameplayAbility::UFrameForgeGameplayAbility()
    {
        // --- Стандартные настройки для большинства способностей ---

        // Способность будет инстанциироваться для каждого актора, что позволяет ей иметь свое состояние.
        InstancingPolicy = EGameplayAbilityInstancingPolicy::InstancedPerActor;

        // По умолчанию способности не активируются автоматически при выдаче
        bActivateAbilityOnGranted = false;

        // По умолчанию реплицируем завершение способности
        // SetReplicateEndAbility(true); // Это делается в конструкторе базового UGameplayAbility

        // --- Сетевые настройки ---
        // По умолчанию используем LocalPredicted для большинства способностей игрока
        // Это дает отзывчивость на клиенте с авторитетной проверкой на сервере.
        NetExecutionPolicy = EGameplayAbilityNetExecutionPolicy::LocalPredicted;

        // Указываем, что способность может быть отменена тегом CancelInputID
        // CancelAbilityInputTag = FGameplayTag::RequestGameplayTag(FName("Input.Cancel")); // Пример
    }

    AFrameForgeCharacter* UFrameForgeGameplayAbility::GetFrameForgeCharacterFromActorInfo() const
    {
        // Получаем ActorInfo, затем Аватара и кастуем к нашему классу персонажа
        return Cast<AFrameForgeCharacter>(GetAvatarActorFromActorInfo());
    }

    AController* UFrameForgeGameplayAbility::GetControllerFromActorInfo() const
    {
        if (CurrentActorInfo)
        {
            return CurrentActorInfo->PlayerController.Get();
        }
        return nullptr;
    }


    void UFrameForgeGameplayAbility::ActivateAbility(const FGameplayAbilitySpecHandle Handle, const FGameplayAbilityActorInfo* ActorInfo, const FGameplayAbilityActivationInfo ActivationInfo, const FGameplayEventData* TriggerEventData)
    {
        Super::ActivateAbility(Handle, ActorInfo, ActivationInfo, TriggerEventData);

        // Применяем теги, принадлежащие этой активации
        if (UAbilitySystemComponent* ASC = GetAbilitySystemComponentFromActorInfo())
        {
            ASC->AddLooseGameplayTags(ActivationOwnedTags);
        }
         else
         {
              UE_LOG(LogTemp, Warning, TEXT("UFrameForgeGameplayAbility::ActivateAbility: Cannot get ASC to add ActivationOwnedTags for ability %s"), *GetName());
         }
    }

    void UFrameForgeGameplayAbility::EndAbility(const FGameplayAbilitySpecHandle Handle, const FGameplayAbilityActorInfo* ActorInfo, const FGameplayAbilityActivationInfo ActivationInfo, bool bReplicateEndAbility, bool bWasCancelled)
    {
         // Снимаем теги, принадлежащие этой активации
         if (CurrentActorInfo) // Используем CurrentActorInfo для безопасности
         {
             if (UAbilitySystemComponent* ASC = CurrentActorInfo->AbilitySystemComponent.Get())
             {
                 ASC->RemoveLooseGameplayTags(ActivationOwnedTags);
             }
             else
             {
                  UE_LOG(LogTemp, Warning, TEXT("UFrameForgeGameplayAbility::EndAbility: Cannot get ASC to remove ActivationOwnedTags for ability %s"), *GetName());
             }
         }

        Super::EndAbility(Handle, ActorInfo, ActivationInfo, bReplicateEndAbility, bWasCancelled);
    }
    ```

**Шаг 8.2: Создание Способностей (Blueprint)**

Теперь создадим конкретные способности в редакторе, наследуясь от `FrameForgeGameplayAbility`.

1.  **Создайте папки** в Content Browser: `Content/Features/Chassis/GAS/Abilities/Base/`
2.  **GA_Character_Jump:**

    *   Имя: `GA_Character_Jump`.
    *   Откройте `GA_Character_Jump`.
    *   Перейдите в Class Defaults.
    *   **Activation Owned Tags:** Оставьте пустым (или добавьте `State.Jumping`, если нужно).
    *   Перейдите в Event Graph.
    *   Найдите или создайте событие `Event ActivateAbility`.
    *   От него вызовите `Get Frame Forge Character from Actor Info`.
    *   От персонажа вызовите стандартную функцию `Jump`.
    *   После `Jump` вызовите `End Ability`.
    *   Скомпилируйте и сохраните.
3.  **GA_Character_Interact:**
    *   Правой кнопкой мыши -> Blueprint Class -> Родитель: `FrameForgeGameplayAbility`.
    *   Имя: `GA_Character_Interact`.
    *   Откройте `GA_Character_Interact`.
    *   Перейдите в Class Defaults.
    *   **Activation Owned Tags:** Можно добавить `State.Interacting`, если взаимодействие длительное.
    *   Перейдите в Event Graph.
    *   От `Event ActivateAbility`:
        *   Получите персонажа (`Get Frame Forge Character from Actor Info`).
        *   Выполните трассировку (например, `LineTraceByChannel` или `SphereTraceByChannel`) вперед от камеры или персонажа на небольшое расстояние (например, 250-300 юнитов). Настройте каналы трассировки (`Visibility` или специальный `Interaction` канал).
        *   Из `Out Hit` сделайте `Break Hit Result`.
        *   Проверьте `Blocking Hit`.
        *   Из `Hit Actor` попробуйте вызвать сообщение интерфейса `BPI_Interactable` -> `Can Interact` (используйте ноду "Does Implement Interface" перед этим).
        *   Если `Can Interact` вернуло `true`:
            *   Вызовите сообщение интерфейса `BPI_Interactable` -> `On Interact Begin` (или как названа ваша функция взаимодействия). Передайте `Hit Actor` как Target.
            *   (Опционально) Если взаимодействие мгновенное, сразу вызовите `End Ability`.
            *   (Опционально) Если взаимодействие удерживаемое, используйте `AbilityTask_WaitInputRelease` и вызовите `On Interact End` / `End Ability` при отпускании или отмене.
        *   Если трассировка не попала, или актор не интерактивный, или `Can Interact` вернуло `false`, просто вызовите `End Ability`.
    *   Скомпилируйте и сохраните.
4.  **GA_Chassis_BaseAttack (Базовый Класс Атаки):**

    *   Имя: `GA_Chassis_BaseAttack`.
    *   Откройте `GA_Chassis_BaseAttack`.
    *   Перейдите в Class Defaults.
    *   **Activation Owned Tags:** Добавьте `State.Attacking.Melee` или `State.Attacking.Ranged` (в зависимости от типа атаки).
    *   **Ability Tags:** Добавьте тег, идентифицирующий эту способность как базовую атаку, например, `Ability.Attack.Base`. Это важно для блокировки этой способности, когда экипировано оружие.
    *   **Cooldown:** Создайте новый ассет `GameplayEffect` (например, `GE_Cooldown_BaseAttack`), установите `Duration Policy` = `Has Duration`, укажите длительность (например, 0.5 секунды) и добавьте тег кулдауна (`Cooldown.Attack.Base`). Назначьте этот GE в поле `Cooldown Gameplay Effect Class`.

        *   `DamageEffectClass` (Тип: TSubclassOf Gameplay Effect, Instance Editable: true) - Эффект урона для этой атаки.
        *   `DamageEventTag` (Тип: Gameplay Tag, Instance Editable: true, Default: `Event.Montage.DamageTick`) - Тег события из анимации для нанесения урона.

    *   От `Event ActivateAbility`:
        *   Используйте Ability Task `Play Montage and Wait for Event`.
            *   Подключите `AttackMontage`.
            *   Подключите `DamageEventTag` в `Event Tags`.
            *   Rate: 1.0. Start Section: None.
        *   От выхода `On Event Received`:
            *   (Здесь будет логика нанесения урона - см. ниже)

        *   От выходов `On Completed`, `On Blend Out`, `On Interrupted`, `On Cancelled`: вызовите `End Ability`.
    *   **Логика Нанесения Урона (от `On Event Received`):**

        *   Выполните логику попадания:
            *   **Для Мили:** Сделайте `SphereOverlapActors` или `BoxOverlapActors` перед персонажем в момент события. Проигнорируйте самого себя. Переберите найденных акторов (`For Each Loop`). Проверьте, что актор реализует `IAbilitySystemInterface` (или `BPI_Damageable`). Получите его ASC.
            *   **Для Рейндж (импульс):** Аналогично мили, но, возможно, с другой формой/дальностью.
        *   Для каждого валидного найденного ASC:
            *   Создайте `GameplayEffectSpecHandle` из `DamageEffectClass` (`Make Outgoing Gameplay Effect Spec`). Установите контекст (`Make Effect Context Handle`), можно добавить источник урона.
            *   Примените эффект к цели (`Apply Gameplay Effect Spec to Target`).
    *   Скомпилируйте и сохраните `GA_Chassis_BaseAttack`.

**Шаг 8.3: Выдача Начальных Способностей (C++)**

Теперь модифицируем `AFrameForgeCharacter`, чтобы он выдавал эти способности при инициализации.

1.  **Откройте `FrameForgeCharacter.h`**.
2.  **Включите заголовки**:
    ```cpp

    // FrameForgeGameplayAbility.h уже должен быть включен, если нет - добавьте
    ```
3.  **Добавьте `UPROPERTY`** для хранения списка начальных способностей:
    ```cpp
    protected:
        // --- Начальные Настройки GAS ---
        // ... (InitialStatsEffect уже есть) ...

        // Начальные способности, которые выдаются при спавне (устанавливается в Blueprint наследниках Шасси).
        UPROPERTY(EditDefaultsOnly, BlueprintReadOnly, Category = "GAS|Initialization")

    ```
4.  **Откройте `FrameForgeCharacter.cpp`**.
5.  **Модифицируйте `GrantInitialAbilitiesAndEffects`**, добавив логику выдачи способностей:
    ```cpp
    void AFrameForgeCharacter::GrantInitialAbilitiesAndEffects()
    {
        if (GetLocalRole() != ROLE_Authority) return;
        AFrameForgePlayerState* PS = GetPlayerState<AFrameForgePlayerState>();
        if (!PS) return;
        UAbilitySystemComponent* ASC = PS->GetAbilitySystemComponent();
        if (!ASC) return;

        // --- Применение Начальных Атрибутов (код из шага 6) ---
        if (!bASCEffectsApplied)
        {
             if (IsValid(InitialStatsEffect))
             {
                  // ... (код применения InitialStatsEffect) ...
                  // bASCEffectsApplied = true; // Устанавливаем флаг здесь
             }
             // ... (логи ошибок) ...
        }
        // --- ---

        // --- Выдача Начальных Способностей ---
        if (!bAbilitiesInitialized)
        {
            for (TSubclassOf<UFrameForgeGameplayAbility> AbilityClass : InitialAbilities)
            {
                if (!IsValid(AbilityClass))
                {
                    UE_LOG(LogTemp, Warning, TEXT("GrantInitialAbilitiesAndEffects: Invalid AbilityClass in InitialAbilities for %s"), *GetName());
                    continue;
                }

                // Получаем InputID из CDO (Class Default Object) способности.
                // Это требует, чтобы вы установили InputID как переменную в BP способности,
                // ИЛИ вы можете жестко закодировать InputID здесь на основе класса,
                // ИЛИ (лучше) создать DataAsset для способностей, где будет храниться InputID.
                // Пока сделаем простой вариант: предположим, что InputID можно получить из CDO.
                // Если нет, вам нужно будет изменить эту логику.
                // UFrameForgeGameplayAbility* AbilityCDO = AbilityClass->GetDefaultObject<UFrameForgeGameplayAbility>();
                // EAbilityInputID InputID = AbilityCDO ? AbilityCDO->AbilityInputID : EAbilityInputID::None; // НЕ РАБОТАЕТ ТАК ПРОСТО

                // --- !!! ВАЖНО: Определение InputID для базовых способностей ---
                // Так как InputID не является прямым свойством GA, установим его здесь вручную
                // при создании Spec. Это менее гибко, чем DataAsset, но проще для начала.
                EAbilityInputID InputID = EAbilityInputID::None;
                if (AbilityClass->IsChildOf(GA_Character_Jump::StaticClass())) { // Используйте .h или создайте BP и получите класс
                     InputID = EAbilityInputID::Jump;
                } else if (AbilityClass->IsChildOf(GA_Character_Interact::StaticClass())) {
                     InputID = EAbilityInputID::Interact;
                } else if (AbilityClass->IsChildOf(GA_Chassis_BaseAttack::StaticClass())) { // Проверяем родителя базовой атаки
                     InputID = EAbilityInputID::PrimaryAttack;
                }
                // Добавьте другие проверки для базовых способностей, если они есть

                if (InputID != EAbilityInputID::None)
                {
                    // Создаем спецификацию способности
                    int32 AbilityLevel = 1; // Уровень способности
                    FGameplayAbilitySpec AbilitySpec(AbilityClass, AbilityLevel, static_cast<int32>(InputID), this); // Передаем InputID и SourceObject

                    // Выдаем способность компоненту
                    FGameplayAbilitySpecHandle AbilityHandle = ASC->GiveAbility(AbilitySpec);

                    if(AbilityHandle.IsValid())
                    {
                        UE_LOG(LogTemp, Log, TEXT("GrantInitialAbilitiesAndEffects: Granted ability %s with InputID %d to %s"), *AbilityClass->GetName(), static_cast<int32>(InputID), *GetName());
                    }
                    else
                    {
                        UE_LOG(LogTemp, Error, TEXT("GrantInitialAbilitiesAndEffects: Failed to grant ability %s to %s"), *AbilityClass->GetName(), *GetName());
                    }
                }
                 else
                 {
                      UE_LOG(LogTemp, Warning, TEXT("GrantInitialAbilitiesAndEffects: Could not determine InputID for AbilityClass %s for %s. Ability NOT granted with input binding."), *AbilityClass->GetName(), *GetName());
                      // Можно выдать способность без InputID, если она пассивная или активируется иначе
                      // FGameplayAbilitySpec AbilitySpec(AbilityClass, 1, INDEX_NONE, this);
                      // ASC->GiveAbility(AbilitySpec);
                 }
            }
            bAbilitiesInitialized = true; // Устанавливаем флаг
        }
        // --- ---
    }
    ```
    *Ключевой момент:* Мы определяем `InputID` для базовых способностей в коде C++ при их выдаче, проверяя класс способности. Это гарантирует правильную привязку к вводу.
