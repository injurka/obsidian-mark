**Интеграция Пользовательского Интерфейса (UI) с GAS**. Мы сосредоточимся на отображении ключевой информации из GAS на HUD'е игрока.

**Задача:** Связать элементы UI (полосы здоровья/энергии, иконки способностей с кулдаунами/зарядами, индикаторы статус-эффектов) с данными из `AbilitySystemComponent` (ASC). Использовать делегаты для атрибутов и отслеживание тегов/спецификаций для способностей и статусов.

**Зачем:** Предоставить игроку критически важную информацию о состоянии его Шасси и доступности способностей в реальном времени, что необходимо для принятия тактических решений.

**GAS Компоненты и Механизмы UE:** `UAbilitySystemComponent`, `GetGameplayAttributeValueChangeDelegate`, `RegisterGameplayTagEvent`, `FGameplayAbilitySpec`, `GetCooldownTimeRemaining`, `ActiveGameplayEffects`, `HasMatchingGameplayTag`, `AttributeSet`, UI Виджеты (WBP).

---

**Подробная Реализация Шага:**

Предполагается, что у вас уже есть базовые виджеты, созданные ранее (см. раздел UI в предыдущих ответах), такие как:
*   `WBP_HUD_Main`: Основной контейнер HUD.
*   `WBP_HUD_AttributeBar`: Виджет для отображения полосы атрибута (здоровье, энергия).
*   `WBP_HUD_AbilityIcon`: Виджет для отображения иконки способности с кулдауном/зарядами.
*   `WBP_HUD_StatusEffectList`: Контейнер для иконок статусов.
*   `WBP_HUD_StatusEffectIcon`: Иконка одного статуса.

**Шаг 19.1: Получение Ссылки на ASC в UI**

UI (особенно HUD) существует на клиенте и должен получить доступ к ASC *локального* игрока.

1.  **В `WBP_HUD_Main` (или его C++ родительском классе, если есть):**
    *   Создайте переменную `OwnerASC` типа `Ability System Component (Object Reference)`.
    *   **В Event `Construct` (или `NativeConstruct` в C++):**
        *   Получите `Owning Player Pawn`.
        *   Попытайтесь получить `Player State` из пешки (`Get Player State`).
        *   Попытайтесь получить `Ability System Component` из `Player State` (используя интерфейс `IAbilitySystemInterface` -> `Get Ability System Component`).
        *   **Сохраните** полученный ASC в переменную `OwnerASC`.
        *   **Добавьте проверку `IsValid`** на `OwnerASC`. Если он невалиден, возможно, HUD создался до полной инициализации игрока. В этом случае можно использовать таймер (`Set Timer by Event`) с коротким интервалом, чтобы повторить попытку получения ASC несколько раз, пока он не станет валидным.
        *   **После успешного получения `OwnerASC`:** Вызовите пользовательское событие (или функцию) `InitializeHUDWidgets`.
2.  **В `InitializeHUDWidgets`:**
    *   Получите ссылки на ваши дочерние виджеты (Полосы атрибутов, Иконки способностей).
    *   Вызовите у них функции инициализации, передав им ссылку на `OwnerASC`.

**Шаг 19.2: Интеграция Полос Атрибутов (`WBP_HUD_AttributeBar`)**

Этот виджет должен отображать текущее и максимальное значение атрибута и реагировать на их изменения.

1.  **В `WBP_HUD_AttributeBar`:**
    *   **Переменные:**
        *   `OwnerASC` (Ability System Component, Instance Editable, Expose on Spawn) - Получаем от `WBP_HUD_Main`.
        *   `AttributeToDisplay` (FGameplayAttribute, Instance Editable, Expose on Spawn) - Какой атрибут отображать (Health, Energy).
        *   `MaxAttributeToDisplay` (FGameplayAttribute, Instance Editable, Expose on Spawn) - Соответствующий максимальный атрибут (MaxHealth, MaxEnergy).
        *   `CurrentValue` (float)
        *   `MaxValue` (float)
    *   **UI Элементы:**
        *   `ProgressBar` (назовем `AttributeProgressBar`)
        *   `TextBlock` (назовем `ValueText`, опционально, для отображения "100/150")
2.  **Функция `Initialize (OwnerASC_Input, Attribute, MaxAttribute)`:**
    *   Сохраните переданные параметры в переменные виджета.
    *   **Проверьте `IsValid(OwnerASC)`**.
    *   **Получите Начальные Значения:**
        *   `OwnerASC` -> `Get Numeric Attribute Value`: Передайте `AttributeToDisplay`, получите `CurrentValue`.
        *   `OwnerASC` -> `Get Numeric Attribute Value`: Передайте `MaxAttributeToDisplay`, получите `MaxValue`.
    *   **Обновите Виджет:** Вызовите новую функцию `UpdateAttributeBar`.
    *   **Подписка на Делегаты:**
        *   `OwnerASC` -> `Get Gameplay Attribute Value Change Delegate`: Передайте `AttributeToDisplay`. От выхода `Delegate` вызовите `Bind Event to OnAttributeChanged`. Создайте новое событие `OnCurrentAttributeChanged`.
        *   `OwnerASC` -> `Get Gameplay Attribute Value Change Delegate`: Передайте `MaxAttributeToDisplay`. От выхода `Delegate` вызовите `Bind Event to OnAttributeChanged`. Создайте новое событие `OnMaxAttributeChanged`.
3.  **Функция `UpdateAttributeBar`:**
    *   Проверьте `MaxValue > 0`.
    *   Рассчитайте процент: `Percent = CurrentValue / MaxValue`.
    *   `AttributeProgressBar` -> `Set Percent`: Установите рассчитанный `Percent`.
    *   (Опционально) `ValueText` -> `Set Text`: Сформатируйте строку (например, `FString::Printf(TEXT("%.0f / %.0f"), CurrentValue, MaxValue)`).
4.  **Событие `OnCurrentAttributeChanged (Payload)`:**
    *   Из `Payload` (`On Attribute Change Data`) вытяните `New Value`.
    *   Установите `CurrentValue = New Value`.
    *   Вызовите `UpdateAttributeBar`.
5.  **Событие `OnMaxAttributeChanged (Payload)`:**
    *   Из `Payload` вытяните `New Value`.
    *   Установите `MaxValue = New Value`.
    *   *(Важно)* Если `CurrentValue > MaxValue`, установите `CurrentValue = MaxValue` (хотя это должно обрабатываться и в AttributeSet).
    *   Вызовите `UpdateAttributeBar`.
6.  **В `WBP_HUD_Main`:** При создании `WBP_HUD_AttributeBar` (для Health, Energy и т.д.), вызовите его функцию `Initialize`, передав `OwnerASC` и соответствующие структуры `FGameplayAttribute` (вы можете создать переменные типа `FGameplayAttribute` в `WBP_HUD_Main` и установить их в редакторе, выбрав атрибуты из `BaseAttributeSet`).

**Шаг 19.3: Интеграция Иконок Способностей (`WBP_HUD_AbilityIcon`)**

Этот виджет должен показывать иконку, кулдаун и (если есть) заряды способности.

1.  **В `WBP_HUD_AbilityIcon`:**
    *   **Переменные:**
        *   `OwnerASC` (Ability System Component, Instance Editable, Expose on Spawn).
        *   `BoundInputID` (EAbilityInputID, Instance Editable, Expose on Spawn) - К какому слоту привязана иконка.
        *   `AbilitySpecHandle` (FGameplayAbilitySpecHandle) - Хэндл текущей способности в этом слоте.
        *   `CooldownTag` (FGameplayTag) - Тег кулдауна этой способности.
        *   `CooldownRemaining` (float)
        *   `CooldownDuration` (float)
        *   `CurrentCharges` (int)
        *   `MaxCharges` (int)
    *   **UI Элементы:**
        *   `Image` (назовем `AbilityIconImage`)
        *   `Image` (назовем `CooldownOverlayImage`) - Полупрозрачный оверлей для кулдауна.
        *   `TextBlock` (назовем `CooldownText`) - Текст с оставшимся временем.
        *   `TextBlock` (назовем `ChargeText`) - Текст с количеством зарядов.
2.  **Функция `Initialize (OwnerASC_Input, InputID_Input)`:**
    *   Сохраните `OwnerASC` и `BoundInputID`.
    *   **Проверьте `IsValid(OwnerASC)`**.
    *   **Найдите Способность:** Вызовите новую функцию `UpdateAbilityInfo`.
    *   **Подписка на События Слота:** (Сложнее, требует связи с `ChassisSlotManagerComponent`)
        *   Получите `SlotManagerComponent` у владельца ASC.
        *   Подпишитесь на его делегаты `OnItemEquipped`/`OnItemUnequipped` (если вы их создали). При срабатывании для `BoundInputID` вызывайте `UpdateAbilityInfo`.
        *   *Альтернатива:* Периодически (раз в секунду или реже) проверяйте `UpdateAbilityInfo`, если не хотите использовать делегаты.
3.  **Функция `UpdateAbilityInfo`:**
    *   `AbilitySpecHandle` = `Invalid`. `CooldownTag` = `Empty`. `CooldownRemaining` = 0. `CooldownDuration` = 0. `CurrentCharges` = 0. `MaxCharges` = 0.
    *   Скройте/очистите все элементы UI (`CooldownOverlay`, `CooldownText`, `ChargeText`). Установите `AbilityIconImage` в пустую текстуру или иконку "пустого слота".
    *   **Найдите Spec:** `OwnerASC` -> `Find Ability Spec From Input ID`: Передайте `BoundInputID`. Сохраните результат в `AbilitySpecHandle`.
    *   **Если `AbilitySpecHandle` валиден:**
        *   `OwnerASC` -> `Find Ability Spec From Handle`: Передайте `AbilitySpecHandle`. Получите `Ability Spec`.
        *   Из `Ability Spec`:
            *   `Get Ability CDO` (Class Default Object). Получите иконку способности (`ItemIcon` из `ModuleAbilityItemData`, если способность получена оттуда - это требует доработки получения данных) и установите в `AbilityIconImage`.
            *   `Get Dynamic Ability Tags` -> Найдите тег кулдауна (например, `Cooldown.Module.KineticRepulsor`) и сохраните в `CooldownTag`. *Примечание: Тег кулдауна лучше хранить в Data Asset способности.*
            *   Получите `Level` (если нужно).
            *   Получите `Current Ability Charges` и сохраните в `CurrentCharges`.
            *   `(Сложнее)` Получите `Max Ability Charges` (может храниться в GE зарядов или в самой способности). Сохраните в `MaxCharges`.
        *   **Обновите UI Зарядов:** Если `MaxCharges > 0`, покажите `ChargeText` и установите текст (например, `CurrentCharges`). Иначе скройте `ChargeText`.
        *   **Проверьте Кулдаун:** Вызовите `CheckCooldown`.
        *   **Подписка на Тег Кулдауна:**
            *   Отпишитесь от предыдущего тега (если был).
            *   Если `CooldownTag` валиден: `OwnerASC` -> `Register Gameplay Tag Event`: `Tag` = `CooldownTag`, `Event Type` = `EGameplayTagEventType::NewOrRemoved`. `Bind Event to OnCooldownTagChanged`.
4.  **Функция `CheckCooldown`:**
    *   Если `AbilitySpecHandle` невалиден или `CooldownTag` невалиден, скройте элементы кулдауна и вызовите `Stop Cooldown Timer` (см. ниже). Выход.
    *   `OwnerASC` -> `Get Cooldown Time Remaining and Duration`: Передайте `CooldownTag`. Получите `Time Remaining` и `Duration`.
    *   Сохраните их в `CooldownRemaining` и `CooldownDuration`.
    *   **Если `Time Remaining > 0`:**
        *   Вызовите `UpdateCooldownVisuals`.
        *   Вызовите `Start Cooldown Timer`.
    *   **Иначе (Кулдауна нет):**
        *   Вызовите `UpdateCooldownVisuals` (чтобы скрыть оверлей/текст).
        *   Вызовите `Stop Cooldown Timer`.
5.  **Функция `UpdateCooldownVisuals`:**
    *   **Если `CooldownRemaining > 0` и `CooldownDuration > 0`:**
        *   Покажите `CooldownOverlayImage` и `CooldownText`.
        *   Установите `CooldownText` (например, `FString::Printf(TEXT("%.1f"), CooldownRemaining)`).
        *   Установите заливку (`Percent`) для `CooldownOverlayImage` (если это материал с параметром): `Percent = CooldownRemaining / CooldownDuration`.
    *   **Иначе:** Скройте `CooldownOverlayImage` и `CooldownText`.
6.  **Таймер Кулдауна (в Event Graph):**
    *   Создайте пользовательское событие `TickCooldownTimer`.
    *   Внутри `TickCooldownTimer`:
        *   Уменьшите `CooldownRemaining` на время шага таймера (например, 0.1 сек).
        *   Если `CooldownRemaining <= 0`, вызовите `Stop Cooldown Timer` и `UpdateCooldownVisuals`.
        *   Иначе вызовите `UpdateCooldownVisuals`.
    *   Функция `Start Cooldown Timer`: `Set Timer by Event Name`: `Event Name` = `TickCooldownTimer`, `Time` = 0.1, `Looping` = true. Сохраните хэндл таймера.
    *   Функция `Stop Cooldown Timer`: `Clear and Invalidate Timer by Handle`: Передайте сохраненный хэндл.
7.  **Событие `OnCooldownTagChanged (Tag, Count)`:**
    *   Вызовите `CheckCooldown`. (Это обновит состояние кулдауна, когда тег добавляется или удаляется).
8.  **В `WBP_HUD_Main`:** Создайте `WBP_HUD_AbilityIcon` для каждого слота (`Ability1`, `Ability2`, `Utility`, `MovementAbility`), вызовите `Initialize`, передав `OwnerASC` и соответствующий `EAbilityInputID`.

**Шаг 19.4: Интеграция Иконок Статус-Эффектов (`WBP_HUD_StatusEffectList` и `WBP_HUD_StatusEffectIcon`)**

Этот виджет должен показывать иконки активных баффов и дебаффов.

1.  **В `WBP_HUD_StatusEffectIcon`:**
    *   **Переменные:** `StatusTag` (Gameplay Tag), `IconTexture` (Texture2D), `Duration` (float, опционально), `Stacks` (int, опционально).
    *   **UI Элементы:** `Image` (`StatusIconImage`), `TextBlock` (`DurationText`, опционально), `TextBlock` (`StackCountText`, опционально).
    *   **Функция `SetStatusInfo (Tag, Icon, Duration, Stacks)`:** Устанавливает данные и обновляет UI.
2.  **В `WBP_HUD_StatusEffectList`:**
    *   **Переменные:** `OwnerASC` (Ability System Component), `DisplayedStatusTags` (Map: Gameplay Tag -> WBP_HUD_StatusEffectIcon Reference).
    *   **UI Элементы:** `HorizontalBox` или `WrapBox` (назовем `StatusIconContainer`).
3.  **Функция `Initialize (OwnerASC_Input)`:**
    *   Сохраните `OwnerASC`.
    *   **Проверьте `IsValid(OwnerASC)`**.
    *   **Подписка на Теги:**
        *   Создайте массив `TagsToMonitor` типа `Array of Gameplay Tag`. Добавьте сюда ВСЕ теги статусов, которые вы хотите отслеживать (например, `State.Debuff.Burning`, `State.Debuff.Frozen`, `State.Buff.SpeedBoost`, ...).
        *   В цикле (`For Each Loop`) пройдитесь по `TagsToMonitor`:
            *   `OwnerASC` -> `Register Gameplay Tag Event`: `Tag` = (текущий тег из цикла), `Event Type` = `EGameplayTagEventType::NewOrRemoved`. `Bind Event to OnStatusTagChanged`.
    *   **Начальное Обновление:** Вызовите функцию `RefreshAllStatusIcons`.
4.  **Функция `RefreshAllStatusIcons`:**
    *   Очистите `StatusIconContainer` (`Clear Children`).
    *   Очистите карту `DisplayedStatusTags`.
    *   `OwnerASC` -> `Get Owned Gameplay Tags` (получить все активные теги).
    *   В цикле по `TagsToMonitor`:
        *   Проверьте, есть ли текущий тег `StatusTag` в `Owned Gameplay Tags` (`Has Tag`).
        *   Если есть: Вызовите `AddStatusIcon(StatusTag)`.
5.  **Событие `OnStatusTagChanged (Tag, Count)`:**
    *   **Если `Count > 0` (Тег добавлен):** Вызовите `AddStatusIcon(Tag)`.
    *   **Если `Count == 0` (Тег удален):** Вызовите `RemoveStatusIcon(Tag)`.
6.  **Функция `AddStatusIcon (TagToAdd)`:**
    *   Проверьте, что иконка для `TagToAdd` еще не отображается (проверка по карте `DisplayedStatusTags`).
    *   **(Получение Данных):** Определите иконку, длительность (если нужно), стаки (если нужно) для этого `TagToAdd`. Это можно сделать через `DataTable` (Тег -> Иконка, Описание), или через поиск активного GE с этим тегом и чтение его данных. *Это самая сложная часть.*
        *   *Простой вариант:* Захардкодить или использовать `Select` ноду на основе `TagToAdd` для выбора иконки.
        *   *Продвинутый вариант:* `OwnerASC` -> `Get Active Gameplay Effects`: Отфильтруйте эффекты, которые предоставляют `TagToAdd`. Из найденного эффекта получите `Duration Remaining` и `Stack Count`. Найдите `DataTable` с информацией об иконках по тегу.
    *   `Create Widget`: Класс = `WBP_HUD_StatusEffectIcon`.
    *   Вызовите `SetStatusInfo` на созданном виджете, передав тег, иконку и др. данные.
    *   `StatusIconContainer` -> `Add Child`.
    *   Добавьте виджет в карту `DisplayedStatusTags` (Key = `TagToAdd`, Value = ссылка на виджет).
7.  **Функция `RemoveStatusIcon (TagToRemove)`:**
    *   Найдите виджет в карте `DisplayedStatusTags` по `TagToRemove`.
    *   Если найден:
        *   `StatusIconContainer` -> `Remove Child`.
        *   Удалите запись из `DisplayedStatusTags`.
8.  **В `WBP_HUD_Main`:** Создайте `WBP_HUD_StatusEffectList`, вызовите `Initialize`, передав `OwnerASC`.

**Шаг 19.5: Компиляция и Тестирование**

1.  **Пересоберите C++ проект**, если вносили изменения.
2.  **Запустите игру** (рекомендуется мультиплеер).
3.  **Тестирование:**
    *   **Атрибуты:** Получите урон, потратьте энергию. Проверьте, обновляются ли полосы здоровья/энергии корректно и плавно на клиенте и сервере.
    *   **Способности:**
        *   Экипируйте модули в разные слоты. Отображаются ли правильные иконки?
        *   Используйте способности. Отображается ли анимация/текст кулдауна? Уменьшается ли он со временем? Исчезает ли он по окончании?
        *   Если есть способности с зарядами, отображается ли их количество? Уменьшается/увеличивается ли оно при использовании/восстановлении?
    *   **Статусы:**
        *   Примените к себе или другому игроку статус-эффекты (горение, заморозка, замедление). Появляются ли соответствующие иконки в списке статусов?
        *   Исчезают ли иконки, когда эффект заканчивается?
    *   **Смена Предметов:** Снимите модуль способности. Исчезает ли его иконка с HUD? Экипируйте другой модуль в тот же слот. Появляется ли новая иконка с правильной информацией?

Вы успешно интегрировали основные элементы пользовательского интерфейса (HUD) с Gameplay Ability System. Полосы атрибутов теперь динамически обновляются с использованием эффективных делегатов. Иконки способностей отображают информацию о кулдаунах и зарядах, реагируя на изменения в ASC (через проверку спецификаций и отслеживание тегов кулдауна).
