**Интеграция GAS**.

**Задача:** Подключить модуль Gameplay Ability System к вашему проекту Unreal Engine.

**Зачем:** Это самый первый и абсолютно необходимый шаг. Без подключения модуля ваш проект просто не будет "знать" о существовании классов и функций GAS (таких как `UAbilitySystemComponent`, `UGameplayAbility`, `UGameplayEffect` и т.д.), и вы не сможете их использовать ни в C++, ни в Blueprint. Это как добавить нужную библиотеку или фреймворк в программный проект.

**GAS Компоненты (в контексте этого шага):** Модули движка `GameplayAbilities`, `GameplayTags`, `GameplayTasks`.

---

**Подробная Реализация Шага:**

Процесс интеграции включает в себя модификацию конфигурационного файла сборки вашего проекта.

1.  **Найдите Файл Сборки Проекта (`Build.cs`):**
    *   Перейдите в папку вашего проекта Unreal Engine.
    *   Откройте папку `Source`.
    *   Внутри папки `Source` найдите папку с именем вашего проекта (например, `FrameForge`).
    *   В этой папке вы найдете файл C# с именем `[ИмяВашегоПроекта].Build.cs` (например, `FrameForge.Build.cs`).

2.  **Откройте Файл `[ИмяВашегоПроекта].Build.cs`:**
    *   Откройте этот файл в вашем редакторе кода (например, Visual Studio, Rider, VS Code).

3.  **Найдите Списки Зависимостей:**
    *   Внутри класса `[ИмяВашегоПроекта]` (который наследуется от `ModuleRules`), найдите строки, которые добавляют модули в списки зависимостей. Обычно это выглядит так:
        ```csharp
        PublicDependencyModuleNames.AddRange(new string[] { "Core", "CoreUObject", "Engine", "InputCore", /* ... другие модули ... */ });

        PrivateDependencyModuleNames.AddRange(new string[] { /* ... другие модули ... */ });
        ```
    *   **`PublicDependencyModuleNames`:** Модули, перечисленные здесь, делают свои *публичные* заголовочные файлы (`Public` папка модуля) доступными для вашего проекта и для других модулей, которые могут зависеть от вашего проекта.
    *   **`PrivateDependencyModuleNames`:** Модули здесь делают доступными только свои *приватные* заголовочные файлы (`Private` папка) и исходный код для *вашего* проекта, но не для других модулей, зависящих от вашего.

4.  **Добавьте Модули GAS:**
    *   Для работы с GAS вам необходимо добавить как минимум три модуля: `GameplayAbilities`, `GameplayTags` и `GameplayTasks`.
    *   **Рекомендуется добавлять их в `PublicDependencyModuleNames`**, так как вы, скорее всего, будете включать их заголовочные файлы (`.h`) напрямую в коде вашего проекта (например, `#include "AbilitySystemComponent.h"`).
    *   **Модифицируйте** строку `PublicDependencyModuleNames.AddRange(...)`, добавив туда названия нужных модулей:

        ```csharp
        // Внутри вашего файла [ИмяВашегоПроекта].Build.cs

        using UnrealBuildTool;

        public class FrameForge : ModuleRules // Замените FrameForge на имя вашего проекта
        {
            public FrameForge(ReadOnlyTargetRules Target) : base(Target) // Замените FrameForge
            {
                PCHUsage = PCHUsageMode.UseExplicitOrSharedPCHs;

                PublicDependencyModuleNames.AddRange(new string[] {
                    "Core",
                    "CoreUObject",
                    "Engine",
                    "InputCore",
                    "EnhancedInput", // Вероятно, он вам тоже понадобится для привязки ввода к GAS
                    // --- ДОБАВЬТЕ ЭТИ СТРОКИ ---
                    "GameplayAbilities",
                    "GameplayTags",
                    "GameplayTasks"
                    // --- КОНЕЦ ДОБАВЛЕННЫХ СТРОК ---
                });

                PrivateDependencyModuleNames.AddRange(new string[] {
                    // Возможно, здесь уже есть какие-то модули
                });

                // Uncomment if you are using Slate UI
                // PrivateDependencyModuleNames.AddRange(new string[] { "Slate", "SlateCore" });

                // Uncomment if you are using online features
                // PrivateDependencyModuleNames.Add("OnlineSubsystem");

                // To include OnlineSubsystemSteam, add it to the plugins section in your uproject file with the Enabled attribute set to true
            }
        }
        ```
    *   **Важно:** Убедитесь, что названия модулей написаны точно (`"GameplayAbilities"`, `"GameplayTags"`, `"GameplayTasks"`), включая регистр букв, и разделены запятыми внутри `new string[] { ... }`.

5.  **Сохраните Файл `Build.cs`.**

6.  **Обновите Проектные Файлы Visual Studio / Rider:**
    *   Закройте Visual Studio / Rider (если он был открыт).
    *   Найдите файл вашего проекта с расширением `.uproject` в корневой папке проекта.
    *   Кликните по нему правой кнопкой мыши.
    *   В контекстном меню выберите опцию `Generate Visual Studio project files` (или аналогичную для Rider, если она есть; часто Rider подхватывает изменения автоматически при открытии, но генерация через `.uproject` - самый надежный способ).
    *   Этот процесс перегенерирует файлы решения (`.sln`) и проекта (`.vcxproj`), чтобы ваша IDE "узнала" о новых зависимостях.

7.  **Пересоберите (Rebuild) Проект:**
    *   Откройте ваше решение (`.sln`) в Visual Studio / Rider.
    *   Выполните полную пересборку проекта (Build -> Rebuild Solution в Visual Studio, или аналогичная команда в Rider). Это необходимо, чтобы скомпилировать проект с учетом новых модулей.
    *   *Альтернативно:* Если редактор Unreal Engine открыт, вы можете нажать кнопку `Compile` на главной панели инструментов. Редактор попытается выполнить "hot reload", но после добавления модулей часто требуется перезапуск редактора и полная пересборка из IDE. **Надежнее всего пересобрать из IDE.**

**Проверка Успешности:**

*   **Компиляция:** Если проект успешно скомпилировался без ошибок после добавления модулей и пересборки, это хороший знак.
*   **Доступность Классов:** Попробуйте в любом C++ файле вашего проекта (например, в `.h` файле вашего базового персонажа) написать `#include "AbilitySystemComponent.h"`. Если автодополнение работает и компиляция проходит, значит, модуль `GameplayAbilities` подключен успешно.
*   **Доступность в Blueprint:** После перезапуска редактора попробуйте создать новый Blueprint. В списке родительских классов (Parent Class) вы теперь должны иметь возможность найти классы из GAS, например, `GameplayAbility` или `GameplayEffectExecutionCalculation`.

**Возможные Проблемы на Этом Этапе:**

*   **Опечатки:** Дважды проверьте написание имен модулей в `Build.cs`.
*   **Не обновлены файлы проекта:** Если вы забыли выполнить `Generate Visual Studio project files`, IDE может не видеть новые зависимости, и компиляция будет падать с ошибками "Cannot open include file".
*   **Проблемы с компиляцией:** Если возникают ошибки компиляции, внимательно прочитайте лог. Возможно, проблема не в подключении модулей, а в другом коде или конфликтах.

**Итог Шага:**

После выполнения этих действий ваш проект Unreal Engine будет успешно интегрирован с Gameplay Ability System. Вы подготовили почву для создания компонентов GAS, атрибутов, способностей и эффектов на следующих этапах вашего roadmap. Вы не увидите никаких *видимых* изменений в игре на этом этапе, но ваш проект теперь обладает необходимыми инструментами для реализации продвинутых механик персонажа.
