**Реализация Пассивных Компонентов** с использованием Gameplay Effects.

**Задача:** Создать `GameplayEffect` (GE) для каждого пассивного компонента из GDD (Титановая Обшивка, Сервоприводы "Рывок", Модуль Точного Прицеливания и т.д.). Настроить эти GE так, чтобы они модифицировали атрибуты персонажа (например, добавляли здоровье, умножали скорость) или предоставляли геймплей-теги, пока предмет экипирован. Убедиться, что они имеют бесконечную длительность и корректно удаляются при снятии предмета с использованием `ItemSourceTag`.

**Зачем:** Это основной механизм для реализации пассивных бонусов от предметов в *Frame Forge*. Игроки должны чувствовать изменение характеристик своего Шасси при экипировке этих компонентов.

**GAS Компоненты и Механизмы UE:** `UGameplayEffect`, `FGameplayModifierInfo` (внутри GE), `DurationPolicy`, `Modifiers` (Attribute, Modifier Op, Magnitude), `GrantedTags`, `ScalableFloat`, `ComponentPassiveItemData` (Data Asset), `ChassisSlotManagerComponent::ApplyPassiveEffectToOwner`, `ChassisSlotManagerComponent::RemovePassiveEffectFromOwner`.

---

**Подробная Реализация Шага:**

**Шаг 10.1: Создание Ассетов `GameplayEffect` (в Редакторе)**

Для каждого пассивного компонента, который дает статы или теги, нам нужен отдельный ассет `GameplayEffect`.

1.  **Откройте Unreal Editor**.
2.  Перейдите в Content Browser, в папку, где хранятся эффекты компонентов (например, `Content/Features/Items/GAS/GameplayEffects/Components/`).
3.  **Кликните правой кнопкой мыши -> Blueprint Class**.
4.  В окне "Pick Parent Class" разверните "All Classes" и найдите `GameplayEffect`. Выберите его.
5.  **Назовите** ассет в соответствии с компонентом, например:
    *   `GE_Component_TitaniumPlating_Stats`
    *   `GE_Component_BurstServos_Stats`
    *   `GE_Component_TargetingModule_Stats`
    *   `GE_Component_EvasionPredictor_Tag` (Если компонент дает тег, а не стат)
    *   `GE_Component_SelfSealGel_Regen` (Для регенерации может потребоваться периодический эффект)
6.  **Повторите** для всех пассивных компонентов из вашего GDD.

**Шаг 10.2: Конфигурация Каждого `GameplayEffect`**

Теперь настроим каждый созданный GE.

1.  **Откройте ассет GE** (например, `GE_Component_TitaniumPlating_Stats`).
2.  **Настройте Основные Свойства:**
    *   **Duration Policy:** Установите `Infinite`. Эффект должен действовать постоянно, пока активен (т.е., пока предмет экипирован).
3.  **Настройте Модификаторы (`Modifiers`):**
    *   Это список изменений атрибутов, которые применяет этот GE. Нажмите `+` рядом с `Modifiers`, чтобы добавить новый.
    *   **Пример для `GE_Component_TitaniumPlating_Stats`:**
        *   **Модификатор 0:**
            *   **Attribute:** `BaseAttributeSet.MaxHealth` (Выберите атрибут максимального здоровья).
            *   **Modifier Op:** `Add` (Мы добавляем плоское значение к базовому MaxHealth).
            *   **Magnitude Calculation Type:** `Scalable Float`.
            *   **Magnitude (Scalable Float):** Нажмите на стрелку, чтобы развернуть. В поле `Value` введите бонус к здоровью (например, `50.0`).
        *   *(Опционально)* Можно добавить второй модификатор, чтобы сразу *увеличить* текущее здоровье на ту же величину (если это требуется дизайном, иначе здоровье зажмется в `PostAttributeBaseChange`):
            *   **Модификатор 1:**
                *   **Attribute:** `BaseAttributeSet.Health`
                *   **Modifier Op:** `Add`
                *   **Magnitude Calculation Type:** `Scalable Float`
                *   **Magnitude (Scalable Float):** `Value` = `50.0`
    *   **Пример для `GE_Component_BurstServos_Stats`:**
        *   **Модификатор 0:**
            *   **Attribute:** `BaseAttributeSet.MovementSpeed` (Выберите атрибут скорости).
            *   **Modifier Op:** `Multiply` (Мы умножаем базовую скорость). *Важно: Операция Multiply в GAS обычно умножает *базовое* значение атрибута, а не текущее.* Для сложения процентных бонусов часто используют `Add` с другим атрибутом или Execution Calculation. Но для простоты начнем с `Multiply`.
            *   **Magnitude Calculation Type:** `Scalable Float`.
            *   **Magnitude (Scalable Float):** `Value` = `0.1` (Это означает +10% к базовой скорости. 1.0 = 100%, 0.1 = 10%).
    *   **Пример для `GE_Component_TargetingModule_Stats`:**
        *   **Модификатор 0:**
            *   **Attribute:** `BaseAttributeSet.CritChance` (Выберите атрибут шанса крита).
            *   **Modifier Op:** `Add` (Добавляем плоский шанс, например, 0.05 для +5%).
            *   **Magnitude Calculation Type:** `Scalable Float`.
            *   **Magnitude (Scalable Float):** `Value` = `0.05`.
    *   **Пример для `GE_Component_SelfSealGel_Regen` (Регенерация):**
        *   **Duration Policy:** `Infinite`.
        *   **Period:** Установите интервал регенерации (например, `1.0` секунда). Установите `Execute Periodic Effect On Application` = `false` (чтобы не лечить сразу).
        *   **Modifiers:**
            *   **Модификатор 0:**
                *   **Attribute:** `BaseAttributeSet.Health` (Лечим текущее здоровье).
                *   **Modifier Op:** `Add`.
                *   **Magnitude Calculation Type:** `Scalable Float`.
                *   **Magnitude (Scalable Float):** `Value` = `2.0` (например, лечить по 2 HP в секунду).
        *   **Requirements:** Добавьте `Application Tag Requirements`. Укажите, что эффект должен применяться только если у цели *нет* тега `State.Combat` (или аналогичного), чтобы регенерация работала только вне боя (если это требуется дизайном).
            *   `Must Have Tags`: Пусто.
            *   `Must Not Have Tags`: Добавьте тег `State.Combat`.
4.  **Настройте Предоставляемые Теги (`Granted Tags`):**
    *   Используйте это, если компонент должен просто дать владельцу определенный тег, пока активен.
    *   **Пример для `GE_Component_EvasionPredictor_Tag`:**
        *   **Duration Policy:** `Infinite`.
        *   **Modifiers:** Оставьте пустым.
        *   **Granted Tags:** Нажмите `+` рядом с `Granted Tags`. В поле `Added` выберите или создайте тег, который будет сигнализировать о наличии этого пассивного эффекта, например, `Passive.CanEvade`.
5.  **Настройте Теги Ассета (`Asset Tags`):**
    *   Добавьте теги для организации и поиска, например:
        *   `Component.Passive.Stats`
        *   `Component.Passive.Health`
        *   `Component.Passive.Movement`
        *   `Component.Passive.TagGrant`
6.  **Настройте Стэкинг (`Stacking`):**
    *   По умолчанию, для эффектов с `Infinite` длительностью, если применяется *точно такой же* GE (тот же класс), он обычно просто обновляет контекст.
    *   **Важно:** Наша система с `ItemSourceTag`, добавляемым в `DynamicGrantedTags` при применении эффекта в `ApplyPassiveEffectToOwner`, делает каждый экземпляр эффекта уникальным для системы стекинга. Это означает, что если игрок каким-то образом экипирует два "Титановых Обшивки" (каждая со своим `ItemSourceTag`), оба соответствующих `GE_Component_TitaniumPlating_Stats` будут активны одновременно, и их модификаторы `Add MaxHealth` будут суммироваться. Это желаемое поведение для независимых пассивных бонусов.
    *   Поэтому специфические настройки стекинга внутри GE нам сейчас не требуются.
7.  **Скомпилируйте и Сохраните** каждый ассет GE.

**Шаг 10.3: Создание / Обновление Ассетов `ComponentPassiveItemData`**

Убедитесь, что для каждого пассивного компонента существует соответствующий Data Asset (`DA_Component_...`) и он правильно настроен.

1.  Перейдите в `Content/Features/Items/Data/Components/` (или где вы их храните).
2.  **Создайте** (ПКМ -> Miscellaneous -> Data Asset -> родитель `ComponentPassiveItemData`) или **откройте** существующий Data Asset (например, `DA_Component_TitaniumPlating`).
3.  **Заполните / Проверьте Свойства:**
    *   **Compatible Slot Type:** Установите `Component`.
    *   **Item Source Tag:** **КРИТИЧЕСКИ ВАЖНО!** Убедитесь, что здесь назначен **уникальный** геймплей-тег для *этого конкретного типа предмета*. Например:
        *   `Item.Source.Component.TitaniumPlating`
        *   `Item.Source.Component.BurstServos`
        *   `Item.Source.Component.TargetingModule`
        *   `Item.Source.Component.EvasionPredictor`
        *   Создайте эти теги в `Project Settings -> Gameplay Tags`.
    *   **Display Name:** "Титановая Обшивка" (или другое).
    *   **Item Icon:** Назначьте иконку.
    *   **Granted Effect Class:** Выберите соответствующий `GameplayEffect`, который вы создали и настроили на шаге 10.2 (например, для `DA_Component_TitaniumPlating` выберите `GE_Component_TitaniumPlating_Stats`).
    *   **Attachment...:** Настройте визуальный аттачмент, если нужно.
4.  **Повторите** для всех пассивных компонентов.
5.  **Сохраните** все Data Assets.

**Шаг 10.4: Проверка Логики `ChassisSlotManagerComponent`**

Мы уже реализовали основную логику в шаге 9, но давайте еще раз посмотрим на ключевые моменты в `ChassisSlotManagerComponent.cpp`, связанные с пассивными эффектами:

*   **`EquipItem` вызывает `ApplyPassiveEffectToOwner`** для `ComponentPassiveItemData`.
*   **`ApplyPassiveEffectToOwner`:**
    *   Получает `EffectClass` и `ItemSourceTag` из `PassiveData`.
    *   Проверяет их валидность.
    *   Создает `SpecHandle`.
    *   **Добавляет `ItemSourceTag` в `SpecHandle.Data->DynamicGrantedTags`**. <--- Это ключ к уникальности экземпляров!
    *   Применяет спецификацию (`ApplyGameplayEffectSpecToSelf`).
*   **`UnequipItem` вызывает `RemovePassiveEffectFromOwner`** для слотов, где был пассивный эффект (проверяя по `ItemSourceTag`).
*   **`RemovePassiveEffectFromOwner`:**
    *   Получает `ItemSourceTag` из `FEquippedSlotInfo`.
    *   Создает `FGameplayTagContainer` с этим тегом.
    *   Вызывает `ASC->RemoveActiveGameplayEffectsWithGrantedTags(TagToRemoveContainer)`. <--- Это ключ к удалению нужного экземпляра.

*Проверка:* Код соответствует описанию. Логика добавления и удаления пассивных эффектов по тегу источника реализована.

**Шаг 10.5: Компиляция и Тестирование**

1.  **Пересоберите C++ проект**, если вносили изменения в код (хотя на этом шаге мы в основном работали в редакторе).
2.  **Настройте `BP_ItemPickup`** в мире, назначив ему один из ваших `DA_Component_...` (например, `DA_Component_BurstServos`).
3.  **Запустите игру** (рекомендуется в режиме 2 игроков, Play As Client, чтобы проверить репликацию).
4.  **Проверка До Экипировки:**
    *   Используйте `showdebug abilitysystem`. Запомните текущие значения атрибутов (например, `MovementSpeed`). Проверьте секцию `Active Gameplay Effects` - она должна быть пустой или содержать только начальные эффекты Шасси.
5.  **Экипировка:**
    *   Подберите предмет (например, Сервоприводы).
    *   Снова используйте `showdebug abilitysystem`.
    *   **Проверьте Атрибуты:** Изменилось ли значение `MovementSpeed`? Оно должно увеличиться (или измениться в соответствии с вашей логикой `Multiply`). Проверьте и на сервере, и на клиенте.
    *   **Проверьте Активные Эффекты:** Найдите секцию `Active Gameplay Effects`. Должен появиться ваш эффект (например, `GE_Component_BurstServos_Stats`). Разверните его информацию.
    *   **Проверьте Теги Эффекта:** В информации об активном эффекте найдите секцию `Granted Tags` или `Dynamic Tags`. Вы должны увидеть там ваш **`Item.Source.Component.BurstServos`** тег. Это подтверждает, что тег источника был правильно добавлен при применении.
6.  **Экипировка Второго (если возможно):** Если ваш дизайн позволяет экипировать два одинаковых компонента (например, два слота Компонентов), попробуйте подобрать второй. Проверьте, что атрибут изменился *еще раз* (бонусы сложились), и что в `Active Gameplay Effects` теперь *два* экземпляра `GE_Component_BurstServos_Stats`, каждый со своим (одинаковым в данном случае, но это не важно для системы) `Item.Source.Component.BurstServos` тегом в `DynamicGrantedTags`.
7.  **Снятие (если реализовали Unequip):**
    *   Выполните действие снятия предмета (например, через UI инвентаря или команду).
    *   Используйте `showdebug abilitysystem`.
    *   **Проверьте Атрибуты:** Вернулось ли значение `MovementSpeed` к исходному (или к значению с одним компонентом, если снимали второй)?
    *   **Проверьте Активные Эффекты:** Исчез ли соответствующий `GE_Component_BurstServos_Stats` из списка активных эффектов? Если было два, должен остаться один.
8.  **Протестируйте** разные компоненты (на здоровье, шанс крита, дающие теги), чтобы убедиться, что их эффекты применяются и удаляются корректно.

**Итог Шага:**

Вы успешно реализовали систему пассивных компонентов *Frame Forge*. Вы создали и настроили `GameplayEffect` ассеты для представления бонусов от этих компонентов, установив им бесконечную длительность и соответствующие модификаторы атрибутов или предоставляемые теги. Вы связали эти GE с Data Assets предметов (`ComponentPassiveItemData`), назначив уникальные `ItemSourceTag` для каждого типа предмета. Ваша система экипировки (`ChassisSlotManagerComponent`) теперь корректно применяет эти эффекты при экипировке (добавляя тег источника к экземпляру эффекта) и надежно удаляет их при снятии (используя тег источника). Игроки теперь могут находить и экипировать пассивные компоненты, ощущая их влияние на характеристики своего Шасси.
