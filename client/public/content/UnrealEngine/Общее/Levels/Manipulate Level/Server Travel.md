Отлично, давайте подробно и по шагам разберем `Seamless Travel` в Unreal Engine 5. Это мощная система, специально разработанная для **многопользовательских игр**, чтобы переходить между уровнями (картами), не разрывая соединение игроков с сервером и сохраняя определенные данные.

**Зачем нужен Seamless Travel?**

Стандартная функция `Open Level` в многопользовательской игре работает так:
1.  Сервер загружает новую карту.
2.  Все клиенты **отключаются** от сервера.
3.  Клиенты самостоятельно загружают новую карту.
4.  Клиенты **заново подключаются** к серверу.

Это приводит к разрыву игрового процесса, потере временных данных и необходимости заново устанавливать соединение. `Seamless Travel` решает эту проблему.

**Как работает Seamless Travel (высокоуровнево)?**

1.  **Инициация:** Сервер решает перейти на новую карту и вызывает специальную функцию (`ServerTravel`).
2.  **Переходная карта (Transition Map):** Сервер и все подключенные клиенты сначала загружают **маленькую, временную карту-заглушку** (Transition Map). Это происходит *без разрыва соединения*.
3.  **Загрузка целевой карты:** Находясь на переходной карте, сервер начинает загружать **основную целевую карту** в фоновом режиме. Клиенты ждут команды сервера.
4.  **Финальный переход:** Как только сервер загрузил целевую карту, он дает команду клиентам также загрузить ее. Опять же, это происходит без разрыва соединения.
5.  **Продолжение игры:** Все оказываются на новой карте, сохранив свои `PlayerController`, `PlayerState` и другие необходимые данные.

**Поэтапная реализация и настройка:**

**Шаг 1: Включение Seamless Travel в GameMode**

*   Откройте ваш основной `GameMode` Blueprint (или C++ класс), который используется в вашей игре.
*   Перейдите в `Class Defaults`.
*   Найдите секцию `Travel` (или используйте поиск).
*   Установите галочку **`Use Seamless Travel`**.

**Шаг 2: Настройка Переходной Карты (Transition Map)**

*   Seamless Travel требует наличия переходной карты. Это должен быть очень легкий, почти пустой уровень.
*   Создайте новый уровень (`File -> New Level -> Empty Level` или `Basic`). Сохраните его (например, `TransitionMap`).
*   В `Project Settings -> Project -> Maps & Modes`:
    *   Найдите секцию `Transition Map`.
    *   Укажите созданный вами `TransitionMap` в поле `Transition Map`.
    *   **(Опционально) Loading Screen Map:** Можно указать карту, которая будет показываться *во время* загрузки. Часто это та же Transition Map или еще более простая карта с виджетом загрузки. Если оставить пустым, будет использоваться Transition Map.

**Шаг 3: Инициирование Перехода (Сервер)**

*   Переход **всегда** инициируется сервером.
*   В логике вашего `GameMode` (или другого серверного объекта), когда нужно перейти на следующий уровень (например, после входа в портал всеми игроками):
    *   Вызовите функцию **`Server Travel`**.
    *   В поле `Map Name` укажите имя целевой карты (например, `Level2_Map`).
    *   **Важно:** Убедитесь, что этот вызов происходит только на сервере (используйте проверку `Has Authority` или `Is Server`).

    ```blueprint
    # Пример в Blueprint (в GameMode)
    if (Has Authority())
    {
        Server Travel("Level2_Map", false, false); // Map Name, Absolute?, Should Skip GameNotify?
    }
    ```

**Шаг 4: Реализация Загрузочного Экрана (Клиент)**

Seamless Travel сам по себе *не показывает* красивый загрузочный экран. Он просто переносит игроков. Вам нужно вручную реализовать отображение UI во время этого процесса.

1.  **Создайте виджет загрузки:** `WBP_LoadingScreen` (как обсуждалось ранее).
2.  **Когда показывать экран:**
    *   **Перед вызовом `ServerTravel`:** Сервер может отправить RPC (Remote Procedure Call) всем клиентам, чтобы они показали свой виджет загрузки *незамедлительно перед* тем, как сервер вызовет `ServerTravel`. Это самый простой способ.
    *   **На переходной карте:** В `BeginPlay` `PlayerController` или `GameMode` на *клиенте* в `TransitionMap` можно показать виджет загрузки. Это гарантирует, что он появится во время фазы ожидания.
3.  **Когда скрывать экран:**
    *   В `BeginPlay` `PlayerController` (или другом подходящем классе) на *клиенте* в **целевой карте** (например, `Level2_Map`) скройте виджет загрузки. Это произойдет после того, как целевая карта будет полностью загружена и игра на ней начнется.
4.  **Использование GameInstance:** Так как `GameInstance` сохраняется между переходами уровней (даже с Seamless Travel), он является хорошим местом для хранения ссылки на виджет загрузки или для реализации функций `ShowLoadingScreen`/`HideLoadingScreen`, которые затем вызываются из `PlayerController` или `GameMode` на клиенте.

**Пример логики показа/скрытия (через PlayerController клиента):**

*   **Сервер (в GameMode, перед Server Travel):**
    *   Перебрать всех `PlayerController`.
    *   Вызвать кастомный RPC `Client_ShowLoadingScreen` на каждом `PlayerController`.
    *   Вызвать `ServerTravel("NextLevel")`.

*   **Клиент (в PlayerController):**
    *   Реализовать событие `Client_ShowLoadingScreen` (установить `Run on Owning Client`):
        *   Получить `GameInstance`.
        *   Вызвать `GameInstance.ShowLoadingScreen()`.
    *   В событии `BeginPlay` (когда загрузится *новая* целевая карта):
        *   Получить `GameInstance`.
        *   Вызвать `GameInstance.HideLoadingScreen()`.

**Шаг 5: Сохранение Состояния Игроков и Актеров**

Что сохраняется автоматически при Seamless Travel:

*   **Соединение:** Клиенты остаются подключенными.
*   **`GameMode`:** Экземпляр `GameMode` на сервере уничтожается и создается новый для целевого уровня.
*   **`GameState`:** Экземпляр сохраняется и переносится на новый уровень.
*   **`PlayerController`:** Экземпляры сохраняются для каждого подключенного игрока.
*   **`PlayerState`:** Экземпляры сохраняются для каждого `PlayerController`.
*   **HUD:** Сохраняется (если настроено).

Что **не** сохраняется автоматически:

*   **`Pawn` (Персонаж):** По умолчанию, `Pawn`, которым управлял `PlayerController`, уничтожается при переходе. Новый `Pawn` обычно создается на новом уровне стандартным механизмом спавна `GameMode`.
*   **Большинство других Актеров:** Все актеры на старом уровне уничтожаются (кроме тех, что находятся в Persistent Level, если он используется, но это другая концепция).

**Как сохранить данные персонажа или других актеров:**

1.  **Сохранение в `PlayerState`:** Перед началом перехода (`ServerTravel`), скопируйте важные данные из вашего `Pawn` (здоровье, инвентарь и т.д.) в соответствующие переменные в `PlayerState` этого игрока. `PlayerState` реплицируется и сохраняется при переходе. На новом уровне, когда будет создан новый `Pawn`, скопируйте данные обратно из `PlayerState` в новый `Pawn`. Это самый распространенный и рекомендуемый способ для данных, специфичных для игрока.
2.  **Сохранение в `GameState`:** Для данных, общих для всех игроков (например, состояние мира, номер волны), используйте `GameState`.
3.  **Сохранение в `GameInstance`:** Можно временно хранить данные в `GameInstance` на сервере, но это менее надежно для сетевой игры и не реплицируется автоматически. Лучше использовать `PlayerState` и `GameState`.
4.  **Перенос специфических Актеров (`GetSeamlessTravelActorList`):** Для более сложного переноса конкретных актеров (кроме стандартных сохраняемых), вы можете переопределить функцию `GetSeamlessTravelActorList` в вашем `GameMode`. Эта функция вызывается на сервере перед переходом. Вы должны добавить в список (`InOutActorList`) актеров, которые вы хотите сохранить и перенести на новую карту. Движок попытается сохранить их состояние. Это более сложный метод и используется реже.

**Важные функции и события (C++ / Blueprint):**

*   `AGameModeBase::bUseSeamlessTravel` (Свойство)
*   `UGameMapsSettings::TransitionMap` (Настройка проекта)
*   `AGameModeBase::ServerTravel(MapName, bAbsolute, bShouldNotify)` (Функция, сервер)
*   `UWorld::SeamlessTravel(URL, bAbsolute)` (Функция, внутренняя, вызывается `ServerTravel`)
*   `AGameModeBase::GetSeamlessTravelActorList(bToTransition, InOutActorList)` (Функция для переопределения)
*   `APlayerController::ClientTravel(URL, TravelType, bSeamless, MapPackageGuid)` (RPC, вызывается сервером на клиентах для инициации перехода)
*   `UGameInstance::GetGameModeDelegate().AddOnSeamlessTravelDuringLoadEvent(Handle)` (C++ делегат, срабатывает на клиенте во время загрузки)
*   `UGameInstance::GetGameModeDelegate().AddOnSeamlessTravelEndEvent(Handle)` (C++ делегат, срабатывает на клиенте после загрузки)
