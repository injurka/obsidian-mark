**Реализация Модулей Активных Способностей**.

**Задача:** Для каждого активного модуля (Репульсор, Фазовый Сдвиг и т.д.) создать свою `GameplayAbility` (GA). Каждая GA будет привязана к своему `EAbilityInputID`. GA должна содержать логику способности, стоимость (Cost GE), кулдаун (Cooldown GE). Способность выдается при экипировке модуля через `ChassisSlotManagerComponent`.

**Зачем:** Это позволяет игроку динамически получать и использовать активные умения, находя соответствующие модули, что является ядром боевой системы *Frame Forge*.

**GAS Компоненты и Механизмы UE:** `UGameplayAbility` (наследуемся от `FrameForgeGameplayAbility`), `GameplayEffect` (для Cost и Cooldown), `AbilityTask_PlayMontageAndWait`, `AbilityTask_WaitDelay`, `AbilityTask_WaitTargetData`, `CommitAbility`, `EndAbility`, `ApplyGameplayEffectToOwner/Target`, `SpawnActor`, `LineTrace`, `SphereOverlap`, `ModuleAbilityItemData`, `ChassisSlotManagerComponent::GrantAbilityToOwner`, `ChassisSlotManagerComponent::ClearAbilityFromOwner`.

**Подробная Реализация Шага:**

**Шаг 11.1: Создание Gameplay Effects для Кулдаунов (Cooldown GE)**

Кулдауны реализуются через GE, которые применяют специальный тег на время действия кулдауна.

1.  **Откройте Unreal Editor**.
2.  Перейдите в папку для эффектов способностей (например, `Content/Features/Items/GAS/GameplayEffects/Modules/Cooldowns/`).
3.  **Создайте GE для каждой активной способности**:
    *   ПКМ -> Blueprint Class -> Родитель: `GameplayEffect`.
    *   Имя: `GE_Cooldown_KineticRepulsor`.
    *   Имя: `GE_Cooldown_PhaseBlink`.
    *   Имя: `GE_Cooldown_ResonanceMine`.
    *   ... и так далее для всех активных модулей.
4.  **Настройте каждый Cooldown GE** (например, `GE_Cooldown_KineticRepulsor`):
    *   **Duration Policy:** `Has Duration`.
    *   **Duration Magnitude:** Установите `Scalable Float` и введите длительность кулдауна в секундах (например, `5.0` для Репульсора).
    *   **Modifiers:** Оставьте пустым (этот эффект не меняет атрибуты).
    *   **Granted Tags:** Самое важное! Нажмите `+` рядом с `Granted Tags`. В поле `Added` создайте и/или выберите **уникальный тег кулдауна** для этой способности. Стандартная практика: `Cooldown.<Category>.<AbilityName>`.
        *   Пример для Репульсора: `Cooldown.Module.KineticRepulsor`.
        *   Пример для Фазового Сдвига: `Cooldown.Module.PhaseBlink`.
        *   Создайте эти теги в `Project Settings -> Gameplay Tags`.
    *   **Asset Tags:** Добавьте тег `Ability.Cooldown` для организации.
5.  **Сохраните** все Cooldown GE.

**Шаг 11.2: Создание Gameplay Effects для Стоимости (Cost GE)**

Стоимость (например, расход энергии) реализуется через GE с мгновенным действием, который вычитает значение из атрибута.

1.  Перейдите в папку для эффектов стоимости (например, `Content/Features/Items/GAS/GameplayEffects/Modules/Costs/`).
2.  **Создайте GE для каждой активной способности, имеющей стоимость**:
    *   ПКМ -> Blueprint Class -> Родитель: `GameplayEffect`.
    *   Имя: `GE_Cost_KineticRepulsor`.
    *   Имя: `GE_Cost_PhaseBlink`.
    *   ... и так далее.
3.  **Настройте каждый Cost GE** (например, `GE_Cost_KineticRepulsor`):
    *   **Duration Policy:** `Instant`. Стоимость применяется мгновенно.
    *   **Modifiers:** Нажмите `+`.
        *   **Attribute:** `BaseAttributeSet.Energy` (Выберите атрибут Энергии).
        *   **Modifier Op:** `Add` (Мы *добавляем* отрицательное значение, чтобы вычесть).
        *   **Magnitude Calculation Type:** `Scalable Float`.
        *   **Magnitude (Scalable Float):** Введите **отрицательное** значение стоимости (например, `-15.0` для Репульсора, если он стоит 15 энергии).
    *   **Asset Tags:** Добавьте тег `Ability.Cost` для организации.
4.  **Сохраните** все Cost GE.

**Шаг 11.3: Создание Ассетов `GameplayAbility` (Blueprint)**

Теперь создадим сами способности.

1.  Перейдите в папку для способностей модулей (например, `Content/Features/Items/GAS/Abilities/Modules/Ability/` или `/Movement/`).
2.  **Создайте BP для каждой активной способности**, наследуясь от вашего базового класса `FrameForgeGameplayAbility`:
    *   ПКМ -> Blueprint Class -> Родитель: `FrameForgeGameplayAbility`.
    *   Имя: `GA_Module_KineticRepulsor`.
    *   Имя: `GA_Module_PhaseBlink`.
    *   Имя: `GA_Module_ResonanceMine`.
    *   ... и так далее.
3.  **Настройте Class Defaults** для каждой способности (пример для `GA_Module_KineticRepulsor`):
    *   **Ability Tags:** Добавьте тег, идентифицирующий эту способность, например, `Ability.Module.Active.KineticRepulsor`.
    *   **Activation Owned Tags:** Добавьте тег, активный во время действия способности, например, `State.Activating.KineticRepulsor`. Это может использоваться для анимации или блокировки других действий.
    *   **Activation Blocked Tags:** Добавьте теги, которые должны блокировать активацию этой способности:
        *   `State.Dead` (нельзя использовать мертвым)
        *   `State.Stunned` (нельзя использовать оглушенным)
        *   `Cooldown.Module.KineticRepulsor` (нельзя использовать, пока активен тег кулдауна ЭТОЙ ЖЕ способности).
    *   **Cancel Abilities with Tag:** (Опционально) Если активация этой способности должна отменять другие (например, прицеливание), добавьте сюда соответствующие теги.
    *   **Block Abilities with Tag:** (Опционально) Если активация этой способности должна блокировать другие (например, нельзя стрелять во время Репульсора), добавьте сюда теги блокируемых способностей.
    *   **Cooldown Gameplay Effect Class:** Выберите соответствующий Cooldown GE (например, `GE_Cooldown_KineticRepulsor`).
    *   **Cost Gameplay Effect Class:** Выберите соответствующий Cost GE (например, `GE_Cost_KineticRepulsor`). Если у способности нет стоимости, оставьте пустым.

**Шаг 11.4: Реализация Логики Способности (Event Graph)**

Это сердце способности - что она делает при активации.

1.  **Откройте Event Graph** вашей способности (например, `GA_Module_KineticRepulsor`).
2.  Найдите или создайте событие **`Event ActivateAbility`**.
3.  **Критический Шаг: Commit Ability:**
    *   Сразу после `Event ActivateAbility` вызовите ноду `Commit Ability`. Эта нода автоматически проверяет наличие блокирующих тегов, применяет Cost GE и Cooldown GE.
    *   От выхода `Commit Ability` добавьте ноду `Branch`. Условие - возвращаемое значение `Commit Ability` (true - успешно, false - не удалось).
    *   **Если False (Не удалось):** Подключите к ноде `End Ability`. Способность не активируется (не хватило энергии, кулдаун активен и т.д.).
    *   **Если True (Успешно):** Продолжайте реализацию основной логики способности.
4.  **Основная Логика (Пример для `GA_Module_KineticRepulsor`):**
    *   Получите персонажа: `Get Frame Forge Character from Actor Info`.
    *   Получите его местоположение: `Get Actor Location`.
    *   **(Визуал/Звук - Способ 1: Простой)** Вызовите `Spawn Emitter at Location` (выберите эффект взрывной волны) и `Play Sound at Location` (выберите звук репульсора). *Примечание: Использование Gameplay Cues (Шаг 17) - более правильный и гибкий подход.*
    *   Выполните поиск врагов: `Sphere Overlap Actors`.
        *   `Sphere Pos`: Местоположение персонажа.
        *   `Sphere Radius`: Установите радиус действия репульсора (например, 500.0). Сделайте это переменной (`RepulsorRadius`).
        *   `Object Types`: Добавьте `Pawn`.
        *   `Actor Class Filter`: Установите ваш базовый класс врага (`BP_BaseAICharacter` или аналогичный).
        *   `Actors to Ignore`: Добавьте массив, содержащий `Self` (полученный из `Get Frame Forge Character from Actor Info`).
    *   Из `Out Actors` вызовите `For Each Loop`.
    *   Внутри цикла (`Loop Body`):
        *   Получите текущего врага из `Array Element`.
        *   **(Опционально) Проверка линии видимости:** `Line Trace By Channel` от игрока к врагу. Если есть преграда, пропустите этого врага (`Branch`).
        *   Получите компонент движения врага: `Get Movement Component`, затем `Cast To CharacterMovementComponent`.
        *   Если каст успешен:
            *   Рассчитайте вектор отталкивания: `Get Actor Location` (Враг) - `Get Actor Location` (Игрок).
            *   Нормализуйте вектор: `Normalize`.
            *   Вызовите `Launch Character` на враге (из `Array Element`).
            *   `Launch Velocity`: Умножьте нормализованный вектор на силу отталкивания (сделайте переменной, например, `RepulsorStrength` = 1500.0).
            *   `XYOverride`: true. `ZOverride`: true (или false, если хотите сохранить вертикальный импульс).
        *   **(Опционально) Нанесение урона:** Создайте GE для урона репульсора (`GE_Damage_KineticRepulsor`, Instant, Modifier Add Health -5.0). Создайте Spec (`Make Outgoing Spec`) и примените к врагу (`Apply Gameplay Effect Spec to Target`).
    *   После выхода `Completed` из `For Each Loop`:
        *   Вызовите `End Ability`.
5.  **Логика для Других Способностей (Примеры):**
    *   **`GA_Module_PhaseBlink`:**
        *   После `Commit Ability`:
        *   Получите персонажа, его `Controller`.
        *   Получите вектор направления: `Get Control Rotation` -> `Get Forward Vector`.
        *   Рассчитайте точку назначения: `Get Actor Location` + (Forward Vector * BlinkDistance (переменная)).
        *   **(Опционально) Проверка точки назначения:** Сделайте трассировку капсулой (`Capsule Trace By Channel`) в точку назначения, чтобы убедиться, что там нет стен. Если есть - `End Ability` или найдите ближайшую свободную точку.
        *   Вызовите `Teleport To` на персонаже.
        *   **(Визуал/Звук):** Эффекты в точке старта и финиша.
        *   Вызовите `End Ability`.
    *   **`GA_Module_ResonanceMine`:**
        *   После `Commit Ability`:
        *   Получите персонажа, его локацию/направление.
        *   Рассчитайте точку спавна мины перед персонажем.
        *   Используйте `Spawn Actor From Class`, чтобы создать актор мины (`BP_Deployable_ResonanceMine`). Установите владельца (`Instigator`).
        *   **(Визуал/Звук):** Эффект броска.
        *   Вызовите `End Ability`. (Сама мина будет иметь свою логику притягивания/взрыва).
6.  **Скомпилируйте и Сохраните** все ассеты GA.

**Шаг 11.5: Создание / Обновление Ассетов `ModuleAbilityItemData`**

Убедитесь, что для каждого активного модуля существует Data Asset и он правильно настроен.

1.  Перейдите в `Content/Features/Items/Data/Modules/Ability/` (или `/Movement/`).
2.  **Создайте** или **откройте** Data Asset (например, `DA_Module_KineticRepulsor`).
3.  **Заполните / Проверьте Свойства:**
    *   `Compatible Slot Type`: `Ability` (или `Movement`).
    *   `Item Source Tag`: Назначьте **уникальный** тег (например, `Item.Source.Module.Ability.KineticRepulsor`).
    *   `Display Name`, `Item Icon`.
    *   **`Granted Ability Class`:** Выберите соответствующий `GA_Module_...` (например, `GA_Module_KineticRepulsor`).
    *   **`Ability Input ID`:** Выберите `InputID`, к которому должна быть привязана эта способность (например, `Ability1` для Q, `Ability2` для E, `Utility` для Shift, `MovementAbility` для Пробела в воздухе).
    *   `Attachment...`.
4.  **Повторите** для всех активных модулей.
5.  **Сохраните** все Data Assets.

**Шаг 11.6: Проверка Логики `ChassisSlotManagerComponent`**

Перепроверьте `ChassisSlotManagerComponent::GrantAbilityToOwner` и `ClearAbilityFromOwner`.

*   Убедитесь, что `GrantAbilityToOwner` правильно получает `AbilityClass` и `InputID` из `ModuleAbilityItemData` (или других дочерних классов) и передает их при вызове `ASC->GiveAbility()`.
*   Убедитесь, что `ClearAbilityFromOwner` использует `GrantedAbilityHandle`, сохраненный в `FEquippedSlotInfo`, для вызова `ASC->ClearAbility()`.

*Проверка:* Логика, реализованная в шаге 9, должна корректно обрабатывать `ModuleAbilityItemData` и передавать `InputID`.

**Шаг 11.7: Компиляция и Тестирование**

1.  **Пересоберите C++ проект**, если вносили изменения.
2.  **Настройте `BP_ItemPickup`** с одним из ваших `DA_Module_...` (например, `DA_Module_KineticRepulsor`).
3.  **Запустите игру** (рекомендуется мультиплеер).
4.  **Проверка До Экипировки:**
    *   Нажмите кнопку, соответствующую `InputID` модуля (например, Q для `Ability1`). Ничего не должно происходить.
    *   Проверьте `showdebug abilitysystem` - способности модуля не должно быть в списке.
5.  **Экипировка:**
    *   Подберите модуль.
    *   Проверьте `showdebug abilitysystem`:
        *   Появилась ли способность (например, `GA_Module_KineticRepulsor`) в списке `Abilities`?
        *   Указан ли у нее правильный `Input` (например, `5` для `Ability1`)?
6.  **Тестирование Активации:**
    *   Нажмите кнопку способности (например, Q).
    *   **Проверьте Логику:** Сработал ли эффект способности (враги отброшены, персонаж телепортировался)?
    *   **Проверьте Стоимость:** Уменьшилось ли значение атрибута `Energy` на величину, указанную в Cost GE?
    *   **Проверьте Кулдаун:** Сразу после активации проверьте `showdebug abilitysystem`. Появился ли у персонажа соответствующий тег кулдауна (например, `Cooldown.Module.KineticRepulsor`)? Появился ли активный `GE_Cooldown_...` в списке эффектов с таймером? Попробуйте нажать кнопку способности еще раз - она не должна активироваться, пока тег кулдауна активен (`Commit Ability` должен вернуть false). Дождитесь окончания кулдауна (тег исчезнет) и попробуйте снова - способность должна сработать.
7.  **Снятие Модуля:**
    *   Снимите модуль (если реализовали).
    *   Проверьте `showdebug abilitysystem` - способность должна исчезнуть из списка.
    *   Попробуйте нажать кнопку способности - она больше не должна активироваться.
