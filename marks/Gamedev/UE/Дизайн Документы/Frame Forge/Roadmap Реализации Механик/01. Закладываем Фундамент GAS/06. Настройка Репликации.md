Хотя часть этой настройки мы уже затронули при создании компонентов в `PlayerState` и `AttributeSet`, здесь мы сфокусируемся на том, чтобы *убедиться* в правильности всех элементов, отвечающих за синхронизацию GAS в мультиплеере.

**Задача:** Убедиться, что `AbilitySystemComponent` и `AttributeSet`, а также содержащиеся в них данные (активные эффекты, значения атрибутов), корректно настроены для репликации между сервером и клиентами.

**Зачем:** Без правильной репликации клиенты не будут видеть актуальное состояние здоровья, энергии, активных баффов/дебаффов или способностей других игроков (или даже свое собственное, если сервер вносит коррективы). Геймплей в мультиплеере будет рассинхронизирован и неработоспособен.

**GAS Компоненты и Механизмы UE (в контексте этого шага):**
*   `UPROPERTY(Replicated)` / `UPROPERTY(ReplicatedUsing=...)` в `.h` файлах.
*   `AActor::SetReplicates(true)` / `UActorComponent::SetIsReplicated(true)` в `.cpp` файлах (конструкторы).
*   `UAbilitySystemComponent::SetReplicationMode(...)`.
*   Функция `GetLifetimeReplicatedProps(TArray<FLifetimeProperty>& OutLifetimeProps) const override`.
*   Макрос `DOREPLIFETIME_CONDITION_NOTIFY`.
*   `OnRep_` функции для атрибутов.

**Шаг 5.2: Проверка Настроек Репликации `AbilitySystemComponent`**

Теперь проверим настройки *самого* `AbilitySystemComponent` внутри `PlayerState`.

1.  **Откройте `FrameForgePlayerState.cpp`**.
2.  **Найдите конструктор `AFrameForgePlayerState::AFrameForgePlayerState()`**.
3.  **Убедитесь, что `AbilitySystemComponent` создается** (`CreateDefaultSubobject`).
4.  **Убедитесь, что вызывается `SetIsReplicated(true)`** для ASC. Это включает репликацию *внутреннего состояния* компонента (активные эффекты, теги, способности).
5.  **Убедитесь, что установлен режим репликации `SetReplicationMode()`**. Для управляемых игроком персонажей рекомендуется `EGameplayEffectReplicationMode::Mixed`.
    *   `Mixed`: Сервер реплицирует Gameplay Effects. Клиент может предсказывать (predict) применение своих способностей для мгновенной реакции, но сервер имеет авторитет и может корректировать. Подходит для Player Characters.
    *   `Full`: Сервер полностью контролирует и реплицирует все. Клиент ничего не предсказывает. Подходит для AI или объектов мира, управляемых сервером.
    *   `Minimal`: Реплицируется только минимально необходимая информация (например, для косметических целей). Редко используется для основного персонажа.

    ```cpp
    // FrameForge/Source/FrameForge/FrameForgePlayerState.cpp
    AFrameForgePlayerState::AFrameForgePlayerState()
    {
        // --- GAS Components Creation ---
        AbilitySystemComponent = CreateDefaultSubobject<UAbilitySystemComponent>(TEXT("AbilitySystemComponent"));

        // ---> Проверка 1: Включение репликации состояния ASC <---
        AbilitySystemComponent->SetIsReplicated(true);

        // ---> Проверка 2: Установка режима репликации <---
        AbilitySystemComponent->SetReplicationMode(EGameplayEffectReplicationMode::Mixed);

        // Создаем Attribute Set...
        AttributeSet = CreateDefaultSubobject<UBaseAttributeSet>(TEXT("AttributeSet")); // Ваше имя AS

        // Установка OwnerActor...
        AbilitySystemComponent->SetOwnerActor(this);

        // NetUpdateFrequency...
        NetUpdateFrequency = 100.0f;
    }
    ```
    *Проверка:* `SetIsReplicated(true)` и `SetReplicationMode(EGameplayEffectReplicationMode::Mixed)` вызываются для `AbilitySystemComponent`. **Выполнено.**

**Шаг 5.3: Проверка Настроек Репликации `AttributeSet` и Его Атрибутов**

Теперь самая важная часть: репликация самих значений атрибутов.

1.  **Откройте `BaseAttributeSet.h`**.
2.  **Найдите объявления атрибутов** (`Health`, `MaxHealth` и т.д.).
3.  **Убедитесь, что КАЖДЫЙ** атрибут, который должен быть синхронизирован с клиентами (то есть, практически все, кроме мета-атрибутов `Damage` и `Healing`), помечен `UPROPERTY(..., ReplicatedUsing = OnRep_ИмяАтрибута)`.
    *   `ReplicatedUsing` указывает функцию, которая будет вызвана на клиенте при получении обновленного значения. Это необходимо для `GAMEPLAYATTRIBUTE_REPNOTIFY`.

    ```cpp
    // FrameForge/Source/FrameForge/BaseAttributeSet.h
    ...
        // ---> Проверка 3: UPROPERTY с ReplicatedUsing для каждого атрибута <---
        UPROPERTY(BlueprintReadOnly, Category = "Attributes | Health", ReplicatedUsing = OnRep_Health)
        FGameplayAttributeData Health;
        ATTRIBUTE_ACCESSORS(UBaseAttributeSet, Health);

        UPROPERTY(BlueprintReadOnly, Category = "Attributes | Health", ReplicatedUsing = OnRep_MaxHealth)
        FGameplayAttributeData MaxHealth;
        ATTRIBUTE_ACCESSORS(UBaseAttributeSet, MaxHealth);

        // ... и так далее для Energy, MaxEnergy, Armor, MovementSpeed, Stamina, MaxStamina, AttackPower, CritChance, CritDamage ...

        // Мета-атрибуты НЕ требуют ReplicatedUsing
        UPROPERTY(BlueprintReadOnly, Category = "Attributes | Meta")
        FGameplayAttributeData Damage;
        ATTRIBUTE_ACCESSORS(UBaseAttributeSet, Damage);

        UPROPERTY(BlueprintReadOnly, Category = "Attributes | Meta")
        FGameplayAttributeData Healing;
        ATTRIBUTE_ACCESSORS(UBaseAttributeSet, Healing);
    ...
    protected:
        // ---> Проверка 4: Объявление UFUNCTION() для каждой OnRep_ функции <---
        UFUNCTION() virtual void OnRep_Health(const FGameplayAttributeData& OldHealth);
        UFUNCTION() virtual void OnRep_MaxHealth(const FGameplayAttributeData& OldMaxHealth);
        // ... и так далее для всех реплицируемых атрибутов ...
    ...
    ```
    *Проверка:* Все не-мета атрибуты имеют `UPROPERTY(..., ReplicatedUsing = ...)` и соответствующие `UFUNCTION() void OnRep_...`. **Выполнено.**

4.  **Откройте `BaseAttributeSet.cpp`**.
5.  **Найдите функцию `GetLifetimeReplicatedProps`**.
6.  **Убедитесь, что для КАЖДОГО** реплицируемого атрибута (тех, что с `ReplicatedUsing`) есть строка `DOREPLIFETIME_CONDITION_NOTIFY(...)`.
    *   `DOREPLIFETIME_CONDITION_NOTIFY` регистрирует свойство для репликации.
    *   `UBaseAttributeSet`: Класс, которому принадлежит свойство.
    *   `Health`: Имя свойства (атрибута).
    *   `COND_None`: Условие репликации. `None` означает "реплицировать всегда, если значение изменилось на сервере".
    *   `REPNOTIFY_Always`: Условие вызова `OnRep_` функции. `Always` означает "вызывать `OnRep_` на клиенте *всегда*, когда приходит обновление с сервера, даже если значение на клиенте уже было таким же (например, из-за предсказания)". Это важно для корректной работы делегатов изменения атрибутов и UI в GAS.

    ```cpp
    // FrameForge/Source/FrameForge/BaseAttributeSet.cpp
    #include "Net/UnrealNetwork.h" // Убедитесь, что включен

    void UBaseAttributeSet::GetLifetimeReplicatedProps(TArray<FLifetimeProperty>& OutLifetimeProps) const
    {
        Super::GetLifetimeReplicatedProps(OutLifetimeProps);

        // ---> Проверка 5: DOREPLIFETIME_CONDITION_NOTIFY для каждого атрибута <---
        DOREPLIFETIME_CONDITION_NOTIFY(UBaseAttributeSet, Health,       COND_None, REPNOTIFY_Always);
        DOREPLIFETIME_CONDITION_NOTIFY(UBaseAttributeSet, MaxHealth,    COND_None, REPNOTIFY_Always);
        DOREPLIFETIME_CONDITION_NOTIFY(UBaseAttributeSet, Energy,       COND_None, REPNOTIFY_Always);
        DOREPLIFETIME_CONDITION_NOTIFY(UBaseAttributeSet, MaxEnergy,    COND_None, REPNOTIFY_Always);
        DOREPLIFETIME_CONDITION_NOTIFY(UBaseAttributeSet, Armor,        COND_None, REPNOTIFY_Always);
        DOREPLIFETIME_CONDITION_NOTIFY(UBaseAttributeSet, MovementSpeed,COND_None, REPNOTIFY_Always);
        DOREPLIFETIME_CONDITION_NOTIFY(UBaseAttributeSet, Stamina,      COND_None, REPNOTIFY_Always);
        DOREPLIFETIME_CONDITION_NOTIFY(UBaseAttributeSet, MaxStamina,   COND_None, REPNOTIFY_Always);
        DOREPLIFETIME_CONDITION_NOTIFY(UBaseAttributeSet, AttackPower,  COND_None, REPNOTIFY_Always);
        DOREPLIFETIME_CONDITION_NOTIFY(UBaseAttributeSet, CritChance,   COND_None, REPNOTIFY_Always);
        DOREPLIFETIME_CONDITION_NOTIFY(UBaseAttributeSet, CritDamage,   COND_None, REPNOTIFY_Always);
    }
    ```
    *Проверка:* Для каждого атрибута из шага 5.3 (кроме мета) есть соответствующая строка `DOREPLIFETIME_CONDITION_NOTIFY`. **Выполнено.**

7.  **Найдите реализации `OnRep_` функций**.
8.  **Убедитесь, что КАЖДАЯ** `OnRep_` функция вызывает макрос `GAMEPLAYATTRIBUTE_REPNOTIFY`. Этот макрос выполняет внутреннюю работу GAS по обновлению атрибута и вызову делегатов изменения на клиенте.

    ```cpp
    // FrameForge/Source/FrameForge/BaseAttributeSet.cpp
    ...
    // ---> Проверка 6: Вызов GAMEPLAYATTRIBUTE_REPNOTIFY в каждой OnRep_ функции <---
    void UBaseAttributeSet::OnRep_Health(const FGameplayAttributeData& OldHealth)             { GAMEPLAYATTRIBUTE_REPNOTIFY(UBaseAttributeSet, Health, OldHealth); }
    void UBaseAttributeSet::OnRep_MaxHealth(const FGameplayAttributeData& OldMaxHealth)       { GAMEPLAYATTRIBUTE_REPNOTIFY(UBaseAttributeSet, MaxHealth, OldMaxHealth); }
    // ... и так далее для всех реплицируемых атрибутов ...
    ```
    *Проверка:* Все `OnRep_` функции реализованы и вызывают `GAMEPLAYATTRIBUTE_REPNOTIFY`. **Выполнено.**
