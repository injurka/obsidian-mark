**Добавление Компонентов GAS**.

**Задача:** Добавить `UAbilitySystemComponent` (ASC) и базовый `UAttributeSet` к вашим C++ классам (`AFrameForgePlayerState`). Реализовать интерфейс `IAbilitySystemInterface` на Персонаже (`AFrameForgeCharacter`), чтобы он мог получать доступ к ASC из своего `PlayerState`.

**Зачем:**
*   **ASC - "Мозг" GAS:** `AbilitySystemComponent` управляет способностями, эффектами и тегами. Без него GAS не функционирует.
*   **AttributeSet - "Характеристики":** `AttributeSet` хранит числовые значения (Здоровье, Энергия и т.д.), на которые влияют Gameplay Effects.
*   **IAbilitySystemInterface - "Доступ":** Этот интерфейс предоставляет стандартный способ для любого актора (в нашем случае, Персонажа) сообщить системе, где находится его `AbilitySystemComponent`. Это необходимо для многих внутренних механик GAS и для удобства разработки.
*   **Правильное Владение:** Размещая ASC и AttributeSet в `APlayerState`, мы обеспечиваем их корректную работу и репликацию в мультиплеере, даже если Персонаж умирает и респавнится.

**GAS Компоненты (в контексте этого шага):** `UAbilitySystemComponent`, `UAttributeSet` (базовый класс), `IAbilitySystemInterface`.

**Шаг 3.3: Модификация AFrameForgeCharacter (Реализация Интерфейса)**

Персонажу нужно предоставить доступ к ASC, который находится в его PlayerState.

1.  **Откройте `FrameForgeCharacter.h`**.
2.  **Включите заголовок** интерфейса:
    ```cpp
    #include "AbilitySystemInterface.h"
    ```
3.  **Добавьте `IAbilitySystemInterface`** к списку наследования класса:
    ```cpp
    class FRAMEFORGE_API AFrameForgeCharacter : public ACharacter, public IAbilitySystemInterface // <--- Добавлено ", public IAbilitySystemInterface"
    ```
4.  **Объявите функцию интерфейса** (она должна быть `virtual` и `override`):
    ```cpp
    public: // Убедитесь, что она в public секции
        /** Реализация IAbilitySystemInterface */
        virtual class UAbilitySystemComponent* GetAbilitySystemComponent() const override;
    ```

5.  **Откройте `FrameForgeCharacter.cpp`**.
6.  **Включите заголовки** `FrameForgePlayerState` и `AbilitySystemComponent`:
    ```cpp
    #include "FrameForgePlayerState.h"
    #include "AbilitySystemComponent.h"
    ```
7.  **Реализуйте функцию `GetAbilitySystemComponent`**:
    ```cpp
    UAbilitySystemComponent* AFrameForgeCharacter::GetAbilitySystemComponent() const
    {
        // Получаем PlayerState
        AFrameForgePlayerState* PS = GetPlayerState<AFrameForgePlayerState>();

        // Проверяем, что PlayerState действителен и возвращаем его ASC
        // Если PlayerState невалиден (например, на ранних этапах инициализации или для AI без PlayerState), вернется nullptr
        if (PS)
        {
            return PS->GetAbilitySystemComponent();
        }

        // Возвращаем nullptr, если PlayerState не найден или не того типа
        UE_LOG(LogTemp, Warning, TEXT("AFrameForgeCharacter::GetAbilitySystemComponent: PlayerState is not valid or not AFrameForgePlayerState for %s"), *GetName());
        return nullptr;
    }
    ```
    *Эта реализация делегирует запрос к `PlayerState`, который является настоящим владельцем ASC.*
