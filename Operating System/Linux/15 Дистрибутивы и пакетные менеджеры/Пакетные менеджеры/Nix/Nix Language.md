Основы синтаксиса языка Nix

Nix — это **функциональный** и **ленивый** язык программирования.
*   **Функциональный:** В основном вы будете работать с неизменяемыми значениями и функциями, которые преобразуют одни значения в другие.
*   **Ленивый:** Выражения вычисляются только тогда, когда их результат действительно необходим. Это важная особенность, но на начальном этапе достаточно просто о ней помнить.

Язык Nix в основном предназначен для создания и манипулирования **структурами данных**, похожими на JSON, но с добавлением переменных, функций и некоторых других возможностей.

Давайте рассмотрим основные строительные блоки языка.

### 1. Комментарии

Как и в любом языке, вы можете оставлять комментарии, которые игнорируются интерпретатором Nix.

*   **Однострочные комментарии:** Начинаются с символа `#` и продолжаются до конца строки.
    ```nix
    # Это однострочный комментарий
    ```
*   **Многострочные комментарии:** Заключаются между `/*` и `*/`.
    ```nix
    /*
      Это многострочный комментарий.
      Он может занимать несколько строк.
    */
    ```

### 2. Основные (примитивные) типы значений

Nix оперирует различными типами данных. Вот самые простые из них:

*   **Строки (Strings):** Текстовые данные.
    *   Обычные строки заключаются в двойные кавычки (`"`). Специальные символы (например, `"` или `$`) нужно экранировать с помощью обратного слеша (`\`).
        ```nix
        "Привет, Nix!"
        "Это строка с \"кавычками\" внутри."
        "Путь: /home/user"
        "Переменная ${переменная} будет интерполирована (об этом позже)."
        ```
    *   "Indented strings" (строки с отступом) заключаются в две одинарные кавычки (`''`). Они удобны для многострочного текста и не требуют экранирования большинства символов, кроме `${` и `''`. Начальные отступы (пробелы), общие для всех строк (кроме первой), удаляются.
        ```nix
        ''
          Это многострочный текст.
            Отступы сохраняются относительно
          минимального отступа.
          Символы вроде " и \ экранировать не нужно.
        ''
        ```

*   **Числа (Numbers):**
    *   Целые числа (Integers): `10`, `0`, `-5`.
    *   Числа с плавающей точкой (Floats): `3.14`, `-0.5`, `1.0`. Используется точка `.` в качестве разделителя.

*   **Булевы значения (Booleans):**
    *   `true` (истина)
    *   `false` (ложь)
    *   *Важно:* Значения чувствительны к регистру. `True` или `FALSE` не являются валидными булевыми значениями.

*   **Null:**
    *   `null` представляет отсутствие значения (похоже на `null` в JSON или `None` в Python).

*   **Пути (Paths):**
    *   Литералы путей представляют собой пути в файловой системе. Они записываются как есть, но должны быть абсолютными (`/path/to/file`) или относительными к текущему файлу Nix (`./relative/path`, `../other/path`). Можно использовать `~/` для домашней директории (Nix подставит правильный путь).
        ```nix
        /etc/nixos/configuration.nix
        ./my-module.nix
        ../images/logo.png
        ~/Downloads/file.zip
        ```
    *   *Важно:* Когда путь используется в контексте сборки (деривации), Nix обычно копирует этот файл или директорию в `/nix/store`, чтобы гарантировать чистоту и воспроизводимость сборки.

### 3. Составные типы значений

*   **Списки (Lists):**
    *   Упорядоченная последовательность значений, заключенная в квадратные скобки `[ ]`.
    *   Элементы списка разделяются **пробелами** (не запятыми!).
    *   Списки могут содержать значения разных типов.
        ```nix
        [ 1 2 3 4 ]                         # Список целых чисел
        [ "apple" "banana" "cherry" ]     # Список строк
        [ true false true ]                 # Список булевых значений
        [ 1 "two" false ./file.txt null ] # Список со смешанными типами
        [ ]                                 # Пустой список
        [ [1 2] ["a" "b"] ]               # Список списков
        ```

*   **Множества Атрибутов (Attribute Sets или Attrsets):**
    *   Это **ключевая** структура данных в Nix! Похожа на объекты в JavaScript, словари в Python или карты в других языках.
    *   Представляет собой неупорядоченную коллекцию пар "ключ-значение".
    *   Заключаются в фигурные скобки `{ }`.
    *   Каждая пара состоит из имени атрибута (ключа), знака равенства `=` и значения.
    *   Пары ключ-значение **обязательно** разделяются точкой с запятой `;`.
    *   Ключи обычно являются идентификаторами (начинаются с буквы или `_`, содержат буквы, цифры, `_`, `-`). Если ключ содержит другие символы или совпадает с ключевым словом, его нужно заключать в двойные кавычки (как строку).
        ```nix
        {
          name = "my-package";             # Ключ 'name', значение - строка
          version = "1.2.3";               # Ключ 'version', значение - строка
          enabled = true;                  # Ключ 'enabled', значение - булево
          count = 10;                      # Ключ 'count', значение - число
          dependencies = [ "pkg1" "pkg2" ]; # Ключ 'dependencies', значение - список
          settings = {                     # Ключ 'settings', значение - другое множество
            port = 8080;
            host = "localhost";
          };
          "key-with-hyphens" = null;       # Ключ - строка, значение - null
        } # <--- Фигурная скобка закрывает множество

        {} # Пустое множество атрибутов
        ```
    *   **Доступ к значениям:** Значения из множества атрибутов извлекаются с помощью **точечной нотации** (`set.key`).
        ```nix
        let
          config = { host = "example.com"; port = 443; };
        in
          config.host # Результат: "example.com"
        ```
        (Мы подробнее рассмотрим `let ... in ...` в следующем разделе).

### Краткий итог

Мы рассмотрели самые базовые элементы синтаксиса Nix:
*   Комментарии (`#`, `/* */`)
*   Примитивные типы: строки (`"..."`, `''...''`), числа (`123`, `1.23`), булевы (`true`, `false`), `null`, пути (`/path`, `./path`).
*   Составные типы: списки (`[ val1 val2 ]`), множества атрибутов (`{ key1 = val1; key2 = val2; }`).

Множества атрибутов и списки являются основными структурами, которые вы будете использовать для описания конфигураций и пакетов в NixOS. Понимание их синтаксиса — первый шаг к освоению языка Nix. В следующих разделах мы рассмотрим, как эти элементы взаимодействуют друг с другом с помощью переменных, функций и встроенных возможностей Nix.

Встроенные функции (import, builtins.*)

В предыдущем разделе мы познакомились с базовыми типами данных и синтаксисом языка Nix. Теперь давайте рассмотрим "инструменты", которые предоставляет сам язык для работы с этими данными и взаимодействия с окружением — **встроенные функции** (built-in functions или просто builtins).

### Что такое встроенные функции?

Встроенные функции — это функции, которые являются частью самого интерпретатора Nix. Вам не нужно их определять или подключать из каких-то библиотек (как, например, функции из `nixpkgs`, о которых мы поговорим позже). Они доступны "из коробки" и предоставляют базовые возможности, необходимые для написания Nix-выражений.

Два основных способа доступа к встроенным функциям — это специальная функция `import` и пространство имен `builtins`.

### 1. `import`: Загрузка Nix-выражений из файлов

Одной из самых часто используемых встроенных конструкций является `import`. Технически это не совсем функция в том же смысле, что и функции в `builtins`, а скорее специальная языковая конструкция, но ведет она себя похоже.

*   **Назначение:** `import` используется для загрузки и вычисления содержимого другого `.nix` файла. Это позволяет разбивать сложные конфигурации или описания пакетов на более мелкие, управляемые части.
*   **Синтаксис:**
    ```nix
    import <путь_к_файлу>
    ```
    Где `<путь_к_файлу>` — это путь к другому `.nix` файлу. Путь может быть:
    *   **Абсолютным:** Начинается с `/`, например, `/etc/nixos/my-settings.nix`.
    *   **Относительным:** Начинается с `./` или `../`, например, `./modules/networking.nix`. Относительные пути разрешаются *относительно местоположения файла, в котором находится сам `import`*.
    *   **Путь из Nix search path:** Начинается с `<` и `>` (например, `<nixpkgs>`). Об этом подробнее позже, когда будем говорить про каналы и Flakes.

*   **Что возвращает `import`?** Он возвращает *результат вычисления* выражения, содержащегося в импортируемом файле. Обычно Nix-файлы, предназначенные для импорта, содержат одно основное выражение, часто это множество атрибутов (attrset) или функция.

*   **Пример:**
    Предположим, у нас есть файл `settings.nix` с таким содержимым:
    ```nix
    # Файл: settings.nix
    {
      host = "my-server.com";
      port = 8080;
      enableFeatureX = true;
    }
    ```
    В другом файле (`main.nix`, находящемся в той же директории) мы можем импортировать эти настройки:
    ```nix
    # Файл: main.nix
    let
      # Импортируем содержимое settings.nix
      mySettings = import ./settings.nix;
    in
      # Теперь можно использовать значения из импортированного файла
      "Connecting to ${mySettings.host} on port ${toString mySettings.port}"
      # Результат вычисления этого файла будет строка:
      # "Connecting to my-server.com on port 8080"
    ```

*   **Важно:** `import` **вычисляет** импортируемый файл. Если в файле есть какие-то операции, они будут выполнены в момент импорта.

### 2. Пространство имен `builtins`

Большинство других встроенных функций доступны через специальное встроенное множество атрибутов (attrset) под названием `builtins`. Чтобы вызвать такую функцию, вы используете точечную нотацию: `builtins.<имя_функции>`.

Использование `builtins.` помогает избежать конфликтов имен и явно указывает, что вызывается именно встроенная функция языка, а не функция, определенная где-то еще (например, в `nixpkgs` или вашем коде).

Вот несколько категорий и примеров часто используемых встроенных функций из `builtins`:

*   **Проверка типов:** Позволяют узнать тип значения.
    *   `builtins.isAttrs <значение>`: Возвращает `true`, если значение - множество атрибутов, иначе `false`.
    *   `builtins.isList <значение>`: Возвращает `true`, если значение - список.
    *   `builtins.isString <значение>`: Возвращает `true`, если значение - строка.
    *   `builtins.isFunction <значение>`: Возвращает `true`, если значение - функция.
    *   `builtins.isNull <значение>`: Возвращает `true`, если значение - `null`.
    *   `builtins.isInt <значение>`: Возвращает `true`, если значение - целое число.
    *   *(и другие `is*` функции)*
    ```nix
    builtins.isAttrs { a = 1; }  # -> true
    builtins.isList [ 1 2 ]    # -> true
    builtins.isString "hello"  # -> true
    builtins.isString 123      # -> false
    ```

*   **Преобразование типов:**
    *   `builtins.toString <значение>`: Преобразует значение (например, число, булево значение, путь) в строку.
    *   `builtins.toJSON <значение>`: Конвертирует Nix-значение (множество, список и т.д.) в строку формата JSON.
    *   `builtins.fromJSON <строка>`: Парсит строку JSON и возвращает соответствующее Nix-значение.
    ```nix
    builtins.toString 123       # -> "123"
    builtins.toString true      # -> "1" (исторически так, будьте внимательны!)
    builtins.toString /etc/nixos # -> "/etc/nixos" (копирует путь в store при сборке)
    builtins.toJSON { a = [1 "b"]; } # -> "{\"a\":[1,\"b\"]}"
    ```

*   **Работа с множествами атрибутов (Attrsets):**
    *   `builtins.attrNames <множество>`: Возвращает список строк с именами атрибутов (ключами) множества, отсортированный лексикографически.
    *   `builtins.attrValues <множество>`: Возвращает список значений атрибутов множества, в порядке, соответствующем `attrNames`.
    *   `builtins.hasAttr <имя_атрибута> <множество>`: Возвращает `true`, если множество содержит атрибут с указанным именем (имя передается как строка).
    *   `builtins.getAttr <имя_атрибута> <множество>`: Возвращает значение атрибута с указанным именем. В отличие от `set.attr`, позволяет использовать имя атрибута из переменной. Вызывает ошибку, если атрибута нет.
    ```nix
    let data = { name = "Nix"; year = 2003; };
    in builtins.attrNames data    # -> [ "name" "year" ]
    in builtins.attrValues data   # -> [ "Nix" 2003 ]
    in builtins.hasAttr "year" data # -> true
    in builtins.getAttr "name" data # -> "Nix"
    ```

*   **Работа со списками:**
    *   `builtins.length <список>`: Возвращает количество элементов в списке.
    *   `builtins.elemAt <список> <индекс>`: Возвращает элемент списка по индексу (индексация с 0).
    *   *(и другие, например, `map`, `filter`, `foldl'` - хотя часто используются аналоги из `lib` в `nixpkgs`)*
    ```nix
    builtins.length [ 10 20 30 ] # -> 3
    builtins.elemAt [ "a" "b" "c" ] 1 # -> "b"
    ```

*   **Работа с файловой системой и путями:**
    *   `builtins.readFile <путь>`: Читает содержимое файла и возвращает его как строку.
    *   `builtins.pathExists <путь>`: Возвращает `true`, если файл или директория по указанному пути существует.
    *   `builtins.toPath <строка>`: Преобразует строку, содержащую путь, в значение типа "путь".
    ```nix
    # Предположим, файл ./message.txt содержит "Hello"
    builtins.readFile ./message.txt # -> "Hello"
    builtins.pathExists /etc/nixos # -> true (обычно)
    ```

*   **Получение данных из внешних источников (Fetching):**
    *   `builtins.fetchGit <url>` или `builtins.fetchGit { url = ...; rev = ...; }`: Скачивает репозиторий Git и возвращает путь к нему в `/nix/store`.
    *   `builtins.fetchTarball <url>`: Скачивает и распаковывает архив tarball, возвращает путь к содержимому в `/nix/store`.
    *   *(и другие `fetch*` функции)* Эти функции критически важны для получения исходного кода пакетов. Они гарантируют воспроизводимость, часто требуя указания хеша содержимого.
    ```nix
    # Пример (может потребоваться хеш для чистоты):
    builtins.fetchTarball "https://example.com/source.tar.gz"
    ```

*   **Хеширование:**
    *   `builtins.hashString <алгоритм> <строка>`: Вычисляет хеш строки с использованием указанного алгоритма (например, `"sha256"`).
    ```nix
    builtins.hashString "sha256" "hello nix"
    # -> "1sh3mwn05w1n38fyj1dr6sy9ym35c9n62x2ihq4q3fz4gxp28kzm" (примерный результат)
    ```

*   **Информация об окружении:**
    *   `builtins.currentSystem`: Возвращает строку, идентифицирующую текущую систему (например, `"x86_64-linux"` или `"aarch64-darwin"`).
    *   `builtins.currentTime`: Возвращает текущее время как целое число (количество секунд с начала эпохи Unix). *Использование этой функции делает выражение **нечистым** (impure), так как результат меняется со временем.*

*   **Отладка и ошибки:**
    *   `builtins.trace <значение_для_отслеживания> <выражение>`: При вычислении `<выражение>`, печатает строковое представление `<значение_для_отслеживания>` в stderr, а затем возвращает результат вычисления `<выражение>`. Очень полезно для отладки.
    *   `builtins.abort <строка_ошибки>`: Прерывает вычисление и выводит сообщение об ошибке.
    ```nix
    let x = 5; y = 10;
    in builtins.trace "Промежуточное значение y: ${toString y}" (x + y)
    # Напечатает: trace: Промежуточное значение y: 10
    # Вернет: 15

    # builtins.abort "Что-то пошло не так!" # Прервет выполнение
    ```

Локальные переменные (`let ... in ...`)

Когда Nix-выражения становятся сложнее, может возникнуть необходимость использовать промежуточные результаты вычислений или дать имена определенным значениям, чтобы сделать код более читаемым и избежать повторений. Для этого в языке Nix существует специальная конструкция `let ... in ...`.

### Что такое `let ... in ...`?

Конструкция `let ... in ...` позволяет определить **локальные переменные** (часто их называют **привязками** или **bindings**), которые будут доступны только внутри определенной части вашего кода. Она помогает структурировать код и повысить его читаемость.

### Синтаксис

Базовая структура выглядит так:

```nix
let
  # Здесь определяются переменные (привязки)
  имя_переменной_1 = выражение_1;
  имя_переменной_2 = выражение_2;
  # ... другие переменные ...
  имя_переменной_N = выражение_N; # Точка с запятой обязательна после каждой привязки!
in
  # Здесь идет основное выражение, которое будет вычислено
  # и станет результатом всей конструкции let ... in ...
  # В этом выражении можно использовать переменные, определенные выше.
  тело_выражения
```

**Разберем по частям:**

1.  **`let`**: Ключевое слово, которое начинает блок определения локальных переменных.
2.  **Блок определений (bindings)**: Между `let` и `in` вы определяете одну или несколько переменных.
    *   Каждое определение состоит из имени переменной, знака равенства (`=`) и Nix-выражения, результат вычисления которого будет присвоен этой переменной.
    *   **Крайне важно:** Каждое определение переменной должно заканчиваться точкой с запятой (`;`).
    *   Имена переменных подчиняются тем же правилам, что и ключи в множествах атрибутов (обычно начинаются с буквы или `_`, содержат буквы, цифры, `_`, `-`).
3.  **`in`**: Ключевое слово, которое разделяет блок определений переменных и основное тело выражения.
4.  **Тело выражения (body)**: Это Nix-выражение, которое следует за `in`.
    *   Внутри этого выражения вы можете использовать все переменные, определенные в `let`-блоке.
    *   Результат вычисления этого `тела_выражения` является результатом *всей* конструкции `let ... in ...`.

### Область видимости (Scope)

Переменные, определенные внутри `let`-блока, являются **локальными**. Это означает, что они видны и доступны **только** внутри `тела_выражения`, следующего за `in`. Они не существуют за пределами конструкции `let ... in ...`.

```nix
let
  message = "Hello";
in
  message + ", Nix!" # -> "Hello, Nix!"

# Здесь переменная 'message' уже недоступна.
# Попытка использовать 'message' здесь приведет к ошибке "undefined variable 'message'".
```

### Примеры использования

1.  **Простые вычисления:**

    ```nix
    let
      a = 5;
      b = 10;
      sum = a + b;
    in
      "Сумма ${toString a} и ${toString b} равна ${toString sum}"
    # Результат: "Сумма 5 и 10 равна 15"
    ```

2.  **Избегание повторений:**

    ```nix
    let
      userName = "alice";
      homeDir = "/home/${userName}";
      configPath = "${homeDir}/.config/my-app";
      dataPath = "${homeDir}/.local/share/my-app";
    in
      {
        # Множество атрибутов, использующее определенные переменные
        user = userName;
        configurationFile = configPath;
        dataDirectory = dataPath;
        # Можно использовать переменные прямо внутри строк
        welcomeMessage = "Добро пожаловать, ${userName}! Ваши данные в ${dataPath}";
      }
    ```
    Без `let ... in ...` пришлось бы повторять `/home/alice` несколько раз.

3.  **Взаимная зависимость переменных:** Переменные внутри одного `let`-блока могут ссылаться друг на друга, причем порядок их определения не важен (из-за ленивой природы Nix).

    ```nix
    let
      appName = "super-editor";
      version = "1.2.3";
      packageName = "${appName}-${version}"; # Использует appName и version
    in
      packageName
    # Результат: "super-editor-1.2.3"
    ```

    ```nix
    # Порядок не важен:
    let
      fullName = "${firstName} ${lastName}"; # Использует firstName и lastName
      firstName = "Jane";
      lastName = "Doe";
    in
      fullName
    # Результат: "Jane Doe"
    ```

### Ключевые характеристики `let ... in ...`

*   **Локальность:** Переменные видны только внутри `in`-блока.
*   **Неизменяемость (Immutability):** После определения значение переменной в `let`-блоке не может быть изменено. Это определения, а не изменяемые присваивания, как в императивных языках.
*   **Рекурсивность (Recursion):** Переменные в одном `let`-блоке могут ссылаться друг на друга.
*   **Ленивость (Laziness):** Значение переменной вычисляется только тогда, когда оно действительно требуется в `in`-части. Если переменная определена, но никогда не используется в `in`-блоке, ее значение даже не будет вычислено.
*   **`let ... in ...` само по себе является выражением:** Всю конструкцию `let ... in ...` можно использовать везде, где ожидается Nix-выражение (например, как значение атрибута в множестве или как элемент списка).

```nix
{
  calculationResult = let x = 10; y = 20; in x * y; # let...in как значение атрибута
  message = let name = "Bob"; in "User: ${name}";
}
```

### Заключение

Конструкция `let ... in ...` — это ваш основной инструмент для создания локальных переменных в Nix. Она помогает разбить сложные вычисления на управляемые шаги, дать понятные имена промежуточным значениям и сделать ваш Nix-код значительно более чистым, понятным и поддерживаемым. Вы будете встречать и использовать `let ... in ...` повсеместно при работе с Nix и NixOS.

Определение и использование функций

Функции — это фундаментальный строительный блок в языке Nix. Они позволяют инкапсулировать логику, создавать абстракции и повторно использовать код. Поскольку Nix — это функциональный язык, понимание работы с функциями имеет решающее значение.

### Что такое функция в Nix?

Как и в других языках программирования, функция в Nix — это блок кода, который:
1.  Принимает ноль или больше входных значений (аргументов).
2.  Выполняет некоторые вычисления на основе этих аргументов.
3.  Возвращает одно результирующее значение.

Ключевая особенность Nix — функции являются **значениями первого класса**. Это значит, что их можно:
*   Присваивать переменным.
*   Передавать как аргументы другим функциям.
*   Возвращать как результат из других функций.
*   Хранить в списках или множествах атрибутов.

### Определение функций

#### 1. Простейшая форма: один аргумент

Самый базовый синтаксис для определения функции:

```nix
имя_аргумента: тело_функции
```

*   `имя_аргумента`: Имя, под которым входное значение будет доступно внутри функции.
*   `: `: Двоеточие разделяет имя аргумента и тело функции.
*   `тело_функции`: Nix-выражение, которое вычисляется при вызове функции. Результат этого выражения и будет результатом работы функции.

**Пример:** Функция, которая добавляет 1 к своему аргументу:

```nix
x: x + 1
```

Чтобы использовать эту функцию, ей обычно дают имя с помощью `let ... in ...` или определяют как атрибут множества:

```nix
let
  # Присваиваем имя 'addOne' нашей функции
  addOne = x: x + 1;
in
  # Теперь используем функцию с именем 'addOne'
  addOne 5 # Результат будет 6
```

#### 2. Функции, принимающие множество атрибутов (Attrset) - Самый частый случай!

Очень распространенный и идиоматичный для Nix способ определения функций — это когда функция ожидает на входе **одно** значение, которое является **множеством атрибутов (attrset)**. Вместо того чтобы просто дать имя всему множеству, можно сразу "распаковать" (деструктурировать) нужные атрибуты из него.

```nix
{ аргумент1, аргумент2, ... }: тело_функции
```

*   Фигурные скобки `{ ... }` в позиции аргумента указывают, что функция ожидает множество атрибутов.
*   `аргумент1`, `аргумент2`, ... — это имена **ключей**, которые функция ожидает найти в переданном ей множестве. Значения этих ключей станут локальными переменными внутри тела функции.

**Пример:** Функция, которая формирует строку приветствия, используя имя и возраст из входного множества.

```nix
let
  generateGreeting = { name, age }: "Привет, ${name}! Тебе ${toString age} лет.";
in
  # Вызываем функцию, передавая ей множество атрибутов
  generateGreeting { name = "Алиса"; age = 30; }
  # Результат: "Привет, Алиса! Тебе 30 лет."
```

#### 3. Значения по умолчанию для аргументов

При использовании паттерна с множеством атрибутов можно указать значения по умолчанию для аргументов с помощью знака вопроса `?`. Если при вызове функции соответствующий атрибут в множестве не будет передан, будет использовано значение по умолчанию.

```nix
{ аргумент1 ? значение_по_умолчанию1, аргумент2 ? значение_по_умолчанию2 }: тело_функции
```

**Пример:** Функция для создания URL, с хостом и портом по умолчанию.

```nix
let
  makeUrl = { host ? "localhost", port ? 80, path ? "/" }:
    "http://${host}:${toString port}${path}";
in
  # Вызовы:
  makeUrl { host = "example.com"; port = 443; } # -> "http://example.com:443/"
  makeUrl { host = "test.org"; }               # -> "http://test.org:80/" (port и path по умолчанию)
  makeUrl {}                                   # -> "http://localhost:80/" (все по умолчанию)
```

#### 4. Принятие любых аргументов (`...`)

Иногда нужно определить функцию, которая принимает множество атрибутов, но вас интересуют только некоторые из них, а остальные нужно либо игнорировать, либо передать дальше. Для этого используется многоточие `...`.

```nix
{ аргумент1, аргумент2, ... }: тело_функции
```

Это означает: "Функция ожидает множество атрибутов, из которого нужно извлечь `аргумент1` и `аргумент2`. Любые другие атрибуты в этом множестве тоже допустимы, но они не будут доступны как отдельные переменные внутри функции (если только не использовать `@` паттерн, см. ниже)."

**Пример:** Функция, которая извлекает информацию о пользователе, игнорируя остальные данные.

```nix
let
  getUserInfo = { name, email, ... }: { user = name; contact = email; };
in
  getUserInfo { name = "Боб"; age = 42; email = "bob@example.com"; city = "Nixville"; }
  # Результат: { user = "Боб"; contact = "bob@example.com"; }
  # Атрибуты age и city были приняты, но проигнорированы в теле функции.
```

#### 5. Доступ ко всему множеству аргументов (`@` паттерн)

Что если вы хотите и распаковать некоторые аргументы, и иметь доступ ко всему исходному множеству атрибутов, которое было передано функции? Для этого используется `@`-паттерн:

```nix
имя_для_всего_множества @ { аргумент1, аргумент2, ... }: тело_функции
```

*   `имя_для_всего_множества`: Переменная, которая будет содержать всё входное множество атрибутов.
*   `{ аргумент1, аргумент2, ... }`: Распаковка нужных атрибутов, как и раньше.

**Пример:** Функция для получения исходного кода, которая требует `url` и `rev`, но передает все аргументы (включая `url`, `rev` и, возможно, другие, вроде `sha256`) во встроенную функцию `fetchGit`.

```nix
# Функция принимает множество, извлекает url и rev,
# но передает все исходное множество 'attrs' дальше.
let fetch = attrs @ { url, rev, ... }: builtins.fetchGit attrs;
in fetch { url = "https://github.com/NixOS/nix.git"; rev = "2.18.1"; sha256 = "..."; }
```

#### 6. Функции с несколькими аргументами (Currying)

Технически, все функции в Nix принимают ровно один аргумент. Как же тогда работать с несколькими аргументами? Nix использует технику, называемую **каррирование (currying)**. Функция, которая "выглядит" так, будто принимает несколько аргументов, на самом деле является функцией, принимающей первый аргумент и возвращающей *новую функцию*, которая принимает второй аргумент, и так далее.

```nix
арг1: арг2: арг3: тело_функции_использующее_арг1_арг2_арг3
```

**Пример:** Функция умножения двух чисел.

```nix
let
  multiply = x: y: x * y;
  # Это эквивалентно: multiply = x: (y: x * y);
  # multiply - это функция, которая принимает x и возвращает НОВУЮ функцию (y: x * y)

  multiplyBy5 = multiply 5; # multiplyBy5 теперь функция (y: 5 * y)
in
  # Вызовы:
  multiply 3 4        # -> 12 (Передаем оба аргумента последовательно)
  multiplyBy5 10      # -> 50 (Используем частично примененную функцию)
```

Хотя каррирование является основой, на практике для функций с несколькими *именованными* параметрами почти всегда используется паттерн с множеством атрибутов (`{ arg1, arg2, ... }: ...`), так как он более читаем и гибок (порядок аргументов не важен, легко добавлять умолчания).

### Использование (вызов) функций

Вызов функции в Nix очень прост: нужно написать имя функции, а затем через **пробел** передать ей аргумент. Скобки вокруг аргумента нужны только для управления порядком вычислений или если сам аргумент является сложным выражением, требующим группировки.

```nix
имя_функции аргумент
```

**Примеры вызовов:**

```nix
let
  addOne = x: x + 1;
  generateGreeting = { name, age }: "Привет, ${name}! Тебе ${toString age} лет.";
  multiply = x: y: x * y;
in
[ # Создаем список результатов вызовов

  # 1. Вызов функции с одним простым аргументом
  addOne 10                       # -> 11

  # 2. Вызов функции, ожидающей множество атрибутов
  generateGreeting { name = "Карл"; age = 25; } # -> "Привет, Карл! Тебе 25 лет."

  # 3. Вызов каррированной функции
  multiply 6 7                    # -> 42

  # 4. Частичное применение каррированной функции
  (multiply 5) 8                  # -> 40 (Сначала multiply 5 создает новую функцию, потом ей передается 8)

  # 5. Передача результата одной функции как аргумента другой
  addOne (multiply 2 3)           # -> addOne 6 -> 7

]
```

### Заключение

Функции — это мощный инструмент в Nix для создания абстрактных, повторно используемых и декларативных описаний. Наиболее распространенным способом определения функций, особенно для конфигураций и пакетов, является использование множества атрибутов в качестве аргумента (`{ arg1, arg2 ? defaultValue, ... }:`). Понимание того, как определять и вызывать функции, является ключевым шагом к мастерству владения языком Nix.

Концепция дериваций

До сих пор мы рассматривали язык Nix как способ описания данных — списков, множеств атрибутов, строк, функций. Теперь мы подходим к тому, *как* Nix использует эти описания для построения реальных программ, библиотек и компонентов системы. Центральную роль в этом процессе играют **деривации (derivations)**.

### Что такое деривация?

Представьте себе очень подробный, точный и неизменный **рецепт** для создания какого-либо программного компонента (пакета, конфигурационного файла, скрипта и т.д.). Этот рецепт содержит абсолютно всё, что нужно знать для его воспроизводимого приготовления:

1.  **Точные ингредиенты:** Какие конкретные версии исходного кода, зависимостей (других пакетов/библиотек), патчей и инструментов для сборки нужны. Важно, что это не просто "библиотека X", а "библиотека X, находящаяся по точному пути `/nix/store/hash-библиотека-X`".
2.  **Инструменты:** Какая программа будет выполнять "приготовление" (например, стандартная командная оболочка `/bin/sh`).
3.  **Пошаговая инструкция:** Детальный скрипт, описывающий все шаги сборки (распаковка исходников, применение патчей, конфигурирование, компиляция, установка).
4.  **Условия приготовления:** На какой архитектуре и операционной системе должна происходить сборка (например, `x86_64-linux` или `aarch64-darwin`).
5.  **Ожидаемый результат:** Как должен называться и где должен располагаться конечный продукт (уникальный путь в `/nix/store`).

Вот эта полная спецификация, этот "рецепт", и есть **деривация** в Nix.

**Ключевые моменты:**

*   **Деривация — это не сам пакет:** Это не скомпилированная программа или библиотека. Это *описание того, как* эту программу или библиотеку получить.
*   **Деривация — это значение в Nix:** В языке Nix деривация представляется как особый тип данных (обычно результат вызова функции `mkDerivation` или подобных).
*   **Деривация хранится в Nix Store:** Когда Nix "инстанциирует" деривацию, он создает специальный текстовый файл с расширением `.drv` в директории `/nix/store`. Например: `/nix/store/agy1wnq3zqv3q5q4n2f9kzzq6a7z9z1j-bash-5.2-p15.drv`. Этот `.drv` файл содержит всю информацию "рецепта" в сериализованном виде. Именно этот `.drv` файл Nix использует для выполнения сборки.
*   **Уникальность и чистота:** Путь к `.drv` файлу (и его содержимое) зависит от *всех* входов, упомянутых в рецепте. Любое изменение в исходниках, зависимостях, скрипте сборки или флагах компиляции приведет к созданию *новой*, другой деривации с другим хешем в имени файла. Это гарантирует, что каждая деривация точно описывает один конкретный процесс сборки.

### Как создаются деривации? Функция `mkDerivation`

Хотя можно было бы вручную описывать все детали деривации, это было бы очень утомительно и подвержено ошибкам. В экосистеме Nix, особенно в репозитории `nixpkgs` (огромной коллекции пакетов Nix), для создания дериваций используется стандартная **встроенная функция** (предоставляемая `nixpkgs`) под названием `mkDerivation`.

`mkDerivation` — это функция Nix, которая принимает на вход **множество атрибутов (attrset)**. Эти атрибуты описывают пакет на более высоком уровне, а `mkDerivation` уже сама генерирует детальный скрипт сборки и все остальные низкоуровневые детали для `.drv` файла.

**Типичные аргументы для `mkDerivation`:**

*   `pname` (или `name`): Название пакета (например, `"bash"`).
*   `version`: Версия пакета (например, `"5.2-p15"`).
*   `src`: Источник пакета. Обычно это результат вызова другой функции, скачивающей исходный код (например, `fetchurl`, `fetchgit`). Этот результат является путем в `/nix/store` к скачанным исходникам.
*   `buildInputs`: Список *других дериваций*, которые необходимы во время сборки пакета (например, компилятор `gcc`, инструмент `make`, библиотеки, от которых зависит пакет). Nix гарантирует, что все зависимости из `buildInputs` будут доступны во время выполнения скрипта сборки.
*   `nativeBuildInputs`: Список дериваций, необходимых для сборки, но только на системе сборки (например, `pkg-config`, `bison`). Актуально при кросс-компиляции.
*   `configureFlags`: Список строк, передаваемых скрипту `configure`.
*   `buildPhase`, `installPhase`, `checkPhase`, `fixupPhase`, etc.: Строки, содержащие shell-скрипты, которые переопределяют или дополняют стандартные фазы сборки (если стандартного поведения недостаточно).
*   `meta`: Множество атрибутов с метаданными о пакете (описание, лицензия, домашняя страница, платформа и т.д.).

**Упрощенный пример (концептуальный):**

```nix
# Это Nix-выражение, описывающее, как собрать пакет 'hello'
let
  pkgs = import <nixpkgs> {}; # Импортируем функции и пакеты из nixpkgs
in
pkgs.stdenv.mkDerivation { # Используем mkDerivation из стандартного окружения nixpkgs
  pname = "hello";
  version = "2.12.1";

  # Указываем, где взять исходный код
  src = pkgs.fetchurl {
    url = "mirror://gnu/hello/hello-2.12.1.tar.gz";
    sha256 = "sha256-hash-goes-here"; # Хеш для проверки целостности
  };

  # Указываем зависимости, необходимые для сборки
  buildInputs = [ pkgs.gettext ];

  # Метаданные (описание, лицензия и т.д.)
  meta = {
    description = "A program that produces a familiar, friendly greeting";
    homepage = "https://www.gnu.org/software/hello/";
    license = pkgs.lib.licenses.gpl3Plus; # Используем стандартные определения лицензий
  };
}
```

**Что происходит, когда Nix вычисляет это выражение?**

1.  Он *не собирает* пакет `hello` немедленно.
2.  Он вычисляет все входные данные для `mkDerivation` (включая скачивание `src`, если его еще нет в `/nix/store`, и вычисление дериваций для `buildInputs`).
3.  Функция `mkDerivation` генерирует полную спецификацию сборки.
4.  Nix создает (или находит в кеше) соответствующий `.drv` файл в `/nix/store`, например `/nix/store/xyz...-hello-2.12.1.drv`.
5.  Результатом всего Nix-выражения является *специальное значение*, представляющее эту деривацию (которое неявно ссылается на путь к `.drv` файлу).

### От деривации (`.drv`) к результату в `/nix/store`

Когда вы просите Nix *собрать* (или "реализовать") деривацию (например, командой `nix-build` или `nix build`), происходит следующее:

1.  Nix читает `.drv` файл.
2.  Он проверяет, существует ли уже в `/nix/store` (или в бинарном кеше) *ожидаемый выходной путь*, указанный внутри `.drv` файла (например, `/nix/store/abc...-hello-2.12.1`).
3.  **Если выходной путь существует (кеш):** Сборка не нужна! Nix просто возвращает этот путь. В этом сила кеширования Nix.
4.  **Если выходного пути нет:**
    *   Nix рекурсивно убеждается, что все *входные деривации* (зависимости из `buildInputs` и т.д.) уже собраны и их результаты доступны в `/nix/store`.
    *   Nix подготавливает изолированное, чистое окружение для сборки (обычно с помощью "песочницы" - sandbox). В этом окружении доступны только явно указанные в деривации зависимости и инструменты. Нет доступа к сети (кроме как для скачивания предопределенных источников) или к неявным файлам хост-системы.
    *   Он запускает указанный в деривации `builder` (обычно `/bin/sh`) и передает ему сгенерированный `mkDerivation` скрипт сборки.
    *   Скрипт выполняется в изолированном окружении.
    *   Если скрипт успешно завершается, его результаты (установленные файлы) помещаются в тот самый *ожидаемый выходной путь* в `/nix/store`, который был предопределен в `.drv` файле.
    *   Nix регистрирует этот путь как "валидный" в своей базе данных.

### Зачем всё это?

Концепция дериваций — это основа для главных преимуществ Nix:

*   **Воспроизводимость:** Поскольку деривация фиксирует *все* входы, сборка одной и той же деривации на разных машинах (той же архитектуры) или в разное время должна давать идентичный результат.
*   **Надежность:** Изолированная среда сборки предотвращает влияние случайных факторов хост-системы на результат.
*   **Кеширование:** Если деривация с точно такими же входами уже была собрана кем-то (например, на официальных серверах NixOS) и ее результат есть в бинарном кеше, вам не нужно собирать ее локально — Nix просто скачает готовый результат.
*   **Атомарность:** Сборка либо полностью успешна и результат помещается в `/nix/store`, либо неудачна и никаких следов в выходном пути не остается.

### Заключение

Деривация (`.drv` файл в `/nix/store`) — это формализованный, неизменяемый рецепт сборки программного компонента, сгенерированный из Nix-выражения (часто с помощью `mkDerivation`). Она содержит все необходимые инструкции, зависимости, инструменты и ожидаемый результат. Реализация деривации — это процесс выполнения этого рецепта в чистой среде для получения выходного артефакта в `/nix/store`. Понимание дериваций критически важно для понимания того, как Nix управляет пакетами и конфигурациями.


---

Отладка Nix-выражений (`nix repl`, `builtins.trace`)

Написание Nix-выражений, особенно сложных, неизбежно приводит к ситуациям, когда что-то идет не так или результат оказывается не тем, что вы ожидали. Отладка кода на функциональном и ленивом языке, как Nix, может иметь свои особенности. К счастью, Nix предоставляет несколько инструментов, которые помогут вам понять, что происходит внутри ваших выражений.

Два основных инструмента для отладки Nix-кода — это интерактивная среда `nix repl` и встроенная функция `builtins.trace`.

### 1. `nix repl`: Интерактивная среда (Read-Eval-Print Loop)

REPL (Read-Eval-Print Loop) — это интерактивная командная строка, которая позволяет вам вводить Nix-выражения, немедленно их вычислять (Eval), видеть результат (Print) и повторять этот цикл (Loop). Это отличный инструмент для:

*   Быстрых экспериментов с синтаксисом языка.
*   Проверки работы небольших функций или выражений.
*   Изучения структуры данных (списков, множеств).
*   Загрузки `.nix` файлов и исследования определенных в них значений.

#### Как запустить?

Просто выполните команду в вашем терминале:

```bash
nix repl
```

Вы увидите приглашение `nix-repl>`.

#### Основные возможности:

*   **Вычисление простых выражений:** Вводите любое валидное Nix-выражение и нажимайте Enter.
    ```nix
    nix-repl> 1 + 2
    3

    nix-repl> "Hello, " + "Nix!"
    "Hello, Nix!"

    nix-repl> [ 10 20 30 ]
    [ 10 20 30 ]

    nix-repl> { name = "NixOS"; stable = true; }
    { name = "NixOS"; stable = true; }
    ```

*   **Использование `let ... in ...`:** Можно определять локальные переменные.
    ```nix
    nix-repl> let a = 5; b = 10; in a * b
    50
    ```

*   **Определение и вызов функций:**
    ```nix
    nix-repl> double = x: x * 2
    «lambda @ /tmp/nix-repl-история/history:1:1»

    nix-repl> double 7
    14

    nix-repl> greet = { name ? "Anonymous" }: "Hello, ${name}!"

    nix-repl> greet {}
    "Hello, Anonymous!"

    nix-repl> greet { name = "Alice"; }
    "Hello, Alice!"
    ```
    *(Примечание: REPL может показать `«lambda...»` для обозначения функции).*

*   **Загрузка файла (`:l` или `:load`):** Самая мощная функция REPL — загрузка кода из файла. Значение, вычисленное из файла, становится доступным в REPL, обычно под именем `it` (если файл содержит множество) или напрямую, если файл возвращает функцию.
    Предположим, у вас есть файл `my-config.nix`:
    ```nix
    # my-config.nix
    {
      user = "testuser";
      packages = [ "git" "vim" ];
      settings = {
        theme = "dark";
        active = true;
      };
    }
    ```
    Теперь в `nix repl`:
    ```nix
    nix-repl> :l my-config.nix
    Added 3 variables.

    nix-repl> user
    "testuser"

    nix-repl> packages
    [ "git" "vim" ]

    nix-repl> settings.theme
    "dark"
    ```
    Если бы файл содержал `let ... in ...` или просто значение, оно было бы доступно под именем переменной или как результат. Если файл возвращает функцию, вы можете присвоить её переменной и вызывать.

*   **Автодополнение (Tab):** Попробуйте нажать Tab для автодополнения имен переменных и атрибутов.

*   **Просмотр встроенных функций (`builtins.` + Tab):** Наберите `builtins.` и нажмите Tab, чтобы увидеть список доступных встроенных функций.

#### Когда использовать `nix repl`?

`nix repl` идеально подходит для изоляции и проверки небольших частей вашего кода. Если вы не уверены, как работает конкретная функция Nix или как правильно составить выражение, REPL — ваш лучший друг для быстрых тестов. Он также незаменим для изучения содержимого файлов конфигурации или модулей.

### 2. `builtins.trace`: "printf-отладка" для Nix

Иногда проблема возникает глубоко внутри вычислений, например, при сборке пакета или применении конфигурации NixOS, и `nix repl` использовать неудобно. В таких случаях на помощь приходит `builtins.trace`.

Это встроенная функция, которая работает по принципу "printf-отладки": она печатает значение в консоль (точнее, в `stderr` - стандартный поток ошибок) во время вычисления, не изменяя при этом сам результат вычисления.

#### Синтаксис:

```nix
builtins.trace <значение_для_вывода> <выражение_для_возврата>
```

*   `<значение_для_вывода>`: Это значение будет преобразовано в строку и напечатано в `stderr` во время *вычисления*.
*   `<выражение_для_возврата>`: Это основное выражение, результат которого будет возвращен функцией `builtins.trace`. **Важно:** `trace` не меняет результат, он просто добавляет "побочный эффект" в виде вывода сообщения.

#### Как это работает:

Когда Nix доходит до вычисления `<выражение_для_возврата>`, он сначала вычисляет `<значение_для_вывода>`, печатает его строковое представление с префиксом `trace: ` и только потом возвращает результат вычисления `<выражение_для_возврата>`.

#### Пример:

```nix
let
  a = 5;
  b = 10;
  result = builtins.trace "Проверяем значение 'a': ${toString a}" (a + b);
in
  result * 2
```

При вычислении этого кода произойдет следующее:

1.  Nix начнет вычислять `result`.
2.  Дойдет до `builtins.trace`.
3.  Вычислит первый аргумент: `"Проверяем значение 'a': ${toString a}"` -> `"Проверяем значение 'a': 5"`.
4.  Напечатает в `stderr`: `trace: Проверяем значение 'a': 5`
5.  Вычислит второй аргумент: `a + b` -> `5 + 10` -> `15`.
6.  `builtins.trace` вернет `15`. Переменная `result` получит значение `15`.
7.  Будет вычислено `result * 2` -> `15 * 2` -> `30`.
8.  Конечный результат всего `let ... in ...` выражения будет `30`.

#### Советы по использованию `builtins.trace`:

*   **Осмысленные сообщения:** Не выводите просто значение, добавляйте поясняющий текст, чтобы понять, что именно вы отслеживаете. Используйте интерполяцию строк (`"${...}"`) и `builtins.toString`, если нужно.
*   **Вставляйте стратегически:** Размещайте `trace` в тех местах, где вы хотите проверить промежуточные значения или понять, какой путь выполнения выбирается (например, в ветках `if ... then ... else ...`).
*   **Отладка функций:** Используйте `trace` внутри функций, чтобы увидеть значения аргументов или промежуточные результаты.
    ```nix
    let
      processItem = item:
        let
          processed = builtins.trace "Обрабатываю элемент: ${item.name}" (item.value * 10);
        in
          { result = processed; };
    in
      processItem { name = "widget"; value = 5; }
    ```
    Вывод: `trace: Обрабатываю элемент: widget`
    Результат: `{ result = 50; }`
*   **Учитывайте ленивость:** `trace` сработает только тогда, когда значение, которое он "оборачивает", действительно понадобится для конечного результата. Если часть кода никогда не вычисляется, `trace` в ней не сработает. Иногда `trace` может срабатывать несколько раз, если значение используется в разных местах.
*   **Вывод в `stderr`:** Помните, что вывод `trace` идет в стандартный поток ошибок. При выполнении команд вроде `nixos-rebuild` вы увидите эти `trace:` сообщения среди прочего вывода сборки.

#### Когда использовать `builtins.trace`?

`builtins.trace` полезен, когда вам нужно заглянуть "внутрь" процесса вычисления, который нельзя легко воспроизвести в `nix repl`, например, во время сложной сборки пакета или применения конфигурации системы. Это основной способ понять поток данных и значения переменных в реальном времени.

### Другие советы по отладке

*   **Читайте сообщения об ошибках:** Nix часто выдает подробные сообщения об ошибках, включая трассировку стека, которая показывает, в каком файле и строке произошла проблема. Учитесь их читать!
*   **Упрощайте:** Если у вас сложное выражение, разбейте его на более мелкие части с помощью `let ... in ...`. Проверяйте каждую часть отдельно (возможно, с помощью `nix repl` или `builtins.trace`).
*   **`nix-instantiate --eval`:** Эта команда позволяет вычислить Nix-выражение из файла без интерактивного режима REPL. Полезно для быстрой проверки значения конкретного атрибута: `nix-instantiate --eval my-config.nix -A settings.theme`.

### Заключение

Отладка в Nix требует некоторой практики, но `nix repl` и `builtins.trace` предоставляют мощные средства для исследования и понимания ваших выражений. Используйте `nix repl` для интерактивных экспериментов и исследования структур, а `builtins.trace` — для отслеживания значений во время более сложных вычислений. Со временем и опытом вы научитесь быстро находить и исправлять ошибки в своем Nix-коде.
