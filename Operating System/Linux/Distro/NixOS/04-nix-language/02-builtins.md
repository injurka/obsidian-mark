Встроенные функции (import, builtins.*)

В предыдущем разделе мы познакомились с базовыми типами данных и синтаксисом языка Nix. Теперь давайте рассмотрим "инструменты", которые предоставляет сам язык для работы с этими данными и взаимодействия с окружением — **встроенные функции** (built-in functions или просто builtins).

### Что такое встроенные функции?

Встроенные функции — это функции, которые являются частью самого интерпретатора Nix. Вам не нужно их определять или подключать из каких-то библиотек (как, например, функции из `nixpkgs`, о которых мы поговорим позже). Они доступны "из коробки" и предоставляют базовые возможности, необходимые для написания Nix-выражений.

Два основных способа доступа к встроенным функциям — это специальная функция `import` и пространство имен `builtins`.

### 1. `import`: Загрузка Nix-выражений из файлов

Одной из самых часто используемых встроенных конструкций является `import`. Технически это не совсем функция в том же смысле, что и функции в `builtins`, а скорее специальная языковая конструкция, но ведет она себя похоже.

*   **Назначение:** `import` используется для загрузки и вычисления содержимого другого `.nix` файла. Это позволяет разбивать сложные конфигурации или описания пакетов на более мелкие, управляемые части.
*   **Синтаксис:**
    ```nix
    import <путь_к_файлу>
    ```
    Где `<путь_к_файлу>` — это путь к другому `.nix` файлу. Путь может быть:
    *   **Абсолютным:** Начинается с `/`, например, `/etc/nixos/my-settings.nix`.
    *   **Относительным:** Начинается с `./` или `../`, например, `./modules/networking.nix`. Относительные пути разрешаются *относительно местоположения файла, в котором находится сам `import`*.
    *   **Путь из Nix search path:** Начинается с `<` и `>` (например, `<nixpkgs>`). Об этом подробнее позже, когда будем говорить про каналы и Flakes.

*   **Что возвращает `import`?** Он возвращает *результат вычисления* выражения, содержащегося в импортируемом файле. Обычно Nix-файлы, предназначенные для импорта, содержат одно основное выражение, часто это множество атрибутов (attrset) или функция.

*   **Пример:**
    Предположим, у нас есть файл `settings.nix` с таким содержимым:
    ```nix
    # Файл: settings.nix
    {
      host = "my-server.com";
      port = 8080;
      enableFeatureX = true;
    }
    ```
    В другом файле (`main.nix`, находящемся в той же директории) мы можем импортировать эти настройки:
    ```nix
    # Файл: main.nix
    let
      # Импортируем содержимое settings.nix
      mySettings = import ./settings.nix;
    in
      # Теперь можно использовать значения из импортированного файла
      "Connecting to ${mySettings.host} on port ${toString mySettings.port}"
      # Результат вычисления этого файла будет строка:
      # "Connecting to my-server.com on port 8080"
    ```

*   **Важно:** `import` **вычисляет** импортируемый файл. Если в файле есть какие-то операции, они будут выполнены в момент импорта.

### 2. Пространство имен `builtins`

Большинство других встроенных функций доступны через специальное встроенное множество атрибутов (attrset) под названием `builtins`. Чтобы вызвать такую функцию, вы используете точечную нотацию: `builtins.<имя_функции>`.

Использование `builtins.` помогает избежать конфликтов имен и явно указывает, что вызывается именно встроенная функция языка, а не функция, определенная где-то еще (например, в `nixpkgs` или вашем коде).

Вот несколько категорий и примеров часто используемых встроенных функций из `builtins`:

*   **Проверка типов:** Позволяют узнать тип значения.
    *   `builtins.isAttrs <значение>`: Возвращает `true`, если значение - множество атрибутов, иначе `false`.
    *   `builtins.isList <значение>`: Возвращает `true`, если значение - список.
    *   `builtins.isString <значение>`: Возвращает `true`, если значение - строка.
    *   `builtins.isFunction <значение>`: Возвращает `true`, если значение - функция.
    *   `builtins.isNull <значение>`: Возвращает `true`, если значение - `null`.
    *   `builtins.isInt <значение>`: Возвращает `true`, если значение - целое число.
    *   *(и другие `is*` функции)*
    ```nix
    builtins.isAttrs { a = 1; }  # -> true
    builtins.isList [ 1 2 ]    # -> true
    builtins.isString "hello"  # -> true
    builtins.isString 123      # -> false
    ```

*   **Преобразование типов:**
    *   `builtins.toString <значение>`: Преобразует значение (например, число, булево значение, путь) в строку.
    *   `builtins.toJSON <значение>`: Конвертирует Nix-значение (множество, список и т.д.) в строку формата JSON.
    *   `builtins.fromJSON <строка>`: Парсит строку JSON и возвращает соответствующее Nix-значение.
    ```nix
    builtins.toString 123       # -> "123"
    builtins.toString true      # -> "1" (исторически так, будьте внимательны!)
    builtins.toString /etc/nixos # -> "/etc/nixos" (копирует путь в store при сборке)
    builtins.toJSON { a = [1 "b"]; } # -> "{\"a\":[1,\"b\"]}"
    ```

*   **Работа с множествами атрибутов (Attrsets):**
    *   `builtins.attrNames <множество>`: Возвращает список строк с именами атрибутов (ключами) множества, отсортированный лексикографически.
    *   `builtins.attrValues <множество>`: Возвращает список значений атрибутов множества, в порядке, соответствующем `attrNames`.
    *   `builtins.hasAttr <имя_атрибута> <множество>`: Возвращает `true`, если множество содержит атрибут с указанным именем (имя передается как строка).
    *   `builtins.getAttr <имя_атрибута> <множество>`: Возвращает значение атрибута с указанным именем. В отличие от `set.attr`, позволяет использовать имя атрибута из переменной. Вызывает ошибку, если атрибута нет.
    ```nix
    let data = { name = "Nix"; year = 2003; };
    in builtins.attrNames data    # -> [ "name" "year" ]
    in builtins.attrValues data   # -> [ "Nix" 2003 ]
    in builtins.hasAttr "year" data # -> true
    in builtins.getAttr "name" data # -> "Nix"
    ```

*   **Работа со списками:**
    *   `builtins.length <список>`: Возвращает количество элементов в списке.
    *   `builtins.elemAt <список> <индекс>`: Возвращает элемент списка по индексу (индексация с 0).
    *   *(и другие, например, `map`, `filter`, `foldl'` - хотя часто используются аналоги из `lib` в `nixpkgs`)*
    ```nix
    builtins.length [ 10 20 30 ] # -> 3
    builtins.elemAt [ "a" "b" "c" ] 1 # -> "b"
    ```

*   **Работа с файловой системой и путями:**
    *   `builtins.readFile <путь>`: Читает содержимое файла и возвращает его как строку.
    *   `builtins.pathExists <путь>`: Возвращает `true`, если файл или директория по указанному пути существует.
    *   `builtins.toPath <строка>`: Преобразует строку, содержащую путь, в значение типа "путь".
    ```nix
    # Предположим, файл ./message.txt содержит "Hello"
    builtins.readFile ./message.txt # -> "Hello"
    builtins.pathExists /etc/nixos # -> true (обычно)
    ```

*   **Получение данных из внешних источников (Fetching):**
    *   `builtins.fetchGit <url>` или `builtins.fetchGit { url = ...; rev = ...; }`: Скачивает репозиторий Git и возвращает путь к нему в `/nix/store`.
    *   `builtins.fetchTarball <url>`: Скачивает и распаковывает архив tarball, возвращает путь к содержимому в `/nix/store`.
    *   *(и другие `fetch*` функции)* Эти функции критически важны для получения исходного кода пакетов. Они гарантируют воспроизводимость, часто требуя указания хеша содержимого.
    ```nix
    # Пример (может потребоваться хеш для чистоты):
    builtins.fetchTarball "https://example.com/source.tar.gz"
    ```

*   **Хеширование:**
    *   `builtins.hashString <алгоритм> <строка>`: Вычисляет хеш строки с использованием указанного алгоритма (например, `"sha256"`).
    ```nix
    builtins.hashString "sha256" "hello nix"
    # -> "1sh3mwn05w1n38fyj1dr6sy9ym35c9n62x2ihq4q3fz4gxp28kzm" (примерный результат)
    ```

*   **Информация об окружении:**
    *   `builtins.currentSystem`: Возвращает строку, идентифицирующую текущую систему (например, `"x86_64-linux"` или `"aarch64-darwin"`).
    *   `builtins.currentTime`: Возвращает текущее время как целое число (количество секунд с начала эпохи Unix). *Использование этой функции делает выражение **нечистым** (impure), так как результат меняется со временем.*

*   **Отладка и ошибки:**
    *   `builtins.trace <значение_для_отслеживания> <выражение>`: При вычислении `<выражение>`, печатает строковое представление `<значение_для_отслеживания>` в stderr, а затем возвращает результат вычисления `<выражение>`. Очень полезно для отладки.
    *   `builtins.abort <строка_ошибки>`: Прерывает вычисление и выводит сообщение об ошибке.
    ```nix
    let x = 5; y = 10;
    in builtins.trace "Промежуточное значение y: ${toString y}" (x + y)
    # Напечатает: trace: Промежуточное значение y: 10
    # Вернет: 15

    # builtins.abort "Что-то пошло не так!" # Прервет выполнение
    ```
